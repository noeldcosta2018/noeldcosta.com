S/4HANA माइग्रेशन assessment आपको बताता है कि आपके ECC सिस्टम को ले जाने में कितनी लागत और कितना समय लगेगा, और कौन सा रास्ता सही बैठता है। SAP Readiness Check उस assessment का तकनीकी आधा हिस्सा है: यह आपके सिस्टम की तुलना S/4HANA से करता है और बताता है कि क्या टूटेगा, लेकिन यह आपके लिए फ़ैसले नहीं करता।

छोटा जवाब: पहले Readiness Check चलाइए, production में, custom code के नतीजे upload करके। फिर असली प्रयास उस पर लगाइए जो यह नहीं देख सकता, यानी कि क्या आपकी प्रक्रियाएँ, डेटा, custom objects और interfaces को आगे जाना भी चाहिए।

माइग्रेशन के पूरे क्रम के लिए मेरी [ECC से S/4HANA माइग्रेशन गाइड](/hi/ecc-to-s4hana-migration/) से शुरू कीजिए।

## SAP Readiness Check क्या है

SAP Readiness Check for SAP S/4HANA, SAP का एक cloud application है। आप अपने ECC सिस्टम में data collectors चलाते हैं, नतीजे upload करते हैं और एक interactive dashboard पाते हैं जो दिखाता है कि S/4HANA उस सिस्टम पर कैसे असर डालता है।

SAP के [Readiness Check key feature overview](https://help.sap.com/doc/bb0e7ba5158c424ab7ce010228bf1de1/latest/en-US/Key%20Feature%20Overview%20SAP%20Readiness%20Check.pdf) (सितंबर 2026) के अनुसार यह SAP for Me पर सक्रिय SAP maintenance agreement वाले सभी ग्राहकों को उपलब्ध है। SAP Cloud ALM tenant वाले ग्राहक इसे वहाँ भी चला सकते हैं, और निष्कर्षों को project tasks के रूप में Cloud ALM में भेज सकते हैं।

आप इसे अलग से नहीं खरीदते। असली लागत आपकी Basis टीम और नतीजे पढ़ने वाले लोगों का समय है।

SAP upgrades, BW/4HANA और दूसरे products के लिए अलग scenarios चलाता है। ECC माइग्रेशन के लिए आपको SAP Readiness Check for SAP S/4HANA चाहिए। Target, S/4HANA on-premise या SAP S/4HANA Cloud Private Edition हो सकता है, जो RISE with SAP का target है, जैसा कि [conversion की तैयारी पर SAP की learning content](https://learning.sap.com/courses/implementing-sap-s-4hana-cloud-private-edition/performing-system-preparation-activities-for-system-conversions_c131e647-d7d1-4887-a2ff-c01b25966a52) समझाती है।

## Readiness Check क्या कवर करता है

S/4HANA scenario के लिए SAP की मौजूदा list में 17 checks हैं। नीचे की table उन checks को समूहों में रखती है जो माइग्रेशन के फ़ैसले के लिए सबसे ज़्यादा मायने रखते हैं, साथ में यह कि हर एक क्या बताता है और कहाँ मैं सावधान रहूँगा।

| Check | यह आपको क्या बताता है | कहाँ सावधान रहें |
|---|---|---|
| Simplification items | आपके सिस्टम पर S/4HANA के कौन से बदलाव लागू होते हैं, effort ranking और संबंधित activities के साथ | ज़्यादातर table contents और इस्तेमाल हुए transactions पर आधारित, इसलिए यह प्रासंगिकता दिखाता है, आपका समाधान नहीं |
| Add-on compatibility | आपके target release के लिए हर SAP और third-party add-on compatible है, incompatible है या unknown | Incompatible add-ons, SUM में conversion को रोकते हैं; "unknown" का मतलब है vendor को call करना |
| Active business functions | ऐसे business functions जो incompatible हैं और conversion को रोक देंगे | यहाँ कोई blocker हो तो जल्दी SAP support incident चाहिए |
| Custom code analysis | ATC या Custom Code Migration app के निष्कर्ष, असर के हिसाब से समूहबद्ध, quick fix counts और used या unused scope के साथ | तभी दिखता है जब आप custom code के नतीजे अलग से upload करें |
| SAP S/4HANA sizing | शुरुआती HANA memory और disk size, top tables और archiving की संभावना | Sizing का शुरुआती बिंदु, अंतिम hardware या RISE sizing नहीं |
| Integration | IDocs, RFCs और BAPIs, web services, OData, BW extractors, flat files और SLT की सूची, संभावित असर के साथ | सिर्फ इसी सिस्टम के technical interfaces दिखाता है, दूसरे छोर के सिस्टम नहीं |
| Customer vendor integration | कितने customers और vendors पहले से business partners हैं, और data quality के मसले | Business partner conversion किसी भी दूसरी prerequisite से ज़्यादा टीमों को पकड़ लेता है |
| Financial data quality | General ledger, asset accounting और material ledger में विसंगतियाँ, साल और company code के हिसाब से | Category D निष्कर्षों को system-specific सुधार चाहिए, जिसमें समय लगता है |
| Planned downtime calculator | एक data centre में standard SUM conversion के लिए अपेक्षित business downtime | सिर्फ संकेत भर; असली window आपका cutover प्लान तय करता है |
| App availability और recommended Fiori apps | Deprecated या बदले जा चुके transactions, और आपके इस्तेमाल के लिए उपयुक्त Fiori apps | सिफ़ारिशें, UX डिज़ाइन नहीं |
| Business Process Discovery | Process automation rates, overdue backlog और non-standard order types | Process insight की एक झलक, जिसे नीचे और विस्तार से कवर किया गया है |

## इसे कैसे चलाएँ

मुख्य मार्गदर्शन [SAP Note 2913617](https://me.sap.com/notes/2913617), SAP Readiness Check for SAP S/4HANA है। शुरू करने से पहले इसका मौजूदा version पढ़िए, क्योंकि SAP prerequisite notes को नियमित रूप से अपडेट करता है।

<stepper title="Readiness Check चलाना" steps="तैयारी|Collect|Custom code|Upload|समीक्षा" bodies="SAP Note 2913617 में सूचीबद्ध notes को उस सिस्टम में implement कीजिए जिसका आप विश्लेषण करेंगे, आमतौर पर production।|Data collection report RC_COLLECT_ANALYSIS_DATA को background job के रूप में चलाइए, target release चुनिए, फिर ZIP download कीजिए।|ATC या Custom Code Migration app में S/4HANA custom code checks चलाइए और नतीजे export कीजिए।|SAP for Me में SAP Readiness Check page पर एक नया analysis बनाइए और दोनों files upload कीजिए।|Basis, finance, process owners और अपने custom code lead के साथ हर check को देखिए।"></stepper>

कुछ बातें जो चरणों की list नहीं दिखाती।

1. **Production इस्तेमाल कीजिए.** SAP का मार्गदर्शन production का विश्लेषण करने का है, क्योंकि उन्हीं नतीजों पर आप योजना बनाएँगे। कई checks असली usage history पर निर्भर करते हैं, जो sandbox में नहीं होती।
2. **Custom code के नतीजे upload कीजिए.** मुख्य data collection अपने आप आपके custom code का विश्लेषण नहीं करता। अगर कोई ATC या Custom Code Migration app के नतीजे उसी analysis में upload नहीं करता, तो custom code वाला हिस्सा खाली रहता है और report आपके सिस्टम से ज़्यादा साफ़ दिखती है।
3. **Target release जाँचिए.** वही S/4HANA या Private Edition release चुनिए जिस पर आप असल में पहुँचेंगे। Simplification items और add-on की स्थिति releases के बीच बदलती है।
4. **कुछ आगे-पीछे की उम्मीद रखिए.** Data collectors विफल होते हैं, notes गायब होते हैं और बड़े सिस्टम पर jobs लंबे चलते हैं। इसके लिए सिर्फ प्रयास नहीं, बीतने वाले समय की भी योजना बनाइए।

Landing page [me.sap.com/readinesscheck](https://me.sap.com/readinesscheck) पर है।

## Readiness Check क्या छोड़ देता है

Check एक सवाल में अच्छा है: इस सिस्टम में क्या S/4HANA से टकराता है। यह इस सवाल का जवाब देने के लिए नहीं बना कि क्या उस चीज़ को मौजूद रहना भी चाहिए।

### Custom objects

मेरे अनुभव में, Readiness Check जो छोड़ देता है और जो बाद में तकलीफ़ देता है, वह custom objects हैं। यह बताता है कि कौन सा custom code simplification items के सामने टूटता है। यह नहीं बताता कि कौन से Z-programs, tables, enhancements, forms और reports अब भी किसी business उद्देश्य को पूरा करते हैं, कौन से standard S/4HANA function की नकल हैं, या किन्हें सालों से किसी ने नहीं चलाया।

यह कमी इसलिए मायने रखती है क्योंकि जिन प्रोग्राम्स को मैं देखता हूँ, उनमें custom code वह चरण है जो सबसे ज़्यादा बार overrun होता है। यह वह छिपी लागत भी है जिसे बजट में सबसे ज़्यादा भुला दिया जाता है।

निष्कर्षों की संख्या और custom objects की संख्या अलग-अलग संख्याएँ हैं। एक प्रोग्राम में smartShift के साथ विश्लेषण ने हमें 18,000 custom objects से 3,200 पर ला दिया। अकेला Readiness Check यह कटौती नहीं कर पाता, क्योंकि यह असर मापता है, मूल्य नहीं।

इसलिए मैं custom code वाले हिस्से को inventory की शुरुआत मानता हूँ, अंत नहीं। Custom Code Migration app used और unused scope जोड़ता है, smartShift automated विश्लेषण और remediation जोड़ता है, और business में किसी को अब भी यह तय करना होता है कि क्या हटेगा।

### विश्लेषित सिस्टम के बाहर की हर चीज़

Check एक ECC सिस्टम को देखता है। यह ये चीज़ें नहीं देखता:

1. **Process design.** क्या आपके order-to-cash या record-to-report को redesign करना चाहिए, यही greenfield, brownfield या selective तय करता है।
2. **Interfaces का दूसरा छोर.** यह ECC में interfaces सूचीबद्ध करता है। Middleware, third-party systems और उनके owners इसके दायरे से बाहर हैं।
3. **वह डेटा जो आपने अभी load नहीं किया.** Non-SAP systems का डेटा, और finance और business partner के बाहर की data quality।
4. **संगठन और बदलाव.** फ़ैसलों का owner कौन है, users कितने तैयार हैं और प्रोग्राम के दौरान business कितना झेल सकता है।
5. **Commercials.** Licence conversion, RISE scope और partner की लागत किसी SAP dashboard में नहीं हैं।

Business Process Discovery, process performance की पहली झलक देता है। एक गहरा SAP विश्लेषण SAP Signavio Process Insights, discovery edition है, जिसे SAP का [value of support page](https://support.sap.com/en/release-upgrade-maintenance/value-support.html) छह lines of business में process सुधारों पर सिफ़ारिशों के रूप में बताता है। उपयोगी input, लेकिन फिर भी डिज़ाइन नहीं।

## पूरा S/4HANA माइग्रेशन assessment क्या जोड़ता है

माइग्रेशन assessment, Readiness Check को एक input के रूप में लेता है और उसे ऐसे फ़ैसलों में बदलता है जिनके लिए आप पैसा दे सकें। दोनों की तुलना ऐसी है।

| सवाल | SAP Readiness Check | पूरा माइग्रेशन assessment |
|---|---|---|
| ECC में क्या S/4HANA से टकराता है? | हाँ, विस्तार से | Check के नतीजों का इस्तेमाल करता है |
| कौन से custom objects रखें, हटाएँ या दोबारा बनाएँ? | आंशिक रूप से: असर, और usage अगर आप Custom Code Migration app इस्तेमाल करें | हाँ: object inventory, usage, business owner, फ़ैसला |
| Greenfield, brownfield या selective? | नहीं | हाँ, process और डेटा के निष्कर्षों के आधार पर |
| कौन से interfaces और बाहरी सिस्टम बदलते हैं? | सिर्फ ECC की तरफ़ | दोनों छोर, owners और remediation के साथ |
| Finance के आगे हमारा डेटा कितना साफ़ है? | आंशिक रूप से | हाँ, cleansing प्लान और owner के साथ |
| इसमें कितना समय और कितनी लागत लगेगी? | सिर्फ downtime और sizing के अनुमान | समय-सीमा, लागत की रेंज और contingency |
| कौन सा deployment और commercial model? | नहीं | On-premise, Private Edition या Public Edition, और क्या negotiate करना है |

मैं जो tools इस्तेमाल करता हूँ, वे हैं SAP Readiness Check, custom code के लिए Custom Code Migration app और smartShift, और जहाँ selective data transition विचार में हो वहाँ SNP या Natuvion। इनमें से कोई भी आपके process owners के साथ डिज़ाइन समीक्षा की जगह नहीं लेता।

फिर बाकी काम मेरा रास्ते वाला नियम करता है। जब आप दूसरे सिस्टम से आ रहे हों या नई प्रक्रियाएँ तय करनी हों तब greenfield, जब प्रक्रियाएँ तय हैं और चल रही हैं तब brownfield, और जब कुछ क्षेत्रों की प्रक्रियाएँ दोबारा तय करनी हों तब selective। अगर पैसा खर्च करने से पहले आप एक शुरुआती राय चाहते हैं, तो मेरा मुफ़्त [S/4HANA माइग्रेशन assessment tool](/hi/sap-s4hana-migration-strategy-greenfield-vs-brownfield/) इन्हीं समझौतों से होकर गुज़रता है।

इसका output सीधे एक [माइग्रेशन timeline और प्रोजेक्ट प्लान](/hi/s4hana-migration-timeline-project-plan/) और एक [माइग्रेशन cost अनुमान](/hi/s4hana-migration-cost/) में जाना चाहिए। यही वह चीज़ भी है जो आप partners को देते हैं: अगर वे आपके assessment का जवाब किसी specific high-level डिज़ाइन से नहीं दे सकते, तो यह आपको कुछ बताता है। [S/4HANA माइग्रेशन partner चुनने](/hi/choose-s4hana-migration-partner/) पर मेरी गाइड उस कदम को कवर करती है।

## एक ठीक-ठाक assessment में कितना समय लगता है

यह निर्भर करता है। मैं कोई एक संख्या नहीं दूँगा, क्योंकि कंपनियों के बीच इसे तय करने वाले कारक बहुत अलग होते हैं।

ये चीज़ें इसे आगे-पीछे करती हैं:

1. **Systems और clients की संख्या.** एक ECC production सिस्टम, अलग BW, CRM और SRM वाले पाँच सिस्टम से अलग काम है।
2. **Custom code की मात्रा.** हज़ारों custom objects को usage analysis और business फ़ैसलों की ज़रूरत होती है, और यह लोगों का समय है, tool का नहीं।
3. **Interfaces.** हर बाहरी सिस्टम को एक owner चाहिए जो बता सके कि उसकी तरफ़ क्या बदलता है।
4. **Entities और देश.** ज़्यादा company codes का मतलब है localisation, tax और reporting के ज़्यादा सवाल।
5. **Data quality.** बड़ी financial विसंगतियों या बिखरे business partner डेटा की जाँच ज़रूरी है, किसी के अनुमान लगा सकने से पहले।
6. **Business की उपलब्धता.** जो process owners assessment को असली घंटे दे सकते हैं, वे इसे किसी भी tool से ज़्यादा छोटा करते हैं।
7. **पहुँच.** Notes के approve होने और production jobs के schedule होने का इंतज़ार, बिना कोई विश्लेषण किए, बीतने वाला समय बढ़ाता है।

मैं जो नहीं करूँगा, वह है build जल्दी शुरू करने के लिए assessment को छोटा करना। जिन 21 SAP प्रोग्राम्स का मैंने नेतृत्व किया है या जिन्हें संकट से निकाला है, उनमें सबसे बड़ी गलती जो मैं देखता हूँ वह है शुरुआत में ठीक से योजना न बनाना। Assessment वहीं है जहाँ से वह योजना शुरू होती है।

## मैं आगे क्या करूँगा

अपनी Basis टीम से कहिए कि इसी महीने production में SAP Note 2913617 implement करे और custom code के नतीजों समेत Readiness Check चलाए। फिर अपने finance lead, एक process owner और अपने custom code lead के साथ आधा दिन रखिए, उसे साथ बैठकर पढ़िए और उन सवालों की list बनाइए जिनका यह जवाब नहीं देता।

वही list आपके माइग्रेशन assessment का scope है। अगर partners के पास जाने से पहले आप उस पर एक स्वतंत्र राय चाहते हैं, तो [संपर्क कीजिए](/hi/contact-noel-erp-support/)।

## अक्सर पूछे जाने वाले सवाल

<details>
<summary>S/4HANA के लिए SAP Readiness Check क्या है?</summary>

यह SAP का एक cloud application है जो SAP S/4HANA के मुकाबले आपके SAP ERP सिस्टम का विश्लेषण करता है। आप सिस्टम में data collectors चलाते हैं, नतीजे SAP for Me पर upload करते हैं और एक dashboard पाते हैं जो simplification items, add-ons, business functions, custom code, sizing, interfaces, business partner, financial data quality और recommended Fiori apps को कवर करता है।

</details>

<details>
<summary>क्या SAP ग्राहकों के लिए SAP Readiness Check मुफ़्त है?</summary>

SAP इसे SAP for Me पर सक्रिय SAP maintenance agreement वाले सभी ग्राहकों को उपलब्ध कराता है, और Cloud ALM tenant वाले ग्राहकों के लिए SAP Cloud ALM में। असली लागत सिस्टम तैयार करने और नतीजों की व्याख्या करने में लगने वाला आंतरिक और partner का समय है।

</details>

<details>
<summary>SAP Readiness Check कैसे चलाया जाता है?</summary>

SAP Note 2913617 के notes implement कीजिए, आमतौर पर production में। Data collection report RC_COLLECT_ANALYSIS_DATA चलाइए, ZIP download कीजिए और custom code analysis को ATC या Custom Code Migration app में अलग से चलाइए। दोनों को SAP for Me में SAP Readiness Check page पर एक ही analysis में upload कीजिए।

</details>

<details>
<summary>SAP Readiness Check क्या कवर नहीं करता?</summary>

यह तय नहीं करता कि आपके custom objects की अब भी ज़रूरत है या नहीं, आपकी प्रक्रियाओं को redesign करना चाहिए या नहीं, आपके interfaces के दूसरे छोर पर क्या होता है, या प्रोग्राम की लागत कितनी होगी। यह तकनीकी compatibility के लिए एक सिस्टम का विश्लेषण करता है। वे दूसरे सवाल पूरे माइग्रेशन assessment के हिस्से हैं।

</details>

<details>
<summary>S/4HANA माइग्रेशन assessment में कितना समय लगता है?</summary>

यह systems की संख्या, custom code की मात्रा, interfaces और entities की संख्या, आपके डेटा की हालत और इस पर निर्भर करता है कि process owners इसे कितना समय दे सकते हैं।

</details>

<details>
<summary>क्या greenfield या brownfield चुनने से पहले Readiness Check चलाना चाहिए?</summary>

हाँ। यह दिखाता है कि आपके सिस्टम का कितना हिस्सा S/4HANA से टकराता है, जो रास्ते के फ़ैसले का एक input है। फ़ैसला खुद इस पर निर्भर करता है कि आपकी प्रक्रियाएँ तय हैं और चल रही हैं या नहीं, जिसे check नहीं मापता।

</details>
