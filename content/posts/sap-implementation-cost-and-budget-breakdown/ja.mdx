SAPの導入に固定価格はありません。小規模企業なら、50万ドルを下回ることもあります。従業員200人から1,000人の中堅企業が、RISE with SAPの下でS/4HANA Cloud Private Editionを導入する場合は、200万〜1,000万ドルを見込んでください。大企業のプログラムは、連携作業が始まる前に2,000万ドルを超えることがあります。

最初の見積もりがカバーするのは、通常、ライセンスとパートナーの構築作業です。データクレンジング、追加のテストサイクル、きちんとしたトレーニング、本稼働後の数か月間は、ほとんど含まれません。このギャップが、CFOを不意打ちします。

いま予算を組んでいるなら、まず下のレンジから始め、そのレンジの中で金額を上下させる6つの要因を順に確認してください。要因の大半は、プログラムの最初の6週間で決まります。値付けされるものは、わずかです。

## 企業規模別のSAP導入コスト

以下は、ライセンスまたはサブスクリプション、パートナーのサービス、データ、テスト、トレーニング、ハイパーケアを含む、プログラム全体の総額のレンジです。

| 企業規模 | 総コストの範囲（USD） | 典型的なSAP製品 | 金額を押し上げる要因 |
|---|---|---|---|
| 小規模（従業員200人未満） | 8万〜50万ドル | SAP Business One、S/4HANA Cloud Public Edition | 業界別アドオン、レガシーデータの量 |
| 中堅企業（200〜1,000人） | RISEで200万〜1,000万ドル、GROWで200万〜600万ドル | S/4HANA Cloud Private EditionまたはPublic Edition | 連携、データ品質、国別ローカライゼーション |
| 大企業（1,000〜10,000人） | 2,000万〜8,000万ドル以上 | RISEで提供されるS/4HANA Private Edition、またはオンプレミス | 複数システムの連携、カスタムコード、テスト範囲 |
| グローバルグループ（10,000人以上） | 8,000万ドル以上 | S/4HANA Private Editionまたはオンプレミス、SAP BTP | 複数国への展開、規制、大規模な変革管理 |

下限を実現するには、スコープの厳格な管理、クリーンコア、無理のない日額単価の組み合わせが必要です。上限は、それらが崩れたときに起きることです。

### 費用の行き先

最も大きな割合を占めるのは、ソフトウェアではなく導入サービスです。次の配分を、私は出発点として使っています。

| コストの構成要素 | 総額に占める一般的な割合 | 含まれるもの |
|---|---|---|
| 導入サービス | 35〜50% | コンサルティング、設定、テスト、プロジェクト管理 |
| ライセンスまたはサブスクリプション | 10〜20% | S/4HANA本体に加え、Ariba、SuccessFactors、BTPなどのアドオン |
| カスタム開発と拡張 | 5〜15% | ABAP、Fioriアプリ、BTPの拡張、サードパーティとのインターフェース |
| データ移行 | 5〜10% | 抽出、クレンジング、変換、検証 |
| トレーニングと変更管理 | 5〜10% | エンドユーザートレーニング、アダプションツール、チェンジエージェント |
| インフラとホスティング | 5〜10% | ホスティング、ネットワーク、ミドルウェア |
| ハイパーケア | 3〜5% | 本稼働後のサポートと安定化 |

予備費は水増しではありません。ある通信会社が、導入予算に15%のバッファーを上乗せしていたことを覚えています。レガシーデータから、誰も計画していなかった連携作業が出てきたとき、その一部を使いました。バッファーがなければ、プログラムは止まっていたでしょう。予備費は、パートナーの価格の中ではなく、御社の側で持ってください。

## 金額を左右する6つの要因

### 1. 提供形態：RISE、GROW、オンプレミス

提供形態の選択は、誰かがトランザクションを設定するより前に、コストの形を決めます。

**RISE with SAP**は、S/4HANA Cloud Private Edition、ハイパースケーラーのホスティング、技術的なマネージドサービス、SAP BTPクレジットを、1つのサブスクリプションにまとめたものです。価格は、フルユーザー相当（FUE）の数とコミットした契約期間に応じて決まります。契約は1本で済みます。一方で、各コンポーネントを個別に交渉することはできなくなります。

**GROW with SAP**は、中規模企業向けにS/4HANA Cloud Public Editionをパッケージ化したものです。設定のオプションはPrivate Editionより限られており、拡張はリリース済みのインターフェースを通じてしかできないため、システムがクリーンコアを強制します。その代わり、導入は速く、多くの場合6〜9か月です。

**オンプレミスのS/4HANA**は、永続ライセンスに年間サポートを加えたものです。Enterprise Supportの費用は毎年ライセンス価値の約22%で、[Computerworldが2009年に報じています](https://www.computerworld.com/article/1553083/sap-agrees-to-delay-full-price-hike-on-enterprise-support-switch.html)。7〜10年という期間で見ると、自社のインフラチームを持つ企業は、オンプレミスのほうが安く収まることがあります。クラウドが自動的に安いわけではありません。見る期間、ユーザー数の伸び、クラウドを使わない場合のホスティングコストによって変わります。

### 2. パートナー費用と日額単価の組み合わせ

パートナーと、そのパートナーが要員を配置する拠点の組み合わせは、ほかのどのベンダー選定よりも予算を動かします。次は、2026年の上級コンサルタントの日額単価の目安です。

| 地域 | 上級コンサルタントの日額単価（USD） | 典型的な用途 |
|---|---|---|
| 米国（オンショア） | 1,800〜3,500ドル | リードアーキテクト、プログラムディレクター、米国の規制対象のワークストリーム |
| GCC（リヤド、アブダビ、ドバイ） | 1,200〜2,000ドル | 地域展開のプログラムリード、財務アーキテクト |
| ニアショア（東欧、メキシコ） | 700〜1,400ドル | 機能リード、連携開発者 |
| オフショア（インド、フィリピン） | 300〜700ドル | ABAP開発、Fiori拡張、サポート |

オンショアのシニア人材が多すぎると、大規模なプログラムでは数百万ドルが上乗せされることがあります。少なすぎて、現地に財務リードがいない場合は、本稼働の半年後に月次決算の問題として表面化しがちです。高くつくのは、こちらの間違いです。

Tier 1のファーム（Deloitte、Accenture、PwC、EY、IBM、DXC）は、体制の整った進め方と、より高い単価をもたらします。Tier 2とTier 3のファームは日額では安いものの、複雑なプログラムでは、より多くの指示が必要になることがよくあります。いずれにせよ、最初にあいまいにした目標は、あとで工数として支払うことになります。あいまいさが手戻りを生み、手戻りは課金対象です。

### 3. カスタマイズとクリーンコア

SAP標準に変更を加えるたびに、コード、ドキュメント、テストの工数が増え、アップグレードのたびに再テストが必要になります。私の経験では、あらゆるものをカスタマイズする企業は、導入に30〜50%多く費やしています。

6か国にまたがるグローバル導入の1つでは、税ロジックがすべてABAPで作り込まれていました。技術的には動いていました。ところが、ある国が税率を変更すると、現場は開発依頼を起票し、構築を待ち、すべてを再テストしなければなりませんでした。標準の税設定で、大半は対応できたはずです。

クリーンコアは、SAPがいまこの問題をとらえている枠組みです。Public Editionではシステムがそれを強制します。Private Editionとオンプレミスではコアを変更することもできるため、これはガバナンス上の判断になります。拡張は、リリース済みのAPIの上に置くべきで、ABAP Cloudか、SAP BTP上のサイドバイサイドで構築します。私の[クリーンコアガイド](/ja/sap-clean-core-strategy-what-it-means-for-your-business/)で、SAPのAからDの拡張レベルを説明しています。

### 4. データ移行

データが、チームの期待ほどきれいなことはまれです。レガシーシステムには、重複、空白のフィールド、誰も説明できないレコードがたまっていきます。

在庫テーブルにエントリーが欠けていたというだけで、本稼働が数週間遅れたクライアントを覚えています。プロファイリングの予定が遅く組まれていました。欠落が表に出た頃には、計画に余裕は残っていませんでした。規制の厳しい業界では、さらに別の層が加わります。購買発注書、請求書、財務記録は、新しいシステムで読める形で、7〜10年保管する必要があることがあります。計画の立て方は、私の[データ移行の記事](/ja/why-sap-data-migration-fails-and-how-to-fix-it/)で扱っています。

### 5. トレーニングと変更管理

トレーニングは、ほとんどのチームが削ろうとする項目です。そして、延長されたハイパーケアとなって戻ってくる項目でもあります。

私はかつて、参加したユーザーが圧倒されて終わったトレーニングセッションに出席したことがあります。本稼働の日が来ると、彼らはスプレッドシートに戻っていきました。私が関わった別の会社では、ユーザーがきちんとしたトレーニングを受けなかったために、2か月分の作業をやり直す羽目になりました。

デジタルアダプションツールは、集合研修の時間を減らせます。SAPは2024年9月にWalkMeの買収を完了したため、WalkMeは現在、SAP自身のポートフォリオの中でSAP Enable Nowと並んでいます。SAP以外の主な代替はWhatfixです。どれも、人々が毎日回すプロセスの実践の代わりにはなりません。

### 6. 本稼働後の運用コスト

本稼働はゴールではありません。サポート、アップグレード、安定化、拡張の保守は、いずれも継続的なコストがかかります。オンプレミスのサポートは、前述の22%です。RISEとGROWではサポートはサブスクリプションに含まれますが、追加のマネージドサービスは別料金です。

まだECCを使っている場合は、時間が重要です。エンハンスメントパッケージ6〜8のSAP ERP 6.0は、2027年末でメインストリームメンテナンスが終了します。任意の延長メンテナンスは2030年末まで続き、メンテナンスのベース料金に2ポイントを上乗せした割増料金がかかります（[SAP News](https://news.sap.com/2020/02/sap-s4hana-maintenance-2040-clarity-choice-sap-business-suite-7/)）。SAP Solution Manager 7.2のメインストリームメンテナンスも2027年に終了し、SAPはそれまでにSAP Cloud ALMへ移行することを推奨しています。これらの日付を、ビジネスケースに入れてください。

### AIツールで変わること、変わらないこと

SAPは現在、コンサルタント向けのJouleを提供しており、JouleはSAP Activate Roadmap Viewer内の質問に答えます。SAP Build CodeはJouleを使って、BTP上のJavaやJavaScriptアプリケーション向けに、データモデル、アプリのロジック、テストスクリプトを生成します。これらのツールは、設計や構築の一部の作業を短縮できます。ただし、SAPは、予算に組み込めるような削減効果を公表していません。パートナーに、これらをどう使っているか、そしてそれが工数見積もりに反映されているかを尋ねてください。反映されていなければ、削減分はパートナーの利益になります。

## 契約締結後に表面化する6つのコスト

どれも秘密ではありません。ほとんどの最初の見積もりに、ただ含まれていないだけです。

1. **データクレンジング。** プロファイリングを行うと、想定よりも多くの問題が見つかるのがほとんどです。カットオーバー前ではなく、最初のフェーズに予定してください。
2. **スケジュールを取り戻すために削られたトレーニング。** 単発のワークショップでは、新しい働き方は定着しません。ユーザーには、毎日回すトランザクションを練習する時間が必要です。
3. **サイロ化した連携テスト。** 私が関わったある会社は、ワークフローを個別にテストしたため、ユーザー受け入れテスト（UAT）を1か月近く延長せざるを得ませんでした。受注は、在庫、請求、財務に連鎖します。まとめてテストしてください。
4. **積み重なる変更要求。** 「必須項目を追加する」という1件のチケットが、帳票、レポート、権限にまたがる2日分の調整に膨らむのを見たことがあります。変更要求は毎週、予算に照らして確認してください。
5. **手薄なハイパーケア。** テスト環境は、現実の業務のプレッシャーを再現しません。初日に十分な数のトレーニング済みサポート要員がいなければ、応答時間が延び、ユーザーはすぐに信頼を失います。
6. **監査とコンプライアンスの検証。** 私がアドバイスしたある公共部門の展開では、監査上の問い合わせを片付けるためだけに、本稼働後に1か月の検証が必要でした。その工数は、計画に一度も入っていませんでした。

## 固定価格、タイム・アンド・マテリアル、またはその併用

固定価格が機能するのは、スコープが明確に定義されていて、変わる可能性が低い場合です。デリバリーのリスクはパートナーが負うので、パートナーはそのリスクを価格に織り込みます。合意したスコープ外の変更は、すべて交渉事になります。

タイム・アンド・マテリアルが機能するのは、要件が変化していく場合で、大規模なSAPプログラムの大半がこれに当たります。実際に行った作業に対して支払います。リスクは御社の予算にかかるので、厳格なスコープ管理が必要です。

複雑なプログラムでは、私はハイブリッドを好みます。設計や初期設定のように内容が明確なフェーズは固定価格、連携、テスト、本稼働後の作業はタイム・アンド・マテリアルです。どのモデルを選んでも、スコープ管理は御社の側から行う必要があります。

サブスクリプションか永続ライセンスかという問いも似ています。サブスクリプション（RISEまたはGROW）は、初期コストが低く、アップグレードはSAPが管理し、インフラの作業も少なくて済みます。永続ライセンスのオンプレミスは、初期コストが高くなる代わりに、アップグレードの時期とデータを完全に自社で管理できます。新規の大企業プログラムの大半では、いまの実質的な標準はRISEです。オンプレミスが選ばれるのは、通常、データレジデンシーやソブリンティの理由からです。

## コストでSAPはOracleやDynamics 365とどう違うか

SAPは通常Oracle Cloud ERPよりコストが高く、同程度のスコープであれば、どちらも通常Microsoft Dynamics 365より高くなります。SAPもOracleも、クラウドERPの定価を公表していません。見積もりは、ユーザーの構成、モジュール、契約期間によって決まります。Microsoftは公表しています。Dynamics 365 Financeの定価は、1ユーザーあたり月額210ドル（年払い）です（[Microsoftの価格ページ](https://www.microsoft.com/en-us/dynamics-365/products/finance/pricing)）。

グローバルに事業を展開するクライアントや、規制の厳しい環境にあるクライアントの中には、財務、サプライチェーン、生産にわたる深さを理由に、SAPに傾くところがあります。その深さが不要なら、そこに過剰な費用をかけてしまいかねません。[SAPとOracleの比較](/ja/sap-vs-oracle-which-erp-is-better-for-your-business/)で、さらに詳しく書いています。

## 署名前の予算チェックリスト

作業範囲記述書（SoW）に署名する前に、プログラムディレクターとこれを確認してください。各チェックには、クライアント側の責任者がいます。

1. **データリード：** データプロファイリングが、カットオーバー直前だけでなく、最初のフェーズに予定されている。
2. **チェンジリード：** トレーニングがユーザーグループごとに見積もられ、練習時間を含んでいる。
3. **テストマネージャー：** モジュールをまたぐテストサイクルが、SoWに明記されている。たとえば、受注から入金まで、調達から支払まで、記録から報告まで。
4. **財務コントローラー：** 規制対象のプロセスについて、監査と検証の工数がスコープに含まれている。
5. **プログラムディレクター：** ハイパーケアの期間と体制が、契約に書かれている。
6. **CFO：** 10〜20%の予備費を、パートナーの価格の中ではなく、御社が保持している。
7. **ソリューションアーキテクト：** スコープに合意する前に、既存のカスタムコードが分類されている。
8. **調達：** パートナーが、AIツールが見積もりにどう影響するかを説明している。

ご自身のケースの最初の数字がほしい場合は、[SAP導入コスト計算ツール](/ja/sap-implementation-cost-calculator/)を試し、その結果をこのチェックリストに照らして検証してください。

## よくある質問

<details>
<summary>SAP導入コストには何が含まれますか？</summary>

ライセンス以上のものが含まれます。導入サービスが通常は最大の構成要素で、総額の35〜50%を占めます。ライセンスまたはサブスクリプションは10〜20%です。カスタム開発、データ移行、トレーニング、インフラはそれぞれおよそ5〜15%、ハイパーケアは3〜5%です。その上に、10〜20%の予備費を確保してください。

</details>

<details>
<summary>中堅企業のSAP導入には、いくらかかりますか？</summary>

従業員200人から1,000人の場合、RISEの下のS/4HANA Cloud Private Editionで、200万〜1,000万ドルを見込んでください。GROW with SAPで、Public Editionがスコープに合うなら、200万〜600万ドルです。どこに収まるかは、モジュールの範囲、データ品質、連携、標準プロセスからどれだけ離れるかによって決まります。このレンジのRISEプログラムは、多くの場合9〜18か月かかります。GROWプログラムは、多くの場合6〜9か月です。

</details>

<details>
<summary>SAPのクラウドは、オンプレミスより安いですか？</summary>

必ずしもそうではありません。クラウドは初期コストが低く、ハードウェアが不要で、始めるのも早く、アップグレードも含まれます。オンプレミスは初期コストが高く、その後、サポートとして毎年ライセンス価値の約22%がかかります。7〜10年で見ると、自社のインフラチームを持つ企業は、オンプレミスのほうが安く収まることがあります。システムを実際に運用するつもりの期間で、総コストを比較してください。

</details>

<details>
<summary>SAP導入で最大の隠れたコストは何ですか？</summary>

遅れて見つかったデータクレンジング、スケジュールを守るために削られたトレーニング、モジュールごとに行った連携テスト、積み重なる変更要求、手薄すぎるハイパーケア、そして誰もスコープに入れなかった監査の検証です。6つとも予測できます。見積もりに入っていないだけで、未知のものではありません。

</details>

<details>
<summary>SAP導入は、固定価格とタイム・アンド・マテリアルのどちらにすべきですか？</summary>

固定価格が向くのは、スコープが安定していて、文書化もしっかりしているフェーズです。タイム・アンド・マテリアルが向くのは、連携やテストのように、要件が変わる作業です。複雑なプログラムの大半は、ハイブリッドを使います。どちらにしても、スコープ管理はクライアント側から行う必要があります。

</details>

<details>
<summary>SAPの導入コストは、OracleやMicrosoft Dynamicsと比べてどうですか？</summary>

3つの中ではSAPが通常最も高く、次にOracle、その次がDynamics 365です。SAPとOracleは、クラウドERPの定価を公表していません。Dynamics 365 Financeの定価は、1ユーザーあたり月額210ドル（年払い）です。SAPの割高さが買うのは、財務、サプライチェーン、生産にわたる深さで、複数の国にまたがる規制の厳しい事業で最も効いてきます。

</details>

<details>
<summary>JouleやSAP Build Codeで、SAP導入コストは下がりますか？</summary>

一部の作業は短縮できます。コンサルタント向けのJouleは、設定やABAPに関する質問に答え、SAP Build CodeはJouleを使って、BTPアプリケーション向けのデータモデル、ロジック、テストスクリプトを生成します。ただし、SAPは、予算に組み込める削減効果を公表していません。パートナーに、これらのツールをどう使っているか、そしてそれが見積もりをどう変えるかを尋ねてください。

</details>

<details>
<summary>SAP ECCのサポートはいつ終わりますか？</summary>

エンハンスメントパッケージ6〜8のSAP ERP 6.0は、2027年12月31日にメインストリームメンテナンスが終了します。任意の延長メンテナンスは2030年12月31日まで続き、メンテナンスのベース料金に2パーセントポイントを上乗せした割増料金がかかります。それより古いエンハンスメントパッケージは、2025年末にメインストリームメンテナンスが終了しています。

</details>
