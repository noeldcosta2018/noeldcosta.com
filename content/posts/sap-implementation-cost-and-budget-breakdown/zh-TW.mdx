SAP 導入沒有固定價格。小型企業可能低於 50 萬美元。員工數 200 至 1,000 人、在 RISE with SAP 之下使用 S/4HANA Cloud Private Edition 的中型企業，應規劃 200 萬至 1,000 萬美元。大型企業的專案，在整合工作開始之前就可能超過 2,000 萬美元。

最初的報價通常涵蓋授權與導入夥伴的建置工作。它很少涵蓋資料清理、額外的測試週期、像樣的訓練，或上線之後的那幾個月。這個落差，正是讓財務長措手不及的地方。

如果您現在正在編列預算，請從下列區間開始，再逐一檢視會讓您在區間內上調或下調的六項驅動因素。其中多數因素，在專案的前六週就已決定。卻很少被標價。

## 依公司規模看 SAP 導入成本

以下是整個專案的總區間，涵蓋授權或訂閱、夥伴服務、資料、測試、訓練與 hypercare。

| 公司規模 | 總成本區間（美元） | 典型 SAP 產品 | 推高成本的因素 |
|---|---|---|---|
| 小型（200 人以下） | 8 萬至 50 萬 | SAP Business One、S/4HANA Cloud Public Edition | 產業附加方案、舊系統資料量 |
| 中型企業（200 至 1,000 人） | RISE 上 200 萬至 1,000 萬；GROW 上 200 萬至 600 萬 | S/4HANA Cloud Private Edition 或 Public Edition | 整合、資料品質、各國在地化 |
| 大型企業（1,000 至 10,000 人） | 2,000 萬至 8,000 萬以上 | RISE 之下的 S/4HANA Private Edition，或地端版 | 多系統整合、客製程式碼、測試範圍 |
| 全球集團（10,000 人以上） | 8,000 萬以上 | S/4HANA Private Edition 或地端版、SAP BTP | 跨國推行、法規、大規模的變革 |

要落在下限，需要嚴格的範疇控管、Clean Core，以及合理的人天費率組合。上限，則是這些因素失控時會發生的情況。

### 錢花在哪裡

導入服務，而不是軟體，占了最大的份額。以下是我作為起點使用的分配。

| 成本組成 | 占總額的典型比例 | 涵蓋內容 |
|---|---|---|
| 導入服務 | 35% 至 50% | 顧問、配置、測試、專案管理 |
| 授權或訂閱 | 10% 至 20% | S/4HANA 核心，加上 Ariba、SuccessFactors、BTP 等附加方案 |
| 客製開發與擴充 | 5% 至 15% | ABAP、Fiori 應用程式、BTP 擴充、第三方介面 |
| 資料遷移 | 5% 至 10% | 擷取、清理、轉換、驗證 |
| 訓練與變革管理 | 5% 至 10% | 終端使用者訓練、採用工具、變革推動者 |
| 基礎架構與託管 | 5% 至 10% | 託管、網路、中介軟體 |
| Hypercare | 3% 至 5% | 上線後的支援與穩定化 |

應變準備金不是灌水。我記得一家電信公司在導入預算中加了 15% 的緩衝。當舊系統資料引發出沒人規劃過的整合工作時，他們動用了其中一部分。沒有這筆緩衝，專案就會停擺。請把它留在您這一側的桌上，而不是放在導入夥伴的報價裡。

## 決定總額的六項驅動因素

### 1. 部署模式：RISE、GROW 或地端

部署方式的選擇，在任何人配置第一筆交易之前，就已決定了成本的輪廓。

**RISE with SAP** 把 S/4HANA Cloud Private Edition、超大規模雲端業者（hyperscaler）託管、技術託管服務與 SAP BTP 額度，捆綁成一份訂閱。價格隨完整使用者當量（FUE）與承諾期限而變動。您得到一份合約。您也失去了逐項單獨議價的能力。

**GROW with SAP** 為中型企業打包 S/4HANA Cloud Public Edition。配置選項比 Private Edition 窄，且只能透過已發布的介面擴充，因此系統強制落實 Clean Core。作為回報，部署更快，通常為六到九個月。

**地端 S/4HANA** 意味著永久授權加年度支援。Enterprise Support 每年約為授權價值的 22%，如 [Computerworld 在 2009 年所報導](https://www.computerworld.com/article/1553083/sap-agrees-to-delay-full-price-hike-on-enterprise-support-switch.html)。在七到十年的期間內，擁有自家基礎架構團隊的公司，採用地端版仍可能比較便宜。雲端不會自動是較便宜的選項。這取決於時間跨度、使用者成長，以及若不上雲，您的託管成本是多少。

### 2. 夥伴費用與人天費率組合

導入夥伴，以及他們用來配置人力的地點組合，對預算的影響比任何其他廠商決策都大。以下是 2026 年資深顧問的參考人天費率。

| 地區 | 資深人天費率（美元） | 典型用途 |
|---|---|---|
| 美國在地 | 1,800 至 3,500 | 首席架構師、專案總監、受美國法規規範的工作串 |
| GCC（利雅德、阿布達比、杜拜） | 1,200 至 2,000 | 區域推行中的專案主持人、財務架構師 |
| 近岸（東歐、墨西哥） | 700 至 1,400 | 功能負責人、整合開發人員 |
| 離岸（印度、菲律賓） | 300 至 700 | ABAP 開發、Fiori 擴充、支援 |

在地資深人員過多，可能讓大型專案多出數百萬美元。太少、而且現場沒有財務主管，則往往在上線六個月後，以月結問題的形式浮現。那才是代價更高的錯誤。

第一級廠商（Deloitte、Accenture、PwC、EY、IBM、DXC）帶來架構化的方法，費率也較高。第二、三級廠商每天的成本較低，但在複雜專案上往往需要更多指引。不論哪一種，一開始模糊的目標，之後都會用工時來付。模糊造成返工，而返工是要計費的。

### 3. 客製化與 Clean Core

對 SAP 標準的每一項變更，都會增加程式碼、文件與測試工作，而且每次升級都必須重新測試。依我的經驗，什麼都客製的公司，導入成本會多出 30% 至 50%。

在一個橫跨六個國家的全球導入中，稅務邏輯完全以 ABAP 建構。技術上，它能運作。當某個國家調整稅率時，業務必須提出開發需求、等待建置完成，再把所有東西重新測試。標準的稅務配置本可處理其中大部分。

Clean Core 是 SAP 現在對此的說法。在 Public Edition 中，系統強制落實。在 Private Edition 與地端，您仍然可以修改核心，所以這是治理上的決定。擴充應該放在已發布的 API 上，以 ABAP Cloud 或在 SAP BTP 上並行建置。我的 [Clean Core 指南](/zh-TW/sap-clean-core-strategy-what-it-means-for-your-business/)說明了 SAP 的 A 到 D 擴充層級。

### 4. 資料遷移

資料很少像團隊預期的那麼乾淨。舊系統會累積重複資料、空白欄位，以及沒人解釋得了的紀錄。

我記得有一位客戶，只因為庫存資料表中缺了一些項目，就把上線日期延後了好幾週。資料剖析排得太晚。等到缺口浮現時，計畫已沒有任何緩衝。受監管的產業還多一層要求：採購單、發票與財務紀錄，可能需要保存七到十年，而且是以新系統讀得懂的形式。我的[資料遷移文章](/zh-TW/why-sap-data-migration-fails-and-how-to-fix-it/)說明了如何規劃這件事。

### 5. 訓練與變革管理

訓練是多數團隊最想砍的一項。它也是會以延長 hypercare 的形式回頭找上門的一項。

我曾參加過一場讓使用者不知所措的訓練。上線之後，他們又回到試算表。我合作過的另一家公司，因為使用者略過了正規訓練，得把兩個月的工作重做。

數位採用工具可以減少課堂時數。SAP 於 2024 年 9 月完成對 WalkMe 的收購，因此 WalkMe 現在與 SAP Enable Now 一同列在 SAP 自己的產品組合中。Whatfix 則是主要的非 SAP 替代方案。沒有任何一項能取代對人們每天要執行的流程所做的實際演練。

### 6. 上線後的營運成本

上線不是終點線。支援、升級、穩定化與擴充的維護，全都帶來持續的成本。地端的支援就是上述的 22%。在 RISE 與 GROW 之下，支援包含在訂閱內，但額外的託管服務要另外付費。

如果您仍在 ECC 上，時間很關鍵。採用增強包 6 至 8 的 SAP ERP 6.0，主流維護將於 2027 年底結束。選用的延長維護可持續到 2030 年底，在維護費基數上加收兩個百分點（[SAP News](https://news.sap.com/2020/02/sap-s4hana-maintenance-2040-clarity-choice-sap-business-suite-7/)）。SAP Solution Manager 7.2 的主流維護也將於 2027 年結束，SAP 建議在此之前遷移到 SAP Cloud ALM。請把這些日期放進商業案例。

### AI 工具改變了什麼，又沒改變什麼

SAP 現在提供 Joule for consultants，Joule 也能在 SAP Activate Roadmap Viewer 中回答問題。SAP Build Code 使用 Joule，為 BTP 上的 Java 與 JavaScript 應用程式產生資料模型、應用邏輯與測試腳本。這些工具可以縮短部分設計與建置工作。SAP 並未發布任何我願意放進預算的節省幅度。請問您的導入夥伴如何使用它們，以及這是否反映在工時估算中。如果沒有，節省的部分就落入他們的利潤。

## 合約簽署之後才冒出來的六項成本

這些都不是祕密。它們只是不在多數最初的報價裡。

1. **資料清理。** 資料剖析幾乎總是找到比預期更多的問題。請排在第一階段，而不是切換之前。
2. **為追回進度而被砍掉的訓練。** 一次性的工作坊無法讓新的工作方式紮根。使用者需要在每天要執行的交易上實際練習。
3. **各自為政的整合測試。** 我合作過的一家公司，因為各流程各自獨立測試，不得不把使用者驗收測試（UAT）延長近一個月。銷售訂單會連動庫存、開票與財務。請一起測試。
4. **變更需求不斷疊加。** 我看過一張工單，內容是「新增一個必填欄位」，結果演變成橫跨表單、報表與授權的兩天調整。請每週對照預算審視變更需求。
5. **單薄的 hypercare。** 測試環境無法重現真實的業務壓力。第一天若沒有足夠受過訓練的支援人員，回應時間就會拖長，使用者很快就失去信心。
6. **稽核與法遵驗證。** 我曾提供顧問意見的一個公部門推行，在上線後需要一個月的驗證，只為了處理稽核查詢。這項工作從未被放進計畫。

## 固定價格、實支實付，還是兩者並用

固定價格適用於範疇定義明確、不太可能變動的情況。導入夥伴承擔交付風險，因此夥伴會把這項風險計入價格。每一項超出約定範疇的變更，都會變成談判。

實支實付（time and material）適用於需求會演變的情況，這涵蓋大多數大型 SAP 專案。您按實際工作付費。風險曝露在您的預算中，所以您需要嚴格的範疇控管。

在複雜的專案上，我偏好混合式：定義明確的階段（例如設計與初始配置）採固定價格，整合、測試與上線後工作則採實支實付。不論選哪一種模式，範疇控管都必須來自您這一方。

訂閱與永久授權的問題也類似。訂閱（RISE 或 GROW）讓您的前期成本較低、升級由 SAP 管理，基礎架構工作也較少。永久授權的地端版，讓您完全掌控升級時機與資料，但前期成本較高。對多數新的企業專案而言，今天實際的預設選擇是 RISE。選擇地端，通常是出於資料落地或主權的考量。

## SAP 與 Oracle、Dynamics 365 的成本比較

對於相近的範疇，SAP 通常比 Oracle Cloud ERP 貴，而兩者通常都比 Microsoft Dynamics 365 貴。SAP 與 Oracle 都沒有公布其雲端 ERP 的牌價；報價取決於使用者組合、模組與期限。Microsoft 則有公布：Dynamics 365 Finance 的牌價為每位使用者每月 210 美元，按年支付（[Microsoft 定價](https://www.microsoft.com/en-us/dynamics-365/products/finance/pricing)）。

我的一些營運遍及全球、或處於受監管環境的客戶，因為 SAP 在財務、供應鏈與生產方面的深度而傾向選擇它。如果您不需要那樣的深度，就可能為它多花錢。我的 [SAP 與 Oracle 比較](/zh-TW/sap-vs-oracle-which-erp-is-better-for-your-business/)有更深入的說明。

## 簽約前的預算檢查清單

請在簽署工作說明書（SoW）之前，與您的專案總監逐項檢視。每一項檢查，在客戶這一側都有一位負責人。

1. **資料負責人：** 資料剖析排在第一階段，而不只是切換之前。
2. **變革負責人：** 訓練依使用者群組標價，並包含練習時間。
3. **測試經理：** 跨模組的測試週期在 SoW 中有明列，例如訂單到收款、採購到付款，以及記錄到報告。
4. **財務主管：** 針對受監管的流程，已界定稽核與驗證工作的範疇。
5. **專案總監：** hypercare 的期間與人力配置已寫入合約。
6. **財務長：** 10% 至 20% 的應變準備金由您掌管，而不是放在導入夥伴的報價內。
7. **解決方案架構師：** 在範疇確定之前，已將現有的客製程式碼分類。
8. **採購：** 導入夥伴說明 AI 工具如何影響其估算。

如果您想為自己的情況取得第一個數字，請試試 [SAP 導入成本計算工具](/zh-TW/sap-implementation-cost-calculator/)，再用這份清單檢驗。

## 常見問題

<details>
<summary>SAP 導入成本包含哪些項目？</summary>

不只是授權。導入服務通常是最大的一項，占總額的 35% 至 50%。授權或訂閱占 10% 至 20%。客製開發、資料遷移、訓練與基礎架構各約占 5% 至 15%，hypercare 占 3% 至 5%。另外還要預留 10% 至 20% 的應變準備金。

</details>

<details>
<summary>中型企業的 SAP 導入要花多少錢？</summary>

員工數 200 至 1,000 人，在 RISE 之下使用 S/4HANA Cloud Private Edition，請規劃 200 萬至 1,000 萬美元。如果 Public Edition 符合您的範疇，採用 GROW with SAP，請規劃 200 萬至 600 萬美元。最終落在哪裡，取決於模組範疇、資料品質、整合，以及您偏離標準流程的程度。這個區間內的 RISE 專案，往往需要 9 至 18 個月；GROW 專案則往往需要 6 至 9 個月。

</details>

<details>
<summary>SAP 雲端比地端便宜嗎？</summary>

不一定。雲端的前期成本較低：不需硬體、啟動較快、升級已包含。地端的前期成本較高，之後每年的支援費用約為授權價值的 22%。在七到十年的期間內，擁有自家基礎架構團隊的公司，採用地端版可能比較便宜。請以您實際打算運行系統的時間跨度，比較總成本。

</details>

<details>
<summary>SAP 導入中最大的隱藏成本是什麼？</summary>

太晚才發現的資料清理、為趕進度而砍掉的訓練、逐模組進行的整合測試、不斷疊加的變更需求、過於單薄的 hypercare，以及沒人界定範疇的稽核驗證。這六項全都可以預見。它們是被報價遺漏，而不是未知。

</details>

<details>
<summary>SAP 導入該選固定價格還是實支實付？</summary>

固定價格適合範疇穩定、文件完整的階段。實支實付適合需求會改變的工作，例如整合與測試。多數複雜的專案採用混合式。不論哪一種，範疇控管都必須來自客戶這一方。

</details>

<details>
<summary>SAP 導入成本與 Oracle 或 Microsoft Dynamics 相比如何？</summary>

SAP 通常是三者中最貴的，其次是 Oracle，再來是 Dynamics 365。SAP 與 Oracle 不公布雲端 ERP 的牌價。Dynamics 365 Finance 的牌價為每位使用者每月 210 美元，按年支付。SAP 的溢價買到的是財務、供應鏈與生產方面的深度，這對跨國、受監管的營運最為重要。

</details>

<details>
<summary>Joule 與 SAP Build Code 能降低 SAP 導入成本嗎？</summary>

它們可以縮短部分工作。Joule for consultants 能回答配置與 ABAP 的問題，SAP Build Code 則使用 Joule，為 BTP 應用程式產生資料模型、邏輯與測試腳本。SAP 並未發布您可以據以編列預算的節省幅度。請問您的導入夥伴如何使用這些工具，以及這如何改變他們的估算。

</details>

<details>
<summary>SAP ECC 的支援何時結束？</summary>

採用增強包 6 至 8 的 SAP ERP 6.0，主流維護將於 2027 年 12 月 31 日結束。選用的延長維護可持續到 2030 年 12 月 31 日，在維護費基數上加收兩個百分點。較舊的增強包，主流維護已於 2025 年底結束。

</details>
