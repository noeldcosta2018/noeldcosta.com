Το Databricks Genie επιτρέπει στους επιχειρηματικούς χρήστες να κάνουν ερωτήσεις σε εταιρικά δεδομένα με διακυβέρνηση σε απλή φυσική γλώσσα και να παίρνουν πίσω SQL, έναν πίνακα αποτελεσμάτων και ένα διάγραμμα. Λειτουργεί καλά όταν μια ομάδα δεδομένων έχει επιμεληθεί έναν στενό τομέα με ορισμένες μετρικές, και άσχημα όταν το στρέφουν σε ακατέργαστους πίνακες και το αφήνουν να μαντεύει.

Το Agent Bricks είναι το άλλο μισό. Εκεί οι developers χτίζουν, διαθέτουν και αξιολογούν προσαρμοσμένους AI agents που μπορούν να καλούν το Genie, έγγραφα, functions και εξωτερικά εργαλεία.

Έχω δουλέψει με το Databricks σε προγράμματα πλατφορμών δεδομένων στη μεταποίηση και την άμυνα. Η άποψή μου είναι απλή. Το επίπεδο AI είναι πλέον αρκετά καλό για να μπει μπροστά σε planners, μηχανικούς ποιότητας και ομάδες Οικονομικών.

Το δύσκολο κομμάτι είναι η σημασιολογική δουλειά και η δουλειά διακυβέρνησης από κάτω, και η προετοιμασία των επιχειρηματικών χρηστών για να το χρησιμοποιήσουν. Εκεί πρέπει να πάει το μεγαλύτερο μέρος της πιλοτικής προσπάθειας.

## Τι είναι το Databricks Genie στα τέλη του 2026

Η Databricks μετονόμασε το μεγαλύτερο μέρος της οικογένειας Genie το 2026, οπότε τα παλαιότερα άρθρα θα σας μπερδέψουν. Η εμπειρία επιχειρηματικού χρήστη που λεγόταν Databricks One έγινε Genie One τον Ιούνιο του 2026.

Τα Genie spaces έγιναν Genie Agents τον Ιούλιο του 2026. Το Databricks Assistant είναι πλέον Genie Code.

Ο πίνακας δείχνει τι κάνει κάθε κομμάτι και την κατάστασή του τον Οκτώβριο του 2026.

| Προϊόν | Τι κάνει | Ποιος το χρησιμοποιεί | Κατάσταση (Οκτώβριος 2026) |
|---|---|---|---|
| Genie One | Ένα ενιαίο chat interface για dashboards, Genie Agents και εφαρμογές· επίσης εφαρμογές iOS και Android | Επιχειρηματικοί χρήστες | Chat GA από τον Ιούνιο του 2026· mobile app σε Public Preview |
| Genie Agents (πρώην Genie spaces) | Ένα επιμελημένο chat ειδικού τομέα πάνω σε έως 50 πίνακες, views ή metric views | Οι αναλυτές το χτίζουν, οι επιχειρηματικοί χρήστες ρωτούν | Agent mode GA από τον Ιούλιο του 2026· αρκετά add-ons σε Beta |
| Genie Code (πρώην Databricks Assistant) | Βοηθός κώδικα και δεδομένων για notebooks, pipelines και dashboards | Μηχανικοί, αναλυτές | Pay-as-you-go από τις 8 Ιουλίου 2026 |
| Conversation API | Ενσωματώνει τα Genie Agents σε εφαρμογές, chatbots και άλλους agents | Developers | Τα APIs του agent mode και η ανάκτηση οπτικοποιήσεων GA από τον Αύγουστο του 2026 |
| MCP connectors που παρέχει η Databricks | Επιτρέπουν στο Genie One και στο Genie Code να χρησιμοποιούν εξωτερικά εργαλεία μέσω Model Context Protocol | Διαχειριστές, developers | GA από τον Σεπτέμβριο του 2026· οι ενέργειες εγγραφής σε Beta |

Ένα Genie Agent επιλέγει σχετικά metadata, οδηγίες, παραδείγματα SQL και ιστορικό συνομιλίας και μετά παράγει SQL. Αυτή η SQL τρέχει σε Pro ή serverless SQL warehouse και είναι πάντα μόνο για ανάγνωση.

Το σημείο διακυβέρνησης που μετράει περισσότερο: σύμφωνα με την [τεκμηρίωση ρύθμισης των Genie Agents](https://docs.databricks.com/aws/en/genie-agents/set-up), η πρόσβαση στα δεδομένα αξιολογείται πάντα με τα δικαιώματα Unity Catalog του κάθε τελικού χρήστη. Ένας χρήστης που ρωτά για δεδομένα που δεν μπορεί να δει παίρνει κενή απάντηση.

Τα row filters και τα column masks ισχύουν. Τα credentials του warehouse του δημιουργού είναι ενσωματωμένα ώστε οι χρήστες να μπορούν να τρέχουν queries, αλλά δεν διευρύνουν την πρόσβαση κανενός στα δεδομένα.

## Τι κάνει το Databricks Genie ακριβές και πού αποτυγχάνει

Το μοντέλο δεν είναι ο μοχλός της ακρίβειας. Η επιμέλεια είναι. Ο [οδηγός βελτίωσης ποιότητας των Genie Agents](https://docs.databricks.com/aws/en/genie-agents/tune-quality) προτείνει να ορίζετε την επιχειρηματική λογική ως SQL expressions, γιατί δίνουν πιο συνεπή αποτελέσματα από τις οδηγίες σε κείμενο.

Κατά σειρά επίδρασης, από όσα έχω δει:

1. **Metric views.** Το Unity Catalog Business Semantics, με τα metric views στον πυρήνα του, έγινε GA τον Απρίλιο του 2026. Ορίζετε το «first-pass yield» ή την «εμπρόθεσμη παράδοση» μία φορά, με ετικέτες και συνώνυμα, και τα Genie Agents μπορούν να χτιστούν απευθείας από πάνω. Αν η μετρική είναι ορισμένη, το Genie δεν χρειάζεται να τη συμπεράνει.
2. **Παραδείγματα SQL queries.** Συνδυάστε μια πραγματική ερώτηση με την SQL που την απαντά, εστιάζοντας στη λογική που είναι μοναδική για εσάς: πώς υπολογίζεται το κόστος απορριμμάτων, ποια εργοστάσια ανήκουν σε ποια περιοχή.
3. **SQL functions ως αξιόπιστα assets.** Οι functions του Unity Catalog κρατούν λογική που ένα στατικό query δεν μπορεί. Όταν το Genie χρησιμοποιεί παραμετροποιημένο query ή function, η απάντηση σημαίνεται ως επαληθευμένη. Οι χρήστες χρειάζονται `EXECUTE` σε αυτές τις functions.
4. **Το knowledge store.** Περιγραφές, συνώνυμα, σχέσεις joins και κρυφές στήλες. Η απόκρυψη διπλών τεχνικών στηλών βοηθά περισσότερο απ' όσο περιμένει ο κόσμος.
5. **Γενικές οδηγίες.** Κείμενο για πλαίσιο που ισχύει παντού και δεν χωρά πουθενά αλλού. Κρατήστε το σύντομο και χωρίς αντιφάσεις.

Υπάρχουν αυστηρά όρια. 50 πίνακες, views ή metric views ανά agent.

100 οδηγίες, όπου κάθε παράδειγμα query και κάθε SQL function μετράει ως μία. 200 snippets για joins και SQL expressions.

Αντιμετωπίζω αυτά τα όρια ως οδηγία σχεδιασμού. Ένα Genie Agent που καλύπτει «όλη τη μεταποίηση» θα απογοητεύσει. Ένα που καλύπτει «ειδοποιήσεις ποιότητας και απορρίμματα για δύο εργοστάσια» μπορεί να είναι πολύ καλό.

### Πού αποτυγχάνει το Genie

Αυτό είναι το κομμάτι που παραλείπουν οι επιδείξεις των προμηθευτών.

1. **Αόριστοι επιχειρηματικοί όροι.** Ρωτήστε «ποιο ήταν το περιθώριό μας το προηγούμενο τρίμηνο» πάνω σε ακατέργαστους πίνακες ERP και το Genie θα διαλέξει έναν ορισμό. Μπορεί να μην είναι ο ορισμός των Οικονομικών. Αν τα δεδομένα από SAP, Oracle ή Dynamics 365 φτάνουν χωρίς επίπεδο μετρικών με διακυβέρνηση, περιμένετε εύλογους αριθμούς που δεν συμφωνούν.
2. **Ακατάστατα κύρια δεδομένα.** Διπλοί κωδικοί υλικών, ασυνεπείς κωδικοί εργοστασίων και περιγραφές ελαττωμάτων σε ελεύθερο κείμενο βγάζουν σίγουρες λάθος απαντήσεις. Το Genie μεγεθύνει την ποιότητα αυτού που του δίνετε.
3. **Διφορούμενες ερωτήσεις.** «Ποια γραμμή είναι η χειρότερη;» Χειρότερη σε τι; Η καλή επιμέλεια και τα δείγματα ερωτήσεων καθοδηγούν τους χρήστες. Τίποτα δεν καταργεί την ανάγκη να είναι συγκεκριμένοι.
4. **Γλώσσα.** Η τεκμηρίωση σημειώνει ότι τα prompts τυλίγονται σε αγγλικά, οπότε οι απαντήσεις μπορεί να επιστρέφουν στα αγγλικά ακόμη κι όταν οι χρήστες γράφουν σε άλλη γλώσσα. Δοκιμάστε το πριν το διαθέσετε σε μη αγγλόφωνα εργοστάσια.
5. **Ενέργεια, όχι πληροφορία.** Η SQL που παράγεται είναι μόνο για ανάγνωση. Αυτό είναι πλεονέκτημα για τον έλεγχο. Σημαίνει επίσης ότι το Genie λέει σε έναν planner συντήρησης ποια assets έχουν καθυστερήσει, αλλά δεν ανοίγει την εντολή εργασίας.

## Agent Bricks, MCP και Unity Gateway

Και το Agent Bricks άλλαξε μορφή. Η [επισκόπηση του Agent Bricks](https://docs.databricks.com/aws/en/agents/concepts/) το περιγράφει πλέον ως την πλατφόρμα ανάπτυξης agents της Databricks για όσους γράφουν κώδικα.

Φέρνετε το δικό σας framework και μοντέλο, στήνετε τον σκελετό με το Agent Bricks CLI και κάνετε deploy στο Agent Runtime πάνω στο Databricks Apps. Παλαιότερο υλικό αποκαλεί αυτό το επίπεδο Mosaic AI Agent Framework, και κάποιες ετικέτες Mosaic AI εμφανίζονται ακόμη στην τεκμηρίωση.

Δύο πράγματα πρέπει να ξέρουν οι αγοραστές. Το Knowledge Assistant και το Supervisor Agent, οι παλαιότεροι declarative builders, «δεν προτείνονται πλέον για νέους agents», και το Supervisor API έχει αποσυρθεί.

Η Databricks κατευθύνει τους χρήστες low-code στα Genie Agents και τους developers στο CLI. Αν ένας SI προτείνει σχεδιασμό χτισμένο σε ένα από τα δύο, ρωτήστε γιατί.

Για εξαγωγή από έγγραφα, ο προτεινόμενος δρόμος είναι οι AI Functions, που ταξινομούν, εξάγουν, συνοψίζουν και αναλύουν έγγραφα από SQL. Για έναν κατασκευαστή, αυτό καλύπτει πιστοποιητικά προμηθευτών, αναφορές επιθεωρήσεων και αρχεία συντήρησης.

Η αξιολόγηση γίνεται μέσω του managed MLflow: traces κάθε βήματος του agent, ενσωματωμένοι LLM judges όπως η ορθότητα, custom scorers και ανατροφοδότηση από ειδικούς. Οι ίδιοι scorers μπορούν να παρακολουθούν ένα δείγμα της παραγωγικής κίνησης.

Το [Unity Gateway](https://docs.databricks.com/aws/en/unity-gateway/) (τα URLs γράφουν ακόμη ai-gateway) είναι το control plane. Σας δίνει rate limits σε υπηρεσίες μοντέλων και MCP, service policies για guardrails, κάλυψη PII, παρακολούθηση χρήσης σε system tables, καταγραφή αιτημάτων και αποκρίσεων σε πίνακες Unity Catalog και fallbacks ανάμεσα σε μοντέλα. Οι MCP servers που παρέχει η Databricks και οι καταχωρημένοι MCP servers χρησιμοποιούν δικαιώματα Unity Catalog, οπότε ένας agent που καλεί τον MCP server του Genie One δεσμεύεται ακόμη από όσα μπορεί να δει ο χρήστης.

## Επιλογή πρώτης χρήσης στη μεταποίηση και την άμυνα

Στη μεταποίηση, θα ξεκινούσα με ερωτήσεις ποιότητας και συντήρησης πάνω σε δεδομένα που ήδη διακυβερνάτε. Απορρίμματα και επανεργασία ανά γραμμή, βάρδια και υλικό. Ανοιχτές ειδοποιήσεις ποιότητας ανά προμηθευτή.

Μέσος χρόνος μεταξύ βλαβών για κρίσιμα assets, από δεδομένα συντήρησης εγκαταστάσεων του ERP συνδεδεμένα με συνόψεις από historians ή MES. Αυτές οι ερωτήσεις έχουν σαφείς υπευθύνους και χρήστες που σήμερα περιμένουν μέρες για έναν αναλυτή.

Αποφύγετε την πρόβλεψη ζήτησης ή το cost-to-serve για πρώτο πιλοτικό. Οι ορισμοί αμφισβητούνται και τα δεδομένα απλώνονται σε πάρα πολλά συστήματα.

Στην άμυνα, η χρήση μετράει λιγότερο από τους ελέγχους. Διαλέξτε κάτι μη διαβαθμισμένο, ελέγξιμο και ευαίσθητο σε δικαιώματα: διαθεσιμότητα ανταλλακτικών, κατάσταση ορόσημων συμβάσεων ή απόδοση παραδόσεων προμηθευτών. Ο σκοπός του πιλοτικού είναι να αποδείξει ότι τα row filters, τα column masks και οι σημάνσεις ελέγχου εξαγωγών συμπεριφέρονται σωστά σε ερωτήσεις φυσικής γλώσσας.

Ελέγξτε νωρίς την εγκατάσταση. Τα [release notes του AWS GovCloud](https://docs.databricks.com/aws/en/release-notes/gov-cloud/2026) δείχνουν το Genie και τα Genie Agents GA εκεί από τον Ιανουάριο του 2026 και το Genie One από τις 22 Ιανουαρίου 2026, σε GovCloud και GovCloud DoD. Το Unity Gateway έφτασε στο GovCloud σε Public Preview τον Σεπτέμβριο του 2026, χωρίς budgets, inference tables ή service policies.

Το agent mode εκτός Αμερικής, Ευρώπης, Αυστραλίας, Νέας Ζηλανδίας και Ιαπωνίας χρειάζεται ενεργοποιημένη επεξεργασία cross-Geo. Για ένα πρόγραμμα ευαίσθητο σε θέματα κυριαρχίας στον Κόλπο ή στην Ασία, αυτό είναι απόφαση πολιτικής, όχι ένα κουτάκι.

## Σχέδιο πιλοτικού σε δέκα βήματα

Αυτή είναι η σειρά που θα ακολουθούσα. Αν τα δεδομένα είναι ήδη υπό διακυβέρνηση στο Unity Catalog, ο περισσότερος χρόνος πηγαίνει στα βήματα 3 έως 7. Στα πιλοτικά φυσικής γλώσσας όπου έχω δουλέψει, αυτό που πήγε στραβά ήταν η ένταξη των χρηστών.

Οι επιχειρηματικοί χρήστες δεν είχαν ενταχθεί σωστά, οπότε ήταν απροετοίμαστοι, και αυτό το κενό είναι σε μεγάλο βαθμό ο λόγος που το σημασιολογικό επίπεδο και η πιλοτική δουλειά πήραν περίπου δύο μήνες. Εντάξτε τους χρήστες σας παράλληλα με την ανάπτυξη, όχι μετά.

1. **Διαλέξτε έναν τομέα και έναν χορηγό.** Έναν υπεύθυνο ποιότητας εργοστασίου ή έναν επικεφαλής logistics, όχι «την επιχείρηση».
2. **Γράψτε 50 έως 100 πραγματικές ερωτήσεις** από τους ανθρώπους που θα το χρησιμοποιήσουν. Αυτές γίνονται το σημείο αναφοράς σας.
3. **Αναθέστε και ορίστε κάθε μετρική.** Τα Οικονομικά ή η παραγωγή εγκρίνουν τον ορισμό πριν γίνει metric view.
4. **Χτίστε metric views και επιμελημένους πίνακες.** Μείνετε πολύ κάτω από το όριο των 50 πινάκων.
5. **Προσθέστε παραδείγματα SQL, functions και συνώνυμα** για τις ερωτήσεις που αποτυγχάνουν την πρώτη φορά.
6. **Δοκιμάστε τα δικαιώματα ως πραγματικοί χρήστες.** Συνδεθείτε ως χρήστης με περιορισμούς και κάντε ερωτήσεις σχεδιασμένες να διαρρεύσουν δεδομένα. Καταγράψτε τα αποτελέσματα.
7. **Τρέξτε το σημείο αναφοράς και καταγράψτε την ακρίβεια** πριν το δει οποιοσδήποτε χρήστης.
8. **Διαθέστε το σε 10 έως 20 χρήστες** με βρόχο ανατροφοδότησης και επώνυμο data steward που ελέγχει κάθε εβδομάδα τις αρνητικά βαθμολογημένες απαντήσεις.
9. **Ορίστε budgets και ειδοποιήσεις** πριν μεγαλώσει η χρήση.
10. **Αποφασίστε σε σταθερή ημερομηνία:** επέκταση, διόρθωση ή διακοπή, με κριτήρια που συμφωνήθηκαν στο βήμα 1.

Οι άνθρωποι μένουν μέσα στη διαδικασία σε όλη τη διάρκεια. Ένας data steward κατέχει την επιμέλεια.

Όποιος χρησιμοποιεί μια απάντηση για οικονομικό στοιχείο, απόφαση ασφάλειας ή συμβατική δέσμευση την ελέγχει απέναντι στην αναφορά προέλευσης μέχρι το σημείο αναφοράς να αποδείξει ότι είναι αξιόπιστη. Για κάθε agent που γράφει σε σύστημα, ένας άνθρωπος εγκρίνει την ενέργεια.

## Διακυβέρνηση, κόστος και τι να μετράτε

Το Genie είναι φθηνό στη δοκιμή αυτή τη στιγμή. Σύμφωνα με την [τεκμηρίωση budgets του Genie](https://docs.databricks.com/aws/en/genie/budgets), η χρήση LLM του Genie One και των Genie Agents είναι δωρεάν έως τις 31 Ιανουαρίου 2027. Τα service principals εξαιρούνται και χρεώνονται για όλη τη χρήση, κάτι που μετράει αν ενσωματώνετε το Genie μέσω του API.

Το compute των SQL warehouses χρεώνεται χωριστά και είναι το πραγματικό κόστος λειτουργίας. Το Genie Code είναι pay-as-you-go από τις 8 Ιουλίου 2026, με δωρεάν ποσόστωση 150 DBUs ανά χρήστη τον μήνα.

Η σελίδα τιμολόγησης της Databricks τοποθετεί τα 150 DBUs στα $10,50 στο US East (τιμή καταλόγου, ελεγμένη τον Οκτώβριο του 2026). Οι περιοχές διαφέρουν, και οι εταιρικές εκπτώσεις και δεσμεύσεις αλλάζουν τον αριθμό.

Τα budgets μπορούν να ορίσουν κοινά όρια και όρια ανά χρήστη, αλλά το μπλοκάρισμα είναι κατά προσέγγιση, οπότε ένα budget δεν είναι αυστηρό ανώτατο όριο. Κάντε συμφωνία με το `system.billing.usage`. Ο [οδηγός μου για την τιμολόγηση του Databricks](/el/databricks-pricing-explained/) καλύπτει τη διαστασιολόγηση των warehouses.

Τι να μετράτε:

| Μέτρο | Γιατί μετράει | Στόχος που συμφωνείται πριν από το go-live |
|---|---|---|
| Ακρίβεια στο σημείο αναφοράς | Δείχνει αν η επιμέλεια λειτουργεί | Ένα όριο ανά τομέα, εγκεκριμένο από τον υπεύθυνο της μετρικής |
| Ποσοστό επαληθευμένων απαντήσεων | Οι απαντήσεις πάνω σε αξιόπιστη SQL είναι ασφαλέστερες | Ανοδικό από εβδομάδα σε εβδομάδα |
| Ποσοστό αρνητικών βαθμολογιών και χρόνος διόρθωσης | Σας λέει αν η επιμέλεια δεδομένων λειτουργεί | Έλεγχος κάθε εβδομάδα |
| Αποτελέσματα δοκιμών δικαιωμάτων | Αποδεικνύει ότι οι έλεγχοι αντέχουν | Μηδέν διαρροές |
| Αιτήματα προς αναλυτές που αποφεύχθηκαν | Το business case | Βάση μετρημένη πριν από το πιλοτικό |
| Κόστος warehouse ανά ενεργό χρήστη | Πραγματικό κόστος λειτουργίας | Εντός budget |

Η διακυβέρνηση είναι εδώ το θεμέλιο. Αν το Unity Catalog δεν είναι ακόμη στη θέση του, ξεκινήστε από εκεί. Ο [οδηγός μου για το Unity Catalog και τη διακυβέρνηση δεδομένων](/el/databricks-unity-catalog-data-governance/) και ο [οδηγός μου για πλαίσιο διακυβέρνησης AI](/el/ai-governance-framework-guide-building-a-responsible-ai-plan/) καλύπτουν την προεργασία.

## Από πού να ξεκινήσετε

Πάρτε έναν τομέα, γράψτε τις 50 ερωτήσεις που κάνουν πραγματικά οι χρήστες σας και ελέγξτε σε πόσες μπορούν να απαντήσουν τα τρέχοντα δεδομένα σας με ορισμένες μετρικές. Αυτή η άσκηση σας λέει περισσότερα για την ετοιμότητα για το Genie από οποιαδήποτε επίδειξη. Αν ζυγίζετε και την εναλλακτική, συγκρίνετέ το με το [Snowflake Cortex AI και το Snowflake Intelligence](/el/snowflake-cortex-ai-snowflake-intelligence/).

Βοηθώ οργανισμούς να παίρνουν αυτές τις αποφάσεις και να οριοθετούν πιλοτικά. Αν θέλετε μια δεύτερη ματιά, [κλείστε μια κλήση](/el/contact-noel-erp-support/).

## Συχνές ερωτήσεις

<details>
<summary>Τι είναι το Databricks Genie;</summary>

Το Databricks Genie είναι μια οικογένεια εργαλείων AI που απαντούν σε ερωτήσεις φυσικής γλώσσας χρησιμοποιώντας δεδομένα με διακυβέρνηση στο Databricks. Το Genie One είναι το interface για επιχειρηματικούς χρήστες, τα Genie Agents είναι επιμελημένα chats ειδικού τομέα (πρώην Genie spaces) και το Genie Code είναι ο βοηθός για developers και αναλυτές. Οι απαντήσεις παράγονται ως SQL μόνο για ανάγνωση και σέβονται τα δικαιώματα Unity Catalog του κάθε χρήστη.

</details>

<details>
<summary>Ποια είναι η διαφορά ανάμεσα σε Genie spaces και Genie Agents;</summary>

Καμία λειτουργική. Η Databricks μετονόμασε τα Genie spaces σε Genie Agents τον Ιούλιο του 2026 και δήλωσε ότι οι δυνατότητες δεν άλλαξαν. Παλαιότερα άρθρα, εκπαιδευτικό υλικό και αναρτήσεις της κοινότητας χρησιμοποιούν ακόμη το «Genie spaces».

</details>

<details>
<summary>Πόσο κοστίζει το Databricks Genie;</summary>

Η χρήση LLM του Genie One και των Genie Agents είναι δωρεάν για τους χρήστες έως τις 31 Ιανουαρίου 2027. Τα service principals χρεώνονται και το compute των SQL warehouses χρεώνεται χωριστά. Το Genie Code είναι pay-as-you-go πάνω από μια δωρεάν μηνιαία ποσόστωση.

</details>

<details>
<summary>Είναι το Databricks Genie αρκετά ακριβές για οικονομικές ή λειτουργικές αναφορές;</summary>

Μπορεί να είναι, μέσα σε έναν επιμελημένο τομέα με metric views, παραδείγματα SQL και αξιόπιστες functions, μετρημένο απέναντι σε ένα σύνολο ερωτήσεων αναφοράς. Αν το στρέψετε σε ακατέργαστους πίνακες, θα βγάλει εύλογες απαντήσεις που μπορεί να μη συμφωνούν με τους ορισμούς σας. Θεωρήστε το μη επαληθευμένο για οικονομικές αποφάσεις ή αποφάσεις ασφάλειας μέχρι το σημείο αναφοράς να αποδείξει το αντίθετο.

</details>

<details>
<summary>Σε τι χρησιμοποιείται το Databricks Agent Bricks;</summary>

Στην ανάπτυξη, τη διάθεση και τη διακυβέρνηση προσαρμοσμένων AI agents με το δικό σας framework και μοντέλο. Περιλαμβάνει το Agent Bricks CLI, το Agent Runtime, managed memory και αξιολόγηση με MLflow. Το Knowledge Assistant και το Supervisor Agent δεν προτείνονται πλέον για νέους agents.

</details>

<details>
<summary>Υποστηρίζει το Databricks το MCP;</summary>

Ναι. Η Databricks παρέχει managed MCP servers, όπως για το Genie One και το Databricks SQL, και μπορείτε να καταχωρίσετε εξωτερικούς servers ή να χτίσετε δικούς σας στο Databricks Apps. Η πρόσβαση διακυβερνάται μέσω των δικαιωμάτων του Unity Catalog και του Unity Gateway.

</details>
