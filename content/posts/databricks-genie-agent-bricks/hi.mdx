Databricks Genie बिज़नेस यूज़र्स को कंपनी के गवर्न किए गए डेटा से सरल अंग्रेज़ी में सवाल पूछने देता है और बदले में SQL, एक result table और एक chart देता है। यह तब अच्छा काम करता है जब डेटा टीम ने परिभाषित metrics के साथ एक सीमित domain को curate किया हो, और तब ख़राब जब इसे कच्ची टेबल्स पर छोड़ दिया जाए और अंदाज़ा लगाने दिया जाए।

Agent Bricks दूसरा आधा हिस्सा है। यह वह जगह है जहाँ डेवलपर custom AI agents बनाते, deploy करते और उनका मूल्यांकन करते हैं, जो Genie, दस्तावेज़ों, functions और बाहरी टूल्स को call कर सकते हैं।

मैंने मैन्युफैक्चरिंग और डिफ़ेंस में data platform programmes पर Databricks के साथ काम किया है। मेरा नज़रिया सीधा है। AI layer अब इतनी अच्छी है कि उसे planners, quality engineers और फ़ाइनेंस टीमों के सामने रखा जा सके।

कठिन हिस्सा नीचे का semantic और governance काम है, और बिज़नेस यूज़र्स को इसे इस्तेमाल करने के लिए तैयार करना। Pilot की ज़्यादातर मेहनत वहीं जानी चाहिए।

## 2026 के अंत में Databricks Genie क्या है

Databricks ने 2026 में Genie परिवार के ज़्यादातर हिस्सों के नाम बदल दिए, इसलिए पुराने लेख आपको उलझा देंगे। बिज़नेस यूज़र का अनुभव, जिसे पहले Databricks One कहा जाता था, June 2026 में Genie One बन गया।

Genie spaces, July 2026 में Genie Agents बन गए। Databricks Assistant अब Genie Code है।

नीचे की टेबल बताती है कि हर हिस्सा क्या करता है और October 2026 तक उसकी स्थिति क्या है।

| प्रोडक्ट | यह क्या करता है | कौन इस्तेमाल करता है | स्थिति (October 2026) |
|---|---|---|---|
| Genie One | डैशबोर्ड, Genie Agents और ऐप्स पर एक chat interface; iOS और Android ऐप्स भी | बिज़नेस यूज़र्स | Chat, June 2026 से GA; mobile app Public Preview में |
| Genie Agents (पहले Genie spaces) | अधिकतम 50 टेबल्स, views या metric views पर curated, domain-specific chat | एनालिस्ट बनाते हैं, बिज़नेस यूज़र्स पूछते हैं | Agent mode, July 2026 से GA; कई add-ons Beta में |
| Genie Code (पहले Databricks Assistant) | Notebooks, pipelines और डैशबोर्ड के लिए coding और डेटा assistant | इंजीनियर, एनालिस्ट | 8 July 2026 से pay-as-you-go |
| Conversation API | Genie Agents को ऐप्स, chatbots और दूसरे agents में embed करता है | डेवलपर | Agent mode APIs और visualisation retrieval, August 2026 से GA |
| Databricks-provided MCP connectors | Genie One और Genie Code को Model Context Protocol के ज़रिए बाहरी टूल्स इस्तेमाल करने देते हैं | Admins, डेवलपर | September 2026 से GA; write actions Beta में |

एक Genie Agent प्रासंगिक metadata, निर्देश, example SQL और chat history चुनता है, फिर SQL बनाता है। वह SQL एक Pro या serverless SQL warehouse पर चलता है और हमेशा read-only होता है।

Governance की सबसे अहम बात: [Genie Agent set-up documentation](https://docs.databricks.com/aws/en/genie-agents/set-up) के अनुसार, डेटा access हमेशा हर अंतिम यूज़र की अपनी Unity Catalog permissions से जाँचा जाता है। जो यूज़र ऐसे डेटा के बारे में पूछता है जिसे वह नहीं देख सकता, उसे ख़ाली जवाब मिलता है।

Row filters और column masks लागू होते हैं। Author के warehouse credentials embed होते हैं ताकि यूज़र queries चला सकें, लेकिन वे किसी का डेटा access नहीं बढ़ाते।

## Databricks Genie को सटीक क्या बनाता है, और यह कहाँ चूकता है

सटीकता की कुंजी मॉडल नहीं है। Curation है। [Genie Agent quality tuning guide](https://docs.databricks.com/aws/en/genie-agents/tune-quality) बिज़नेस logic को SQL expressions के रूप में परिभाषित करने की सलाह देती है, क्योंकि वे text निर्देशों से ज़्यादा सुसंगत नतीजे देते हैं।

असर के क्रम में, जो मैंने देखा है:

1. **Metric views.** Unity Catalog Business Semantics, जिसके केंद्र में metric views हैं, April 2026 में GA हुआ। आप "first-pass yield" या "on-time delivery" को labels और synonyms के साथ एक बार परिभाषित करते हैं, और Genie Agents सीधे उसके ऊपर बनाए जा सकते हैं। अगर metric परिभाषित है, तो Genie को उसका अंदाज़ा नहीं लगाना पड़ता।
2. **Example SQL queries.** एक असली सवाल को उस SQL के साथ जोड़ें जो उसका जवाब देता है, उस logic पर ध्यान देते हुए जो सिर्फ़ आपके यहाँ है: scrap की लागत कैसे निकाली जाती है, कौन से प्लांट किस region में जुड़ते हैं।
3. **Trusted assets के रूप में SQL functions.** Unity Catalog functions में ऐसा logic होता है जो एक static query नहीं रख सकती। जब Genie किसी parameterised query या function का इस्तेमाल करता है, तो जवाब verified के रूप में चिह्नित होता है। यूज़र्स को उन functions पर `EXECUTE` चाहिए।
4. **Knowledge store.** विवरण, synonyms, join relationships और छिपे हुए columns। Duplicate technical columns छिपाना लोगों की उम्मीद से ज़्यादा मदद करता है।
5. **सामान्य निर्देश.** उस संदर्भ के लिए text जो हर जगह लागू होता है और कहीं और फ़िट नहीं बैठता। इसे छोटा और विरोधाभासों से मुक्त रखें।

कुछ सख़्त सीमाएँ हैं। हर agent के लिए 50 टेबल्स, views या metric views।

100 निर्देश, जिनमें हर example query और SQL function एक गिना जाता है। Joins और SQL expressions के लिए 200 snippets।

मैं इन सीमाओं को डिज़ाइन के मार्गदर्शन की तरह लेता हूँ। "पूरी मैन्युफैक्चरिंग" को कवर करने वाला Genie Agent निराश करेगा। "दो प्लांट्स के quality notifications और scrap" को कवर करने वाला बहुत अच्छा हो सकता है।

### Genie कहाँ चूकता है

यह वह हिस्सा है जिसे वेंडर demos छोड़ देते हैं।

1. **अपरिभाषित बिज़नेस शब्द.** कच्ची ERP टेबल्स पर "पिछली तिमाही में हमारा margin कितना था" पूछें, और Genie कोई एक परिभाषा चुन लेगा। ज़रूरी नहीं कि वह फ़ाइनेंस की परिभाषा हो। अगर SAP, Oracle या Dynamics 365 का डेटा बिना गवर्न की गई metric layer के आता है, तो ऐसे विश्वसनीय दिखने वाले आँकड़ों की उम्मीद रखें जो मेल नहीं खाते।
2. **बिखरा हुआ master data.** Duplicate material numbers, असंगत plant codes और free-text defect विवरण, आत्मविश्वास से भरे ग़लत जवाब देते हैं। Genie उसी चीज़ की quality को बढ़ा देता है जो उसे दी जाती है।
3. **अस्पष्ट सवाल.** "कौन सी लाइन सबसे ख़राब है?" किस मामले में ख़राब? अच्छी curation और sample सवाल यूज़र्स को सही दिशा देते हैं। लेकिन कोई भी चीज़ उनके स्पष्ट होने की ज़रूरत ख़त्म नहीं करती।
4. **भाषा.** Docs बताते हैं कि prompts अंग्रेज़ी में लपेटे जाते हैं, इसलिए यूज़र्स किसी दूसरी भाषा में लिखें तब भी जवाब अंग्रेज़ी में आ सकते हैं। गैर-अंग्रेज़ी प्लांट्स में rollout से पहले इसे परखें।
5. **कार्रवाई, insight नहीं.** बनाया गया SQL read-only होता है। नियंत्रण के लिए यह ताक़त है। इसका मतलब यह भी है कि Genie, maintenance planner को बताता है कि कौन से assets overdue हैं; वह work order नहीं बनाता।

## Agent Bricks, MCP और Unity Gateway

Agent Bricks का रूप भी बदला है। [Agent Bricks overview](https://docs.databricks.com/aws/en/agents/concepts/) अब इसे कोड लिखने वालों के लिए Databricks का agent developer प्लेटफ़ॉर्म बताता है।

आप अपना framework और मॉडल लाते हैं, Agent Bricks CLI से ढाँचा बनाते हैं और Databricks Apps पर Agent Runtime में deploy करते हैं। पुरानी सामग्री इस layer को Mosaic AI Agent Framework कहती है, और कुछ Mosaic AI labels अब भी docs में दिखते हैं।

ख़रीदारों को दो बातें पता होनी चाहिए। Knowledge Assistant और Supervisor Agent, जो पहले के declarative builders थे, अब "नए agents के लिए अनुशंसित नहीं" हैं, और Supervisor API deprecated है।

Databricks, low-code यूज़र्स को Genie Agents की ओर और डेवलपर्स को CLI की ओर भेजता है। अगर कोई SI इनमें से किसी पर बना डिज़ाइन प्रस्तावित कर रहा है, तो पूछें क्यों।

दस्तावेज़ों से extraction के लिए सुझाया गया रास्ता AI Functions है, जो SQL से दस्तावेज़ों को classify, extract, summarise और parse करते हैं। किसी manufacturer के लिए इसमें सप्लायर certificates, inspection reports और maintenance logs आते हैं।

मूल्यांकन managed MLflow से होता है: हर agent step के traces, correctness जैसे built-in LLM judges, custom scorers और विशेषज्ञ feedback। वही scorers production traffic के एक sample की निगरानी कर सकते हैं।

[Unity Gateway](https://docs.databricks.com/aws/en/unity-gateway/) (URLs में अब भी ai-gateway लिखा है) control plane है। यह आपको model और MCP services पर rate limits, guardrails के लिए service policies, PII masking, system tables में usage tracking, Unity Catalog टेबल्स में request और response logging, और मॉडल्स के बीच fallbacks देता है। Databricks-provided और registered MCP servers, Unity Catalog permissions इस्तेमाल करते हैं, इसलिए Genie One MCP server को call करने वाला agent भी उसी से बँधा रहता है जो यूज़र देख सकता है।

## मैन्युफैक्चरिंग और डिफ़ेंस में पहला use case चुनना

मैन्युफैक्चरिंग में मैं उस डेटा पर quality और maintenance के सवालों से शुरू करूँगा जिसे आप पहले से गवर्न करते हैं। लाइन, शिफ़्ट और material के हिसाब से scrap और rework। सप्लायर के हिसाब से खुले quality notifications।

महत्वपूर्ण assets के लिए mean time between failures, ERP plant maintenance डेटा को historian या MES summaries से जोड़कर। इन सवालों के साफ़ मालिक हैं, और इनके यूज़र्स आज किसी एनालिस्ट के लिए दिनों इंतज़ार करते हैं।

पहले pilot के लिए demand forecasting या cost-to-serve से बचें। परिभाषाओं पर विवाद होता है और डेटा बहुत सारे सिस्टम में फैला होता है।

डिफ़ेंस में use case से ज़्यादा controls मायने रखते हैं। कुछ ऐसा चुनें जो unclassified, ऑडिट योग्य और permission के प्रति संवेदनशील हो: spares की उपलब्धता, contract milestone की स्थिति या सप्लायर delivery performance। Pilot का मक़सद यह साबित करना है कि सरल भाषा के सवालों के तहत row filters, column masks और export-controlled flags सही बर्ताव करते हैं।

Deployment जल्दी जाँचें। [AWS GovCloud release notes](https://docs.databricks.com/aws/en/release-notes/gov-cloud/2026) दिखाते हैं कि Genie और Genie Agents वहाँ January 2026 से GA हैं और Genie One 22 January 2026 से, GovCloud और GovCloud DoD दोनों में। Unity Gateway, September 2026 में GovCloud पर Public Preview में पहुँचा, बिना budgets, inference tables या service policies के।

Americas, Europe, Australia, New Zealand और Japan के बाहर agent mode के लिए cross-Geo processing चालू करना पड़ता है। खाड़ी या एशिया में sovereignty को लेकर संवेदनशील programme के लिए यह policy का फ़ैसला है, कोई checkbox नहीं।

## दस चरणों में pilot योजना

यह वह क्रम है जो मैं चलाऊँगा। अगर डेटा पहले से Unity Catalog में गवर्न है, तो ज़्यादातर समय चरण 3 से 7 पर जाता है। जिन natural-language pilots पर मैंने काम किया है, उनमें गड़बड़ onboarding में हुई।

बिज़नेस यूज़र्स का onboarding ठीक से नहीं हुआ था, इसलिए वे तैयार नहीं थे, और यही कमी बड़ी हद तक वजह थी कि semantic layer और pilot के काम में लगभग दो महीने लगे। अपने यूज़र्स का onboarding build के साथ-साथ करें, उसके बाद नहीं।

1. **एक domain और एक sponsor चुनें.** कोई plant quality manager या logistics lead, "बिज़नेस" नहीं।
2. **50 से 100 असली सवाल लिखें**, उन लोगों से जो इसे इस्तेमाल करेंगे। यही आपका benchmark बनेंगे।
3. **हर metric का मालिक और परिभाषा तय करें.** Metric view बनने से पहले फ़ाइनेंस या ऑपरेशंस परिभाषा पर sign-off करे।
4. **Metric views और curated टेबल्स बनाएँ.** 50 टेबल्स की सीमा से काफ़ी नीचे रहें।
5. **Example SQL, functions और synonyms जोड़ें**, उन सवालों के लिए जो पहली बार में fail होते हैं।
6. **असली यूज़र्स के रूप में permissions परखें.** एक सीमित यूज़र के रूप में login करें और ऐसे सवाल पूछें जो डेटा लीक करने के लिए बनाए गए हों। नतीजे रिकॉर्ड करें।
7. **Benchmark चलाएँ और सटीकता रिकॉर्ड करें**, किसी यूज़र के देखने से पहले।
8. **10 से 20 यूज़र्स के लिए जारी करें**, feedback loop के साथ, और एक नामित data steward हर हफ़्ते thumbs-down वाले जवाबों की समीक्षा करे।
9. **Budgets और alerts सेट करें**, इस्तेमाल बढ़ने से पहले।
10. **एक तय तारीख़ पर फ़ैसला करें:** बढ़ाएँ, ठीक करें या रोकें, चरण 1 में तय मापदंडों के आधार पर।

पूरे समय इंसान loop में रहते हैं। Curation का मालिक एक data steward होता है।

जो भी किसी जवाब को फ़ाइनेंशियल आँकड़े, safety फ़ैसले या contract commitment के लिए इस्तेमाल करता है, वह उसे source report से तब तक मिलाता है जब तक benchmark यह साबित न कर दे कि वह भरोसेमंद है। जो भी agent किसी सिस्टम में लिखता है, उसकी कार्रवाई को एक व्यक्ति मंज़ूरी देता है।

## Governance, लागत और क्या मापें

अभी Genie को आज़माना सस्ता है। [Genie budgets documentation](https://docs.databricks.com/aws/en/genie/budgets) के अनुसार, Genie One और Genie Agents का LLM इस्तेमाल 31 January 2027 तक मुफ़्त है। Service principals इसमें शामिल नहीं हैं और उनके हर इस्तेमाल का बिल बनता है, जो तब मायने रखता है जब आप Genie को API के ज़रिए embed करते हैं।

SQL warehouse compute का बिल अलग बनता है और असली चलाने की लागत यही है। Genie Code, 8 July 2026 से pay-as-you-go है, हर यूज़र के लिए हर महीने 150 DBUs की मुफ़्त सीमा के साथ।

Databricks का pricing पेज US East में 150 DBUs को $10.50 बताता है (list price, October 2026 में जाँची गई)। Regions अलग होते हैं, और enterprise छूट और commitments आँकड़ा बदल देते हैं।

Budgets साझा और प्रति-यूज़र सीमाएँ तय कर सकते हैं, लेकिन blocking अनुमानित होती है, इसलिए budget कोई सख़्त सीमा नहीं है। `system.billing.usage` से मिलान करें। मेरी [Databricks pricing गाइड](/hi/databricks-pricing-explained/) warehouse के आकार को कवर करती है।

क्या मापें:

| माप | यह क्यों मायने रखता है | Go-live से पहले तय करने वाला लक्ष्य |
|---|---|---|
| Benchmark सटीकता | दिखाता है कि curation काम कर रहा है या नहीं | हर domain के लिए एक सीमा, metric owner के sign-off के साथ |
| Verified जवाबों का हिस्सा | Trusted SQL पर बने जवाब ज़्यादा सुरक्षित हैं | हफ़्ते-दर-हफ़्ते बढ़ता हुआ |
| Thumbs-down दर और सुधार का समय | बताता है कि stewardship काम कर रही है या नहीं | हर हफ़्ते समीक्षा |
| Permission परीक्षण के नतीजे | साबित करते हैं कि controls टिके हुए हैं | शून्य लीक |
| टाले गए analyst requests | Business case | Pilot से पहले मापा गया baseline |
| हर सक्रिय यूज़र पर warehouse लागत | असली चलाने की लागत | Budget के अंदर |

यहाँ नींव governance है। अगर Unity Catalog अभी तक लागू नहीं है, तो वहीं से शुरू करें; मेरी [Unity Catalog और data governance गाइड](/hi/databricks-unity-catalog-data-governance/) और [AI governance framework गाइड](/hi/ai-governance-framework-guide-building-a-responsible-ai-plan/) बुनियादी काम कवर करती हैं।

## कहाँ से शुरू करें

एक domain लें, वे 50 सवाल लिखें जो आपके यूज़र्स सच में पूछते हैं, और जाँचें कि आपका मौजूदा डेटा परिभाषित metrics के साथ उनमें से कितनों का जवाब दे सकता है। यह अभ्यास किसी भी demo से ज़्यादा बताता है कि आप Genie के लिए कितने तैयार हैं। अगर आप विकल्प भी तौल रहे हैं, तो इसकी तुलना [Snowflake Cortex AI और Snowflake Intelligence](/hi/snowflake-cortex-ai-snowflake-intelligence/) से करें।

मैं संगठनों को ये फ़ैसले लेने और pilots का दायरा तय करने में मदद करता हूँ। अगर आप दूसरा नज़रिया चाहते हैं, तो [कॉल बुक करें](/hi/contact-noel-erp-support/)।

## अक्सर पूछे जाने वाले सवाल

<details>
<summary>Databricks Genie क्या है?</summary>

Databricks Genie, AI टूल्स का एक परिवार है जो Databricks में गवर्न किए गए डेटा से सरल भाषा के सवालों का जवाब देता है। Genie One बिज़नेस यूज़र interface है, Genie Agents curated domain-specific chats हैं (पहले Genie spaces), और Genie Code डेवलपर्स और एनालिस्ट्स के लिए assistant है। जवाब read-only SQL के रूप में बनते हैं और हर यूज़र की Unity Catalog permissions का पालन करते हैं।

</details>

<details>
<summary>Genie spaces और Genie Agents में क्या अंतर है?</summary>

काम के लिहाज़ से कुछ नहीं। Databricks ने July 2026 में Genie spaces का नाम बदलकर Genie Agents कर दिया और कहा कि क्षमताएँ नहीं बदलीं। पुराने लेख, training सामग्री और community posts अब भी "Genie spaces" लिखते हैं।

</details>

<details>
<summary>Databricks Genie की लागत कितनी है?</summary>

Genie One और Genie Agents का LLM इस्तेमाल यूज़र्स के लिए 31 January 2027 तक मुफ़्त है। Service principals का बिल बनता है, और SQL warehouse compute का बिल अलग बनता है। Genie Code एक मुफ़्त मासिक सीमा के ऊपर pay-as-you-go है।

</details>

<details>
<summary>क्या Databricks Genie, फ़ाइनेंस या ऑपरेशंस रिपोर्टिंग के लिए पर्याप्त सटीक है?</summary>

हो सकता है, metric views, example SQL और trusted functions वाले curated domain के अंदर, सवालों के benchmark सेट से मापकर। कच्ची टेबल्स पर लगाने पर यह विश्वसनीय दिखने वाले जवाब देगा जो शायद आपकी परिभाषाओं से मेल न खाएँ। जब तक benchmark कुछ और साबित न करे, फ़ाइनेंशियल या safety फ़ैसलों के लिए इसे unverified मानें।

</details>

<details>
<summary>Databricks Agent Bricks किस काम आता है?</summary>

अपने framework और मॉडल के साथ custom AI agents बनाने, deploy करने और गवर्न करने के लिए। इसमें Agent Bricks CLI, Agent Runtime, managed memory और MLflow evaluation शामिल हैं। नए agents के लिए Knowledge Assistant और Supervisor Agent की अब सलाह नहीं दी जाती।

</details>

<details>
<summary>क्या Databricks, MCP को support करता है?</summary>

हाँ। Databricks managed MCP servers देता है, जिनमें Genie One और Databricks SQL शामिल हैं, और आप बाहरी servers register कर सकते हैं या Databricks Apps पर custom servers बना सकते हैं। Access, Unity Catalog permissions और Unity Gateway के ज़रिए गवर्न होता है।

</details>
