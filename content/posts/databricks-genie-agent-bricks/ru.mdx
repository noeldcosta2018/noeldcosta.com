Databricks Genie позволяет бизнес-пользователям задавать вопросы к управляемым данным компании обычным языком и получать в ответ SQL, таблицу результатов и график. Он хорошо работает, когда команда данных подготовила узкий домен с определёнными метриками, и плохо, когда его направляют на сырые таблицы и оставляют угадывать.

Agent Bricks составляет вторую половину. Здесь разработчики создают, развёртывают и оценивают собственных AI-агентов, которые могут обращаться к Genie, документам, функциям и внешним инструментам.

Я работал с Databricks в программах по созданию платформ данных в производстве и оборонной отрасли. Моя позиция проста. AI-слой теперь достаточно хорош, чтобы поставить его перед планировщиками, инженерами по качеству и финансовыми командами.

Трудная часть лежит ниже: семантическая работа и управление данными, а также подготовка бизнес-пользователей к работе с инструментом. Именно туда должна уходить большая часть усилий в пилоте.

## Что такое Databricks Genie в конце 2026 года

В 2026 году Databricks переименовал большую часть семейства Genie, так что старые статьи будут вас путать. Пользовательский интерфейс для бизнеса, ранее называвшийся Databricks One, в июне 2026 года стал Genie One.

Genie spaces в июле 2026 года стали Genie Agents. Databricks Assistant теперь называется Genie Code.

В таблице ниже показано, что делает каждый компонент и каков его статус на октябрь 2026 года.

| Продукт | Что делает | Кто использует | Статус (октябрь 2026 года) |
|---|---|---|---|
| Genie One | Один чат-интерфейс для дашбордов, Genie Agents и приложений; также приложения для iOS и Android | Бизнес-пользователи | Чат GA с июня 2026 года; мобильное приложение в Public Preview |
| Genie Agents (ранее Genie spaces) | Подготовленный чат по конкретному домену, до 50 таблиц, представлений или metric views | Аналитики строят, бизнес-пользователи спрашивают | Agent mode GA с июля 2026 года; ряд дополнений в Beta |
| Genie Code (ранее Databricks Assistant) | Помощник по коду и данным для ноутбуков, конвейеров и дашбордов | Инженеры, аналитики | Оплата по мере использования с 8 июля 2026 года |
| Conversation API | Встраивает Genie Agents в приложения, чат-боты и других агентов | Разработчики | API для agent mode и получение визуализаций GA с августа 2026 года |
| MCP-коннекторы от Databricks | Позволяют Genie One и Genie Code использовать внешние инструменты через Model Context Protocol | Администраторы, разработчики | GA с сентября 2026 года; операции записи в Beta |

Genie Agent отбирает релевантные метаданные, инструкции, примеры SQL и историю чата, а затем генерирует SQL. Этот SQL выполняется на SQL warehouse типа Pro или serverless и всегда работает только на чтение.

Самый важный момент с точки зрения управления данными: согласно [документации по настройке Genie Agent](https://docs.databricks.com/aws/en/genie-agents/set-up), доступ к данным всегда проверяется по собственным разрешениям Unity Catalog каждого конечного пользователя. Пользователь, который спрашивает о данных, которых он не может видеть, получает пустой ответ.

Фильтры строк и маски столбцов применяются. Учётные данные warehouse автора встроены, чтобы пользователи могли выполнять запросы, но они никому не расширяют доступ к данным.

## Что делает Databricks Genie точным и где он ошибается

Рычаг точности не модель. Рычаг точности: подготовка данных. [Руководство по настройке качества Genie Agent](https://docs.databricks.com/aws/en/genie-agents/tune-quality) рекомендует задавать бизнес-логику в виде SQL-выражений, потому что они дают более стабильные результаты, чем текстовые инструкции.

По степени влияния, исходя из того, что я видел:

1. **Metric views.** Unity Catalog Business Semantics, в основе которой лежат metric views, стала GA в апреле 2026 года. Вы один раз определяете «выход годных с первого предъявления» или «своевременную поставку», с подписями и синонимами, и Genie Agents можно строить прямо поверх них. Если метрика определена, Genie не нужно её угадывать.
2. **Примеры SQL-запросов.** Сопоставьте реальный вопрос с SQL, который на него отвечает, и сосредоточьтесь на логике, уникальной для вас: как считается стоимость брака, какие заводы сводятся в какой регион.
3. **SQL-функции как доверенные активы.** Функции Unity Catalog хранят логику, которую статический запрос не вместит. Когда Genie использует параметризованный запрос или функцию, ответ помечается как проверенный. Пользователям нужно право `EXECUTE` на эти функции.
4. **Хранилище знаний.** Описания, синонимы, связи для соединений и скрытые столбцы. Скрытие дублирующих технических столбцов помогает больше, чем люди ожидают.
5. **Общие инструкции.** Текст для контекста, который применим везде и больше никуда не подходит. Держите его коротким и без противоречий.

Есть жёсткие ограничения. 50 таблиц, представлений или metric views на одного агента.

100 инструкций, где каждый пример запроса и каждая SQL-функция считается за одну. 200 фрагментов для соединений и SQL-выражений.

Я отношусь к этим ограничениям как к подсказке для проектирования. Genie Agent, охватывающий «всё производство», разочарует. Агент по теме «уведомления о качестве и брак на двух заводах» может быть очень хорош.

### Где Genie ошибается

Эту часть демонстрации поставщиков пропускают.

1. **Неопределённые бизнес-термины.** Спросите «какой была наша маржа в прошлом квартале» по сырым таблицам ERP, и Genie выберет определение сам. Это может быть не то определение, которым пользуются финансы. Если данные SAP, Oracle или Dynamics 365 поступают без управляемого слоя метрик, ждите правдоподобных цифр, которые не сходятся.
2. **Неупорядоченные основные данные.** Дублирующиеся номера материалов, несогласованные коды заводов и описания дефектов свободным текстом дают уверенные неправильные ответы. Genie усиливает качество того, что ему дают.
3. **Неоднозначные вопросы.** «Какая линия хуже всех?» Хуже всех в чём? Хорошая подготовка и примеры вопросов направляют пользователей. Но ничто не избавляет их от необходимости формулировать конкретно.
4. **Язык.** В документации отмечено, что промпты оборачиваются на английском, поэтому ответы могут приходить на английском, даже когда пользователи пишут на другом языке. Проверьте это до развёртывания на заводах, где не говорят по-английски.
5. **Действие, а не понимание.** Сгенерированный SQL работает только на чтение. Для контроля это сильная сторона. Но это также значит, что Genie сообщает планировщику обслуживания, какие активы просрочены, но не создаёт заказ на работы.

## Agent Bricks, MCP и Unity Gateway

Agent Bricks тоже изменил форму. В [обзоре Agent Bricks](https://docs.databricks.com/aws/en/agents/concepts/) он теперь описан как платформа Databricks для разработчиков агентов, которые пишут код.

Вы приносите свой фреймворк и модель, создаёте каркас через Agent Bricks CLI и развёртываете в Agent Runtime на Databricks Apps. В более старых материалах этот слой называется Mosaic AI Agent Framework, и некоторые обозначения Mosaic AI всё ещё встречаются в документации.

Покупателям стоит знать две вещи. Knowledge Assistant и Supervisor Agent, более ранние декларативные конструкторы, теперь «больше не рекомендуются для новых агентов», а Supervisor API объявлен устаревшим.

Databricks направляет пользователей low-code к Genie Agents, а разработчиков к CLI. Если системный интегратор предлагает дизайн, построенный на одном из них, спросите почему.

Для извлечения данных из документов рекомендуемый путь: AI Functions, которые классифицируют, извлекают, резюмируют и разбирают документы прямо из SQL. Для производителя это покрывает сертификаты поставщиков, отчёты о контроле и журналы обслуживания.

Оценка проходит через управляемый MLflow: трассировки каждого шага агента, встроенные LLM-судьи, например на корректность, пользовательские оценщики и экспертная обратная связь. Те же оценщики могут отслеживать выборку промышленного трафика.

[Unity Gateway](https://docs.databricks.com/aws/en/unity-gateway/) (в URL всё ещё написано ai-gateway) служит плоскостью управления. Он даёт ограничения частоты запросов к сервисам моделей и MCP, сервисные политики для защитных ограничений, маскирование PII, учёт использования в системных таблицах, журналирование запросов и ответов в таблицы Unity Catalog и переключение между моделями при сбоях. MCP-серверы от Databricks и зарегистрированные MCP-серверы используют разрешения Unity Catalog, поэтому агент, обращающийся к MCP-серверу Genie One, по-прежнему ограничен тем, что может видеть пользователь.

## Выбор первого сценария в производстве и оборонной отрасли

В производстве я бы начинал с вопросов о качестве и обслуживании на данных, которыми вы уже управляете. Брак и переделка по линии, смене и материалу. Открытые уведомления о качестве по поставщику.

Средняя наработка на отказ для критичных активов на основе данных ТОиР из ERP, связанных со сводками из историков или MES. У этих вопросов есть ясные владельцы и пользователи, которые сегодня ждут ответа аналитика днями.

Для первого пилота избегайте прогнозирования спроса или стоимости обслуживания клиента. Определения спорные, а данные охватывают слишком много систем.

В оборонной отрасли сценарий важен меньше, чем средства контроля. Выберите что-то несекретное, проверяемое и чувствительное к разрешениям: наличие запасных частей, статус этапов контракта или показатели поставок поставщиков. Смысл пилота в том, чтобы доказать, что фильтры строк, маски столбцов и пометки экспортного контроля корректно работают при вопросах на естественном языке.

Проверьте варианты развёртывания заранее. Согласно [заметкам о выпуске для AWS GovCloud](https://docs.databricks.com/aws/en/release-notes/gov-cloud/2026), Genie и Genie Agents там GA с января 2026 года, а Genie One с 22 января 2026 года, в GovCloud и GovCloud DoD. Unity Gateway появился в GovCloud в Public Preview в сентябре 2026 года, без бюджетов, inference tables и сервисных политик.

Agent mode за пределами Америки, Европы, Австралии, Новой Зеландии и Японии требует включённой обработки за пределами географии (cross-Geo). Для программы, чувствительной к суверенитету данных, в странах Залива или в Азии это решение на уровне политики, а не галочка.

## План пилота в десять шагов

Вот последовательность, которую я бы выполнял. Если данные уже управляются в Unity Catalog, большая часть времени уходит на шаги с 3 по 7. В пилотах с естественным языком, в которых я работал, проблемы возникали с подготовкой пользователей.

Бизнес-пользователей не ввели в работу должным образом, поэтому они были не готовы, и во многом из-за этого пробела семантический слой и пилот заняли около двух месяцев. Готовьте пользователей параллельно со сборкой, а не после неё.

1. **Выберите один домен и одного спонсора.** Руководителя по качеству на заводе или руководителя логистики, а не «бизнес» вообще.
2. **Соберите от 50 до 100 реальных вопросов** от людей, которые будут этим пользоваться. Они станут вашим эталонным набором.
3. **Добейтесь, чтобы у каждой метрики был владелец и определение.** Финансы или производство утверждают определение до того, как оно станет metric view.
4. **Постройте metric views и подготовленные таблицы.** Держитесь с запасом ниже лимита в 50 таблиц.
5. **Добавьте примеры SQL, функции и синонимы** для вопросов, на которые с первого раза получен неверный ответ.
6. **Тестируйте разрешения от имени реальных пользователей.** Войдите как пользователь с ограниченным доступом и задайте вопросы, рассчитанные на утечку данных. Зафиксируйте результаты.
7. **Прогоните эталонный набор и зафиксируйте точность**, прежде чем это увидит хоть один пользователь.
8. **Откройте доступ группе от 10 до 20 пользователей** с циклом обратной связи и названным распорядителем данных (data steward), который еженедельно разбирает ответы с оценкой «палец вниз».
9. **Настройте бюджеты и оповещения** до того, как использование вырастет.
10. **Примите решение в фиксированную дату:** расширять, исправлять или останавливать, по критериям, согласованным на шаге 1.

Люди остаются в контуре на всём протяжении. Подготовкой данных владеет распорядитель данных.

Любой, кто использует ответ для финансовой цифры, решения по безопасности или контрактного обязательства, сверяет его с исходным отчётом, пока эталонный набор не докажет надёжность. Для любого агента, который записывает данные в систему, действие утверждает человек.

## Управление, затраты и что измерять

Сейчас пробовать Genie дёшево. Согласно [документации по бюджетам Genie](https://docs.databricks.com/aws/en/genie/budgets), использование LLM в Genie One и Genie Agents бесплатно до 31 января 2027 года. Сервисные субъекты (service principals) исключены и оплачивают всё использование, что важно, если вы встраиваете Genie через API.

Вычисления SQL warehouse оплачиваются отдельно и составляют реальную стоимость эксплуатации. Genie Code с 8 июля 2026 года оплачивается по мере использования, с бесплатным лимитом 150 DBU на пользователя в месяц.

На странице цен Databricks 150 DBU стоят $10,50 в US East (цена по прайс-листу, проверено в октябре 2026 года). В других регионах цифры отличаются, а корпоративные скидки и обязательства меняют сумму.

Бюджеты позволяют задавать общие и индивидуальные пороги, но блокировка срабатывает приблизительно, так что бюджет не является жёстким лимитом. Сверяйтесь с `system.billing.usage`. Моё [руководство по ценам Databricks](/ru/databricks-pricing-explained/) разбирает выбор размера warehouse.

Что измерять:

| Показатель | Почему важен | Целевое значение, которое нужно согласовать до go-live |
|---|---|---|
| Точность на эталонном наборе | Показывает, работает ли подготовка данных | Порог для каждого домена, утверждённый владельцем метрики |
| Доля проверенных ответов | Ответы на доверенном SQL безопаснее | Растёт неделя к неделе |
| Доля оценок «палец вниз» и время исправления | Показывает, работает ли распоряжение данными | Разбирается еженедельно |
| Результаты тестов разрешений | Доказывают, что средства контроля держатся | Ноль утечек |
| Предотвращённые запросы к аналитикам | Бизнес-кейс | Базовый уровень измерен до пилота |
| Стоимость warehouse на активного пользователя | Реальная стоимость эксплуатации | В пределах бюджета |

Управление данными здесь является фундаментом. Если Unity Catalog ещё не внедрён, начните с него; моё [руководство по Unity Catalog и управлению данными](/ru/databricks-unity-catalog-data-governance/) и [руководство по фреймворку управления AI](/ru/ai-governance-framework-guide-building-a-responsible-ai-plan/) разбирают подготовительную работу.

## С чего начать

Возьмите один домен, запишите 50 вопросов, которые ваши пользователи действительно задают, и проверьте, на сколько из них ваши текущие данные могут ответить с помощью определённых метрик. Это упражнение скажет вам о готовности к Genie больше, чем любая демонстрация. Если вы также рассматриваете альтернативу, сравните с [Snowflake Cortex AI и Snowflake Intelligence](/ru/snowflake-cortex-ai-snowflake-intelligence/).

Я помогаю организациям принимать такие решения и определять объём пилотов. Если вам нужен второй взгляд, [запишитесь на звонок](/ru/contact-noel-erp-support/).

## Часто задаваемые вопросы

<details>
<summary>Что такое Databricks Genie?</summary>

Databricks Genie представляет собой семейство AI-инструментов, которые отвечают на вопросы на естественном языке, используя управляемые данные в Databricks. Genie One служит интерфейсом для бизнес-пользователей, Genie Agents представляют собой подготовленные чаты по конкретным доменам (ранее Genie spaces), а Genie Code является помощником для разработчиков и аналитиков. Ответы генерируются в виде SQL только для чтения и учитывают разрешения Unity Catalog каждого пользователя.

</details>

<details>
<summary>Чем Genie spaces отличаются от Genie Agents?</summary>

Функционально ничем. Databricks переименовал Genie spaces в Genie Agents в июле 2026 года и заявил, что возможности не изменились. В старых статьях, учебных материалах и публикациях сообщества всё ещё используется «Genie spaces».

</details>

<details>
<summary>Сколько стоит Databricks Genie?</summary>

Использование LLM в Genie One и Genie Agents бесплатно для пользователей до 31 января 2027 года. Сервисные субъекты оплачивают использование, а вычисления SQL warehouse оплачиваются отдельно. Genie Code оплачивается по мере использования сверх бесплатного месячного лимита.

</details>

<details>
<summary>Достаточно ли точен Databricks Genie для финансовой или операционной отчётности?</summary>

Может быть достаточно точен внутри подготовленного домена с metric views, примерами SQL и доверенными функциями, если точность измеряется на эталонном наборе вопросов. Если направить его на сырые таблицы, он будет давать правдоподобные ответы, которые могут не совпадать с вашими определениями. Считайте его ответы непроверенными для финансовых решений и решений по безопасности, пока эталонный набор не докажет обратное.

</details>

<details>
<summary>Для чего используется Databricks Agent Bricks?</summary>

Для создания, развёртывания и управления собственными AI-агентами на вашем фреймворке и вашей модели. В него входят Agent Bricks CLI, Agent Runtime, управляемая память и оценка через MLflow. Knowledge Assistant и Supervisor Agent больше не рекомендуются для новых агентов.

</details>

<details>
<summary>Поддерживает ли Databricks MCP?</summary>

Да. Databricks предоставляет управляемые MCP-серверы, в том числе для Genie One и Databricks SQL, а вы можете регистрировать внешние серверы или создавать собственные на Databricks Apps. Доступ управляется через разрешения Unity Catalog и Unity Gateway.

</details>
