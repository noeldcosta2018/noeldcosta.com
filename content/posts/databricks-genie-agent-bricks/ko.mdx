Databricks Genie를 사용하면 현업 사용자가 거버넌스가 적용된 회사 데이터에 일상 언어로 질문하고, SQL과 결과 테이블, 차트를 돌려받을 수 있습니다. 데이터 팀이 정의된 지표로 좁은 도메인을 큐레이션해 두었을 때는 잘 작동하고, 원시 테이블에 연결해 놓고 추측하게 두면 형편없이 작동합니다.

Agent Bricks는 나머지 절반입니다. 개발자가 Genie, 문서, 함수, 외부 도구를 호출할 수 있는 맞춤형 AI 에이전트를 구축하고 배포하고 평가하는 곳입니다.

저는 제조와 방위 산업의 데이터 플랫폼 프로그램에서 Databricks를 다뤄 왔습니다. 제 견해는 단순합니다. AI 계층은 이제 계획 담당자, 품질 엔지니어, 재무 팀 앞에 내놓을 만큼 충분히 좋아졌습니다.

어려운 부분은 그 아래의 시맨틱 작업과 거버넌스 작업, 그리고 현업 사용자가 이를 쓸 준비를 갖추게 하는 일입니다. 파일럿 노력 대부분은 여기에 들어가야 합니다.

## 2026년 말 기준 Databricks Genie란 무엇일까요

Databricks는 2026년에 Genie 제품군 대부분의 이름을 바꿨으므로, 예전 글을 보면 헷갈릴 것입니다. 이전에 Databricks One이라고 부르던 현업 사용자 경험은 2026년 6월에 Genie One이 되었습니다.

Genie spaces는 2026년 7월에 Genie Agents가 되었습니다. Databricks Assistant는 이제 Genie Code입니다.

아래 표는 각 제품이 하는 일과 2026년 10월 기준 상태를 정리한 것입니다.

| 제품 | 하는 일 | 사용자 | 상태(2026년 10월) |
|---|---|---|---|
| Genie One | 대시보드, Genie Agents, 앱을 아우르는 하나의 채팅 인터페이스, iOS 및 Android 앱도 제공 | 현업 사용자 | 채팅은 2026년 6월부터 GA, 모바일 앱은 Public Preview |
| Genie Agents(이전 Genie spaces) | 최대 50개의 테이블, 뷰, 메트릭 뷰를 대상으로 하는 큐레이션된 도메인별 채팅 | 분석가가 구축하고 현업 사용자가 질문 | 에이전트 모드는 2026년 7월부터 GA, 여러 부가 기능은 Beta |
| Genie Code(이전 Databricks Assistant) | 노트북, 파이프라인, 대시보드를 위한 코딩 및 데이터 어시스턴트 | 엔지니어, 분석가 | 2026년 7월 8일부터 종량제 |
| Conversation API | Genie Agents를 앱, 챗봇, 다른 에이전트에 내장 | 개발자 | 에이전트 모드 API와 시각화 조회는 2026년 8월부터 GA |
| Databricks 제공 MCP 커넥터 | Genie One과 Genie Code가 Model Context Protocol로 외부 도구를 사용하게 함 | 관리자, 개발자 | 2026년 9월부터 GA, 쓰기 작업은 Beta |

Genie Agent는 관련 메타데이터, 지침, 예시 SQL, 채팅 이력을 골라낸 뒤 SQL을 생성합니다. 그 SQL은 Pro 또는 서버리스 SQL 웨어하우스에서 실행되며 항상 읽기 전용입니다.

가장 중요한 거버넌스 포인트는 이것입니다. [Genie Agent 설정 문서](https://docs.databricks.com/aws/en/genie-agents/set-up)에 따르면 데이터 접근은 항상 각 최종 사용자 본인의 Unity Catalog 권한으로 평가됩니다. 볼 수 없는 데이터에 대해 질문한 사용자는 빈 답을 받습니다.

행 필터와 열 마스크가 적용됩니다. 사용자가 쿼리를 실행할 수 있도록 작성자의 웨어하우스 자격 증명이 내장되지만, 그것이 누구의 데이터 접근 범위도 넓히지는 않습니다.

## 무엇이 Databricks Genie를 정확하게 만들고, 어디서 실패할까요

정확도를 좌우하는 것은 모델이 아닙니다. 큐레이션입니다. [Genie Agent 품질 튜닝 가이드](https://docs.databricks.com/aws/en/genie-agents/tune-quality)는 비즈니스 로직을 SQL 표현식으로 정의하라고 권장합니다. 텍스트 지침보다 더 일관된 결과를 주기 때문입니다.

제가 본 바로는 영향이 큰 순서대로 다음과 같습니다.

1. **메트릭 뷰.** 메트릭 뷰를 핵심으로 하는 Unity Catalog Business Semantics는 2026년 4월에 GA가 되었습니다. "직행률(first-pass yield)"이나 "납기 준수율"을 레이블과 동의어와 함께 한 번만 정의하면, 그 위에 바로 Genie Agents를 구축할 수 있습니다. 지표가 정의되어 있으면 Genie가 추론할 필요가 없습니다.
2. **예시 SQL 쿼리.** 실제 질문과 그에 답하는 SQL을 짝지으십시오. 스크랩 비용을 어떻게 계산하는지, 어느 공장이 어느 지역으로 집계되는지처럼 귀사만의 로직에 집중하십시오.
3. **신뢰 자산으로서의 SQL 함수.** Unity Catalog 함수는 정적 쿼리가 담을 수 없는 로직을 담습니다. Genie가 매개변수화된 쿼리나 함수를 사용하면 답이 검증됨으로 표시됩니다. 사용자에게는 그 함수에 대한 `EXECUTE` 권한이 필요합니다.
4. **지식 저장소.** 설명, 동의어, 조인 관계, 숨긴 열입니다. 중복된 기술 열을 숨기는 것이 사람들이 예상하는 것보다 더 도움이 됩니다.
5. **일반 지침.** 모든 곳에 적용되지만 다른 어디에도 맞지 않는 맥락을 위한 텍스트입니다. 짧게, 모순 없이 유지하십시오.

엄격한 한도가 있습니다. 에이전트당 테이블, 뷰, 메트릭 뷰는 50개입니다.

지침은 100개이며, 예시 쿼리와 SQL 함수도 각각 하나로 계산됩니다. 조인과 SQL 표현식을 위한 스니펫은 200개입니다.

저는 이 한도를 설계 지침으로 받아들입니다. "제조 전체"를 다루는 Genie Agent는 실망스러울 것입니다. "두 공장의 품질 통지와 스크랩"을 다루는 Genie Agent는 아주 좋을 수 있습니다.

### Genie가 실패하는 곳

벤더 데모가 건너뛰는 부분입니다.

1. **정의되지 않은 비즈니스 용어.** 원시 ERP 테이블에 대고 "지난 분기 마진은 얼마였나"라고 물으면 Genie가 정의를 하나 고를 것입니다. 그것이 재무의 정의가 아닐 수 있습니다. SAP, Oracle, Dynamics 365 데이터가 거버넌스가 적용된 지표 계층 없이 들어온다면, 그럴듯하지만 맞아떨어지지 않는 숫자를 예상하십시오.
2. **지저분한 마스터 데이터.** 중복된 자재 번호, 일관되지 않은 공장 코드, 자유 텍스트로 된 결함 설명은 자신만만하게 틀린 답을 만듭니다. Genie는 주어진 것의 품질을 증폭합니다.
3. **모호한 질문.** "어느 라인이 가장 나쁜가?" 무엇이 나쁘다는 것입니까? 좋은 큐레이션과 예시 질문이 사용자를 이끌어 줍니다. 그래도 사용자가 구체적으로 물어야 할 필요가 사라지지는 않습니다.
4. **언어.** 문서에 따르면 프롬프트는 영어로 감싸지므로, 사용자가 다른 언어로 써도 답이 영어로 돌아올 수 있습니다. 비영어권 공장에 배포하기 전에 테스트하십시오.
5. **인사이트일 뿐 실행은 아닙니다.** 생성된 SQL은 읽기 전용입니다. 통제 측면에서는 강점입니다. 동시에 Genie는 정비 계획 담당자에게 어떤 자산의 정비가 기한을 넘겼는지 알려 줄 뿐, 작업 오더를 발행하지는 않는다는 뜻입니다.

## Agent Bricks, MCP, Unity Gateway

Agent Bricks도 모습이 바뀌었습니다. [Agent Bricks 개요](https://docs.databricks.com/aws/en/agents/concepts/)는 이제 이를 코드를 작성하는 사람을 위한 Databricks 에이전트 개발자 플랫폼으로 설명합니다.

자체 프레임워크와 모델을 가져와 Agent Bricks CLI로 골격을 만들고, Databricks Apps 위의 Agent Runtime에 배포합니다. 예전 자료에서는 이 계층을 Mosaic AI Agent Framework라고 부르며, 문서에도 아직 Mosaic AI 레이블이 일부 남아 있습니다.

구매자가 알아야 할 것이 두 가지 있습니다. 이전의 선언형 빌더인 Knowledge Assistant와 Supervisor Agent는 이제 "신규 에이전트에는 더 이상 권장되지 않으며", Supervisor API는 지원 중단되었습니다.

Databricks는 로우코드 사용자는 Genie Agents로, 개발자는 CLI로 안내합니다. SI가 둘 중 하나에 기반한 설계를 제안한다면 이유를 물으십시오.

문서에서 정보를 추출하는 권장 경로는 AI Functions입니다. SQL에서 문서를 분류하고, 추출하고, 요약하고, 파싱합니다. 제조업체라면 공급업체 인증서, 검사 보고서, 정비 로그가 여기에 해당합니다.

평가는 관리형 MLflow로 진행합니다. 모든 에이전트 단계의 트레이스, 정확성 같은 내장 LLM 판정기, 사용자 지정 채점기, 전문가 피드백이 있습니다. 같은 채점기로 운영 트래픽의 샘플을 모니터링할 수 있습니다.

[Unity Gateway](https://docs.databricks.com/aws/en/unity-gateway/)(URL에는 아직 ai-gateway라고 되어 있습니다)가 컨트롤 플레인입니다. 모델 및 MCP 서비스에 대한 속도 제한, 가드레일을 위한 서비스 정책, PII 마스킹, 시스템 테이블에서의 사용량 추적, Unity Catalog 테이블로의 요청 및 응답 로깅, 모델 간 폴백을 제공합니다. Databricks 제공 MCP 서버와 등록된 MCP 서버는 Unity Catalog 권한을 사용하므로, Genie One MCP 서버를 호출하는 에이전트도 여전히 사용자가 볼 수 있는 범위에 묶입니다.

## 제조와 방위 산업에서 첫 활용 사례 고르기

제조업이라면 저는 이미 거버넌스를 적용하고 있는 데이터에 대한 품질과 정비 질문으로 시작하겠습니다. 라인, 교대조, 자재별 스크랩과 재작업. 공급업체별 미결 품질 통지.

ERP 설비 보전 데이터를 히스토리안이나 MES 요약과 결합해 구한 핵심 자산의 평균 고장 간격. 이런 질문에는 명확한 책임자가 있고, 지금은 분석가를 며칠씩 기다리는 사용자가 있습니다.

첫 파일럿으로 수요 예측이나 cost-to-serve는 피하십시오. 정의에 대한 이견이 있고 데이터가 너무 많은 시스템에 걸쳐 있습니다.

방위 산업에서는 활용 사례보다 통제가 더 중요합니다. 비기밀이고, 감사 가능하며, 권한에 민감한 것을 고르십시오. 예비 부품 가용성, 계약 마일스톤 현황, 공급업체 납품 실적 같은 것입니다. 파일럿의 목적은 일상 언어 질문에서도 행 필터, 열 마스크, 수출 통제 플래그가 올바르게 작동한다는 것을 증명하는 것입니다.

배포 환경은 일찍 확인하십시오. [AWS GovCloud 릴리스 노트](https://docs.databricks.com/aws/en/release-notes/gov-cloud/2026)에 따르면 Genie와 Genie Agents는 2026년 1월부터, Genie One은 2026년 1월 22일부터 GovCloud와 GovCloud DoD 모두에서 GA입니다. Unity Gateway는 2026년 9월에 Public Preview로 GovCloud에 들어왔지만, 예산, 추론 테이블, 서비스 정책은 빠져 있습니다.

미주, 유럽, 호주, 뉴질랜드, 일본 밖에서 에이전트 모드를 쓰려면 지역 간(cross-Geo) 처리를 활성화해야 합니다. 걸프 지역이나 아시아에서 주권에 민감한 프로그램이라면 이는 체크박스가 아니라 정책 결정입니다.

## 10단계 파일럿 계획

제가 진행할 순서는 이렇습니다. 데이터가 이미 Unity Catalog에서 거버넌스되고 있다면, 시간 대부분은 3~7단계에 들어갑니다. 제가 참여한 일상 언어 질의 파일럿에서 문제가 생긴 곳은 온보딩이었습니다.

현업 사용자가 제대로 온보딩되지 않아 준비가 되어 있지 않았고, 시맨틱 계층과 파일럿 작업에 약 두 달이 걸린 것은 대부분 그 공백 때문이었습니다. 사용자 온보딩은 구축이 끝난 뒤가 아니라 구축과 함께 진행하십시오.

1. **도메인 하나와 후원자 한 명을 고릅니다.** "현업 전체"가 아니라 공장 품질 관리자나 물류 책임자입니다.
2. **실제로 사용할 사람들로부터 실제 질문 50~100개를 받아 적습니다.** 이것이 벤치마크가 됩니다.
3. **지표마다 책임자를 정하고 정의합니다.** 메트릭 뷰가 되기 전에 재무나 운영이 정의를 승인합니다.
4. **메트릭 뷰와 큐레이션된 테이블을 구축합니다.** 50개 테이블 한도보다 충분히 적게 유지하십시오.
5. **처음에 실패한 질문에 대해 예시 SQL, 함수, 동의어를 추가합니다.**
6. **실제 사용자로서 권한을 테스트합니다.** 제한된 사용자로 로그인해 데이터 유출을 노린 질문을 던지십시오. 결과를 기록하십시오.
7. **사용자에게 보여 주기 전에 벤치마크를 실행하고 정확도를 기록합니다.**
8. **사용자 10~20명에게 공개합니다.** 피드백 루프를 두고, 지정된 데이터 스튜어드가 매주 '싫어요' 답변을 검토합니다.
9. **사용량이 늘기 전에 예산과 알림을 설정합니다.**
10. **정해진 날짜에 결정합니다.** 1단계에서 합의한 기준에 따라 확대, 수정, 중단 중 하나를 고릅니다.

처음부터 끝까지 사람이 관여합니다. 큐레이션은 데이터 스튜어드가 책임집니다.

재무 수치, 안전 결정, 계약상 약속에 답을 사용하는 사람은 벤치마크가 신뢰성을 증명할 때까지 원천 리포트와 대조해 확인합니다. 시스템에 쓰기를 하는 에이전트라면 사람이 그 작업을 승인합니다.

## 거버넌스, 비용, 그리고 측정할 것

지금은 Genie를 저렴하게 시험해 볼 수 있습니다. [Genie 예산 문서](https://docs.databricks.com/aws/en/genie/budgets)에 따르면 Genie One과 Genie Agents의 LLM 사용은 2027년 1월 31일까지 무료입니다. 서비스 주체는 제외되어 모든 사용량이 청구되며, API로 Genie를 내장한다면 이 점이 중요합니다.

SQL 웨어하우스 컴퓨트는 별도로 청구되며 이것이 실제 운영 비용입니다. Genie Code는 2026년 7월 8일부터 종량제이며, 사용자당 월 150 DBU의 무료 할당량이 있습니다.

Databricks 가격 페이지 기준으로 150 DBU는 US East에서 $10.50입니다(정가, 2026년 10월 확인). 리전마다 다르며, 엔터프라이즈 할인과 약정이 금액을 바꿉니다.

예산은 공용 및 사용자별 임계값을 설정할 수 있지만 차단은 근사치로 작동하므로, 예산이 엄격한 상한은 아닙니다. `system.billing.usage`와 대조하십시오. 웨어하우스 규모 산정은 제 [Databricks 가격 가이드](/ko/databricks-pricing-explained/)에서 다룹니다.

측정할 것은 다음과 같습니다.

| 지표 | 중요한 이유 | Go-Live 전에 합의할 목표 |
|---|---|---|
| 벤치마크 정확도 | 큐레이션이 효과가 있는지 보여 줌 | 도메인별 기준치, 지표 책임자가 승인 |
| 검증된 답변 비율 | 신뢰할 수 있는 SQL에 기반한 답이 더 안전함 | 주 단위로 상승 |
| '싫어요' 비율과 수정 시간 | 스튜어드십이 작동하는지 알려 줌 | 매주 검토 |
| 권한 테스트 결과 | 통제가 유지됨을 증명 | 유출 0건 |
| 줄어든 분석가 요청 | 비즈니스 케이스 | 파일럿 전에 기준선 측정 |
| 활성 사용자당 웨어하우스 비용 | 실제 운영 비용 | 예산 이내 |

여기서 거버넌스는 기초입니다. Unity Catalog가 아직 갖춰지지 않았다면 거기서 시작하십시오. 제 [Unity Catalog와 데이터 거버넌스 가이드](/ko/databricks-unity-catalog-data-governance/)와 [AI 거버넌스 프레임워크 가이드](/ko/ai-governance-framework-guide-building-a-responsible-ai-plan/)에서 기초 작업을 다룹니다.

## 어디서부터 시작할까요

도메인 하나를 정하고, 사용자가 실제로 묻는 질문 50개를 적은 뒤, 현재 데이터가 정의된 지표로 그중 몇 개에 답할 수 있는지 확인하십시오. 이 작업이 어떤 데모보다 Genie 준비 상태에 대해 더 많은 것을 알려 줍니다. 대안도 함께 검토하고 있다면 [Snowflake Cortex AI와 Snowflake Intelligence](/ko/snowflake-cortex-ai-snowflake-intelligence/)와 비교해 보십시오.

저는 조직이 이런 결정을 내리고 파일럿 범위를 정하도록 돕고 있습니다. 다른 관점이 필요하시면 [상담을 예약](/ko/contact-noel-erp-support/)하십시오.

## 자주 묻는 질문

<details>
<summary>Databricks Genie란 무엇입니까?</summary>

Databricks Genie는 Databricks에서 거버넌스가 적용된 데이터를 사용해 일상 언어 질문에 답하는 AI 도구 제품군입니다. Genie One은 현업 사용자 인터페이스이고, Genie Agents는 큐레이션된 도메인별 채팅(이전 Genie spaces)이며, Genie Code는 개발자와 분석가를 위한 어시스턴트입니다. 답은 읽기 전용 SQL로 생성되며 각 사용자의 Unity Catalog 권한을 따릅니다.

</details>

<details>
<summary>Genie spaces와 Genie Agents의 차이는 무엇입니까?</summary>

기능상으로는 차이가 없습니다. Databricks는 2026년 7월에 Genie spaces의 이름을 Genie Agents로 바꾸면서 기능은 그대로라고 밝혔습니다. 예전 글, 교육 자료, 커뮤니티 게시물에는 아직 "Genie spaces"라는 이름이 쓰입니다.

</details>

<details>
<summary>Databricks Genie의 비용은 얼마입니까?</summary>

Genie One과 Genie Agents의 LLM 사용은 2027년 1월 31일까지 사용자에게 무료입니다. 서비스 주체는 청구되며, SQL 웨어하우스 컴퓨트는 별도로 청구됩니다. Genie Code는 월 무료 할당량을 넘으면 종량제입니다.

</details>

<details>
<summary>Databricks Genie는 재무나 운영 리포팅에 쓸 만큼 정확합니까?</summary>

메트릭 뷰, 예시 SQL, 신뢰할 수 있는 함수를 갖춘 큐레이션된 도메인 안에서, 벤치마크 질문 세트로 측정한다면 그럴 수 있습니다. 원시 테이블에 연결하면 귀사의 정의와 맞지 않을 수 있는 그럴듯한 답을 내놓을 것입니다. 벤치마크가 달리 증명할 때까지는 재무나 안전 결정에 대해 검증되지 않은 것으로 취급하십시오.

</details>

<details>
<summary>Databricks Agent Bricks는 어디에 쓰입니까?</summary>

자체 프레임워크와 모델로 맞춤형 AI 에이전트를 구축하고, 배포하고, 거버넌스하는 데 쓰입니다. Agent Bricks CLI, Agent Runtime, 관리형 메모리, MLflow 평가가 포함됩니다. Knowledge Assistant와 Supervisor Agent는 신규 에이전트에 더 이상 권장되지 않습니다.

</details>

<details>
<summary>Databricks는 MCP를 지원합니까?</summary>

네. Databricks는 Genie One과 Databricks SQL을 포함한 관리형 MCP 서버를 제공하며, 외부 서버를 등록하거나 Databricks Apps 위에 사용자 지정 서버를 구축할 수도 있습니다. 접근은 Unity Catalog 권한과 Unity Gateway로 관리됩니다.

</details>
