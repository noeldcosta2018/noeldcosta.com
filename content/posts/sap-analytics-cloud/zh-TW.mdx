SAP Analytics Cloud（SAC）是 SAP 的雲端產品，把儀表板、規劃與基本的預測分析集中在同一處。如果您使用 SAP，並希望在同一份受治理的資料上做預算、預測與報表，它是正確的選擇。如果您只需要輕量的儀表板，它就是錯誤的選擇。無論哪種情況，只有在餵給它的數字值得信任時，它才行得通。

我曾與一些團隊坐在一起，他們在第一天對 SAC 充滿期待。展示看起來很棒，儀表板很漂亮，每個人都期待立刻獲得洞察。一個月之內，大家就回到了 Excel，交叉核對數字，爭論誰的數字才對。

系統並沒有失敗。失敗的是對資料的信任。

我也看過分析工作陷入停滯，因為資料治理被當成要打勾的項目。當沒有人負責定義時，您的「準時交貨」指標，對不同的團隊會說出不同的故事。儀表板變成爭論的題材，而不是決策的工具。

## SAP Analytics Cloud 能做什麼

SAC 執行在 SAP Business Technology Platform（BTP）上，並結合了多數公司會分別購買的三樣東西。

1. **商業智慧：** 儀表板、報表與故事形式的簡報。
2. **規劃：** 預算、預測、情境模型與版本控制，且規劃資料可以回寫到 S/4HANA。
3. **預測功能：** 趨勢預測、異常偵測與假設情境模型。

這樣的組合，正是它與 Power BI 或 Tableau 的區別，後兩者主要是報表工具。如果貴公司用一個工具做 BI、用試算表做規劃、用電子郵件傳預測，SAC 的主要價值，就是把這三者放到同一個受治理的平台上。

## 有什麼改變：Datasphere、Business Data Cloud 與 Joule

如果您現在正在評估 SAC，有三項改變值得注意。

**Datasphere 是底下的資料層。** SAP Datasphere 在 [2023 年 3 月](https://news.sap.com/2023/03/sap-datasphere-business-data-fabric/)取代了 SAP Data Warehouse Cloud。對新專案來說，常見的設計是以 S/4HANA 作為記錄來源，Datasphere 作為語意層，SAC 位於最上層。已經在使用 BW/4HANA 的公司，則保留它作為經過整理的報表層。

**SAC 現在也在 SAP Business Data Cloud 中銷售。** SAP 在 2025 年 2 月推出 Business Data Cloud。它把 Datasphere、SAC、BW private cloud edition 與 SAP Databricks 整合在同一個方案中（[SAP Learning](https://learning.sap.com/courses/exploring-sap-datasphere/describing-the-role-of-sap-datasphere-in-sap-business-data-cloud)）。在比較每位使用者的價格之前，請向 SAP 詢問適用哪一種商業模式，並檢查您的 S/4HANA 或 RISE 合約中已經包含了什麼。

**Joule 用日常語言回答問題。** SAC 的 Just Ask 功能於 2024 年初正式推出，現在 Joule 會在 SAC 內回答分析性的問題。當模型乾淨並標註了業務意義時，這很有用。Joule 針對不一致的 KPI 定義進行查詢，只會更快地給出同樣錯誤的答案。

## SAC 在哪裡創造價值

**財務規劃與分析。** 預算預測變得可以互動。財務可以由上而下或由下而上建模，並並排比較不同版本。不必再傳送名為「final_v8」的 Excel 檔案。差異分析直接連結到成本中心，而針對價格變動、供應商問題或匯率波動的情境，也不必每次都重建模型。如果您正在比較 SAC 與 SAP 較早期的規劃工具，我的 [SAP BPC 指南](/zh-TW/sap-bpc-features-deployment-best-practice-guide/)談到了兩者的差異。

**採購與供應鏈。** 在一個例子中，一家全球配銷公司用 SAC 整合了來自 40 多家供應商的採購資料。一個季度之內，它就標出了兩家反覆延誤的廠商，重新協商條款，並省下超過 $180,000 的罰款。這些資料一直都存在。SAC 只是把它們放在同一處。

**銷售。** 業務代表在同一個畫面上追蹤業績配額、銷售管道與成交率。主管依據每週的數字進行輔導，而不是等到季末才面對意外。

## SAC 的費用

SAP 的價格是起點，不是上限。我曾與一位客戶（一家汽車領域的中型公司）談過，他們原本預期每位使用者是固定費率。與 SAP 通話之後，他們發現，同樣的授權名稱，會因部署方式不同而意義不同。這類細節往往到很晚才浮現。

SAP 的 [SAC 價格頁面](https://www.sap.com/products/data-cloud/cloud-analytics/pricing.html)已不再顯示每位使用者的價格。它會把您導向業務窗口，並把 SAC 與 SAP Business Data Cloud 並列。以下是我在 2025 年公布的參考數字。請用它們來估算預算，然後再取得正式報價。

| 授權類型 | 參考價格（每位使用者每月） | 議價後區間 |
|---|---|---|
| 商業智慧 | 約 $36 | $30 至 $34 |
| 專業規劃 | 約 $147 | $120 至 $135 |
| 檢視者或唯讀 | 約 $22 | $18 至 $20 |

依規模概估的每月預算如下：

| 組織規模 | 使用者組合 | 預估每月費用 |
|---|---|---|
| 小型（10 至 50 位使用者） | 以 BI 為主，規劃很少 | $2,000 至 $6,000 |
| 中型企業（50 至 250 位使用者） | BI 與規劃均衡 | $8,000 至 $25,000 |
| 大型企業（250 位以上使用者） | 客製授權與 SLA | $30,000 以上 |

授權費很少是最大的數字。導入費用通常為 $50,000 至 $200,000。教育訓練再加 $3,000 至 $10,000。連接非 SAP 系統通常要再加 $10,000 以上，而私有雲部署會讓成本增加 25% 至 40%。我看過專案光靠這幾個項目，預算就比原先翻了一倍。

也要看看您已經擁有什麼。有一位客戶只是改變了使用其企業協議下既有授權權益的方式，就大幅降低了 SAC 的成本。

## SAC、Power BI 與 Tableau 的比較

選擇取決於您是否需要規劃，以及您有多少資料放在 SAP。

| | SAP Analytics Cloud | Power BI | Tableau |
|---|---|---|---|
| 核心重點 | BI、規劃與預測 | BI 與報表 | BI 與視覺化探索 |
| SAP 整合 | 與 S/4HANA、BW/4HANA 及 Datasphere 的原生即時連線 | 連接器 | 連接器 |
| 規劃 | 內建，支援版本與回寫 | 需要其他工具 | 需要其他工具 |
| 視覺化彈性 | 良好，但不如其他兩者靈活 | 高 | 非常高 |
| 最適合 | 重度使用 SAP、需要同時做規劃與 BI 的公司 | 以 Microsoft 為核心、專注於報表的公司 | 針對多樣資料進行探索性分析的團隊 |

我的經驗法則：如果規劃是核心需求，而且您的資料都在 SAP 裡，SAC 通常勝出。如果您只需要報表，而且您的人已經習慣用 Power BI 或 Tableau，那 SAC 大概就太重了。

## 如何導入，才不會最後又回到 Excel

這是我會遵循的順序。

1. **先就 KPI 定義達成共識。** 在任何人建立儀表板之前，「營收」在財務、銷售與營運中必須是同一個意思。
2. **為每個關鍵 KPI 指定負責人。** 由此人簽核變更，並在數字對不上時裁決爭議。
3. **依使用情境選擇即時連線或匯入。** 即時連線直接查詢 S/4HANA，不複製任何資料。匯入連線則把資料複製到 SAC，對大型規劃模型的效能較好，但需要排程更新。
4. **從一個高價值的使用情境開始，** 通常是財務預測或供應商績效。先證明可行，建立信任，再擴大範圍。
5. **好好訓練規劃人員。** BI 使用者幾乎不需要上手訓練。規劃使用者則需要針對規劃引擎、公式與版本管理做真正的訓練。採用度通常就在這裡崩盤。
6. **上線後觀察使用情形。** 如果團隊每週還是匯出到 Excel，就代表有些地方沒有落實。

如果 Excel 習慣才是真正的問題，我那篇[為什麼 CFO 仍然習慣用 Excel](/zh-TW/the-50-billion-erp-failure-why-cfos-still-reach-for-excel-instead/)的文章談到了原因。[FMCG 分析救援案例](/zh-TW/erp-recovery-fmcg-sap-analytics-cloud/)則展示了如何用 SAC 重建對數字的信任。

## 常見問題

<details>
<summary>SAP Analytics Cloud 是什麼？它與 Power BI 有何不同？</summary>

SAP Analytics Cloud 在同一個雲端產品中結合了商業智慧、規劃與預測分析。Power BI 主要是報表與視覺化工具，原生的規劃功能有限。如果您需要在儀表板所在的同一處做預算與預測，而且您的資料都在 SAP，SAC 就是為此而生。如果您只需要報表，Power BI 通常更便宜、更簡單。

</details>

<details>
<summary>SAP Analytics Cloud 要花多少錢？</summary>

SAP 現在透過業務窗口為 SAC 報價，而不是公布價格。作為參考，2025 年商業智慧席位約為每位使用者每月 $36，規劃席位則貴上好幾倍。導入費用通常再加 $50,000 至 $200,000，另有教育訓練與整合費用。SAC 也已納入 SAP Business Data Cloud 提供，因此在比較價格之前，請先詢問適用哪一種商業模式。

</details>

<details>
<summary>SAP Analytics Cloud 值得花這筆錢嗎？</summary>

對適合的公司來說，值得。如果您使用 SAP，需要在同一個受治理的地方做規劃與分析，並且重視結構化的模型勝過臨時的探索，那就合理。如果您只需要基本的儀表板，或您的團隊已經在 Power BI 或 Tableau 上運作順暢，那大概就太重了。

</details>

<details>
<summary>為什麼 SAP Analytics Cloud 的導入成果常常不如預期？</summary>

通常有三個原因：來源資料品質不佳、沒有共識的 KPI 定義，以及對規劃使用者的訓練太少。SAC 呈現的是來源系統裡有什麼。如果各團隊的定義不同，它會把分歧浮現出來，而不是把分歧解決。

</details>

<details>
<summary>SAP Analytics Cloud 如何連接到 S/4HANA？</summary>

透過即時連線或匯入連線。即時連線直接查詢 S/4HANA，隨時顯示最新資料。匯入連線則把資料複製到 SAC，以便在大量資料上更快查詢，並搭配排程更新。規劃結果可以回寫到 S/4HANA，讓計畫與實際之間形成閉環。

</details>

<details>
<summary>SAP Analytics Cloud 與 SAP Datasphere 有什麼差別？</summary>

Datasphere 是資料層：它對來自 SAP 與非 SAP 來源的資料進行建模、整合與治理。SAC 是位於其上的分析與規劃層。在 SAP Business Data Cloud 中，兩者一併提供，由 Datasphere 擔任語意層，SAC 則是人們分析與規劃的地方。

</details>
