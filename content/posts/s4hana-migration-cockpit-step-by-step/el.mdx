Το SAP S/4HANA Migration Cockpit είναι το εργαλείο της SAP για τη φόρτωση κύριων δεδομένων και ανοιχτών εγγραφών σε ένα νέο σύστημα S/4HANA, μέσω της εφαρμογής Fiori Migrate Your Data. Επιλέγετε staging tables ή direct transfer, διαλέγετε τα migration objects, αντιστοιχίζετε τις τιμές, κάνετε προσομοίωση και μετά φορτώνετε, αντικείμενο προς αντικείμενο, με τη σειρά των εξαρτήσεων.

Σύντομη απάντηση για έναν επικεφαλής προγράμματος: χρησιμοποιήστε το για νέα υλοποίηση, σχεδιάστε το ως ροή εργασίας από την πρώτη εβδομάδα και αποφασίστε νωρίς ποιος έχει την ευθύνη των δεδομένων. Το εργαλείο είναι το εύκολο κομμάτι.

Αυτός ο οδηγός είναι ένα σκέλος του [οδηγού μου για τη μετάβαση από ECC σε S/4HANA](/el/ecc-to-s4hana-migration/). Είναι γραμμένος για επικεφαλής προγραμμάτων και δεδομένων που πρέπει να τρέξουν σωστά το cockpit, όχι απλώς να το εγκαταστήσουν.

## Τι είναι το Migration Cockpit και πού εφαρμόζεται

Το cockpit μεταφέρει επιχειρησιακά δεδομένα στο S/4HANA με προκαθορισμένα migration objects. Κάθε αντικείμενο περιγράφει τις δομές πηγής και προορισμού για ένα επιχειρησιακό αντικείμενο, όπως έναν πελάτη, έναν προμηθευτή, ένα υλικό ή μια ανοιχτή εγγραφή, μαζί με τους κανόνες αντιστοίχισης μεταξύ τους.

Η SAP είναι σαφής για το εύρος του. Το cockpit είναι [σχεδιασμένο για την αρχική φόρτωση μιας νέας υλοποίησης](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/29193bf0ebdd4583930b2176cb993268/7a62b59726ce42e7a10770b06940f934.html), και όχι για τον συγχρονισμό συστημάτων ή για μια συνεχή ροή δεδομένων. Μια μετατροπή brownfield δεν το χρησιμοποιεί για τη βασική μεταφορά, γιατί το Software Update Manager μετατρέπει τα δεδομένα επί τόπου.

Δύο σημεία ονοματολογίας γλιτώνουν σύγχυση. Η παλιά συναλλαγή Web Dynpro LTMC έχει [καταργηθεί και δεν μπορεί πλέον να χρησιμοποιηθεί για μετάπτωση δεδομένων](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/29193bf0ebdd4583930b2176cb993268/8f97f0b407024465a283809f0bbe000c.html). Σε αυτήν μπορείτε μόνο να δείτε παλιά έργα. Διάδοχός της είναι η εφαρμογή Fiori Migrate Your Data, και αυτήν εννοούν πλέον οι άνθρωποι όταν λένε «το cockpit».

Εφαρμόζεται σε όλες τις εκδόσεις, με διαφορές στο πώς το διαμορφώνετε και το επεκτείνετε. Ο πίνακας τις συγκρίνει όπως ήταν τον Οκτώβριο του 2026:

| Τομέας | SAP S/4HANA on-premise και SAP Cloud ERP Private (S/4HANA Cloud Private Edition) | SAP S/4HANA Cloud Public Edition |
|---|---|---|
| Εφαρμογή | Migrate Your Data | Migrate Your Data (εφαρμογή F3473) |
| Staging tables | Τοπικό σχήμα S/4HANA ή απομακρυσμένο σχήμα SAP HANA | Τοπικό σχήμα, ή απομακρυσμένο σχήμα SAP HANA Cloud στο SAP BTP. Ρύθμιση μέσω του scope item 2Q2 |
| Direct transfer | Από SAP ERP (ECC 6.0 και νεότερο), SAP AFS 6.0, SAP EWM 5.1 και νεότερο, και SAP APO SPP (SCM 7.14 και νεότερο) | Από SAP ECC 6.0 και νεότερο. Ρύθμιση μέσω του scope item BH3 |
| Αλλαγή αντικειμένων | Συναλλαγή LTMOM, το migration object modeler | Εφαρμογή Model Your Migration Objects για staging, εφαρμογή Implementation Activities για direct transfer. Μόνο released αντικείμενα μπορούν να επεκταθούν |
| Περιορισμός συστήματος-πηγής | Ένα σύστημα S/4HANA δεν μπορεί να είναι η πηγή | Συστήματα S/4HANA, Private Edition και Public Edition δεν μπορούν να είναι η πηγή |

## Staging tables ή direct transfer

Κάθε έργο μετάπτωσης χρησιμοποιεί μία από δύο προσεγγίσεις. Η επιλογή διαμορφώνει όλη τη ροή εργασίας των δεδομένων, οπότε κάντε την στη φάση Explore, όχι στη Realize.

**Staging tables.** Το cockpit δημιουργεί ένα σύνολο πινάκων βάσης δεδομένων για κάθε migration object του έργου σας. Τους γεμίζετε από τα αρχεία προτύπων XML της SAP, από αρχεία CSV ή με δικά σας εργαλεία, όπως το SAP Data Services ή άλλο εργαλείο ETL. Η πηγή μπορεί να είναι οτιδήποτε: ένα παλιό σύστημα SAP, Oracle, Dynamics, ένα εσωτερικά αναπτυγμένο σύστημα ή ένα υπολογιστικό φύλλο.

**Direct transfer.** Το cockpit συνδέεται σε ένα σύστημα-πηγή SAP μέσω RFC και επιλέγει το ίδιο τα δεδομένα, ανά κωδικό εταιρείας για μια πηγή ERP. Οι [προϋποθέσεις](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/29193bf0ebdd4583930b2176cb993268/94f7b5a36db64633a4d49623f66e04c7.html) περιλαμβάνουν το add-on DMIS στο σύστημα-πηγή, το οποίο περιλαμβάνεται στην άδεια του S/4HANA. Τα συστήματα-πηγή μπορούν να είναι non-Unicode.

Έτσι συγκρίνονται οι δύο για τις αποφάσεις που πρέπει να πάρει ένας επικεφαλής δεδομένων:

| Ερώτηση | Staging tables | Direct transfer |
|---|---|---|
| Ποιες πηγές; | Οποιοδήποτε σύστημα, μέσω αρχείων ή εργαλείων | Μόνο υποστηριζόμενες πηγές SAP |
| Πού γίνεται ο καθαρισμός; | Στα staging tables ή πιο πριν, πριν από τη φόρτωση | Κυρίως στο σύστημα-πηγή, πριν από την επιλογή |
| Ποιος μπορεί να ελέγξει τα δεδομένα πριν από τη φόρτωση; | Όποιος έχει πρόσβαση στους πίνακες ή στα αρχεία | Κυρίως η ομάδα του cockpit, μέσα από τις οθόνες του cockpit |
| Προσπάθεια για να ξεκινήσετε | Μεγαλύτερη: χτίζετε την εξαγωγή και γεμίζετε τους πίνακες | Μικρότερη: το cockpit επιλέγει για εσάς |
| Καλύτερη εφαρμογή | Πολλές πηγές, βρώμικα δεδομένα, μεγάλος μετασχηματισμός | Μια καθαρή πηγή SAP ERP που μεταφέρεται σε νέο σχεδιασμό S/4HANA |

Το direct transfer μπορεί επίσης να σταθμεύσει τα επιλεγμένα δεδομένα σε staging tables ως ενδιάμεση αποθήκευση, κάτι που σας δίνει ένα ενδιάμεσο σημείο ελέγχου. Ελέγξτε αν η έκδοσή σας το υποστηρίζει πριν σχεδιάσετε γύρω από αυτό.

### Γιατί οι ομάδες που οδηγώ χρησιμοποιούν staging tables

Οι ομάδες που οδηγώ χρησιμοποιούν το cockpit. Εγώ δεν το τρέχω ο ίδιος. Η προεπιλογή τους, και η δική μου προτίμηση, είναι τα staging tables έναντι του direct transfer.

Ο λόγος είναι ο έλεγχος. Με τα staging tables, τα δεδομένα που θα φορτωθούν βρίσκονται σε πίνακες που μπορείτε να ρωτήσετε, να ελέγξετε με βάση επιχειρησιακούς κανόνες και να διορθώσετε πριν αγγίξει οτιδήποτε το S/4HANA. Οι υπεύθυνοι δεδομένων μπορούν να εγκρίνουν αυτό που πραγματικά βλέπουν, όχι μια επιλογή που πρέπει να εμπιστευτούν.

Διαχωρίζει επίσης τον καθαρισμό από τη φόρτωση. Διπλότυποι προμηθευτές, ελλιπή τραπεζικά στοιχεία και λάθος μονάδες μέτρησης διορθώνονται σε ένα σημείο, με ίχνος ελέγχου, και η ίδια η φόρτωση γίνεται επαναλήψιμη. Το direct transfer ξεκινά πιο γρήγορα, αλλά τείνει να μεταφέρει τις συνήθειες του συστήματος-πηγής κατευθείαν στο νέο.

Το direct transfer έχει πάντως τη θέση του. Αν η πηγή είναι ένα μοναδικό, καλά συντηρημένο σύστημα SAP ERP και ο σχεδιασμός-στόχος είναι κοντά του, γλιτώνει πραγματική δουλειά εξαγωγής.

## Το Migration Cockpit βήμα προς βήμα

Η SAP περιγράφει [τη διαδικασία μετάπτωσης](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/29193bf0ebdd4583930b2176cb993268/c67e14ff693e423aae2b96d9f3b0fc91.html) ως μια σταθερή ακολουθία. Αυτά είναι τα βήματα όπως θα τα τρέξει η ομάδα σας με staging tables.

<stepper title="Η διαδικασία του Migration Cockpit" steps="Δημιουργία έργου|Γέμισμα staging tables|Αντιστοίχιση τιμών|Προσομοίωση|Μετάπτωση και διόρθωση" bodies="Ανοίξτε το Migrate Your Data, δημιουργήστε ένα έργο και επιλέξτε τα migration objects στο εύρος.|Κατεβάστε τα πρότυπα και ανεβάστε τα, ή γεμίστε τους πίνακες με δικά σας εργαλεία.|Επεξεργαστείτε τις ανοιχτές εργασίες αντιστοίχισης: αντιστοιχίσεις τιμών και σταθερές τιμές.|Προσομοιώστε τη φόρτωση και διορθώστε κάθε σφάλμα πριν καταχωρίσετε οτιδήποτε.|Φορτώστε με τη σειρά των εξαρτήσεων, μετά διορθώστε τις αποτυχημένες εγγραφές και κάντε συμφωνία."></stepper>

1. **Δημιουργήστε το έργο μετάπτωσης.** Στην εφαρμογή Migrate Your Data, δημιουργήστε ένα έργο, επιλέξτε πού βρίσκονται τα staging tables (τοπικό ή απομακρυσμένο σχήμα) και επιλέξτε τα αντικείμενα στο εύρος. Η SAP συνιστά να δημιουργείτε τα έργα πρώτα σε ένα δοκιμαστικό σύστημα που είναι αντίγραφο της παραγωγής, και ένα νέο έργο για κάθε δοκιμαστική μεταφορά που ενσωματώνει τις διορθώσεις της προηγούμενης.
2. **Ελέγξτε τις εξαρτήσεις.** Ένα migration object μπορεί να έχει προαπαιτούμενα αντικείμενα που πρέπει να επεξεργαστούν πρώτα, και επόμενα αντικείμενα που έρχονται μετά. Η εφαρμογή Explore Migration Objects (F8638) δείχνει τα υποχρεωτικά και τα προαιρετικά προαπαιτούμενα ως γράφημα. Business partners πριν από τις ανοιχτές εγγραφές, υλικά πριν από τα αποθέματα: το cockpit δεν θα σας αφήσει να παρακάμψετε τη σειρά.
3. **Γεμίστε τα staging tables.** Τα πρότυπα XML είναι η προεπιλεγμένη και συνιστώμενη επιλογή της SAP, γιατί κάθε αρχείο περιέχει όλες τις δομές του αντικειμένου μαζί με οδηγίες. Το CSV είναι επιλογή για ειδικούς, ένα αρχείο ανά δομή. Ένα [μεμονωμένο αρχείο XML μπορεί να φτάσει τα 100 MB](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/29193bf0ebdd4583930b2176cb993268/5cc41962b2624ac5b9a136e69369f5e0.html), και ένα zip με πολλά αρχεία XML δεν μπορεί επίσης να ξεπεράσει τα 100 MB, οπότε τα μεγάλα αντικείμενα χρειάζονται διαχωρισμό ή ένα εργαλείο που γράφει απευθείας στους πίνακες.
4. **Διαβάστε τα μηνύματα επικύρωσης.** Μετά το ανέβασμα, το σύστημα επικυρώνει το αρχείο και προσθέτει ένα φύλλο Messages με κάθε σφάλμα και προειδοποίηση, συνδεδεμένα με το αντίστοιχο κελί. Τα αρχεία με προειδοποιήσεις χρειάζονται κάποιον να αποφασίσει αν μπορούν να αγνοηθούν πριν τα δεδομένα προχωρήσουν.
5. **Επεξεργαστείτε τις εργασίες αντιστοίχισης.** Οι εργασίες αντιστοίχισης τιμών μεταφράζουν τιμές της πηγής σε τιμές προορισμού, όπως παλιούς κωδικούς εγκαταστάσεων σε νέους. Οι εργασίες σταθερών τιμών ορίζουν προεπιλογές. Για μεγάλες αντιστοιχίσεις, κατεβάστε τα πρότυπα αντιστοίχισης αντί να πληκτρολογείτε τιμές στις οθόνες.
6. **Προσομοιώστε.** Η προσομοίωση τρέχει τη φόρτωση χωρίς καταχώριση και δείχνει ποιες εγγραφές θα πετύχαιναν και ποιες θα αποτύγχαναν. Μπορεί να δημιουργήσει νέες εργασίες αντιστοίχισης. Επεξεργαστείτε τις και προσομοιώστε ξανά. Λίγα αντικείμενα δεν μπορούν να προσομοιωθούν, οπότε σχεδιάστε επιπλέον ελέγχους για αυτά.
7. **Μεταπτώστε.** Τρέξτε τη φόρτωση αντικείμενο προς αντικείμενο, πρώτα τα προαπαιτούμενα. Ορισμένα αντικείμενα έχουν περισσότερα από ένα βήματα μεταφοράς, και κάθε βήμα προσομοιώνεται και μεταπτώνεται με τη σειρά του.
8. **Διορθώστε και κάντε συμφωνία.** Διορθώστε τις αποτυχημένες εγγραφές, με αρχεία διόρθωσης όπου χρειάζεται, και μετά συμφωνήστε πλήθη και οικονομικά σύνολα με την πηγή. Μια εργασία που τελειώνει χωρίς σφάλματα δεν αποδεικνύει ότι τα δεδομένα είναι σωστά.

Το direct transfer ακολουθεί το ίδιο μοτίβο, με μία διαφορά στην αρχή. Αντί να γεμίζετε πίνακες, τρέχετε το Select Data στο σύστημα-πηγή, και μπορείτε να περιορίσετε περαιτέρω την επιλογή στο modeler.

## Όταν τα standard αντικείμενα δεν αρκούν

Αργά ή γρήγορα ένα migration object δεν θα ταιριάζει ακριβώς. Ένα προσαρμοσμένο πεδίο στην πηγή, ένας διαχωρισμός που χρειάζεστε κατά την είσοδο ή ένα αντικείμενο που η SAP δεν παραδίδει.

Στο on-premise και στην private edition, το εργαλείο είναι η συναλλαγή LTMOM, το SAP S/4HANA migration object modeler. Επιτρέπει στην ομάδα να επεκτείνει standard αντικείμενα, να προσθέσει πεδία, να ορίσει προσαρμοσμένα αντικείμενα και να διαχειριστεί transports περιεχομένου μετάπτωσης μεταξύ συστημάτων. Χρειάζεται δικό του ρόλο developer, οπότε σχεδιάστε ποιος θα τον έχει.

Στην public edition οι επιλογές είναι πιο περιορισμένες. Για staging tables, η εφαρμογή Model Your Migration Objects μπορεί να [επεκτείνει μόνο ορισμένα migration objects που έχει κάνει released η SAP](https://help.sap.com/docs/SAP_S4HANA_CLOUD/d5699934e7004d048c4801b552f3b013/947d9c3d00fc4e66851a8f5592871ad3.html), με ένα SAP Note ανά αντικείμενο που καταγράφει τι μπορεί να επεκταθεί. Αυτό συνάδει με το μοντέλο clean core της public edition, και είναι καλό τεστ για το αν τα δεδομένα σας χρειάζεται πραγματικά να μοιάζουν με αυτό που ήταν.

Η συμβουλή μου είναι να αντιμετωπίζετε κάθε αλλαγή στο modeler σαν προσαρμοσμένο κώδικα. Καταγράψτε την, δώστε της υπεύθυνο και ρωτήστε αν η επιχείρηση πραγματικά τη χρειάζεται.

## Το cockpit ως πρόγραμμα, όχι ως εργαλείο

Η μετάπτωση δεδομένων είναι το 30 έως 40% της προσπάθειας στα προγράμματα S/4HANA που βλέπω. Το cockpit βρίσκεται μέσα σε αυτή τη ροή εργασίας, οπότε τα περισσότερα από όσα πάνε στραβά με αυτό δεν οφείλονται στο εργαλείο.

Πέντε πράγματα αποφασίζουν αν η δουλειά στο cockpit θα πετύχει:

1. **Ορίστε το εύρος των αντικειμένων στη φάση Explore.** Καταγράψτε κάθε migration object, την πηγή, τον όγκο και τον υπεύθυνό του. Ο [δωρεάν εκτιμητής μετάπτωσης δεδομένων](/el/free-data-migration-estimator-sap-oracle-microsoft/) σας δίνει ένα τεκμηριωμένο εύρος προσπάθειας μόλις έχετε πραγματικά πλήθη.
2. **Ορίστε υπεύθυνους δεδομένων ανά αντικείμενο.** Τα οικονομικά έχουν την ευθύνη για τα οικονομικά δεδομένα πελατών και προμηθευτών, οι προμήθειες για τα υλικά. Το IT δεν μπορεί να αποφασίσει ποιος από δύο διπλότυπους προμηθευτές είναι ο σωστός.
3. **Σχεδιάστε κύκλους φόρτωσης με κριτήρια εξόδου.** Κάθε κύκλος είναι ένα νέο έργο σε δοκιμαστικό σύστημα, και ο καθένας τελειώνει με μια συμφωνία που υπογράφει η επιχείρηση. Ο οδηγός μου για το [γιατί αποτυγχάνει η μετάπτωση δεδομένων SAP](/el/why-sap-data-migration-fails-and-how-to-fix-it/) έχει ένα σχέδιο δοκιμαστικών φορτώσεων που μπορείτε να αντιγράψετε.
4. **Διαστασιολογήστε το παράθυρο cutover.** Τρέξτε έναν κύκλο με πλήρη όγκο παραγωγής. Τα όρια αρχείων και οι χρόνοι φόρτωσης γίνονται ορατά μόνο στο πραγματικό μέγεθος.
5. **Παγώστε τα αντικείμενα και τις αντιστοιχίσεις πριν από το cutover.** Η φόρτωση παραγωγής πρέπει να επαναλαμβάνει την τελική πρόβα, με τα ίδια έργα, πρότυπα και αντιστοιχίσεις.

Το μεγαλύτερο λάθος που βλέπω σε προγράμματα S/4HANA είναι ο ελλιπής σχεδιασμός στην αρχή. Με το cockpit, αυτό εμφανίζεται ως καθυστερημένες λίστες αντικειμένων, υπεύθυνοι που λείπουν και ένας πρώτος κύκλος φόρτωσης στη φάση Realize που βρίσκει προβλήματα που έπρεπε να είχε βρει η Explore.

Αυτοί οι κύκλοι διαμορφώνουν επίσης το συνολικό σχέδιο. Ο [οδηγός μου για το χρονοδιάγραμμα μετάβασης σε S/4HANA](/el/s4hana-migration-timeline-project-plan/) δείχνει πού βρίσκονται οι κύκλοι φόρτωσης ανά διαδρομή, και ο [οδηγός για το κόστος μετάβασης σε S/4HANA](/el/s4hana-migration-cost/) καλύπτει τι καθορίζει τον προϋπολογισμό των δεδομένων.

### Τι να ρωτήσετε τον συνεργάτη σας για το cockpit

Πριν υπογράψετε, ζητήστε από τον συνεργάτη να σας δείξει την προσέγγισή του για τα δεδομένα γραπτώς, όχι σε μια παρουσίαση:

1. Ποια προσέγγιση προτείνει ανά αντικείμενο, staging tables ή direct transfer, και γιατί.
2. Πόσους κύκλους φόρτωσης σχεδιάζει, και ποιο είναι το κριτήριο εξόδου για τον καθένα.
3. Ποια αντικείμενα αναμένει να αλλάξει στο modeler, και ποιος συντηρεί αυτές τις αλλαγές.
4. Ποιος από τη δική σας πλευρά εγκρίνει κάθε αντικείμενο, και πότε.

Οι γενικόλογες απαντήσεις εδώ είναι προειδοποιητικό σημάδι. Ένας συνεργάτης που το έχει ξανακάνει μπορεί να κατονομάσει τα δύσκολα αντικείμενα για τον κλάδο σας.

## Τι θα έκανα στη συνέχεια

Πάρτε αυτόν τον μήνα μια πλήρη εξαγωγή των κύριων δεδομένων πελατών, προμηθευτών και υλικών, μετρήστε τις εγγραφές και αναλύστε την ποιότητα. Μετά αποφασίστε staging tables ή direct transfer ανά αντικείμενο, με ονομαστικούς υπεύθυνους.

Αν δεν έχετε αξιολογήσει ακόμη το σύστημα-πηγή, ξεκινήστε με το [SAP Readiness Check και την αξιολόγηση μετάβασης](/el/sap-readiness-check-migration-assessment/). Αν θέλετε μια ανεξάρτητη ματιά στο σχέδιο μετάπτωσης δεδομένων σας, [επικοινωνήστε μαζί μου](/el/contact-noel-erp-support/).

## Συχνές ερωτήσεις

<details>
<summary>Τι είναι το SAP S/4HANA Migration Cockpit;</summary>

Είναι το εργαλείο της SAP για την αρχική φόρτωση επιχειρησιακών δεδομένων σε ένα νέο σύστημα S/4HANA, που λειτουργεί μέσω της εφαρμογής Fiori Migrate Your Data. Χρησιμοποιεί προκαθορισμένα migration objects για κύρια δεδομένα και ανοιχτές εγγραφές, και υποστηρίζει δύο προσεγγίσεις: staging tables και direct transfer από ένα σύστημα-πηγή SAP.

</details>

<details>
<summary>Είναι ακόμη διαθέσιμη η LTMC στο S/4HANA;</summary>

Όχι, όχι για μετάπτωση δεδομένων. Η SAP έχει καταργήσει τη συναλλαγή LTMC, και δεν μπορεί πλέον να χρησιμοποιηθεί για μετάπτωση δεδομένων στο S/4HANA. Μπορείτε ακόμη να δείτε παλιά έργα σε αυτήν.

Οι νέες μεταπτώσεις τρέχουν στην εφαρμογή Migrate Your Data.

</details>

<details>
<summary>Ποια είναι η διαφορά ανάμεσα στα staging tables και το direct transfer;</summary>

Με τα staging tables, το cockpit δημιουργεί πίνακες ανά migration object, και τους γεμίζετε από πρότυπα XML ή CSV ή με δικά σας εργαλεία, από οποιαδήποτε πηγή. Με το direct transfer, το cockpit διαβάζει τα δεδομένα απευθείας από ένα υποστηριζόμενο σύστημα-πηγή SAP, όπως το SAP ERP 6.0, μέσω σύνδεσης RFC. Τα staging tables σάς δίνουν περισσότερο περιθώριο για έλεγχο και καθαρισμό πριν από τη φόρτωση.

</details>

<details>
<summary>Μπορεί το Migration Cockpit να χρησιμοποιηθεί για μια μετατροπή brownfield;</summary>

Όχι για τη βασική μεταφορά. Η SAP σχεδιάζει το cockpit για την αρχική φόρτωση σε σενάριο νέας υλοποίησης. Μια μετατροπή συστήματος brownfield μετατρέπει τα δεδομένα επί τόπου με το Software Update Manager.

</details>

<details>
<summary>Τι είναι η LTMOM στη SAP;</summary>

Η LTMOM είναι η συναλλαγή για το SAP S/4HANA migration object modeler, που χρησιμοποιείται στο on-premise και στην private edition. Σας επιτρέπει να επεκτείνετε standard migration objects, να προσθέσετε προσαρμοσμένα πεδία, να δημιουργήσετε δικά σας αντικείμενα και να κάνετε transport περιεχομένου μετάπτωσης. Στην public edition, η εφαρμογή Model Your Migration Objects κάνει μια πιο περιορισμένη εκδοχή της ίδιας δουλειάς.

</details>

<details>
<summary>Ποιο είναι το όριο μεγέθους αρχείου στο S/4HANA Migration Cockpit;</summary>

Ένα μεμονωμένο αρχείο προτύπου XML μπορεί να φτάσει τα 100 MB, και ένα zip με πολλά αρχεία XML δεν μπορεί να ξεπεράσει τα 100 MB. Τα αρχεία μέσα στο zip μπορούν να είναι μεγαλύτερα όταν συμπιεστούν, με το όριο ανά αρχείο να εξαρτάται από την έκδοση και το release.

Οι φάκελοι CSV περιορίζονται επίσης στα 100 MB. Για πολύ μεγάλα αντικείμενα, γεμίστε τα staging tables με εργαλείο αντί για αρχεία.

</details>
