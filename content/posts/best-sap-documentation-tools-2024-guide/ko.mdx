2026년 최고의 SAP 문서화 도구는 업무에 따라 달라집니다. 프로세스 맵은 S/4HANA 전환에서 SAP Signavio가 앞섭니다. 설계 결정과 산출물은 Confluence나 SharePoint입니다. 신규 프로젝트의 요구 사항, 테스트, 변경 통제는 SAP Cloud ALM입니다. 교육 자료는 SAP Enable Now, 애플리케이션 내 가이드는 이제 SAP가 소유한 WalkMe입니다. 감사 수준의 기록은 SAP 자체 문서 관리나 OpenText입니다. 이 가이드는 SAP 프로젝트의 문서화를 새로 구축하거나 바로잡는 PMO 리드와 솔루션 아키텍트를 위한 것입니다. 기능 목록이 가장 긴 도구가 아니라, 가장 큰 공백에서 시작하십시오. 제 경험상 실패하는 것은 도구 선택이 아닌 경우가 대부분입니다. 그 주변의 구조와 규율이 문제입니다.

흩어진 Excel 파일과 공유 드라이브로 12개월짜리 SAP 롤아웃을 관리하는 팀을 본 적이 있습니다. 간신히 돌아갔지만, 그건 한 사람이 계속 갱신을 쫓아다녔기 때문입니다. 그 사람이 프로젝트 도중에 떠나자 아무도 결정을 추적할 수 없었습니다.

## 문서화가 빛을 발하는 순간

**회의실에서 의견이 갈릴 때.** UAT 계획 회의에서 겪은 일입니다. 팀들이 테스트 시나리오를 누가 책임지는지를 두고 맞서고 있었습니다. 서명된 프로젝트 헌장을 띄우자 논의는 거기서 끝났습니다. 최소 한 시간은 더 이어졌을 입씨름을 아꼈습니다. 검색할 수 있는 문서는 의미 있는 결정마다 논쟁 한 번씩을 덜어 줍니다.

**감사인이 도착할 때.** 품질 게이트나 감사에서 첫 질문은 늘 같습니다. 증빙을 보여 달라는 것입니다. 통과 또는 실패 상태뿐 아니라 실제 테스트 결과도 보관하십시오. 누가 무엇을 언제 승인했는지 기록하십시오. 감사 추적이 곧 문서입니다.

**컷오버 중에.** 컷오버 때는 아무도 이메일 체인을 뒤지지 않습니다. 구성 문서를 10초 안에 열 수 없다면 이미 시간을 잃은 것입니다. 단순한 명명 규칙과 검색 가능한 저장소가 이를 막아 줍니다.

**사람들이 떠날 때.** 구성이 왜 그렇게 되어 있는지 되짚느라 몇 주를 날리는 팀을 보았습니다. 지식은 다섯 개의 서로 다른 받은 편지함에 있었거나, 이미 떠난 컨설턴트 한 명의 기억에 있었습니다.

압박 속에서 가장 중요한 것들은 도구가 좀처럼 담아내지 못합니다.

1. 컷오버 중에 내린 예외 결정
2. 회의에서 내려졌지만 문서로 남지 않은 구성 결정
3. 범위를 슬그머니 바꾸는 현업 담당자의 의견
4. 하이퍼케어 중에 적용되었지만 설계 문서로 돌아가지 않는 우회 조치

그래서 플랫폼보다 습관이 더 중요합니다.

## 업무별 도구

표는 문서화 업무마다 SAP 기본 옵션과 주요 대안을 짝지어 보여 줍니다.

| 문서화 업무 | SAP 옵션 | 주요 대안 | 대안을 고르는 경우 |
|---|---|---|---|
| 프로세스 매핑과 마이닝 | SAP Signavio | ARIS, Microsoft Visio, IBM Blueworks Live | 이미 보유하고 있거나 범위가 단일 모듈인 경우 |
| 설계 결정과 산출물 | SAP Cloud ALM(요구 사항) | Confluence, SharePoint | 조직이 이미 평소 그곳에서 일하는 경우 |
| 변경 통제와 테스트 증빙 | SAP Cloud ALM | SAP Solution Manager(기존 사용자), ServiceNow, Jira | ITSM을 이미 ServiceNow로 운영하거나 Solution Manager를 구성해 쓰고 있는 경우 |
| 교육 자료 | SAP Enable Now | 영상 및 문서 도구 | 롤아웃 규모가 작은 경우 |
| 애플리케이션 내 가이드 | WalkMe(SAP) | Whatfix | 가이드가 SAP 이외의 여러 애플리케이션에 걸쳐야 하는 경우 |
| SAP 오브젝트에 연결된 기록 | SAP Document Management System | OpenText Extended ECM for SAP | 규제상 SAP DMS를 넘어서는 기록 관리가 필요한 경우 |

## 프로세스 매핑

### SAP Signavio

SAP 프로세스 작업에서 가장 강력한 선택입니다. SAP Signavio Process Manager가 모델링을, SAP Signavio Process Intelligence가 실제 SAP 트랜잭션을 대상으로 한 프로세스 마이닝을 담당합니다. SAP는 2025년 3월에 서술형 프로세스 설명을 BPMN 초안으로 바꿔 주는 [AI 지원 프로세스 모델러](https://news.sap.com/2025/03/sap-signavio-launches-ai-process-modeler-text-to-process/)를 추가했고, Joule도 이 제품군에 통합했습니다.

한 물류 고객사는 실제 SAP 트랜잭션에서 비효율을 찾아낸 뒤 주문-수금(order-to-cash) 사이클 시간을 11% 줄였습니다. 프로세스 마이닝은 시스템이 기록한 내용을 보여 주며, 그 내용은 프로세스 맵이 말하는 것과 다른 경우가 많습니다.

Signavio는 입문용 도구가 아닙니다. 프로세스 비중이 큰 산업에서 S/4HANA 전체 전환을 한다면 제값을 합니다. 단일 모듈 롤아웃이라면 과투자입니다.

### ARIS

컴플라이언스 부담이 큰 프로젝트의 공식 블루프린트 작업에 여전히 쓰입니다. ARIS는 2025년 1월부터 Silver Lake가 소유한 Software AG 지주회사 산하에서 독립 사업으로 운영되고 있습니다. 학습 곡선이 가파릅니다. 공식 블루프린트가 컴플라이언스 산출물인 제약, 금융 서비스, 방산 같은 규제 산업의 전담 프로세스 팀에 맞습니다. 그런 요건이 없는 중견 기업에는 과합니다.

### SAP Build Process Automation

SAP BTP 위의 SAP 워크플로 및 자동화 서비스로, 가벼운 문서화를 위한 프로세스 가시성 구성 요소를 갖추고 있습니다. 전환 프로젝트에서 Signavio를 대체하는 도구는 아니지만, 문서화와 워크플로 자동화가 같은 프로젝트에 있고 이미 BTP를 쓰고 있다면 어울립니다.

### Visio와 IBM Blueworks Live

Visio는 이미 Microsoft 365를 쓰면서 낮은 비용으로 다이어그램이 필요한 팀에 맞습니다. 명명 규칙과 버전 관리는 직접 만들어야 하고, 다이어그램을 실제 가동 중인 시스템과 대조해 주는 것은 없습니다. IBM Blueworks Live는 여전히 활발히 개발되고 있으며 SAP 스택 밖의 협업 매핑에 맞습니다. 어느 쪽도 문서화된 프로세스를 SAP가 실제로 실행하는 것과 일치시켜 주지 못하는데, 전환 프로젝트에서는 이 점이 중요합니다.

## 산출물, 변경 통제, 기록

**Confluence**는 설계 메모, SOP, 의견이 달린 승인 문서에 가장 흔히 쓰는 선택입니다. 이제 Rovo라는 이름으로 나오는 Atlassian의 AI는 유료 플랜에 포함되어 있으며 페이지를 요약하고 초안을 작성합니다. 초안 작성 속도는 높여 주지만, 구조를 대신 잡아 주지는 않습니다.

**SharePoint**는 대부분의 조직에 이미 도입되어 있습니다. 제대로 된 폴더 구조, 버전 관리, 활성화된 Microsoft 365 Copilot이 갖춰지면 산출물을 안정적이고 추적 가능하게 보관하는 저장소가 됩니다.

**SAP Cloud ALM**은 요구 사항, 테스트 관리, 변경 문서화를 한곳에서 다루며 Solution Manager의 전략적 후속 제품입니다. Enterprise Support가 있거나 이를 포함하는 클라우드 구독을 가진 고객에게는 라이선스 비용이 없습니다. RISE, GROW 또는 어떤 S/4HANA 에디션이든 신규 프로젝트라면 기본 도구입니다. 더 자세한 내용은 [SAP 프로젝트 추적 도구](/ko/top-sap-project-tracking-tools-2025/) 비교에서 다룹니다.

**SAP Solution Manager**는 이미 이를 쓰고 있는 대규모 멀티 시스템 프로젝트에는 여전히 비할 데 없는 추적성을 제공하며, 프로세스 문서를 구성, 커스텀 코드, 테스트 결과와 연결합니다. 메인스트림 유지보수는 2027년 말에 끝나고, 일부 기능에 대한 연장 유지보수는 2030년까지 제공됩니다. Cloud ALM으로의 이전을 계획하십시오. 특별한 이유 없이 새 프로젝트를 여기서 시작하지 마십시오.

**ServiceNow**는 조직이 이미 그곳에서 IT 서비스 관리를 운영하고 있고 SAP 변경 요청을 같은 장애 및 변경 워크플로에 넣고 싶을 때 맞습니다. 실제 통합 작업에 필요한 예산을 잡으십시오.

**Jira와 Excel 트랜스포트 추적표**는 규율 있게 검토하는 소규모 프로젝트에서는 여전히 통합니다. 항목 하나만 빠져도 감사 추적이 끊기므로 컴플라이언스에 민감한 환경에서는 피하십시오. 전용 변경 도구는 [SAP 기술 변경 관리 도구](/ko/best-sap-technical-change-management-tools-2025/) 가이드를 참고하십시오.

**SAP Document Management System(DMS)**은 문서를 자재, 오더, 공급업체 등 SAP 오브젝트에 연결하며 버전 관리와 승인 워크플로를 제공합니다. SAP가 솔루션 확장 제품으로 판매하는 **OpenText Extended ECM for SAP**은 증빙 보존이 협상 대상이 아닌 제약, 금융 서비스, 규제 제조업에 더 깊은 기록 관리 기능을 더합니다.

## 교육과 디지털 어답션

**SAP Enable Now**는 프로세스를 한 번 녹화하면 같은 원본에서 문서, 시뮬레이션, 테스트 스크립트를 만들어 냅니다. 비기술 사용자도 결과물을 편집할 수 있습니다. 대규모 롤아웃에서는 그만한 값어치가 있고, 소규모에서는 아마 아닐 것입니다. 활용 방법은 [SAP 교육 전략](/ko/sap-training-strategies-for-employees-to-drive-adoption/) 글에서 다룹니다.

**WalkMe**는 SAP Fiori와 서드파티 애플리케이션 안에서 툴팁, 안내 경로, 단계별 안내 같은 애플리케이션 내 가이드를 제공합니다. [SAP는 2024년 9월에 WalkMe 인수를 완료](https://news.sap.com/2024/09/sap-completes-walkme-acquisition/)했으며 지분 가치 기준 약 15억 달러였고, Enable Now 및 Joule과 함께 배치하고 있습니다. 서드파티 계층이 아니라 SAP 제품으로 평가하십시오.

**Whatfix**는 주요 독립 대안입니다. 가이드가 SAP와 다수의 비SAP 애플리케이션에 걸쳐야 하거나, 어답션 계층을 SAP와 독립적으로 두고 싶을 때 맞습니다.

## AI가 문서화에 더하는 것

이제 주요 벤더는 모두 AI 초안 작성 계층을 갖추고 있습니다. Signavio의 Joule과 AI 지원 모델링, SharePoint와 Teams 전반의 Microsoft 365 Copilot, Confluence의 Rovo입니다. 첫 초안을 더 빨리 만들고, 긴 기록을 요약하고, 회의 녹취록에서 결정 사항을 뽑아냅니다.

무엇을 문서화해야 하는지, 라이브러리를 어떻게 구성해야 하는지, 원본이 맞는지는 AI가 정해 주지 않습니다. AI는 이미 구조가 탄탄한 프로젝트에서 문서화 속도를 높입니다. 그렇지 않은 프로젝트에서는 일관성 없는 문서를 더 빨리 만들어 냅니다. 구조가 먼저고, AI는 그다음입니다.

## 실제 SAP 프로젝트에서 도구를 조합하는 방법

모든 것을 다루는 단일 도구는 없습니다. 일반적인 S/4HANA 브라운필드 프로젝트에 제가 권하는 조합은 다음과 같습니다.

1. **SAP Signavio**: 프로세스 매핑, 마이닝, AI 지원 프로세스 문서화
2. **Confluence 또는 SharePoint**: 산출물과 설계 결정, AI 계층을 켠 상태로
3. **SAP Cloud ALM**: 요구 사항, 변경 통제, 테스트 증빙
4. **SAP Enable Now**: 최종 사용자 교육 자료
5. **WalkMe**: Go-Live 시점의 애플리케이션 내 가이드
6. **OpenText Extended ECM**: 산업이 컴플라이언스 수준의 기록을 요구할 때만

데모가 아니라 팀이 압박 속에서 일하는 방식을 기준으로 고르십시오. 구성 결정이 회의에서 사라진다면 산출물 도구부터 정리하십시오. 새로 합류한 사람이 맥락을 다시 파악하느라 일주일을 쓴다면 도구를 더하기 전에 구조부터 고치십시오. 감사인이 6주 뒤에 오는데 승인 증빙을 찾을 수 없다면 그것이 최우선이며, 제대로 구성한 SharePoint나 ECM이 해결해 줍니다.

올바른 스택은 석 달째에도 팀이 계속 유지할 수 있는 가장 작은 조합입니다.

## 자주 묻는 질문

<details>
<summary>SAP 프로젝트에서 문서화란 무엇입니까?</summary>

SAP 프로젝트 문서화는 시스템이 어떻게 작동하는지, 사람들이 어떻게 사용하는지, 그 과정에서 무엇이 결정되었는지를 기록합니다. 프로세스 맵, 기능 및 기술 명세서, 구성 결정, 테스트 증빙, 최종 사용자 가이드, 컴플라이언스 기록이 여기에 포함됩니다. 작성자가 떠나고 아무것도 기록된 것이 없어서 보고서가 어떻게 만들어졌는지 아무도 말하지 못하는 프로젝트를 본 적이 있습니다. 문서화를 프로젝트 산출물로 다루지 않을 때 치르는 대가입니다.

</details>

<details>
<summary>SAP 문서화가 중요한 이유는 무엇입니까?</summary>

2주짜리 인수인계를 2일로 줄이고, 문제 해결 속도를 높이고, 교육을 일관되게 유지하고, 감사인에게 증빙을 제공합니다. 흔한 실패는 지식이 한 사람의 머릿속에만 있는 것, 변경 후 문서를 갱신하지 않는 것, 아무도 읽지 않는 50쪽짜리 명세서입니다. 가장 혼란을 많이 일으키는 곳에서 시작해 쌓아 가십시오.

</details>

<details>
<summary>SAP에는 기본 제공되는 문서 관리 시스템이 있습니까?</summary>

예. SAP Document Management System(DMS)은 문서를 자재, 오더, 공급업체 등 SAP 오브젝트에 연결하며 버전 관리, 승인 워크플로, 접근 제어를 제공합니다. 규제 산업에서 더 엄격한 기록 관리가 필요하다면, SAP가 솔루션 확장 제품으로 판매하는 OpenText Extended ECM for SAP이 수명 주기와 보존 통제를 더합니다.

</details>

<details>
<summary>SAP의 WalkMe 인수로 무엇이 달라졌습니까?</summary>

SAP는 2024년 9월 12일에 인수를 완료했으며 지분 가치 기준 약 15억 달러였습니다. WalkMe는 이제 SAP의 디지털 어답션 포트폴리오에서 SAP Enable Now 옆에 자리하고, SAP는 이를 Joule과 통합하고 있습니다. 여전히 SAP Fiori와 서드파티 애플리케이션에서 애플리케이션 내 가이드를 제공합니다. SAP 제품으로 평가하십시오.

</details>

<details>
<summary>2026년에 신규 SAP 프로젝트는 Solution Manager와 Cloud ALM 중 무엇을 써야 합니까?</summary>

특별한 이유가 없다면 Cloud ALM입니다. Solution Manager 7.2의 메인스트림 유지보수는 2027년 말에 끝나며, SAP는 2028년 전에 Cloud ALM으로의 이전을 완료할 것을 권고합니다. Cloud ALM은 설정이 더 가볍고, Enterprise Support나 해당 클라우드 구독이 있는 고객에게는 라이선스 비용이 없습니다. 기존 Solution Manager 사용자는 이전 계획을 지금 로드맵에 올려야 합니다.

</details>

<details>
<summary>재무와 물류에서 흔히 쓰는 SAP 문서 유형에는 무엇이 있습니까?</summary>

재무회계에서는 SA(G/L 계정 전표), KR(공급업체 송장), DR(고객 송장), AB(회계 전표, 흔히 반제에 사용), WE(입고 전기), RE(송장 입고)가 있습니다. 구매 요청과 구매 오더는 둘 다 표준 문서 유형으로 NB를 씁니다. 영업에서는 OR(표준 오더), QT(견적), LF(출고 납품), F2(송장)가 있습니다. 각 유형에는 고유한 번호 범위와 필드 통제가 있으므로 설계 단계에서 확정하십시오.

</details>
