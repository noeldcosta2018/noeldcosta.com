Die wichtigsten SAP-Testtools sind SAP Cloud ALM und SAP Solution Manager für das Testmanagement, Tricentis Tosca (von SAP als SAP Test Automation by Tricentis vertrieben), Worksoft, Panaya und UiPath für die Testautomatisierung sowie OpenText LoadRunner für Performancetests. Die meisten S/4HANA-Programme brauchen ein Tool aus jeder Gruppe: eines, um Tests zu verwalten und nachzuverfolgen, eines, um die Regression zu automatisieren, und eines, um Last zu testen.

Ich habe alle sieben eingesetzt oder von meinen Teams einsetzen lassen. Dieser Leitfaden vergleicht, wofür jedes gedacht ist, geprüft gegen die Dokumentation der Anbieter im Oktober 2026, und wie Sie zwischen ihnen wählen. Für die Testarten selbst beginnen Sie mit [SAP-Tests erklärt](/de/sap-testing-explained/).

Ich habe Dutzende Tool-Demos erlebt, in denen alles perfekt funktioniert. Dann brechen im echten Projekt ständig die Skripte, oder die Integration funktioniert nie so, wie der Anbieter sie gezeigt hat. Deshalb wähle ich SAP-Testtools nicht anhand von Funktionslisten aus.

## Die drei Aufgaben eines SAP-Testtoolsets

Tests beanspruchen in den Programmen, die ich leite, rund 35 Prozent des Aufwands. Die Tools entscheiden, wie viel dieses Aufwands wiederholbar ist.

Sie fallen in drei Gruppen. Erwarten Sie nicht, dass ein Tool aus einer Gruppe die Aufgabe einer anderen erledigt.

1. **Testmanagement.** Enthält Testfälle, Testpläne, Durchführungsergebnisse und Fehler und verknüpft sie mit Anforderungen und Änderungen. Hier findet das manuelle Testen statt, und hier schauen Prüfer hin. SAP Cloud ALM, SAP Solution Manager und Panaya Test Management gehören hierher.
2. **Funktionale Testautomatisierung.** Zeichnet Tests von Geschäftsprozessen auf oder modelliert sie und führt sie nach jeder Änderung erneut aus. Tricentis, Worksoft, Panaya Test Automation und UiPath gehören hierher.
3. **Performancetests.** Simuliert viele gleichzeitige Anwender, um Engpässe vor dem Go-live zu finden. OpenText LoadRunner gehört hierher, und SAP vertreibt außerdem Performanceprodukte von Tricentis.

Mehrere Anbieter decken zwei Gruppen ab, und die Grenzen verschieben sich mit jedem Release. Entscheiden Sie zuerst, für welche Aufgabe Sie kaufen, und vergleichen Sie dann Tools innerhalb dieser Gruppe.

## SAP-Testtools im Vergleich

Die Tabelle fasst die sieben Tools zusammen. Jede Zeile ist gegen die eigenen Seiten des Anbieters oder das Support-Portal von SAP geprüft.

| Tool | Anbieter | Hauptaufgabe | Wofür es gedacht ist | Wo es passt |
|---|---|---|---|---|
| SAP Cloud ALM | SAP | Testmanagement | Testfälle, Testpläne, manuelle Durchführung, Fehler, Rückverfolgbarkeit zu Prozessen und Anforderungen | Standard für neue S/4HANA- und RISE-Programme; ein Tenant ist in Enterprise Support enthalten |
| SAP Solution Manager 7.2 | SAP | Testmanagement | Test Suite, Business Process Change Analyzer, Verknüpfung mit dem Change Control | Bestehende On-Premise-Landschaften, die ihn bereits betreiben; Mainstream-Wartung endet 2027 |
| Tricentis Tosca / SAP Test Automation by Tricentis | Tricentis, vertrieben von SAP | Automatisierung | Modellbasierte, codefreie Automatisierung über SAP- und Nicht-SAP-Anwendungen | Programme mit häufigen Releases und gemischten Landschaften |
| Worksoft Certify | Worksoft | Automatisierung | Codefreie Prozessautomatisierung, dazu Prozessaufzeichnung und Auswirkungsanalyse | Prozesslastige Landschaften, in denen Fachanwender Tests bauen sollen |
| Panaya | Panaya | Auswirkungsanalyse, Testmanagement, Automatisierung | Auswirkungsanalyse von Änderungen, Testmanagement und KI-gestützte Automatisierung | Programme mit vielen Upgrades und Änderungen, die wissen müssen, was erneut zu testen ist |
| UiPath Test Manager (UiPath Test Suite) | UiPath | Automatisierung und Testmanagement | Orchestrierung von Tests mit UiPath-Robotern über SAP GUI, Fiori und Nicht-SAP | Unternehmen, die UiPath bereits für Prozessautomatisierung nutzen |
| OpenText LoadRunner | OpenText | Performance | Last- und Parallelitätstests mit den Protokollen SAP, SAP GUI und SAP Web | Spitzenlast- und Parallelitätstests vor dem Go-live |

Keines dieser Tools ist eine schlechte Wahl. Sie unterscheiden sich im Ansatz, in der Lizenzierung und darin, was Ihr Team bereits kennt.

## Testmanagement: Cloud ALM und Solution Manager

### SAP Cloud ALM

Cloud ALM deckt Testvorbereitung, Testpläne, Testdurchführung und Fehler ab. Laut der [Cloud-ALM-Schulung von SAP zum Testen](https://learning.sap.com/courses/implementing-with-sap-cloud-alm/planning-and-executing-testing_ef46a49b-9885-4aaa-841d-5ac9c80a3681) werden Testfälle aus Aktivitäten der Lösungsprozesse aufgebaut, Tester erfassen bestanden oder nicht bestanden je Schritt, und Fehler werden direkt aus fehlgeschlagenen Läufen gemeldet. Das liefert Ihnen Rückverfolgbarkeit vom Prozess über den Test bis zum Fehler.

Bei der Automatisierung orchestriert es, statt selbst auszuführen. SAP nennt zwei integrierte Tools: das SAP S/4HANA Cloud Test Automation Tool und Tricentis Test Automation for SAP. Worksoft, Panaya und UiPath veröffentlichen jeweils eigene Cloud-ALM-Integrationen.

Die Lizenzierung ist einfach. Die [Seite von SAP zu den Nutzungsrechten](https://support.sap.com/en/alm/usage-rights.html) gewährt Kunden mit SAP Enterprise Support, Enterprise Support cloud editions oder Product Support for Large Enterprises einen Tenant. Die Nutzung ist auf das eigene interne Application Lifecycle Management des Kunden beschränkt.

### SAP Solution Manager

Solution Manager 7.2 betreibt in vielen On-Premise-Landschaften noch das Testmanagement. Unter Enterprise Support umfasst sein Leistungsumfang den Business Process Change Analyzer, der den Testumfang auf die Prozesse eingrenzt, die eine Änderung berührt, sowie die Funktionen von SAP zur Testautomatisierung.

Das Datum zählt mehr als die Funktionen. Die [Solution-Manager-Seite von SAP](https://support.sap.com/en/alm/solution-manager.html) nennt Mainstream-Wartung bis Ende 2027. Erweiterte Wartung bis Ende 2030 ist eine Option für ausgewählte Funktionen, darunter die Test Suite, und SAP empfiehlt, vor Ende 2027 auf Cloud ALM zu wechseln.

Führen Sie den Solution Manager in einem neuen Programm nicht für das Testen ein. Wenn er bereits Ihr Change Control steuert, behalten Sie ihn, bis die Landschaft umzieht, und migrieren Sie dann die Testdokumentation im Rahmen dieses Umzugs.

### Tools für manuelles Testen

Wer nach Tools für manuelles SAP-Testen sucht, braucht meist ein Testmanagement, kein separates Produkt. Cloud ALM, Solution Manager, Panaya Test Management und UiPath Test Manager erfassen alle die manuelle Testdurchführung mit Schritten, Ergebnissen und Fehlern.

Was sie ersetzen, ist die Tabellenkalkulation. Eine Tabelle hat keine Verknüpfung zum Transport, keinen Prüfpfad und keine Historie, sobald der nächste Zyklus beginnt.

## Tools für Testautomatisierung: Tricentis, Worksoft, Panaya und UiPath

Alle vier automatisieren Geschäftsprozesse in SAP GUI und Fiori. Die Unterschiede liegen darin, wie Tests gebaut werden, was dazugehört und wie sie sich mit Ihrem Testmanagement-Tool verbinden.

### Tricentis und SAP Test Automation by Tricentis

[SAP Test Automation by Tricentis](https://www.sap.com/products/technology-platform/test-automation.html) ist das von SAP vertriebene, cloudbasierte Tricentis-Produkt. SAP beschreibt es als codefreie, modellbasierte Automatisierung über SAP- und Drittanwendungen, integriert in Cloud ALM. SAP vertreibt außerdem SAP Enterprise Continuous Testing by Tricentis, das Tricentis als Tosca ausweist.

Prüfen Sie Ihren Anspruch, bevor Sie kaufen. Die Seite von SAP zu den Nutzungsrechten gewährt Kunden mit Enterprise Support bis zum 31. Dezember 2028 eine befristete Lizenz für Tricentis Test Automation for SAP, integriert in Cloud ALM. Sie ist auf 5 namentlich benannte Anwender, 500 Testläufe pro Monat, 5 Ausführungsagenten und 12 Monate Aufbewahrung der Ergebnisse begrenzt, also ein Ausgangspunkt und keine Lizenz für Programmgröße.

Eine separate Lizenz deckt Tricentis Test Automation for SAP, integriert in den Solution Manager, bis zum 31. Dezember 2027 ab. Lesen Sie beide Einträge auf der Seite für Ihre Supportart.

### Worksoft

Worksoft Certify ist ein codefreies Automatisierungsprodukt für Tests, die Bereitstellung von Testdaten und Datenkorrekturen. Zur Plattform von Worksoft gehören außerdem Business Capture, das echte Benutzeraktivität als Grundlage für Tests aufzeichnet, und ein Impact-Produkt für die Änderungsanalyse.

Worksoft führt Integrationen mit SAP Cloud ALM und Solution Manager und ist im SAP Store erhältlich. Es passt zu Teams, in denen Experten für Geschäftsprozesse, nicht Entwickler, die Testbibliothek verantworten sollen.

### Panaya

Das Angebot von Panaya umfasst Change Impact Analysis, Test Management, Test Automation und Custom Code Correction. Sein Ausgangspunkt ist die Frage, die jedes Upgrade aufwirft: Was hat diese Änderung berührt, und was muss ich erneut testen?

Damit passt es zu Upgrades, Support Packages und S/4HANA-Konvertierungen, bei denen Eigenentwicklungen und der Umfang der Auswirkungen die Arbeit bestimmen. Die Cloud-ALM-Integration von Panaya deckt derzeit automatisierte Tests aus seinem codefreien Automatisierungsprodukt ab.

### UiPath Test Suite

UiPath Test Manager plant, orchestriert und berichtet über Testläufe, und UiPath-Roboter führen sie aus. UiPath nennt Abdeckung für S/4HANA, ECC, Fiori, WinGUI, WebGUI und Business Client sowie eine Integration mit SAP Cloud ALM.

Die Dokumentation von UiPath beschreibt außerdem eine Solution-Manager-Integration, die Solution Manager 7.2 SP08 oder höher voraussetzt. Das praktische Argument für UiPath ist die Wiederverwendung: Wenn Ihr Unternehmen UiPath bereits für Prozessautomatisierung nutzt, lassen sich Kenntnisse und Lizenzen übertragen.

### Wann sich Automatisierung lohnt

Meine Regel ist einfach. Wenn es sehr viele Testfälle gibt, die umfangreich und wiederholt getestet werden müssen, automatisieren Sie. Darunter ist manuelles Testen in Ordnung, und eine halb aufgebaute Automatisierungsbibliothek kostet mehr, als sie spart.

Wiederholtes Testen ist genau das, was Regression ist. Mein Leitfaden zur [SAP-Testautomatisierung](/de/sap-test-automation-guide/) behandelt, wo Sie anfangen, und der zum [SAP-Regressionstest](/de/sap-regression-testing/) behandelt Upgrade-Zyklen und den Umfang von Releases.

## Tools für Performancetests: OpenText LoadRunner

Funktionale Automatisierung sagt Ihnen, dass ein Prozess für einen Anwender funktioniert. Sie sagt Ihnen nicht, was passiert, wenn Hunderte von Anwendern zum Monatsende buchen. Performancetests müssen vor dem Go-live stattfinden, und die Parallelitätstests, viele Anwender gleichzeitig, sind die, auf die es ankommt.

LoadRunner ist heute ein Produkt von OpenText. Die [Seite von OpenText zu LoadRunner Professional](https://www.opentext.com/products/loadrunner-professional) nennt es inzwischen OpenText Professional Performance Engineering. Seine Protokollliste umfasst SAP, SAP GUI und SAP Web.

OpenText Enterprise Performance Engineering bedient Teams, die Tests an mehreren Standorten gleichzeitig durchführen, und OpenText Core Performance Engineering ist das Cloud-Angebot. SAP vertreibt außerdem Produkte von Tricentis für Performancetests. Mein Leitfaden zu [SAP-Performancetests](/de/sap-performance-testing-it-leaders/) zeigt, wie Sie diese Tests gestalten.

## Wie Sie SAP-Testtools auswählen

Wählen Sie die Tools in dieser Reihenfolge: zuerst Testmanagement, dann Automatisierung, dann Performance. Im Testmanagement liegen Rückverfolgbarkeit und Prüfbarkeit, und es entscheidet, welche Automatisierungsintegrationen einfach sind.

1. **Prüfen Sie, was Sie bereits besitzen.** Cloud ALM und die begrenzte Tricentis-Lizenz kommen mit Enterprise Support. Der Solution Manager kommt mit der On-Premise-Wartung.
2. **Wählen Sie die Testmanagement-Plattform.** Cloud ALM für neue Programme und RISE. Solution Manager nur dort, wo er bereits das Change Control steuert, mit einem Migrationsplan vor 2028.
3. **Zählen Sie Ihre wiederholten Testfälle.** Ist das Regressionsvolumen klein, testen Sie manuell in Ihrem Testmanagement-Tool und verzichten Sie vorerst auf Automatisierung.
4. **Erstellen Sie eine Shortlist für die Automatisierung nach Passung.** Gemischte SAP- und Nicht-SAP-Landschaften, Bedarf an Auswirkungsanalyse, bestehende UiPath-Umgebungen und Verantwortung bei Fachanwendern weisen jeweils auf andere Tools in der Tabelle oben.
5. **Führen Sie einen Pilot mit Ihren eigenen Prozessen durch.** Nutzen Sie einen echten Geschäftsprozessablauf mit Ihren eigenen Daten und Bildschirmen, nicht das Demosystem des Anbieters.
6. **Ergänzen Sie ein Performancetool.** Planen Sie Parallelitätstests für Spitzenzeiten wie den Monatsabschluss.

Diese Fragen trennen eine gute Passung von einer guten Demo.

| Faktor | Zu stellende Frage |
|---|---|
| SAP-Abdeckung | Welche Technologien aus SAP GUI, Fiori und APIs steuert es nativ? |
| Integration | Verbindet es sich mit Cloud ALM oder Solution Manager so, wie Ihr Testmanager arbeitet? |
| Auswirkungsanalyse | Kann es Ihnen sagen, welche Tests ein Transport oder ein Upgrade betrifft? |
| Pflege | Wer repariert nach einem Release defekte Tests, und wie lange dauert das? |
| Verantwortung | Können funktionale Berater und Key User Tests bauen und lesen? |
| Kosten im zweiten Jahr | Was kosten Agenten, Anwender und Pflege nach dem ersten Jahr? |

## Tools sind nicht die ganze Antwort

Der häufigste Testfehler, den ich sehe, ist kein Tool-Problem. Es ist zu wenig Testen im Integrationstest und im Benutzerakzeptanztest. Kein Tool kann einen Plan reparieren, der diesen Zyklen zu wenig Zeit gibt.

Zwei Praktiken zählen mehr als die Frage, welches Produkt Sie kaufen. Testdaten sollten maskiert sein, aber auf Produktionsniveau, mit realistischen Volumen. Betreiben Sie während eines Programms zwei getrennte Landschaften, eine für das Projekt und eine für den laufenden Betrieb, damit Live-Supportänderungen und Projektänderungen getrennt getestet werden.

Cloud-Releases bringen eine weitere Überlegung mit sich. SAP Cloud ERP public edition erhält zwei große Upgrades pro Jahr, im Februar und im August, und Kunden führen Regressionstests im aktualisierten Testsystem durch. Das Test Automation Tool von SAP ist für diese Arbeit enthalten.

Wie Sie Testergebnisse mit Go-live-Entscheidungen verknüpfen, zeigt mein Artikel zu [SAP Quality Gates](/de/sap-quality-gates-implementation/).

## Ihr nächster Schritt

Ordnen Sie die sieben Tools den drei Aufgaben zu und markieren Sie, was Ihr SAP-Supportvertrag bereits enthält. Erstellen Sie dann nur für die Lücken eine Shortlist und vereinbaren Sie Demos mit Ihren eigenen Prozessen.

<summary>Welches sind die wichtigsten SAP-Testtools?</summary>

Für das Testmanagement SAP Cloud ALM und SAP Solution Manager. Für die Testautomatisierung Tricentis Tosca (auch vertrieben als SAP Test Automation by Tricentis), Worksoft Certify, Panaya und UiPath. Für Performancetests OpenText LoadRunner, heute vertrieben als OpenText Professional und Enterprise Performance Engineering.

<details>
<summary>Ist Tricentis in SAP Enterprise Support enthalten?</summary>

Teilweise: SAP gewährt Kunden mit Enterprise Support bis zum 31. Dezember 2028 eine befristete Lizenz für Tricentis Test Automation for SAP, integriert in SAP Cloud ALM. Sie ist auf 5 namentlich benannte Anwender, 500 Testläufe pro Monat und 5 Ausführungsagenten begrenzt. Größere Programme brauchen meist ein vollständiges Tricentis-Produkt, das SAP ebenfalls vertreibt.

</details>

<details>
<summary>Sollte ich SAP Cloud ALM oder Solution Manager für das Testen nutzen?</summary>

Cloud ALM für jedes neue Programm. Es deckt Testvorbereitung, Testpläne, Durchführung und Fehler ab, und ein Tenant ist in Enterprise Support enthalten. Die Mainstream-Wartung des Solution Manager endet Ende 2027, also behalten Sie ihn nur dort, wo er bereits das Change Control steuert, und planen Sie den Wechsel.

</details>

<details>
<summary>Welches ist das beste Tool für manuelles SAP-Testen?</summary>

Ihr Testmanagement-Tool. Cloud ALM, Solution Manager, Panaya und UiPath Test Manager erfassen alle manuelle Testschritte, Ergebnisse und Fehler. Wenn Sie das manuelle Testen aus Tabellen herausholen, erhalten Sie einen Prüfpfad und Verknüpfungen zu Änderungen.

</details>

<details>
<summary>Wann sollte ich SAP-Tests automatisieren?</summary>

Wenn Sie sehr viele Testfälle haben, die umfangreich und wiederholt getestet werden müssen, etwa als Regression über Upgrades und Releases hinweg. Darunter ist manuelles Testen in Ordnung. Einen kleinen, instabilen Testbestand zu automatisieren, kostet in der Pflege meist mehr, als es spart.

</details>

<details>
<summary>Welches Tool wird für SAP-Performancetests verwendet?</summary>

OpenText LoadRunner ist eine verbreitete Wahl, mit den Protokollen SAP, SAP GUI und SAP Web. SAP vertreibt außerdem Produkte von Tricentis für Performancetests. Was Sie auch nutzen: Führen Sie vor dem Go-live Parallelitätstests mit vielen gleichzeitigen Anwendern durch.

</details>
