주요 SAP 테스트 도구는 테스트 관리용 SAP Cloud ALM과 SAP Solution Manager, 테스트 자동화용 Tricentis Tosca(SAP가 SAP Test Automation by Tricentis로 판매), Worksoft, Panaya, UiPath, 그리고 성능 테스트용 OpenText LoadRunner입니다. 대부분의 S/4HANA 프로젝트에는 그룹마다 도구 하나씩이 필요합니다. 테스트를 관리하고 추적하는 도구, 회귀 테스트를 자동화하는 도구, 부하를 테스트하는 도구입니다.

저는 이 일곱 가지를 모두 직접 쓰거나 팀이 쓰도록 했습니다. 이 가이드에서는 2026년 10월 기준 공급업체 문서와 대조해 각 도구가 무엇을 위한 것인지, 그리고 어떻게 고를지 비교합니다. 테스트 유형 자체는 [SAP 테스트 완전 정리](/ko/sap-testing-explained/)부터 보십시오.

모든 것이 완벽하게 작동하는 도구 데모를 수십 번 봤습니다. 그런데 실제 프로젝트에서는 스크립트가 계속 깨지거나, 통합이 공급업체가 보여 준 대로 작동하지 않습니다. 그래서 저는 기능 체크리스트로 SAP 테스트 도구를 고르지 않습니다.

## SAP 테스트 도구가 하는 세 가지 일

제가 운영하는 프로젝트에서 테스트는 공수의 약 35%를 차지합니다. 그 공수 중 얼마나 많은 부분을 반복 가능하게 만들지는 도구가 결정합니다.

도구는 세 그룹으로 나뉩니다. 한 그룹의 도구가 다른 그룹의 일을 해 주리라 기대하지 마십시오.

1. **테스트 관리.** 테스트 케이스, 테스트 계획, 실행 결과, 결함을 보관하고 요구사항 및 변경과 연결합니다. 수동 테스트가 이루어지는 곳이자 감사인이 들여다보는 곳입니다. SAP Cloud ALM, SAP Solution Manager, Panaya Test Management가 여기에 속합니다.
2. **기능 테스트 자동화.** 비즈니스 프로세스 테스트를 기록하거나 모델링하고 변경이 있을 때마다 다시 실행합니다. Tricentis, Worksoft, Panaya Test Automation, UiPath가 여기에 속합니다.
3. **성능 테스트.** 많은 사용자를 동시에 시뮬레이션해 Go-Live 전에 병목을 찾습니다. OpenText LoadRunner가 여기에 속하며, SAP는 Tricentis의 성능 테스트 제품도 재판매합니다.

여러 공급업체가 두 그룹에 걸쳐 있고, 경계는 릴리스마다 바뀝니다. 먼저 어떤 일을 위해 도구를 사는지 정한 뒤 그 그룹 안에서 도구를 비교하십시오.

## SAP 테스트 도구 비교

일곱 가지 도구를 표로 정리했습니다. 각 행은 공급업체 자체 페이지나 SAP 지원 포털과 대조해 확인했습니다.

| 도구 | 공급업체 | 주요 역할 | 용도 | 적합한 곳 |
|---|---|---|---|---|
| SAP Cloud ALM | SAP | 테스트 관리 | 테스트 케이스, 테스트 계획, 수동 실행, 결함, 프로세스 및 요구사항 추적성 | 신규 S/4HANA 및 RISE 프로젝트의 기본값, Enterprise Support에 테넌트 하나 포함 |
| SAP Solution Manager 7.2 | SAP | 테스트 관리 | Test Suite, Business Process Change Analyzer, 변경 관리와의 연결 | 이미 운영 중인 기존 온프레미스 랜드스케이프, 메인스트림 유지보수는 2027년에 종료 |
| Tricentis Tosca / SAP Test Automation by Tricentis | Tricentis, SAP가 재판매 | 자동화 | SAP와 비SAP 애플리케이션 전반의 모델 기반, 코드 없는 자동화 | 릴리스가 잦고 랜드스케이프가 혼합된 프로젝트 |
| Worksoft Certify | Worksoft | 자동화 | 코드 없는 프로세스 자동화와 프로세스 캡처, 영향 분석 | 현업 사용자가 테스트를 만들기를 원하는 프로세스 중심 랜드스케이프 |
| Panaya | Panaya | 영향 분석, 테스트 관리, 자동화 | 변경 영향 분석, 테스트 관리, AI 지원 자동화 | 무엇을 재테스트해야 할지 알아야 하는 업그레이드와 변경이 많은 프로젝트 |
| UiPath Test Manager(UiPath Test Suite) | UiPath | 자동화와 테스트 관리 | SAP GUI, Fiori, 비SAP 전반에서 UiPath 로봇을 활용한 테스트 오케스트레이션 | 이미 프로세스 자동화에 UiPath를 쓰는 기업 |
| OpenText LoadRunner | OpenText | 성능 | SAP, SAP GUI, SAP Web 프로토콜을 이용한 부하 및 동시성 테스트 | Go-Live 전 최대 물량 및 동시성 테스트 |

이 중 나쁜 선택은 없습니다. 접근 방식, 라이선스, 그리고 팀이 이미 알고 있는 것이 다를 뿐입니다.

## 테스트 관리: Cloud ALM과 Solution Manager

### SAP Cloud ALM

Cloud ALM은 테스트 준비, 테스트 계획, 테스트 실행, 결함을 다룹니다. [SAP의 Cloud ALM 테스트 교육 과정](https://learning.sap.com/courses/implementing-with-sap-cloud-alm/planning-and-executing-testing_ef46a49b-9885-4aaa-841d-5ac9c80a3681)에 따르면 테스트 케이스는 솔루션 프로세스 활동에서 만들어지고, 테스터는 단계별로 통과 또는 실패를 기록하며, 결함은 실패한 실행에서 바로 등록됩니다. 그래서 프로세스에서 테스트, 결함까지 추적성이 확보됩니다.

자동화에서는 직접 실행하기보다 오케스트레이션을 합니다. SAP는 두 가지 통합 도구를 명시합니다. SAP S/4HANA Cloud Test Automation Tool과 Tricentis Test Automation for SAP입니다. Worksoft, Panaya, UiPath는 각자 Cloud ALM 통합을 공개하고 있습니다.

라이선스는 간단합니다. [SAP의 사용 권한 페이지](https://support.sap.com/en/alm/usage-rights.html)는 SAP Enterprise Support, Enterprise Support cloud editions 또는 Product Support for Large Enterprises 고객에게 테넌트 하나를 제공합니다. 사용 범위는 고객 자체의 내부 애플리케이션 라이프사이클 관리로 제한됩니다.

### SAP Solution Manager

Solution Manager 7.2는 아직 많은 온프레미스 랜드스케이프에서 테스트 관리를 담당합니다. Enterprise Support 범위에는 변경이 닿는 프로세스로 테스트 범위를 좁혀 주는 Business Process Change Analyzer와 SAP의 테스트 자동화 기능이 포함됩니다.

기능보다 중요한 것은 날짜입니다. [SAP의 Solution Manager 페이지](https://support.sap.com/en/alm/solution-manager.html)에 따르면 메인스트림 유지보수는 2027년 말까지입니다. 테스트 스위트를 포함한 일부 기능에 대해서는 2030년 말까지 연장 유지보수를 선택할 수 있으며, SAP는 2027년 말 전에 Cloud ALM으로 이전할 것을 권장합니다.

신규 프로젝트에서 테스트를 위해 Solution Manager를 도입하지 마십시오. 이미 변경 관리를 Solution Manager로 운영하고 있다면 랜드스케이프가 이전될 때까지 유지하고, 그 이전의 일환으로 테스트 문서를 옮기십시오.

### 수동 테스트 도구

SAP 수동 테스트 도구를 찾는 사람에게 보통 필요한 것은 별도 제품이 아니라 테스트 관리입니다. Cloud ALM, Solution Manager, Panaya Test Management, UiPath Test Manager는 모두 수동 테스트 실행을 단계, 결과, 결함과 함께 기록합니다.

이 도구들이 대체하는 것은 스프레드시트입니다. 스프레드시트에는 트랜스포트와의 연결도, 감사 추적도 없고, 다음 사이클이 시작되면 이력도 남지 않습니다.

## 테스트 자동화 도구: Tricentis, Worksoft, Panaya, UiPath

네 가지 모두 SAP GUI와 Fiori 비즈니스 프로세스를 자동화합니다. 차이는 테스트를 만드는 방식, 함께 제공되는 것, 테스트 관리 도구와 연결되는 방식에 있습니다.

### Tricentis와 SAP Test Automation by Tricentis

[SAP Test Automation by Tricentis](https://www.sap.com/products/technology-platform/test-automation.html)는 SAP가 재판매하는 클라우드 기반 Tricentis 제품입니다. SAP는 이를 SAP와 서드파티 애플리케이션 전반에 걸친 노코드, 모델 기반 자동화이며 Cloud ALM과 통합되어 있다고 설명합니다. SAP는 SAP Enterprise Continuous Testing by Tricentis도 재판매하는데, Tricentis는 이것이 Tosca라고 밝힙니다.

구매 전에 사용 권한을 확인하십시오. SAP의 사용 권한 페이지는 Enterprise Support 고객에게 Cloud ALM과 통합된 Tricentis Test Automation for SAP 기간 라이선스를 2028년 12월 31일까지 제공합니다. 지정 사용자 5명, 월 500회 테스트 실행, 실행 에이전트 5개, 결과 보존 12개월로 제한되어 있으므로, 프로젝트 규모의 라이선스가 아니라 출발점입니다.

Solution Manager와 통합된 Tricentis Test Automation for SAP에 대해서는 별도 라이선스가 2027년 12월 31일까지 적용됩니다. 귀사의 지원 유형에 해당하는 두 항목을 모두 읽어 보십시오.

### Worksoft

Worksoft Certify는 테스트, 테스트 데이터 제공, 데이터 수정을 위한 코드 없는 자동화 제품입니다. Worksoft 플랫폼에는 실제 사용자 활동을 기록해 테스트의 바탕으로 삼는 Business Capture와 변경 분석용 Impact 제품도 있습니다.

Worksoft는 SAP Cloud ALM, Solution Manager와의 통합을 명시하고 있으며 SAP Store에서 구할 수 있습니다. 개발자가 아니라 비즈니스 프로세스 전문가가 테스트 라이브러리를 소유하기를 원하는 팀에 맞습니다.

### Panaya

Panaya의 제품군은 Change Impact Analysis, Test Management, Test Automation, Custom Code Correction을 다룹니다. 출발점은 모든 업그레이드가 던지는 질문입니다. 이 변경이 무엇에 닿았고, 무엇을 다시 테스트해야 하는가?

그래서 커스텀 코드와 영향 범위가 작업을 좌우하는 업그레이드, 서포트 패키지, S/4HANA 전환에 맞습니다. Panaya의 Cloud ALM 통합은 현재 코드 없는 자동화 제품의 자동화 테스트를 다룹니다.

### UiPath Test Suite

UiPath Test Manager는 테스트 실행을 계획하고, 오케스트레이션하고, 보고하며, UiPath 로봇이 테스트를 실행합니다. UiPath는 S/4HANA, ECC, Fiori, WinGUI, WebGUI, Business Client 지원과 SAP Cloud ALM 통합을 명시하고 있습니다.

UiPath 문서에는 Solution Manager 통합도 설명되어 있으며, Solution Manager 7.2 SP08 이상이 필요합니다. UiPath를 택할 현실적인 이유는 재사용입니다. 회사가 이미 프로세스 자동화에 UiPath를 쓰고 있다면 역량과 라이선스를 그대로 활용할 수 있습니다.

### 자동화가 효과를 내는 시점

제 원칙은 단순합니다. 광범위하게 반복 테스트해야 하는 테스트 케이스가 많다면 자동화합니다. 그보다 적다면 수동 테스트로 충분하며, 절반만 만든 자동화 라이브러리는 절약하는 것보다 더 많은 비용이 듭니다.

반복 테스트가 바로 회귀 테스트입니다. 어디서 시작할지는 [SAP 테스트 자동화](/ko/sap-test-automation-guide/) 가이드에서, 업그레이드 주기와 릴리스 범위는 [SAP 회귀 테스트](/ko/sap-regression-testing/)에서 다룹니다.

## 성능 테스트 도구: OpenText LoadRunner

기능 자동화는 프로세스가 사용자 한 명에게 작동한다는 것을 알려 줍니다. 월 마감에 수백 명이 동시에 전기할 때 무슨 일이 일어나는지는 알려 주지 않습니다. 성능 테스트는 반드시 Go-Live 전에 해야 하며, 중요한 것은 많은 사용자가 동시에 작업하는 동시성 테스트입니다.

LoadRunner는 이제 OpenText 제품입니다. [OpenText의 LoadRunner Professional 페이지](https://www.opentext.com/products/loadrunner-professional)는 이 제품을 OpenText Professional Performance Engineering이라고 부릅니다. 지원 프로토콜 목록에는 SAP, SAP GUI, SAP Web이 포함됩니다.

OpenText Enterprise Performance Engineering은 여러 지역에서 동시에 테스트를 실행하는 팀을 위한 제품이고, OpenText Core Performance Engineering은 클라우드 제품입니다. SAP는 Tricentis의 성능 테스트 제품도 재판매합니다. 이런 테스트를 설계하는 방법은 [SAP 성능 테스트](/ko/sap-performance-testing-it-leaders/) 가이드에서 다룹니다.

## SAP 테스트 도구를 고르는 방법

도구는 테스트 관리, 자동화, 성능 순서로 고르십시오. 테스트 관리에 추적성과 감사 기록이 있고, 어떤 자동화 통합이 쉬운지도 테스트 관리 도구가 결정합니다.

1. **이미 보유한 것을 확인합니다.** Cloud ALM과 한도가 있는 Tricentis 라이선스는 Enterprise Support에 포함됩니다. Solution Manager는 온프레미스 유지보수에 포함됩니다.
2. **테스트 관리 플랫폼을 고릅니다.** 신규 프로젝트와 RISE에는 Cloud ALM. Solution Manager는 이미 변경 관리를 운영하는 곳에서만, 2028년 전까지의 이전 계획과 함께.
3. **반복되는 테스트 케이스를 셉니다.** 회귀 테스트 물량이 적다면 테스트 관리 도구에서 수동으로 테스트하고 자동화는 당분간 건너뜁니다.
4. **적합성으로 자동화 도구 후보를 좁힙니다.** SAP와 비SAP가 섞인 랜드스케이프, 변경 영향 분석 필요성, 기존 UiPath 환경, 현업 사용자의 소유 여부가 각각 위 표의 다른 도구를 가리킵니다.
5. **귀사 프로세스로 파일럿을 실행합니다.** 공급업체의 데모 시스템이 아니라 귀사의 데이터와 화면으로 실제 비즈니스 프로세스 흐름 하나를 사용합니다.
6. **성능 테스트 도구를 추가합니다.** 월 마감 같은 최대 부하 기간을 대상으로 동시성 테스트를 계획합니다.

다음 질문이 좋은 데모와 좋은 적합성을 구분해 줍니다.

| 요소 | 던질 질문 |
|---|---|
| SAP 지원 범위 | 어떤 SAP GUI, Fiori, API 기술을 기본으로 구동합니까? |
| 통합 | 귀사 테스트 매니저의 작업 방식대로 Cloud ALM이나 Solution Manager와 연결됩니까? |
| 변경 영향 | 트랜스포트나 업그레이드가 어떤 테스트에 영향을 주는지 알려 줄 수 있습니까? |
| 유지보수 | 릴리스 후 깨진 테스트는 누가 고치며, 얼마나 걸립니까? |
| 소유 | 기능 컨설턴트와 키 유저가 테스트를 만들고 읽을 수 있습니까? |
| 2년 차 비용 | 첫해 이후 에이전트, 사용자, 유지보수 비용은 얼마입니까? |

## 도구가 전부는 아닙니다

제가 가장 자주 보는 테스트 실패는 도구 문제가 아닙니다. 통합 테스트와 사용자 인수 테스트에서 테스트가 충분하지 않은 것입니다. 이 사이클에 시간을 너무 적게 준 계획은 도구로 고칠 수 없습니다.

어떤 제품을 사느냐보다 중요한 관행이 두 가지 있습니다. 테스트 데이터는 마스킹하되 운영 수준이어야 하며, 현실적인 물량을 갖춰야 합니다. 프로젝트 기간에는 랜드스케이프를 두 개로 분리해 하나는 프로젝트용, 하나는 일상 운영용으로 운영하십시오. 그래야 운영 지원 변경과 프로젝트 변경을 따로 테스트할 수 있습니다.

클라우드 릴리스는 고려할 점을 하나 더합니다. SAP Cloud ERP public edition은 1년에 두 번, 2월과 8월에 주요 업그레이드를 받으며, 고객은 업그레이드된 테스트 시스템에서 회귀 테스트를 실행합니다. 이 작업을 위해 SAP의 Test Automation Tool이 포함되어 있습니다.

테스트 결과를 Go-Live 결정과 연결하는 방법은 [SAP 품질 게이트](/ko/sap-quality-gates-implementation/)에 관한 제 글을 참고하십시오.

## 자주 묻는 질문

<details>
<summary>주요 SAP 테스트 도구에는 무엇이 있습니까?</summary>

테스트 관리에는 SAP Cloud ALM과 SAP Solution Manager가 있습니다. 테스트 자동화에는 Tricentis Tosca(SAP Test Automation by Tricentis로도 판매), Worksoft Certify, Panaya, UiPath가 있습니다. 성능 테스트에는 현재 OpenText Professional Performance Engineering과 Enterprise Performance Engineering으로 판매되는 OpenText LoadRunner가 있습니다.

</details>

<details>
<summary>Tricentis는 SAP Enterprise Support에 포함되어 있습니까?</summary>

일부만 포함됩니다. SAP는 Enterprise Support 고객에게 SAP Cloud ALM과 통합된 Tricentis Test Automation for SAP 기간 라이선스를 2028년 12월 31일까지 제공합니다. 지정 사용자 5명, 월 500회 테스트 실행, 실행 에이전트 5개로 제한됩니다. 규모가 큰 프로젝트는 보통 정식 Tricentis 제품이 필요하며, 이 역시 SAP가 재판매합니다.

</details>

<details>
<summary>테스트에는 SAP Cloud ALM과 Solution Manager 중 무엇을 써야 합니까?</summary>

신규 프로젝트라면 Cloud ALM입니다. 테스트 준비, 테스트 계획, 실행, 결함을 다루며, Enterprise Support에 테넌트 하나가 포함되어 있습니다. Solution Manager의 메인스트림 유지보수는 2027년 말에 종료되므로, 이미 변경 관리를 운영하는 곳에서만 유지하고 이전을 계획하십시오.

</details>

<details>
<summary>SAP 수동 테스트에 가장 좋은 도구는 무엇입니까?</summary>

귀사의 테스트 관리 도구입니다. Cloud ALM, Solution Manager, Panaya, UiPath Test Manager는 모두 수동 테스트 단계, 결과, 결함을 기록합니다. 수동 테스트를 스프레드시트에서 옮기면 감사 추적과 변경과의 연결이 생깁니다.

</details>

<details>
<summary>SAP 테스트는 언제 자동화해야 합니까?</summary>

업그레이드와 릴리스에 걸친 회귀 테스트처럼 광범위하게 반복 테스트해야 하는 테스트 케이스가 많을 때입니다. 그보다 적다면 수동 테스트로 충분합니다. 작고 불안정한 테스트 세트를 자동화하면 대개 절약하는 것보다 유지보수 비용이 더 듭니다.

</details>

<details>
<summary>SAP 성능 테스트에는 어떤 도구를 사용합니까?</summary>

SAP, SAP GUI, SAP Web 프로토콜을 지원하는 OpenText LoadRunner가 흔한 선택입니다. SAP는 Tricentis의 성능 테스트 제품도 재판매합니다. 무엇을 쓰든 Go-Live 전에 많은 사용자가 동시에 작업하는 동시성 테스트를 실행하십시오.

</details>
