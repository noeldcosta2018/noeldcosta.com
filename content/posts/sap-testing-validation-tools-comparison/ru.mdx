Основные инструменты тестирования SAP: SAP Cloud ALM и SAP Solution Manager для управления тестированием, Tricentis Tosca (SAP продаёт его как SAP Test Automation by Tricentis), Worksoft, Panaya и UiPath для автоматизации тестирования и OpenText LoadRunner для нагрузочного тестирования. Большинству программ S/4HANA нужен один инструмент из каждой группы: один для управления тестами и их трассировки, один для автоматизации регрессии и один для проверки нагрузки.

Всеми семью я пользовался сам или ими пользовались мои команды. В этом руководстве сравнивается, для чего нужен каждый (проверено по документации поставщиков в октябре 2026 года), и как между ними выбирать. О самих видах тестирования лучше начать с обзора [тестирования SAP](/ru/sap-testing-explained/).

Я видел десятки демонстраций инструментов, где всё работает идеально. Потом в реальном проекте скрипты постоянно ломаются или интеграция так и не работает так, как показывал поставщик. Поэтому я не выбираю инструменты тестирования SAP по спискам функций.

## Три задачи набора инструментов тестирования SAP

В программах, которые я веду, тестирование занимает около 35 процентов трудозатрат. Инструменты определяют, какую часть этих трудозатрат можно повторять.

Они делятся на три группы. Не ждите, что инструмент одной группы выполнит работу другой.

1. **Управление тестированием.** Хранит тестовые сценарии, планы тестирования, результаты выполнения и дефекты и связывает их с требованиями и изменениями. Здесь идёт ручное тестирование и сюда смотрят аудиторы. Сюда относятся SAP Cloud ALM, SAP Solution Manager и Panaya Test Management.
2. **Функциональная автоматизация тестирования.** Записывает или моделирует тесты бизнес-процессов и прогоняет их снова после каждого изменения. Сюда относятся Tricentis, Worksoft, Panaya Test Automation и UiPath.
3. **Нагрузочное тестирование.** Имитирует много пользователей одновременно, чтобы найти узкие места до go-live. Сюда относится OpenText LoadRunner, а SAP также перепродаёт продукты Tricentis для тестирования производительности.

Некоторые поставщики охватывают две группы, и границы смещаются с каждым релизом. Сначала решите, для какой задачи вы покупаете, затем сравнивайте инструменты внутри этой группы.

## Управление тестированием: Cloud ALM и Solution Manager

### SAP Cloud ALM

Cloud ALM охватывает подготовку тестов, планы тестирования, выполнение тестов и дефекты. Согласно [обучению SAP по тестированию в Cloud ALM](https://learning.sap.com/courses/implementing-with-sap-cloud-alm/planning-and-executing-testing_ef46a49b-9885-4aaa-841d-5ac9c80a3681), тестовые сценарии строятся из операций процессов решения, тестировщики отмечают каждый шаг как пройденный или нет, а дефекты регистрируются прямо из неуспешных прогонов. Это даёт трассировку от процесса к тесту и к дефекту.

В автоматизации он оркестрирует, а не выполняет. SAP называет два интегрированных инструмента: SAP S/4HANA Cloud Test Automation Tool и Tricentis Test Automation for SAP. Worksoft, Panaya и UiPath публикуют собственные интеграции с Cloud ALM.

Лицензирование простое. [Страница SAP о правах использования](https://support.sap.com/en/alm/usage-rights.html) предоставляет один тенант клиентам с SAP Enterprise Support, Enterprise Support cloud editions или Product Support for Large Enterprises. Использование ограничено собственным внутренним управлением жизненным циклом приложений клиента.

### SAP Solution Manager

Solution Manager 7.2 по-прежнему ведёт управление тестированием во многих ландшафтах on-premise. В рамках Enterprise Support его объём включает Business Process Change Analyzer, который сужает объём тестов до процессов, затронутых изменением, и функции SAP для автоматизации тестирования.

Дата важнее функций. [Страница SAP о Solution Manager](https://support.sap.com/en/alm/solution-manager.html) указывает основную поддержку до конца 2027 года. Расширенная поддержка до конца 2030 года доступна как опция для отдельных функций, включая набор для тестирования, а SAP рекомендует перейти на Cloud ALM до конца 2027 года.

Не внедряйте Solution Manager для тестирования в новой программе. Если на нём уже работает ваше управление изменениями, оставьте его, пока ландшафт не переедет, а затем перенесите тестовую документацию в рамках этого переезда.

### Инструменты ручного тестирования

Тем, кто ищет инструменты ручного тестирования SAP, обычно нужно управление тестированием, а не отдельный продукт. Cloud ALM, Solution Manager, Panaya Test Management и UiPath Test Manager фиксируют ручное выполнение тестов с шагами, результатами и дефектами.

Заменяют они таблицу Excel. У таблицы нет связи с транспортом, нет журнала аудита и нет истории после начала следующего цикла.

## Инструменты автоматизации тестирования: Tricentis, Worksoft, Panaya и UiPath

Все четыре автоматизируют бизнес-процессы в SAP GUI и Fiori. Различия в том, как строятся тесты, что к ним прилагается и как они подключаются к вашему инструменту управления тестированием.

### Tricentis и SAP Test Automation by Tricentis

[SAP Test Automation by Tricentis](https://www.sap.com/products/technology-platform/test-automation.html) это облачный продукт Tricentis, который перепродаёт SAP. SAP описывает его как модельную автоматизацию без кода для приложений SAP и сторонних приложений, интегрированную с Cloud ALM. SAP также перепродаёт SAP Enterprise Continuous Testing by Tricentis, который Tricentis определяет как Tosca.

Проверьте свои права до покупки. Страница SAP о правах использования предоставляет клиентам Enterprise Support срочную лицензию на Tricentis Test Automation for SAP, интегрированный с Cloud ALM, до 31 декабря 2028 года. Она ограничена 5 именованными пользователями, 500 прогонами тестов в месяц, 5 агентами выполнения и 12 месяцами хранения результатов, поэтому это отправная точка, а не лицензия масштаба программы.

Отдельная лицензия покрывает Tricentis Test Automation for SAP, интегрированный с Solution Manager, до 31 декабря 2027 года. Прочитайте обе записи на странице для вашего типа поддержки.

### Worksoft

Worksoft Certify это продукт автоматизации без кода для тестирования, предоставления тестовых данных и исправления данных. Платформа Worksoft также включает Business Capture, который записывает реальные действия пользователей как основу для тестов, и продукт Impact для анализа изменений.

Worksoft указывает интеграции с SAP Cloud ALM и Solution Manager и доступен в SAP Store. Он подходит командам, где владельцами библиотеки тестов должны быть эксперты по бизнес-процессам, а не разработчики.

### Panaya

Линейка Panaya охватывает Change Impact Analysis, Test Management, Test Automation и Custom Code Correction. Её отправная точка в вопросе, который поднимает каждое обновление: что затронуло это изменение и что мне нужно перепроверить?

Поэтому она подходит для обновлений, пакетов поддержки и конверсий в S/4HANA, где работу определяют собственный код и объём влияния. Интеграция Panaya с Cloud ALM сейчас охватывает автотесты из её продукта автоматизации без кода.

### UiPath Test Suite

UiPath Test Manager планирует и оркестрирует прогоны тестов и формирует отчёты по ним, а роботы UiPath их выполняют. UiPath заявляет поддержку S/4HANA, ECC, Fiori, WinGUI, WebGUI и Business Client, а также интеграцию с SAP Cloud ALM.

Документация UiPath описывает и интеграцию с Solution Manager, для которой нужен Solution Manager 7.2 SP08 или новее. Практический довод за UiPath в повторном использовании: если ваша компания уже использует UiPath для автоматизации процессов, ваши навыки и лицензии переходят дальше.

### Когда автоматизация окупается

Моё правило простое. Если тестовых сценариев много и их нужно тщательно и многократно проверять, автоматизируйте. Если меньше, ручного тестирования достаточно, а наполовину построенная библиотека автоматизации стоит больше, чем экономит.

Многократное тестирование это и есть регрессия. С чего начать, описано в моём руководстве по [автоматизации тестирования SAP](/ru/sap-test-automation-guide/), а циклы обновлений и объём релизов в руководстве по [регрессионному тестированию SAP](/ru/sap-regression-testing/).

## Инструменты нагрузочного тестирования: OpenText LoadRunner

Функциональная автоматизация говорит вам, что процесс работает для одного пользователя. Она не говорит, что произойдёт, когда сотни пользователей проводят документы в конце месяца. Нагрузочное тестирование должно пройти до go-live, и важны именно тесты параллельной работы, когда много пользователей работают одновременно.

LoadRunner теперь продукт OpenText. [Страница OpenText о LoadRunner Professional](https://www.opentext.com/products/loadrunner-professional) теперь называет его OpenText Professional Performance Engineering. В его списке протоколов есть SAP, SAP GUI и SAP Web.

OpenText Enterprise Performance Engineering обслуживает команды, которые проводят тесты одновременно в нескольких местах, а OpenText Core Performance Engineering это облачное предложение. SAP также перепродаёт продукты Tricentis для тестирования производительности. Как проектировать такие тесты, описано в моём руководстве по [тестированию производительности SAP](/ru/sap-performance-testing-it-leaders/).

## Как выбрать инструменты тестирования SAP

Выбирайте инструменты в таком порядке: сначала управление тестированием, затем автоматизация, затем производительность. Управление тестированием хранит трассировку и аудит, и от него зависит, какие интеграции автоматизации будут простыми.

1. **Проверьте, что у вас уже есть.** Cloud ALM и ограниченная лицензия Tricentis входят в Enterprise Support. Solution Manager входит в поддержку on-premise.
2. **Выберите платформу управления тестированием.** Cloud ALM для новых программ и RISE. Solution Manager только там, где на нём уже работает управление изменениями, с планом миграции до 2028 года.
3. **Посчитайте свои повторяющиеся тестовые сценарии.** Если объём регрессии мал, тестируйте вручную в инструменте управления тестированием и пока откажитесь от автоматизации.
4. **Составьте короткий список средств автоматизации по соответствию.** Смешанные ландшафты SAP и не SAP, потребность в анализе влияния изменений, уже работающий UiPath и владение тестами со стороны бизнес-пользователей указывают на разные инструменты из таблицы выше.
5. **Проведите пилот на своих процессах.** Используйте один реальный бизнес-процесс со своими данными и экранами, а не демо-систему поставщика.
6. **Добавьте инструмент нагрузочного тестирования.** Запланируйте тестирование параллельной работы для пиковых периодов, таких как закрытие месяца.

Эти вопросы отделяют хорошее соответствие от хорошей демонстрации.

| Фактор | Какой вопрос задать |
|---|---|
| Покрытие SAP | Какими технологиями SAP GUI, Fiori и API он управляет нативно? |
| Интеграция | Подключается ли он к Cloud ALM или Solution Manager так, как работает ваш менеджер по тестированию? |
| Влияние изменений | Может ли он сказать, какие тесты затрагивает транспорт или обновление? |
| Сопровождение | Кто чинит сломанные тесты после релиза и сколько это занимает? |
| Владение | Могут ли функциональные консультанты и ключевые пользователи создавать и читать тесты? |
| Стоимость второго года | Сколько стоят агенты, пользователи и сопровождение после первого года? |

## Инструменты не решают всё

Самая частая ошибка тестирования, которую я вижу, не связана с инструментами. Это недостаточное тестирование в системном интеграционном и приёмочном тестировании. Инструмент не исправит план, который даёт этим циклам слишком мало времени.

Две практики важнее, чем выбор продукта. Тестовые данные должны быть маскированными, но продуктивного уровня, с реалистичными объёмами. Во время программы держите два отдельных ландшафта, один для проекта и один для текущей деятельности, чтобы изменения сопровождения и изменения проекта тестировались раздельно.

Облачные релизы добавляют ещё одно соображение. SAP Cloud ERP public edition получает два крупных обновления в год, в феврале и августе, и клиенты проводят регрессионные тесты в обновлённой тестовой системе. Для этой работы в поставку входит Test Automation Tool от SAP.

Как связать результаты тестов с решениями о go-live, читайте в моей статье о [quality gates в SAP](/ru/sap-quality-gates-implementation/).

## Ваш следующий шаг

Распределите семь инструментов по трём задачам, затем отметьте, что уже входит в ваш договор поддержки SAP. После этого составляйте короткий список только для пробелов и заказывайте демонстрации на своих процессах.

Если вам нужно второе мнение о наборе инструментов тестирования или плане тестирования, [поговорите со мной](/ru/contact-noel-erp-support/).

<summary>Входит ли Tricentis в SAP Enterprise Support?</summary>

Частично: SAP предоставляет клиентам Enterprise Support срочную лицензию на Tricentis Test Automation for SAP, интегрированный с SAP Cloud ALM, до 31 декабря 2028 года. Она ограничена 5 именованными пользователями, 500 прогонами тестов в месяц и 5 агентами выполнения. Крупным программам обычно нужен полный продукт Tricentis, который SAP тоже перепродаёт.

</details>

<details>
<summary>Что использовать для тестирования: SAP Cloud ALM или Solution Manager?</summary>

Cloud ALM для любой новой программы. Он охватывает подготовку тестов, планы тестирования, выполнение и дефекты, а один тенант входит в Enterprise Support. Основная поддержка Solution Manager заканчивается в конце 2027 года, поэтому оставляйте его только там, где на нём уже работает управление изменениями, и планируйте переход.

</details>

<details>
<summary>Какой инструмент лучше всего подходит для ручного тестирования SAP?</summary>

Ваш инструмент управления тестированием. Cloud ALM, Solution Manager, Panaya и UiPath Test Manager фиксируют шаги ручных тестов, результаты и дефекты. Перенос ручного тестирования из таблиц даёт журнал аудита и связь с изменениями.

</details>

<details>
<summary>Когда стоит автоматизировать тестирование SAP?</summary>

Когда у вас много тестовых сценариев, которые нужно тщательно и многократно проверять, например регрессия при обновлениях и релизах. Если меньше, ручного тестирования достаточно. Автоматизация небольшого нестабильного набора тестов обычно стоит на сопровождение больше, чем экономит.

</details>

<details>
<summary>Какой инструмент используется для тестирования производительности SAP?</summary>

Распространённый выбор: OpenText LoadRunner с протоколами SAP, SAP GUI и SAP Web. SAP также перепродаёт продукты Tricentis для тестирования производительности. Что бы вы ни использовали, проводите тесты параллельной работы с множеством одновременных пользователей до go-live.

</details>
