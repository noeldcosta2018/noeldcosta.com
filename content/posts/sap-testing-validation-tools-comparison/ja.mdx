主なSAPテストツールは、テスト管理ではSAP Cloud ALMとSAP Solution Manager、テスト自動化ではTricentis Tosca（SAPがSAP Test Automation by Tricentisとして販売）、Worksoft、Panaya、UiPath、パフォーマンステストではOpenText LoadRunnerです。ほとんどのS/4HANAプログラムには、各グループから1つずつツールが必要です。テストを管理してトレースするもの、回帰テストを自動化するもの、負荷をテストするものです。

私はこの7つすべてを自分で使うか、チームに使わせてきました。このガイドでは、2026年10月時点のベンダーのドキュメントで確認したうえで、それぞれの用途と選び方を比較します。テストの種類そのものについては、まず[SAPテストとは](/ja/sap-testing-explained/)をお読みください。

すべてが完璧に動くツールのデモに、私は何十回も付き合ってきました。ところが実際のプロジェクトでは、スクリプトは壊れ続け、連携はベンダーが見せたとおりには決して動きません。だから私は、機能のチェックリストでSAPテストツールを選びません。

## SAPのテストツールセットが担う3つの役割

私が運営するプログラムでは、テストが工数の約35パーセントを占めます。その工数のうちどれだけを繰り返し可能にできるかは、ツールで決まります。

ツールは3つのグループに分かれます。あるグループのツールに、別のグループの役割を期待しないでください。

1. **テスト管理。** テストケース、テスト計画、実行結果、不具合を保持し、要件や変更と結びつけます。手動テストが行われ、監査人が確認する場所です。SAP Cloud ALM、SAP Solution Manager、Panaya Test Managementがここに入ります。
2. **機能テストの自動化。** 業務プロセスのテストを記録またはモデル化し、変更のたびに再実行します。Tricentis、Worksoft、Panaya Test Automation、UiPathがここに入ります。
3. **パフォーマンステスト。** 多数のユーザーを同時にシミュレートし、本稼働前にボトルネックを見つけます。OpenText LoadRunnerがここに入り、SAPはTricentisのパフォーマンス製品も再販しています。

複数のベンダーが2つのグループにまたがっており、その境界はリリースのたびに動きます。まずどの役割のために購入するのかを決め、そのうえでそのグループの中でツールを比較してください。

## SAPテストツールの比較

7つのツールを次の表にまとめました。各行は、ベンダー自身のページまたはSAPのサポートポータルで確認しています。

| ツール | ベンダー | 主な役割 | 用途 | 適する場面 |
|---|---|---|---|---|
| SAP Cloud ALM | SAP | テスト管理 | テストケース、テスト計画、手動実行、不具合、プロセスと要件へのトレーサビリティ | 新規のS/4HANAプログラムとRISEプログラムの標準。Enterprise Supportにテナント1つが含まれる |
| SAP Solution Manager 7.2 | SAP | テスト管理 | Test Suite、Business Process Change Analyzer、変更管理との連携 | すでに運用している既存のオンプレミス環境。メインストリームメンテナンスは2027年に終了 |
| Tricentis Tosca / SAP Test Automation by Tricentis | Tricentis（SAPが再販） | 自動化 | SAPとSAP以外のアプリケーションにまたがる、モデルベースでコードレスの自動化 | リリースが頻繁で、混在した環境を持つプログラム |
| Worksoft Certify | Worksoft | 自動化 | コードレスのプロセス自動化に加え、プロセスキャプチャと影響分析 | 業務ユーザーにテストを作らせたい、プロセス中心の環境 |
| Panaya | Panaya | 影響分析、テスト管理、自動化 | 変更影響分析、テスト管理、AI支援の自動化 | 何を再テストすべきかを知る必要がある、アップグレードや変更の多いプログラム |
| UiPath Test Manager（UiPath Test Suite） | UiPath | 自動化とテスト管理 | SAP GUI、Fiori、SAP以外にまたがる、UiPathのロボットによるテストのオーケストレーション | すでにプロセス自動化にUiPathを使っている企業 |
| OpenText LoadRunner | OpenText | パフォーマンス | SAP、SAP GUI、SAP Webのプロトコルによる負荷テストと同時実行テスト | 本稼働前のピーク時のボリュームと同時実行のテスト |

どのツールも悪い選択ではありません。違いは、アプローチ、ライセンス、そしてチームがすでに知っていることにあります。

## テスト管理：Cloud ALMとSolution Manager

### SAP Cloud ALM

Cloud ALMは、テストの準備、テスト計画、テスト実行、不具合をカバーします。[テストに関するSAPのCloud ALMトレーニング](https://learning.sap.com/courses/implementing-with-sap-cloud-alm/planning-and-executing-testing_ef46a49b-9885-4aaa-841d-5ac9c80a3681)によると、テストケースはソリューションのプロセスアクティビティから作成され、テスト担当者はステップごとに合格または不合格を記録し、不具合は失敗した実行から直接起票されます。これで、プロセスからテスト、不具合までのトレーサビリティが得られます。

自動化については、実行するのではなくオーケストレーションを担います。SAPは2つの統合ツールを挙げています。SAP S/4HANA Cloud Test Automation ToolとTricentis Test Automation for SAPです。Worksoft、Panaya、UiPathはそれぞれ独自のCloud ALM連携を公開しています。

ライセンスはシンプルです。[SAPの利用権のページ](https://support.sap.com/en/alm/usage-rights.html)では、SAP Enterprise Support、Enterprise Support cloud editions、Product Support for Large Enterprisesの顧客にテナントを1つ付与しています。用途は顧客自身の社内のアプリケーションライフサイクル管理に限られます。

### SAP Solution Manager

Solution Manager 7.2は、今も多くのオンプレミス環境でテスト管理を担っています。Enterprise Supportのもとでは、その範囲に、テスト範囲を変更が関わるプロセスに絞り込むBusiness Process Change Analyzerと、SAPのテスト自動化機能が含まれます。

機能よりも重要なのは日付です。[SAPのSolution Managerのページ](https://support.sap.com/en/alm/solution-manager.html)では、メインストリームメンテナンスを2027年末までとしています。テストスイートを含む一部の機能については2030年末までの延長メンテナンスを選択でき、SAPは2027年末までにCloud ALMへ移行することを推奨しています。

新しいプログラムで、テストのためにSolution Managerを導入しないでください。すでに変更管理を担っているなら、環境が移行するまで使い続け、その移行の一環としてテストのドキュメントを移してください。

### 手動テストのツール

SAPの手動テストツールを探している人が必要としているのは、たいてい別の製品ではなくテスト管理です。Cloud ALM、Solution Manager、Panaya Test Management、UiPath Test Managerはいずれも、手動テストの実行をステップ、結果、不具合とともに記録します。

これらが置き換えるのはスプレッドシートです。スプレッドシートには移送とのつながりも監査証跡もなく、次のサイクルが始まれば履歴も残りません。

## テスト自動化ツール：Tricentis、Worksoft、Panaya、UiPath

4つとも、SAP GUIとFioriの業務プロセスを自動化します。違いは、テストの作り方、付属するもの、そしてテスト管理ツールとのつながり方にあります。

### TricentisとSAP Test Automation by Tricentis

[SAP Test Automation by Tricentis](https://www.sap.com/products/technology-platform/test-automation.html)は、SAPが再販するクラウドベースのTricentis製品です。SAPはこれを、SAPとサードパーティのアプリケーションにまたがるノーコードでモデルベースの自動化で、Cloud ALMと統合されたものと説明しています。SAPはSAP Enterprise Continuous Testing by Tricentisも再販しており、TricentisはこれをToscaとしています。

購入する前に利用権を確認してください。SAPの利用権のページでは、Enterprise Supportの顧客に、Cloud ALMと統合されたTricentis Test Automation for SAPの期間限定ライセンスを2028年12月31日まで付与しています。上限は指名ユーザー5人、月500回のテスト実行、実行エージェント5つ、結果の保持期間12か月で、プログラム規模のライセンスというより出発点です。

Solution Managerと統合されたTricentis Test Automation for SAPには別のライセンスがあり、期限は2027年12月31日です。ページにある両方の項目を、自社のサポートの種類に照らして読んでください。

### Worksoft

Worksoft Certifyは、テスト、テストデータの準備、データ修正のためのコードレスの自動化製品です。Worksoftのプラットフォームには、実際のユーザーの操作をテストの土台として記録するBusiness Captureと、変更分析のためのImpact製品も含まれています。

WorksoftはSAP Cloud ALMとSolution Managerとの連携を掲げており、SAP Storeで入手できます。開発者ではなく業務プロセスの専門家にテストライブラリを持たせたいチームに向いています。

### Panaya

Panayaの製品群は、Change Impact Analysis、Test Management、Test Automation、Custom Code Correctionをカバーします。出発点は、アップグレードのたびに生じる問いです。この変更は何に影響したのか、何を再テストする必要があるのか。

そのため、カスタムコードと影響範囲が作業を左右するアップグレード、サポートパック、S/4HANAへのシステム変換に適しています。PanayaのCloud ALM連携は現在、同社のコードレス自動化製品による自動テストをカバーしています。

### UiPath Test Suite

UiPath Test Managerはテスト実行を計画し、オーケストレーションし、報告します。実行するのはUiPathのロボットです。UiPathは、S/4HANA、ECC、Fiori、WinGUI、WebGUI、Business Clientへの対応と、SAP Cloud ALM連携を掲げています。

UiPathのドキュメントにはSolution Manager連携の説明もあり、それにはSolution Manager 7.2 SP08以降が必要です。UiPathを選ぶ実務上の理由は再利用です。すでにプロセス自動化にUiPathを使っている企業なら、スキルとライセンスをそのまま生かせます。

### 自動化が元を取れるとき

私のルールはシンプルです。広範囲で繰り返しのテストが必要なテストケースが大量にあるなら、自動化します。それに満たないなら手動テストで十分で、中途半端に作った自動化ライブラリは節約できる以上のコストを生みます。

繰り返しのテストとは、すなわち回帰テストです。私の[SAPテスト自動化](/ja/sap-test-automation-guide/)のガイドではどこから始めるべきかを、[SAP回帰テスト](/ja/sap-regression-testing/)ではアップグレードのサイクルとリリースの範囲を解説しています。

## パフォーマンステストのツール：OpenText LoadRunner

機能テストの自動化でわかるのは、1人のユーザーにとってプロセスが動くことです。月末に何百人ものユーザーが転記したときに何が起きるかはわかりません。パフォーマンステストは本稼働前に実施しなければならず、重要なのは多数のユーザーが同時に作業する同時実行テストです。

LoadRunnerは現在OpenTextの製品です。[OpenTextのLoadRunner Professionalのページ](https://www.opentext.com/products/loadrunner-professional)では、現在の名称をOpenText Professional Performance Engineeringとしています。対応プロトコルには、SAP、SAP GUI、SAP Webが含まれます。

OpenText Enterprise Performance Engineeringは複数の拠点で同時にテストを実行するチーム向けで、OpenText Core Performance Engineeringはクラウド版です。SAPはTricentisのパフォーマンステスト製品も再販しています。そうしたテストの設計方法は、私の[SAPパフォーマンステスト](/ja/sap-performance-testing-it-leaders/)のガイドで解説しています。

## SAPテストツールの選び方

ツールは、テスト管理、自動化、パフォーマンスの順に選んでください。トレーサビリティと監査の拠りどころはテスト管理であり、どの自動化ツールとの連携が容易かもそこで決まります。

1. **すでに持っているものを確認する。** Cloud ALMと上限つきのTricentisのライセンスはEnterprise Supportに含まれています。Solution Managerはオンプレミスの保守契約に含まれています。
2. **テスト管理のプラットフォームを選ぶ。** 新規プログラムとRISEにはCloud ALM。Solution Managerは、すでに変更管理を担っている場合に限り、2028年より前の移行計画とともに使います。
3. **繰り返し実行するテストケースを数える。** 回帰テストの件数が少ないなら、テスト管理ツールで手動テストを行い、自動化は当面見送ります。
4. **適合性で自動化ツールの候補を絞る。** SAPとSAP以外が混在する環境、変更影響分析の必要性、既存のUiPath資産、業務ユーザーによる所有は、それぞれ上の表の異なるツールを指し示します。
5. **自社のプロセスでパイロットを行う。** ベンダーのデモシステムではなく、自社のデータと画面を使って、実際の業務プロセスのフローを1つ実行します。
6. **パフォーマンスのツールを加える。** 月次決算のようなピーク期間に向けて、同時実行テストを計画します。

次の問いが、デモの良さと本当の適合性を見分けます。

| 要素 | 尋ねるべき問い |
|---|---|
| SAPへの対応 | SAP GUI、Fiori、APIのどの技術をネイティブに操作できますか？ |
| 連携 | テストマネージャーの仕事の進め方に合う形で、Cloud ALMやSolution Managerと接続できますか？ |
| 変更影響 | 移送やアップグレードがどのテストに影響するかを示せますか？ |
| 保守 | リリース後に壊れたテストは誰が直し、どれくらいかかりますか？ |
| 所有 | 機能コンサルタントとキーユーザーがテストを作成し、読むことができますか？ |
| 2年目のコスト | 初年度以降、エージェント、ユーザー、保守にいくらかかりますか？ |

## ツールだけでは答えにならない

私が最もよく目にするテストの失敗は、ツールの問題ではありません。結合テストとユーザー受入テストでのテスト不足です。これらのサイクルに十分な時間を与えない計画を、ツールで直すことはできません。

どの製品を買うかよりも重要な実践が2つあります。テストデータはマスキングしたうえで本番レベルとし、現実的なボリュームにすること。そしてプログラムの期間中は、プロジェクト用と通常業務用の2つの環境を別々に運用し、本番保守の変更とプロジェクトの変更を分けてテストすることです。

クラウドのリリースは、もう1つ考慮すべき点を加えます。SAP Cloud ERP public editionでは年2回、2月と8月に大きなアップグレードがあり、顧客はアップグレードされたテストシステムで回帰テストを実行します。その作業のために、SAPのTest Automation Toolが含まれています。

テスト結果を本稼働の判断に結びつけるには、私の[SAP品質ゲート](/ja/sap-quality-gates-implementation/)の記事をご覧ください。

## 次の一歩

7つのツールを3つの役割に照らして並べ、SAPのサポート契約にすでに含まれているものに印をつけてください。そのうえで、足りない部分についてだけ候補を絞り、自社のプロセスでデモを予約してください。

テストツールセットやテスト計画についてセカンドオピニオンが必要であれば、[ご相談ください](/ja/contact-noel-erp-support/)。

## よくある質問

<details>
<summary>主なSAPテストツールは何ですか？</summary>

テスト管理ではSAP Cloud ALMとSAP Solution Managerです。テスト自動化ではTricentis Tosca（SAP Test Automation by Tricentisとしても販売）、Worksoft Certify、Panaya、UiPathです。パフォーマンステストではOpenText LoadRunnerで、現在はOpenText Professional Performance EngineeringおよびEnterprise Performance Engineeringとして販売されています。

</details>

<details>
<summary>TricentisはSAP Enterprise Supportに含まれていますか？</summary>

一部は含まれています。SAPはEnterprise Supportの顧客に、SAP Cloud ALMと統合されたTricentis Test Automation for SAPの期間限定ライセンスを2028年12月31日まで付与しています。上限は指名ユーザー5人、月500回のテスト実行、実行エージェント5つです。大規模なプログラムでは通常、SAPが再販しているTricentisのフル製品が必要になります。

</details>

<details>
<summary>テストにはSAP Cloud ALMとSolution Managerのどちらを使うべきですか？</summary>

新しいプログラムならCloud ALMです。テストの準備、テスト計画、実行、不具合をカバーし、Enterprise Supportにテナントが1つ含まれています。Solution Managerのメインストリームメンテナンスは2027年末に終了するため、すでに変更管理を担っている場合に限って使い続け、移行を計画してください。

</details>

<details>
<summary>SAPの手動テストに最適なツールは何ですか？</summary>

自社のテスト管理ツールです。Cloud ALM、Solution Manager、Panaya、UiPath Test Managerはいずれも、手動テストのステップ、結果、不具合を記録します。手動テストをスプレッドシートから移せば、監査証跡と変更とのつながりが得られます。

</details>

<details>
<summary>SAPテストはいつ自動化すべきですか？</summary>

アップグレードやリリースをまたぐ回帰テストのように、広範囲で繰り返しのテストが必要なテストケースが大量にあるときです。それに満たないなら、手動テストで十分です。小さく不安定なテストセットを自動化すると、たいてい節約できる以上の保守コストがかかります。

</details>

<details>
<summary>SAPのパフォーマンステストにはどのツールが使われますか？</summary>

よく選ばれるのはOpenText LoadRunnerで、SAP、SAP GUI、SAP Webのプロトコルに対応しています。SAPはTricentisのパフォーマンステスト製品も再販しています。どれを使うにしても、本稼働前に多数のユーザーが同時に作業する同時実行テストを実行してください。

</details>
