MRP Live 在 SAP S/4HANA 內，以無限產能規劃要生產和採購什麼，以及什麼時候。內嵌式 PP/DS 以有限產能，為瓶頸資源上的關鍵物料排程；SAP IBP 則以數個月為範圍，規劃整個企業的需求、庫存與供應。

所以 MRP Live 與 PP/DS 的問題關乎工廠：您是否需要在受限的生產線上做有限產能排程？PP/DS 與 IBP 的問題則關乎範圍：您的規劃問題是在一座工廠內，還是跨越整個網路？

我在導入專案中同時用過 MRP Live 和內嵌式 PP/DS，也在情況需要時把客戶轉向 IBP。本文說明每個工具規劃什麼，以及告訴您該升級的訊號。如果您還在挑選 ERP 本身，請先看我對[最佳製造業 ERP](/zh-TW/best-erp-for-manufacturing/) 的比較。

## 四個規劃工具，四個不同的問題

SAP 為使用 S/4HANA 的製造商提供四種規劃選項。傳統 MRP 和 MRP Live 是執行同一套物料規劃的兩種方式。

PP/DS 在同一套系統中加上詳細排程。IBP 則是位於其上的獨立雲端產品。

下表把它們並列比較。

| 工具 | 規劃什麼 | 產能邏輯 | 典型規劃期間 | 在哪裡執行 |
|---|---|---|---|---|
| 傳統 MRP（MD01、MD02、MD03） | 計畫訂單與採購申請 | 無限 | 數天到數月 | S/4HANA 應用伺服器 |
| MRP Live（MD01N） | 同上，但更快，可涵蓋一個或多個工廠 | 無限 | 數天到數月 | 在 SAP HANA 資料庫內 |
| 內嵌式 PP/DS | 訂單在資源上的順序與時間 | 有限，含整備與順序邏輯 | 數小時到數週 | 在 S/4HANA 內 |
| SAP IBP | 整個網路的需求、庫存與供應 | 受限，依時間區間或依訂單 | 數週到數年 | 獨立的 SAP 雲端產品 |

先看產能那一欄。它是這些工具之間最清楚的分界線。

## MRP Live 與傳統 MRP：預設選項

每個 SAP 製造商都從這裡開始。MRP 把預測和銷售訂單與庫存及未結收貨相抵，展開物料清單，並建議要生產什麼、採購什麼。我的 [SAP PP 指南](/zh-TW/sap-pp-production-planning/)詳細介紹了這個模組、主檔資料和規劃週期。

MRP Live 是那套執行的 S/4HANA 版本。SAP 的 [MRP Live 學習單元](https://learning.sap.com/courses/exploring-production-planning-in-sap-s-4hana/outlining-material-requirements-planning-with-mrp-live-1)說明，它把規劃邏輯下推到 HANA 資料庫中，可以線上規劃一個或多個工廠。同一課程也確認，傳統的規劃模式在 S/4HANA 中仍然可用。

### MRP 做不到的事

MRP 假設產能無限。它會把兩百小時的工作排進一個一百小時的工作週。

S/4HANA 中有產能評估和產能平準，但它們位於 MRP 執行之外，而不是之內。當一條線或一座烘爐決定整座工廠的產出時，這個落差就是每天都要面對的問題。

### 傳統 MRP 還是 MRP Live

對多數新的 S/4HANA 設計來說，MRP Live 是預設選項。有些傳統功能的行為不同，或未針對 HANA 最佳化，SAP Knowledge Base Article 2640393 列出了 MRP Live 與傳統 MRP 的差異。

在確定之前，請對照您自己的設計閱讀這份說明。實務上要確認的幾點：

1. 您的批量程序和 MRP 類型是否在 MRP Live 中受支援
2. 您是否依賴受限的規劃範圍，或把 MRP 清單當成快照使用
3. 多階接單生產或專案規劃執行是否屬於您的流程
4. 是否每項自製物料都有有效的生產版本，這是 MRP Live 所需要的

### 預測性 MRP：升級前的一步

預測性物料與資源規劃（pMRP）是 S/4HANA 內的模擬工具。SAP 的 [pMRP 課程](https://learning.sap.com/courses/exploring-production-planning-in-sap-s-4hana/introducing-predictive-mrp-pmrp-)將它描述為 ECC 中長期規劃的後繼者，用來在簡化的計畫上及早發現產能問題。

生管人員在模擬中變更需求、產能或供應來源，再與參考計畫比較。在模擬被發布之前，作業中的 MRP 不會有任何變動。

在您認定只有 PP/DS 或 IBP 才能解決之前，先用 pMRP 跑一次中期產能問題。

## 內嵌式 PP/DS：當有限產能很重要時

PP/DS（Production Planning and Detailed Scheduling，生產規劃與詳細排程）是過去在 SAP APO 中執行的進階規劃引擎。在 S/4HANA 中它是內嵌的，所以不需要另外運行規劃伺服器，也沒有資料需要複製過去。

SAP 的 [PP/DS 學習內容](https://learning.sap.com/courses/exploring-advanced-production-planning-with-sap-s-4hana-pp-ds/outlining-advanced-planning-pp-ds-in-sap-s-4hana-1)描述了在工廠內以精確時間進行的有限產能規劃。資源可以設為有限產能，標準啟發式規則決定規劃步驟，而詳細排程中的最佳化工具可以透過改變現有訂單的順序和資源，減少整備時間、整備成本和延誤。

### PP/DS 與 MRP Live 如何分工

分工依物料而定。標記為進階規劃的物料交給 PP/DS，其餘留在 MRP Live。SAP 自己的建議是：在瓶頸資源上的關鍵產品用 PP/DS 規劃，較不關鍵、以耗用為基礎的物料則用 MRP Live。

由此衍生出兩條設計規則：

1. 把每一項會占用瓶頸資源的物料都放進 PP/DS。一條受限的生產線如果有一半產品以無限產能規劃，就不算有限產能規劃。
2. 把 PP/DS 物料排除在 MRP Live 的規劃範圍之外，否則下一次 MRP 執行可能會覆蓋詳細排程。

### PP/DS 要付出什麼

PP/DS 需要比 MRP 更多的主檔資料，也需要更多紀律來維持資料最新。資源、整備群組、整備矩陣和實際的作業時間都必須正確，排程才有意義。

授權是另一項要確認的事。在設計依賴 PP/DS 之前，請 SAP 以書面確認您的合約如何涵蓋它。

PP/DS 在順序決定成本的工廠最能發揮價值：顏色、等級、尺寸或配方之間的換線。一般而言，塑膠和鋼鐵就是這類生產的典型例子。離散、流程和重複性製造設定的細節，請看我的 [SAP 離散製造與流程製造](/zh-TW/sap-discrete-vs-process-manufacturing/)指南。

## SAP IBP：當問題在於整個網路時

[SAP Integrated Business Planning for Supply Chain](https://help.sap.com/docs/SAP_INTEGRATED_BUSINESS_PLANNING/6b0a6820ebf94ff4a15d68af6db7745b/b48f855725308a1be10000000a44147b.html) 是獨立的雲端產品。它涵蓋銷售與營運規劃、需求、庫存、回應與供應，以及需求驅動補貨。

IBP 回答的是 MRP 和 PP/DS 從來不問的問題。企業應該銷售、存放和供應多少，又該由哪座工廠生產什麼？

### 時間序列規劃與以訂單為基礎的規劃

IBP 回應與供應有兩種規劃方式。時間序列規劃以時間區間運作，透過啟發式規則和最佳化工具，在中長期建立受限、以成本為基礎的供應計畫。

以訂單為基礎的規劃在較短的期間內處理個別訂單。SAP 的[以訂單為基礎的規劃課程](https://learning.sap.com/courses/discovering-order-based-supply-planning-response-with-sap-ibp)涵蓋粗略產能規劃、作業層級的供應計畫、調撥部署，以及與生產規劃的即時整合。這是 IBP 最接近工廠的地方，也是與 PP/DS 的重疊最常引發爭論的地方。

### IBP 仍然需要 S/4HANA 提供什麼

IBP 負責規劃，S/4HANA 負責執行。主檔資料和交易從 S/4HANA 往上流，計畫再往下流回來，而 MRP 或 PP/DS 仍要把它們轉成工廠可以執行的訂單。

IBP 會多出第二套系統和一個需要負責的整合。我的[為什麼 SAP IBP 很重要](/zh-TW/why-sap-integrated-business-planning-sap-ibp-matters/)指南深入介紹了各項應用和整合途徑。

我曾為國防製造業導入 IBP。值不值得，取決於規劃有多複雜，而在許多工廠並不值得。

## 何時該升級：決策準則

沒有任何規則說某個規模的製造商就需要 PP/DS 或 IBP。決策應該跟著您實際遇到的規劃問題走，以下訊號是幫您找出這個問題的一般性指引。

下表把常見訊號對應到通常能處理它的工具。

| 您的工廠或企業出現的訊號 | 通常指向 |
|---|---|
| 生管人員接受大部分 MRP 建議，產能很少成為限制 | 只用 MRP Live |
| 您需要在承諾之前看到中期產能問題 | S/4HANA 內的 pMRP |
| 生管人員每週都要手動重排某一條線的排程 | 內嵌式 PP/DS |
| 換線決定成本，順序很重要 | 內嵌式 PP/DS |
| 訂單跨多個 BOM 層級相互追溯，延誤會連鎖擴散 | 內嵌式 PP/DS |
| 供應決策跨越多座工廠和配銷中心 | SAP IBP |
| 需求需要針對大量客戶和通路做統計預測 | SAP IBP |
| 每月的銷售與營運流程需要財務參與 | SAP IBP |
| 短缺的供應必須依客戶優先順序分配 | SAP IBP 回應與供應 |

只有一個瓶頸的單一工廠，往往只需要 MRP Live 和 PP/DS，僅此而已。需求有季節性的多廠集團，可能需要 IBP 做網路計畫，再用 PP/DS 處理真正限制產出的生產線。

### 購買前要回答的問題

和生管人員一起逐一檢視：

1. 生管人員今天在哪些地方推翻系統，每週要花多少小時？
2. 限制是某座工廠中的某個資源，還是跨工廠和通路的決策？
3. 順序是否會透過整備、清洗或報廢而改變成本？
4. 是否有談定的銷售與營運流程，還是每個部門都帶著自己的數字來？
5. 主檔資料今天的品質是否足以支撐 MRP？如果不行，更進階的工具只會更快地規劃出同樣的錯誤。

如果第 5 題的答案是否，先解決它。

傳統 SOP 在 S/4HANA 中屬於相容性範圍，SAP 指定的後繼者是 IBP，所以這個期限可能比規劃問題本身更早把 IBP 的問題推到您面前。在把它當成急事之前，先確認您自己合約中的使用權。

### 各層如何協同運作

升級的製造商是加上一層，而不是取代下面那一層。

PP/DS 和 MRP Live 在同一套 S/4HANA 系統中以同一份資料執行，所以主要風險是重疊：兩個引擎規劃同一項物料。IBP 在自己的雲端租用戶中執行，所以風險轉移到整合，以及兩套系統意見不一致時由誰負責計畫。

三個權責決策能避免大部分的麻煩：

1. 指定每個物料群組和每個規劃期間由哪個工具規劃，並寫進設計中。
2. 指定由誰解決 IBP 供應計畫與 S/4HANA 排程之間的衝突。
3. 為規劃工具所使用的每個主檔資料領域指定一位負責人。

規劃設計也會影響財務。計畫訂單、生產版本和產能驅動產品成本計算與存貨評價。我看到製造業 ERP 專案失敗最常見的原因，是設計沒有被完整地談定，特別是在財務方面，所以請及早讓財務主管參與規劃設計。

## 從哪裡開始

從您已經有的計畫開始。在乾淨的主檔資料上執行 MRP Live，衡量生管人員在哪裡推翻它，並在 pMRP 中測試中期產能。

如果推翻集中在少數幾個資源上，就只針對那些資源界定 PP/DS 的範圍。如果集中在工廠、通路或部門之間的決策上，那就是 IBP 的議題，而它要從規劃流程開始談，而不是從軟體開始。

對國防與航太的規劃來說，合約成本計算和專案系統對設計的影響，通常不亞於規劃引擎。我的[國防製造業 ERP](/zh-TW/erp-for-defence-manufacturing/) 指南說明了這一面。如果您希望有人對您的工廠實際需要哪一個規劃層提供第二意見，歡迎[與我討論您的 SAP 專案](/zh-TW/contact-noel-erp-support/)。

## 常見問題

<details>
<summary>MRP Live 和 PP/DS 有什麼不同？</summary>

MRP Live 以無限產能規劃要生產和採購什麼，以及什麼時候。內嵌式 PP/DS 以有限產能，搭配整備和順序邏輯，為瓶頸資源上的關鍵物料排程。

兩者都在 S/4HANA 內執行。標記為進階規劃的物料交給 PP/DS，其餘留在 MRP Live。

</details>

<details>
<summary>PP/DS 和 IBP 有什麼不同？</summary>

PP/DS 在 S/4HANA 內，以數小時到數週為範圍為工廠排程。SAP IBP 是獨立的雲端產品，以數週到數年為範圍，跨工廠和通路規劃需求、庫存與供應。

它們回答不同的問題，有些製造商兩者都用：IBP 做網路計畫，PP/DS 處理限制產出的生產線。

</details>

<details>
<summary>SAP IBP 會取代 S/4HANA 中的 MRP 嗎？</summary>

不會。IBP 在網路層級規劃，再把計畫傳回 S/4HANA。仍然要由 MRP Live 或 PP/DS 把這些計畫轉成工廠可以執行的計畫訂單和採購申請。

</details>

<details>
<summary>S/4HANA 中還能使用傳統 MRP 嗎？</summary>

可以。SAP 的學習內容確認傳統規劃模式仍然可用，而 MRP Live（MD01N）是建議的執行方式。SAP Knowledge Base Article 2640393 列出了兩者的差異，請對照您的批量程序和 MRP 類型確認。

</details>

<details>
<summary>有了 MRP Live，還需要 PP/DS 嗎？</summary>

只有在有限產能會影響您的產出時才需要。如果生管人員一直在手動重排瓶頸生產線的排程，或換線決定成本，PP/DS 就值得評估。如果產能很少成為限制，搭配產能評估的 MRP Live 通常就夠了。

</details>

<summary>SAP S/4HANA 中的 pMRP 是什麼？</summary>

預測性物料與資源規劃（pMRP）是 S/4HANA 中的模擬工具，用來在簡化的計畫上及早發現產能問題。SAP 將它描述為 ECC 中長期規劃的後繼者。在生管人員發布之前，模擬不會改變作業中的 MRP。
