RISE with SAP public cloud उन कंपनियों के लिए सही है जिनकी प्रक्रियाएँ standard हैं और जिन्हें बहुत खास configuration नहीं चाहिए। Private cloud उन कंपनियों के लिए सही है जिनकी प्रक्रियाएँ industry-specific हैं, configuration गहरा है, या जिनके पास ऐसा ECC सिस्टम है जिसे वे दोबारा बनाने के बजाय convert करना चाहती हैं।

Public edition आपको SAP की best practices, साल में दो बार SAP द्वारा managed upgrades देता है और SAP code में कोई बदलाव नहीं होने देता। Private edition पूरा configuration, सभी industries और brownfield रास्ता रखता है।

छोटा जवाब: अगर आप SAP के standard पर चल सकते हैं, तो public चुनिए। अगर नहीं चल सकते, या आपको पक्का नहीं पता, तो sign करने से पहले private को गहराई से देखिए।

यह लेख मेरी [ECC से S/4HANA माइग्रेशन गाइड](/hi/ecc-to-s4hana-migration/) की एक कड़ी है। RISE contract में क्या-क्या शामिल होता है, इसके लिए मेरा [RISE with SAP overview](/hi/sap-implementation/rise-with-sap/) पढ़िए। यहाँ मैं सिर्फ edition के फ़ैसले की बात करता हूँ।

## RISE, GROW, public और private: 2026 में नाम

नाम 2025 में बदले, और search में अब भी पुराने नाम ही छाए हुए हैं। अक्टूबर 2026 में स्थिति यह है:

1. **SAP Cloud ERP** SAP के cloud ERP का marketing नाम है। इसका मूल application अब भी SAP S/4HANA Cloud Public Edition कहलाता है, और SAP के अपने blogs अब "SAP Cloud ERP Public Edition" लिखते हैं।
2. **SAP Cloud ERP Private** private cloud product है, जिसे ज़्यादातर लोग अब भी SAP S/4HANA Cloud Private Edition के नाम से खोजते हैं।
3. **RISE with SAP** मौजूदा SAP ग्राहकों के लिए transformation offer है।
4. **SAP GROW**, जिसे ज़्यादातर लोग अब भी GROW with SAP कहते हैं, SAP में नई कंपनियों के लिए offer है।

ज़्यादातर लेख जिस बात में गलती करते हैं: RISE, private cloud का पर्याय नहीं है। अपने [SAP GROW page](https://www.sap.com/products/erp/grow.html) पर SAP कहता है कि RISE with SAP के मूल में SAP Cloud ERP या SAP Cloud ERP Private हो सकता है। GROW, public edition पर बना है।

इसलिए "RISE public या private" एक असली विकल्प है। Commercial wrapper और edition दो अलग फ़ैसले हैं, और edition का फ़ैसला आपको पहले करना चाहिए।

## Public बनाम private cloud S/4HANA: हर edition क्या देता है

SAP, SAP Help Portal पर [public, private और on-premise editions की offering comparison](https://help.sap.com/docs/SAP_S4HANA_CLOUD_PE/b89b8b9026e1456bb2a1df7c0d59c937/1485d139460246d2a4b936c0bb0ca272.html) प्रकाशित करता है। यह table उन हिस्सों का सार है जो ज़्यादातर मामलों का फ़ैसला करते हैं, अक्टूबर 2026 में जाँचा गया:

| क्षेत्र | Public edition (SAP Cloud ERP) | Private edition (SAP Cloud ERP Private) |
|---|---|---|
| आप वहाँ कैसे पहुँचते हैं | सिर्फ नया implementation | नया implementation, system conversion, selective data transition, या lift and shift |
| Configuration | SAP Central Business Configuration | Customizing तक पूरी पहुँच |
| Extensibility | Key user (in-app), ABAP Cloud के साथ developer extensibility, SAP BTP पर side-by-side | सभी extensibility विकल्प |
| SAP code में बदलाव | संभव नहीं | संभव, हालाँकि SAP इसकी सलाह नहीं देता |
| Upgrades | साल में दो, फ़रवरी और अगस्त में, SAP द्वारा managed | हर दो साल में नया release, उसके पहले दो सालों में हर छह महीने में feature packs, आपके कहने पर SAP install करता है |
| Maintenance | आप हमेशा मौजूदा release पर चलते हैं | हर release के लिए सात साल; maintenance में बने रहने के लिए आपको upgrades की योजना बनानी होगी |
| Industries | Consumer products, discrete manufacturing, energy और natural resources, financial services, public services, service industries | सभी industries |
| Add-ons | सिर्फ public edition के लिए qualified add-ons | S/4HANA के लिए qualified add-ons |
| Hosting | SAP data centres या hyperscalers | Hyperscaler, SAP data centre, private data centre या sovereign cloud |

तीन पंक्तियाँ ज़्यादातर मामलों का फ़ैसला करती हैं: configuration, industries और आप वहाँ कैसे पहुँचते हैं।

Central Business Configuration, SAP की best practices को scope करके और फिर उनके भीतर settings बदलकर काम करता है। आपको वह पूरा Customizing tree नहीं मिलता जिसे ECC टीमें जानती हैं। अगर आपका finance, pricing या logistics डिज़ाइन उस tree की गहराई की settings पर टिका है, तो public edition में वे नहीं होंगी।

Industry वाली पंक्ति एक scope का बयान है, marketing list नहीं। अगर आपकी मूल प्रक्रिया public edition की list से बाहर की किसी industry की है, तो किसी और सवाल से पहले ही आप private edition के इलाके में हैं।

Upgrade वाली पंक्ति वह है जिसे CFOs कम आँकते हैं। [Public edition के लिए SAP के upgrade schedule](https://community.sap.com/t5/enterprise-resource-planning-blog-posts-by-sap/getting-ready-for-the-2608-upgrade-of-the-sap-cloud-erp-public-edition/ba-p/14421165) ने three-system landscape वाले ग्राहकों के लिए 2608 production upgrade को 15 और 16 अगस्त 2026 पर रखा। वह तारीख SAP ने तय की, ग्राहक ने नहीं।

## मेरा नियम: standard प्रक्रियाएँ public cloud पर जाती हैं

मेरा नियम छोटा है। जिन standard प्रक्रियाओं को बहुत खास configuration नहीं चाहिए, वे public cloud पर जा सकती हैं।

बाकी सब को ज़्यादा गहराई से देखना होगा। किसी के public cloud के लिए sign करने से पहले मैं ये संकेत जाँचूँगा:

1. **Industry fit.** आपका मूल business public edition की supported industries से बाहर है।
2. **Configuration की गहराई.** Pricing, revenue, costing या settlement का logic ऐसे configuration पर टिका है जिसे कोई fit-to-standard workshop SAP की best practices से map नहीं कर सकती।
3. **Add-ons.** आप किसी ऐसे SAP या partner add-on पर निर्भर हैं जो public edition के लिए qualified नहीं है।
4. **Process ownership.** Business किसी प्रक्रिया को standard के हिसाब से बदलने को तैयार नहीं है, और अधिकार वाला कोई व्यक्ति यह फ़ैसला नहीं लेगा।
5. **History.** आप ECC को उसकी history और configuration के साथ convert करना चाहते हैं, दोबारा implement करके डेटा load करने के बजाय।

अकेला एक संकेत बातचीत का विषय है। दो या ज़्यादा हों, तो मैं उम्मीद करूँगा कि जवाब private edition होगा।

मैंने entertainment industry की एक कंपनी को public cloud चुनते और पछताते देखा है। उसकी ज़रूरतें standard नहीं थीं, और public cloud उसके लिए गलत चुनाव था।

सबक यह नहीं है कि public cloud कमज़ोर है। जिन businesses के लिए इसे बनाया गया, उनके लिए यह अच्छा काम करता है। सबक यह है कि fit की जाँच contract से पहले होनी चाहिए, Explore के दौरान नहीं।

उल्टी गलती से भी सावधान रहिए। ज़्यादातर standard प्रक्रियाओं वाली कोई कंपनी private cloud इसलिए चुनती है क्योंकि वह ज़्यादा सुरक्षित लगता है, फिर उसमें ECC की पुरानी आदतें दोबारा बना लेती है। वे उस लचीलेपन के लिए पैसा देते हैं जिसकी उन्हें ज़रूरत नहीं थी, और ऐसा custom code ढोते हैं जिसका बचाव उन्हें हर upgrade पर करना पड़ेगा।

## Clean core और upgrades: वह समझौता जिस पर आप sign करते हैं

Clean core का मतलब है customisations को न्यूनतम रखना और उन पर अच्छी governance रखना। Edition तय करता है कि इसे लागू कौन करवाता है।

Public edition में सिस्टम इसे लागू करवाता है। नए developments सिर्फ ABAP Cloud और released interfaces का इस्तेमाल करते हैं, और आप SAP code को modify नहीं कर सकते। मेरी [SAP clean core गाइड](/hi/sap-clean-core-strategy-what-it-means-for-your-business/) extension levels को विस्तार से समझाती है।

Private edition में clean core एक governance फ़ैसला है। आप अब भी core को modify कर सकते हैं, और हर modification एक लागत है जिसे आप हर upgrade में साथ ले जाते हैं।

इसीलिए, आप कोई भी edition चुनें, मैं हर exception की ज़िम्मेदारी business और IT की एक design authority को दूँगा। अकेला IT हर उस चीज़ को मंज़ूरी दे देगा जो तकनीकी रूप से संभव है। अकेला business अपनी पुरानी प्रक्रिया वापस माँगेगा।

Clean core की जो सबसे आम गलती मैं देखता हूँ, वह है SAP को Oracle की तरह चलाने की कोशिश। टीमें SAP की standard प्रक्रिया अपनाने के बजाय किसी दूसरे सिस्टम का logic custom code में दोबारा बना देती हैं। Public edition में यह डिज़ाइन के समय ही विफल हो जाता है, और उसे पकड़ने की वही सस्ती जगह है।

Upgrade का समझौता भी इसी logic पर चलता है।

- **Public edition.** आप हमेशा मौजूदा release पर चलते हैं और साल में दो बार नई features पाते हैं। आप साल में दो बार test भी करते हैं, SAP के कैलेंडर पर, चाहे आपका business year-end close के बीच में हो या नहीं।
- **Private edition.** आप maintenance window के भीतर तय करते हैं कि कब upgrade करना है। यह आज़ादी तभी कुछ काम की है जब आप उसका इस्तेमाल करें, क्योंकि जो private edition सिस्टम कभी upgrade नहीं होता, वह cloud invoice वाला एक ECC सिस्टम ही है।

## ECC माइग्रेशन के लिए edition के चुनाव का क्या मतलब है

ECC ग्राहक के लिए edition ही माइग्रेशन का रास्ता तय करता है। Public edition हमेशा एक नया implementation होता है: configuration और प्रक्रियाएँ SAP की best practices पर दोबारा बनती हैं, और सिर्फ business डेटा जाता है। Private edition उन system conversion और selective data transition रास्तों को सपोर्ट करता है जिनका ज़िक्र मेरी माइग्रेशन गाइड में है।

मेरे अनुभव में public edition पर GROW with SAP प्रोजेक्ट में लगभग 6 से 9 महीने लगते हैं। RISE with SAP प्रोग्राम में 9 से 18 महीने लगते हैं, जो ज़्यादातर रास्ते और custom code पर निर्भर करता है। मेरा [S/4HANA माइग्रेशन timeline और प्रोजेक्ट प्लान](/hi/s4hana-migration-timeline-project-plan/) इसे चरण दर चरण खोलकर बताता है।

Two-tier model एक वैध बीच का रास्ता है। SAP ऐसी customer stories प्रकाशित करता है जहाँ parent कंपनी private edition पर चलती है और subsidiaries public edition पर, आपस में integrated। यह तब काम करता है जब subsidiaries सच में standard हों, और यह integration का ऐसा काम जोड़ता है जिसकी ज़िम्मेदारी आपको लेनी होगी।

Edition commercial बातचीत को भी बदलता है। Subscription metrics, full user equivalent (FUE) sizing और हर package में क्या शामिल है, ये अलग होते हैं, और RISE deals में जो जाल मैं सबसे ज़्यादा देखता हूँ वे हैं renewal की शर्तें, FUE sizing और AI credits। [RISE with SAP contract और pricing](/hi/rise-with-sap-contract-pricing/) पर मेरी गाइड बताती है कि क्या negotiate करना है।

Sign करने से पहले मैं SAP और आपके partner से ये सवाल पूछूँगा:

1. हमारी कौन सी end-to-end प्रक्रियाएँ आज public edition के scope में आती हैं, और कौन सी सिर्फ roadmap पर हैं?
2. हमारे कौन से add-ons उस edition के लिए qualified हैं जिसका आप प्रस्ताव दे रहे हैं?
3. हमारे मौजूदा configurations में से किनका Central Business Configuration में कोई समकक्ष नहीं है?
4. हमारे year-end close और peak season के सामने upgrade कैलेंडर कैसा दिखता है?
5. अगर हम public edition से शुरू करें और उससे आगे निकल जाएँ, तो रास्ता क्या है, और क्या वह एक नया प्रोजेक्ट है?
6. हमें हमारे business का high-level डिज़ाइन दिखाइए, editions की कोई generic तुलना नहीं।

आखिरी सवाल सबसे ज़्यादा मायने रखता है। जो partner generic जानकारी से जवाब देता है, वह इस चुनाव पर आपको सलाह देने के लिए तैयार नहीं है। [S/4HANA माइग्रेशन partner चुनने](/hi/choose-s4hana-migration-partner/) पर मेरी गाइड उस बातचीत का बाकी हिस्सा कवर करती है।

## मैं आगे क्या करूँगा

अपनी शीर्ष 20 business प्रक्रियाएँ लीजिए और हर एक को standard, configuration के साथ standard, या specific के रूप में चिह्नित कीजिए। यह process owners के साथ कमरे में बैठकर कीजिए, किसी slide से नहीं।

अगर लगभग सब कुछ standard है, तो public edition का proposal और अपने असली डेटा पर एक fit-to-standard workshop माँगिए। अगर कई मूल प्रक्रियाएँ specific हैं, या आप ECC को convert करना चाहते हैं, तो private edition माँगिए और पहले दिन से clean core governance की योजना बनाइए। मेरा मुफ़्त [greenfield बनाम brownfield माइग्रेशन assessment](/hi/sap-s4hana-migration-strategy-greenfield-vs-brownfield/) रास्ते के सवाल में मदद करता है।

मैं संगठनों को यह फ़ैसला contract के तय कर देने से पहले लेने में मदद करता हूँ। अगर आप एक स्वतंत्र राय चाहते हैं, तो [संपर्क कीजिए](/hi/contact-noel-erp-support/)।

## अक्सर पूछे जाने वाले सवाल

<details>
<summary>RISE with SAP public cloud है या private cloud?</summary>

यह दोनों में से कोई भी हो सकता है। SAP कहता है कि RISE with SAP के मूल में SAP Cloud ERP, यानी public edition, या SAP Cloud ERP Private हो सकता है। जटिल प्रक्रियाओं वाले ज़्यादातर ECC ग्राहक private चुनते हैं, लेकिन RISE अपने आप में edition तय नहीं करता।

</details>

<details>
<summary>S/4HANA Cloud public और private edition में क्या अंतर है?</summary>

Public edition SaaS है, SAP की best practices, SAP Central Business Configuration, साल में SAP द्वारा managed दो upgrades के साथ और SAP code में कोई बदलाव नहीं। Private edition Customizing तक पूरी पहुँच, सभी industries, सभी extensibility विकल्प और ECC से system conversion देता है। इसमें हर दो साल में नया release आता है, हर release के लिए सात साल के maintenance के साथ।

</details>

<details>
<summary>क्या SAP Cloud ERP और S/4HANA Cloud Public Edition एक ही हैं?</summary>

व्यवहार में, हाँ। SAP अपने cloud ERP को SAP Cloud ERP के नाम से बेचता है, और SAP S/4HANA Cloud Public Edition उसका मूल application है। Private product अब SAP Cloud ERP Private कहलाता है, जिसे ज़्यादातर लोग अब भी S/4HANA Cloud Private Edition के नाम से जानते हैं।

</details>

<details>
<summary>क्या मैं SAP ECC को S/4HANA Cloud Public Edition में convert कर सकता हूँ?</summary>

नहीं। Public edition सिर्फ नए implementation को सपोर्ट करता है, इसलिए आप प्रक्रियाओं को SAP की best practices पर दोबारा बनाते हैं और business डेटा migrate करते हैं। ECC से system conversion और selective data transition सिर्फ private edition और on-premise के लिए उपलब्ध हैं।

</details>

<details>
<summary>क्या S/4HANA Cloud Private Edition में SAP code को modify किया जा सकता है?</summary>

हाँ। SAP, private edition में modifications को संभव लेकिन अनुशंसित नहीं बताता। हर modification भविष्य के upgrades में प्रयास जोड़ता है, इसलिए मैं हर एक को business और IT की design authority से गुज़ारूँगा और दर्ज करूँगा कि वह क्यों मौजूद है।

</details>

<details>
<summary>किन कंपनियों को SAP public cloud ERP चुनना चाहिए?</summary>

वे कंपनियाँ जिनकी प्रक्रियाएँ standard हैं और जिन्हें बहुत खास configuration नहीं चाहिए, जो ऐसी industry में हैं जिसे public edition सपोर्ट करता है, और जो SAP की best practices अपनाने को तैयार हैं। Industry-specific प्रक्रियाओं, गहरे configuration या convert किए जाने वाले ECC सिस्टम वाली कंपनियों के लिए आमतौर पर private edition बेहतर बैठता है।

</details>
