RISE with SAP 公有雲適合流程標準、不需要非常特殊設定的企業。私有雲適合有產業特定流程、深度設定，或想轉換而不是重建 ECC 系統的企業。

Public Edition 提供 SAP 的最佳實務、每年兩次由 SAP 管理的升級，而且不能修改 SAP 程式碼。Private Edition 保留完整的設定、所有產業與 Brownfield 路徑。

簡短的答案：如果您能依照 SAP 的標準運作，就選公有雲。如果不能，或者您不確定，在簽約之前請仔細審視私有雲。

本文是我的 [ECC 移轉至 S/4HANA 指南](/zh-TW/ecc-to-s4hana-migration/)的其中一篇延伸文章。RISE 合約包含哪些內容，請閱讀我的 [RISE with SAP 概覽](/zh-TW/sap-implementation/rise-with-sap/)。這裡只討論版本的選擇。

## RISE、GROW、公有雲與私有雲：2026 年的名稱

這些名稱在 2025 年改變了，而舊名稱仍主導搜尋結果。以下是截至 2026 年 10 月的情況：

1. **SAP Cloud ERP** 是 SAP 雲端 ERP 的行銷名稱。它的核心應用程式仍叫 SAP S/4HANA Cloud Public Edition，而 SAP 自己的部落格現在寫作「SAP Cloud ERP Public Edition」。
2. **SAP Cloud ERP Private** 是私有雲產品，大多數人仍以 SAP S/4HANA Cloud Private Edition 搜尋它。
3. **RISE with SAP** 是針對現有 SAP 客戶的轉型方案。
4. **SAP GROW**，大多數人仍稱為 GROW with SAP，是針對新 SAP 客戶的方案。

大多數文章搞錯的一點：RISE 不是私有雲的同義詞。在 [SAP GROW 頁面](https://www.sap.com/products/erp/grow.html)上，SAP 表示 RISE with SAP 的核心可以是 SAP Cloud ERP 或 SAP Cloud ERP Private。GROW 則建立在 Public Edition 上。

所以「RISE 選公有雲還是私有雲」是一個真實的選擇。商業包裝與版本是兩個獨立的決策，而您應該先決定版本。

## S/4HANA 公有雲與私有雲：每個版本允許什麼

SAP 在 SAP Help Portal 上公布了 [Public、Private 與地端版本的方案比較](https://help.sap.com/docs/SAP_S4HANA_CLOUD_PE/b89b8b9026e1456bb2a1df7c0d59c937/1485d139460246d2a4b936c0bb0ca272.html)。下表整理了決定大多數情況的部分，於 2026 年 10 月查核：

| 領域 | Public Edition（SAP Cloud ERP） | Private Edition（SAP Cloud ERP Private） |
|---|---|---|
| 如何到達 | 只能全新導入 | 全新導入、系統轉換、選擇性資料轉換，或原樣搬遷（lift and shift） |
| 設定 | SAP Central Business Configuration | 完整存取客製化設定（Customizing） |
| 擴充 | 關鍵使用者擴充（應用程式內）、使用 ABAP Cloud 的開發人員擴充、在 SAP BTP 上的並行擴充 | 所有擴充選項 |
| 修改 SAP 程式碼 | 不可以 | 可以，但 SAP 不建議 |
| 升級 | 每年兩次，2 月與 8 月，由 SAP 管理 | 每兩年一個新版本，前兩年每六個月一個功能套件，依您的要求由 SAP 安裝 |
| 維護 | 您永遠執行目前的版本 | 每個版本七年；您必須規劃升級才能維持在維護期內 |
| 產業 | 消費品、離散製造、能源與天然資源、金融服務、公共服務、服務業 | 所有產業 |
| 附加元件 | 只能使用通過 Public Edition 認證的附加元件 | 通過 S/4HANA 認證的附加元件 |
| 代管 | SAP 資料中心或超大規模雲端業者 | 超大規模雲端業者、SAP 資料中心、私有資料中心或主權雲 |

決定大多數情況的是三列：設定、產業與如何到達。

Central Business Configuration 的運作方式，是先界定 SAP 最佳實務的範圍，再在其中調整設定。您拿不到 ECC 團隊熟悉的完整客製化設定樹。如果您的財務、定價或物流設計依賴那棵樹深處的設定，Public Edition 不會有這些設定。

產業這一列是範圍聲明，不是行銷清單。如果您的核心流程屬於 Public Edition 清單以外的產業，那麼在其他問題之前，您就已經進入 Private Edition 的範疇了。

升級這一列是財務長最常低估的。[Public Edition 的 SAP 升級時程](https://community.sap.com/t5/enterprise-resource-planning-blog-posts-by-sap/getting-ready-for-the-2608-upgrade-of-the-sap-cloud-erp-public-edition/ba-p/14421165)把三系統環境客戶的 2608 正式環境升級，排在 2026 年 8 月 15 日與 16 日。這個日期是 SAP 訂的，不是客戶。

## 我的原則：標準流程上公有雲

我的原則很簡短。不需要非常特殊設定的標準流程，可以上公有雲。

其他的都需要更仔細地審視。在任何人簽下公有雲之前，我會先檢查以下訊號：

1. **產業適配。**您的核心業務不在 Public Edition 支援的產業內。
2. **設定深度。**定價、收入、成本計算或結算邏輯所依賴的設定，無法在 Fit-to-Standard 工作坊中對應到 SAP 的最佳實務。
3. **附加元件。**您依賴某個沒有通過 Public Edition 認證的 SAP 或合作夥伴附加元件。
4. **流程負責。**業務單位不願意為了配合標準而改變流程，也沒有握有權限的人會要求他們改。
5. **歷史資料。**您想連同歷史資料與設定一起轉換 ECC，而不是重新導入再載入資料。

單一個訊號值得討論。出現兩個以上，我會預期答案是 Private Edition。

我看過一家娛樂產業的公司選了公有雲，後來後悔了。它的需求並不標準，公有雲對它來說是錯誤的選擇。

教訓不是公有雲不好。對於它所設計服務的企業，它運作得很好。教訓是適配性檢查必須在簽約之前完成，而不是在 Explore 階段。

也要留意相反的錯誤。一家流程大多標準的公司，因為覺得比較安全而選了私有雲，然後在裡面重建 ECC 的習慣。他們為自己不需要的彈性付費，還背著每次升級都要捍衛的客製程式碼。

## Clean Core 與升級：您簽下的取捨

Clean Core 代表把客製化降到最低，並妥善治理。版本決定由誰來強制執行。

在 Public Edition 中，由系統強制執行。新的開發只能使用 ABAP Cloud 與已發布的介面，而且您不能修改 SAP 程式碼。我的 [SAP Clean Core 指南](/zh-TW/sap-clean-core-strategy-what-it-means-for-your-business/)詳細說明各個擴充層級。

在 Private Edition 中，Clean Core 是一項治理決策。您仍然可以修改核心，而每一項修改都是您在每次升級時要背負的成本。

這就是為什麼無論您選哪個版本，我都會讓一個由業務與 IT 組成的設計權責單位負責每一個例外。只有 IT 的話，任何技術上可行的東西都會被核准。只有業務的話，他們會要回舊流程。

我最常看到的 Clean Core 錯誤，是試圖讓 SAP 像 Oracle 一樣運作。團隊用客製程式碼重建另一套系統的邏輯，而不是採用 SAP 的標準流程。在 Public Edition 中，這在設計階段就會失敗，而那是發現它代價較低的地方。

升級的取捨也是同樣的邏輯。

- **Public Edition。**您永遠執行目前的版本，每年取得兩次新功能。您也每年依照 SAP 的行事曆測試兩次，不管您的業務是否正處於年結之中。
- **Private Edition。**您可以在維護期內選擇何時升級。這份自由只有在您使用它時才有價值，因為一套從不升級的 Private Edition 系統，就是一套附帶雲端帳單的 ECC 系統。

## 版本選擇對 ECC 移轉的意義

對 ECC 客戶來說，版本決定移轉路徑。Public Edition 一定是全新導入：設定與流程依照 SAP 的最佳實務重建，只移轉業務資料。Private Edition 支援我在移轉指南中說明的系統轉換與選擇性資料轉換路徑。

依我的經驗，在 Public Edition 上的 GROW with SAP 專案大約需要 6 至 9 個月。RISE with SAP 計畫需要 9 至 18 個月，主要取決於路徑與客製程式碼。我的 [S/4HANA 移轉時程與專案計畫](/zh-TW/s4hana-migration-timeline-project-plan/)逐階段拆解這些時程。

雙層架構是一條可行的中間路線。SAP 公布過一些客戶案例，母公司使用 Private Edition，子公司使用 Public Edition，兩者整合在一起。當子公司真的很標準時，它行得通，但它會增加您必須自行負責的整合工作。

版本也會改變商業談判。訂閱計量方式、全職使用者約當數（FUE）的規模估算，以及每個方案包含的內容都不同，而我在 RISE 交易中最常看到的陷阱是續約條款、FUE 規模估算與 AI 點數。我的 [RISE with SAP 合約與定價](/zh-TW/rise-with-sap-contract-pricing/)指南說明要談判什麼。

在簽約之前，我會向 SAP 與您的合作夥伴提出這些問題：

1. 我們的端到端流程中，哪些目前在 Public Edition 的範圍內，哪些只在路線圖上？
2. 我們的附加元件中，哪些通過了您所提議版本的認證？
3. 我們目前的設定中，哪些在 Central Business Configuration 裡沒有對應項目？
4. 升級行事曆和我們的年結與旺季相比是什麼情況？
5. 如果我們從 Public Edition 開始，之後不敷使用，路徑是什麼，那會是一個新專案嗎？
6. 請針對我們的業務展示高階設計，而不是籠統的版本比較。

最後一個問題最重要。用籠統資訊回答的合作夥伴，還沒準備好在這個選擇上為您提供建議。我的[如何選擇 S/4HANA 移轉合作夥伴](/zh-TW/choose-s4hana-migration-partner/)指南涵蓋這段對話的其餘部分。

## 我接下來會怎麼做

拿出您最重要的 20 個業務流程，把每一個標記為標準、標準加設定，或特殊。請流程負責人在場一起做，而不是根據一張投影片。

如果幾乎所有流程都是標準的，請對方提出 Public Edition 的提案，並用您的真實資料進行 Fit-to-Standard 工作坊。如果有幾個核心流程是特殊的，或者您想轉換 ECC，請要求 Private Edition，並從第一天就規劃 Clean Core 治理。我免費的 [Greenfield 與 Brownfield 移轉評估](/zh-TW/sap-s4hana-migration-strategy-greenfield-vs-brownfield/)可以協助回答路徑的問題。

我協助企業在合約把事情定死之前做出這個決定。如果您想要獨立的觀點，[歡迎與我聯絡](/zh-TW/contact-noel-erp-support/)。

## 常見問題

<details>
<summary>RISE with SAP 是公有雲還是私有雲？</summary>

兩者都可以。SAP 表示，RISE with SAP 的核心可以是 SAP Cloud ERP（Public Edition）或 SAP Cloud ERP Private。大多數流程複雜的 ECC 客戶會選私有雲，但 RISE 本身並不決定版本。

</details>

<details>
<summary>S/4HANA Cloud Public Edition 與 Private Edition 有什麼差別？</summary>

Public Edition 是 SaaS，採用 SAP 的最佳實務與 SAP Central Business Configuration，每年由 SAP 管理兩次升級，而且不能修改 SAP 程式碼。Private Edition 提供完整的客製化設定存取、所有產業、所有擴充選項，以及從 ECC 進行系統轉換。它每兩年推出一個新版本，每個版本維護七年。

</details>

<details>
<summary>SAP Cloud ERP 等於 S/4HANA Cloud Public Edition 嗎？</summary>

實務上是的。SAP 以 SAP Cloud ERP 的名稱行銷其雲端 ERP，而 SAP S/4HANA Cloud Public Edition 是它的核心應用程式。私有雲產品現在叫 SAP Cloud ERP Private，大多數人仍稱它為 S/4HANA Cloud Private Edition。

</details>

<details>
<summary>可以把 SAP ECC 轉換到 S/4HANA Cloud Public Edition 嗎？</summary>

不行。Public Edition 只支援全新導入，所以您要依照 SAP 的最佳實務重建流程，並移轉業務資料。從 ECC 進行系統轉換與選擇性資料轉換，只適用於 Private Edition 與地端版本。

</details>

<details>
<summary>可以在 S/4HANA Cloud Private Edition 中修改 SAP 程式碼嗎？</summary>

可以。SAP 把修改列為 Private Edition 中可行但不建議的做法。每一項修改都會增加日後升級的工作量，所以我會讓每一項修改都經過由業務與 IT 組成的設計權責單位，並記錄它存在的理由。

</details>

<details>
<summary>哪些公司應該選擇 SAP 公有雲 ERP？</summary>

流程標準、不需要非常特殊的設定、所屬產業在 Public Edition 的支援範圍內，並且願意採用 SAP 最佳實務的公司。有產業特定流程、深度設定，或想轉換 ECC 系統的公司，通常更適合 Private Edition。

</details>
