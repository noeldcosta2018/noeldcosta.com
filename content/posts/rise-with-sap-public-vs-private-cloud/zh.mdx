RISE with SAP 公有云适合流程标准、不需要非常特殊配置的企业。私有云适合有行业特定流程、深度配置，或者有一套想要转换而不是重建的 ECC 系统的企业。

公有云版为您提供 SAP 最佳实践、每年两次由 SAP 管理的升级，并且不能修改 SAP 代码。私有云版保留完整配置、所有行业和棕地路径。

简短的回答：如果您能按照 SAP 的标准运行，就选公有云。如果不能，或者您不确定，在签约之前要认真考察私有云。

本文是我的 [ECC 到 S/4HANA 迁移指南](/zh-CN/ecc-to-s4hana-migration/)的一篇分支文章。想了解 RISE 合同打包了哪些内容，请读我的 [RISE with SAP 概述](/zh-CN/sap-implementation/rise-with-sap/)。这里我只讨论版本的选择。

## RISE、GROW、公有云和私有云：2026 年的名称

这些名称在 2025 年发生了变化，而旧名称仍然主导着搜索。截至 2026 年 10 月，情况如下：

1. **SAP Cloud ERP** 是 SAP 对其云 ERP 的营销名称。它的核心应用仍然叫 SAP S/4HANA Cloud Public Edition，SAP 自己的博客现在写作“SAP Cloud ERP Public Edition”。
2. **SAP Cloud ERP Private** 是私有云产品，大多数人仍以 SAP S/4HANA Cloud Private Edition 的名称搜索它。
3. **RISE with SAP** 是面向现有 SAP 客户的转型方案。
4. **SAP GROW**，大多数人仍称之为 GROW with SAP，是面向 SAP 新客户的方案。

大多数文章弄错的一点：RISE 不是私有云的同义词。在其 [SAP GROW 页面](https://www.sap.com/products/erp/grow.html)上，SAP 表示 RISE with SAP 的核心可以是 SAP Cloud ERP 或 SAP Cloud ERP Private。GROW 则构建在公有云版之上。

所以，“RISE 选公有云还是私有云”是一个真实存在的选择。商业包装和版本是两个独立的决定，您应该先做版本的决定。

## 公有云与私有云 S/4HANA：每个版本允许什么

SAP 在 SAP Help Portal 上发布了[公有云版、私有云版和本地部署版的产品对比](https://help.sap.com/docs/SAP_S4HANA_CLOUD_PE/b89b8b9026e1456bb2a1df7c0d59c937/1485d139460246d2a4b936c0bb0ca272.html)。下表概括了决定大多数情况的部分，于 2026 年 10 月核实：

| 领域 | 公有云版（SAP Cloud ERP） | 私有云版（SAP Cloud ERP Private） |
|---|---|---|
| 如何到达 | 仅限新实施 | 新实施、系统转换、选择性数据迁移或直接迁移（lift and shift） |
| 配置 | SAP Central Business Configuration | 完全访问 Customizing |
| 扩展性 | 关键用户（应用内）扩展、使用 ABAP Cloud 的开发人员扩展、基于 SAP BTP 的旁路扩展 | 所有扩展选项 |
| 修改 SAP 代码 | 不可能 | 可以，但 SAP 不建议 |
| 升级 | 每年两次，2 月和 8 月，由 SAP 管理 | 每两年发布一个新版本，在其前两年每六个月发布功能包，由 SAP 应您的要求安装 |
| 维护 | 您始终运行当前版本 | 每个版本维护七年；您必须规划升级才能保持在维护期内 |
| 行业 | 消费品、离散制造、能源与自然资源、金融服务、公共服务、服务行业 | 所有行业 |
| 附加组件 | 仅限获得公有云版认证的附加组件 | 获得 S/4HANA 认证的附加组件 |
| 托管 | SAP 数据中心或超大规模云服务商 | 超大规模云服务商、SAP 数据中心、私有数据中心或主权云 |

决定大多数情况的是三行：配置、行业，以及如何到达。

Central Business Configuration 的工作方式是先对 SAP 最佳实践进行范围界定，然后在其范围内调整设置。您得不到 ECC 团队熟悉的完整 Customizing 树。如果您的财务、定价或物流设计依赖于那棵树深处的设置，公有云版就不会提供它们。

行业这一行是范围声明，而不是营销清单。如果您的核心流程属于公有云版清单之外的行业，那么在考虑任何其他问题之前，您就已经进入了私有云版的范畴。

升级这一行是 CFO 最容易低估的。[公有云版的 SAP 升级日程](https://community.sap.com/t5/enterprise-resource-planning-blog-posts-by-sap/getting-ready-for-the-2608-upgrade-of-the-sap-cloud-erp-public-edition/ba-p/14421165)把三系统架构客户的 2608 生产升级定在 2026 年 8 月 15 日和 16 日。这个日期是 SAP 定的，不是客户定的。

## 我的原则：标准流程上公有云

我的原则很简短。不需要非常特殊配置的标准流程，可以上公有云。

其他一切都需要更仔细地审视。在任何人签约公有云之前，我会检查以下信号：

1. **行业匹配度。** 您的核心业务在公有云版支持的行业之外。
2. **配置深度。** 定价、收入、成本核算或结算逻辑依赖于 Fit-to-Standard 研讨会无法映射到 SAP 最佳实践的配置。
3. **附加组件。** 您依赖某个未获得公有云版认证的 SAP 或合作伙伴附加组件。
4. **流程所有权。** 业务不愿意改变流程来匹配标准，而有权做决定的人也不会推动它。
5. **历史数据。** 您希望连同历史数据和配置一起转换 ECC，而不是重新实施并加载数据。

单独出现一个信号，值得讨论。出现两个或更多，我会预期答案是私有云版。

我见过一家娱乐行业的公司选择了公有云，后来又后悔了。它的需求并不标准，公有云并不适合它。

教训并不是公有云不好。对于它所针对的业务，它运行得很好。教训是，匹配度检查必须在签合同之前进行，而不是在 Explore 阶段。

也要提防相反的错误。一家流程基本标准的公司因为觉得更安全而选了私有云，然后在其中重建 ECC 的旧习惯。他们为自己不需要的灵活性付费，还背上了每次升级都要为之辩护的自定义代码。

## Clean Core 与升级：您签下的取舍

Clean Core 意味着把定制化降到最低，并对其进行良好的治理。版本决定了由谁来强制执行。

在公有云版中，由系统强制执行。新开发只能使用 ABAP Cloud 和已发布的接口，您不能修改 SAP 代码。我的 [SAP Clean Core 指南](/zh-CN/sap-clean-core-strategy-what-it-means-for-your-business/)详细讲解了各个扩展层级。

在私有云版中，Clean Core 是一项治理决策。您仍然可以修改核心，而每一次修改都是您在每次升级中都要背负的成本。

这就是为什么无论您选择哪个版本，我都会让一个由业务和 IT 组成的设计委员会负责每一个例外。只有 IT，会批准任何技术上可行的东西。只有业务，会要求恢复原来的流程。

我见过最常见的 Clean Core 错误，是试图让 SAP 像 Oracle 一样工作。团队用自定义代码重建另一个系统的逻辑，而不是采用 SAP 的标准流程。在公有云版中，这在设计阶段就会失败，而那正是发现问题成本更低的地方。

升级上的取舍遵循同样的逻辑。

- **公有云版。** 您始终运行当前版本，每年获得两次新功能。您每年也要测试两次，按照 SAP 的日历，不管您的业务是否正处于年结之中。
- **私有云版。** 您可以在维护窗口内选择何时升级。这种自由只有在您使用它时才有价值，因为一套从不升级的私有云版系统，就是一套收到云账单的 ECC 系统。

## 版本选择对 ECC 迁移意味着什么

对 ECC 客户来说，版本决定了迁移路径。公有云版始终是新实施：配置和流程在 SAP 最佳实践的基础上重建，只迁移业务数据。私有云版支持我在迁移指南中描述的系统转换和选择性数据迁移路径。

根据我的经验，基于公有云版的 GROW with SAP 项目大约需要 6 至 9 个月。RISE with SAP 项目需要 9 至 18 个月，主要取决于路径和自定义代码。我的 [S/4HANA 迁移时间线与项目计划](/zh-CN/s4hana-migration-timeline-project-plan/)逐阶段拆解了这些时间。

两层模式是一条可行的中间路线。SAP 发布过一些客户案例，母公司运行私有云版，子公司运行公有云版，两者集成。当子公司确实是标准业务时，这种模式行得通，但它会增加您必须自己负责的集成工作。

版本也会改变商务谈判。订阅指标、全用户当量（FUE）规模测算以及每个套餐包含的内容都不同，而我在 RISE 交易中最常见的陷阱是续约条款、FUE 规模测算和 AI 积分。我的 [RISE with SAP 合同与定价](/zh-CN/rise-with-sap-contract-pricing/)指南讲解了要谈判什么。

在签约之前，我会向 SAP 和您的合作伙伴提出以下问题：

1. 我们的哪些端到端流程目前在公有云版的范围之内，哪些只在路线图上？
2. 我们的哪些附加组件获得了您所建议版本的认证？
3. 我们当前的哪些配置在 Central Business Configuration 中没有对应项？
4. 升级日历与我们的年结和业务旺季相比是什么样的？
5. 如果我们从公有云版起步，后来业务超出了它的能力，路线是什么，是不是一个新项目？
6. 请给我们看针对我们业务的概要设计，而不是一份笼统的版本对比。

最后一个问题最重要。用笼统信息作答的合作伙伴，还没有准备好就这个选择为您提供建议。我的[如何选择 S/4HANA 迁移合作伙伴](/zh-CN/choose-s4hana-migration-partner/)指南讲解了这场对话的其余部分。

## 我接下来会怎么做

拿出您最重要的 20 个业务流程，把每一个标记为标准、标准加配置或特殊。要让流程负责人在场一起做，而不是照着幻灯片来做。

如果几乎所有流程都是标准的，就请对方提供公有云版方案，并基于您的真实数据举办一次 Fit-to-Standard 研讨会。如果有几个核心流程是特殊的，或者您想转换 ECC，就请对方提供私有云版方案，并从第一天起规划 Clean Core 治理。我免费的[绿地与棕地迁移评估](/zh-CN/sap-s4hana-migration-strategy-greenfield-vs-brownfield/)可以帮助您回答路径问题。

## 常见问题

<details>
<summary>RISE with SAP 是公有云还是私有云？</summary>

两者都可以。SAP 表示，RISE with SAP 的核心可以是公有云版 SAP Cloud ERP，也可以是 SAP Cloud ERP Private。大多数流程复杂的 ECC 客户选择私有云，但 RISE 本身并不决定版本。

</details>

<details>
<summary>S/4HANA Cloud 公有云版和私有云版有什么区别？</summary>

公有云版是 SaaS，提供 SAP 最佳实践、SAP Central Business Configuration、每年两次由 SAP 管理的升级，并且不能修改 SAP 代码。私有云版提供对 Customizing 的完全访问、所有行业、所有扩展选项以及从 ECC 的系统转换。它每两年发布一个新版本，每个版本维护七年。

</details>

<details>
<summary>SAP Cloud ERP 和 S/4HANA Cloud Public Edition 是一回事吗？</summary>

实际上是的。SAP 以 SAP Cloud ERP 的名称销售其云 ERP，而 SAP S/4HANA Cloud Public Edition 是它的核心应用。私有云产品现在叫 SAP Cloud ERP Private，大多数人仍称它为 S/4HANA Cloud Private Edition。

</details>

<details>
<summary>可以把 SAP ECC 转换到 S/4HANA Cloud Public Edition 吗？</summary>

不可以。公有云版只支持新实施，所以您要在 SAP 最佳实践的基础上重建流程，并迁移业务数据。从 ECC 进行的系统转换和选择性数据迁移，只适用于私有云版和本地部署版。

</details>

<details>
<summary>在 S/4HANA Cloud Private Edition 中可以修改 SAP 代码吗？</summary>

可以。SAP 把修改列为在私有云版中可行但不建议。每一次修改都会增加未来升级的工作量，所以我会让每一项修改都经过由业务和 IT 组成的设计委员会，并记录它存在的原因。

</details>

<details>
<summary>哪些企业应该选择 SAP 公有云 ERP？</summary>

流程标准、不需要非常特殊配置、所处行业在公有云版支持范围内，并且愿意采用 SAP 最佳实践的企业。有行业特定流程、深度配置，或者有一套想要转换的 ECC 系统的企业，通常更适合私有云版。

</details>
