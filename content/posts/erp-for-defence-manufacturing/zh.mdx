最适合国防制造业的 ERP，是能按合同核算成本、开票和报告，并把工作作为项目来运行的那一套。车间功能排在第二位。

我在国防制造业实施过 ERP，最关键的领域是合同成本核算和项目系统（SAP Project System，PS）。把这两项做对，设计的其余部分就有了依托。做错了，财务就要花好几年手工对账。

如果要看覆盖所有制造类型的更广泛的厂商对比，请先看我的[制造业最佳 ERP](/zh-CN/best-erp-for-manufacturing/) 指南。本文讲的是当您的客户是国防部或总承包商时，有哪些不同。

## 国防制造业对 ERP 的要求

普通制造商按库存或按订单销售产品。国防制造商通常是按合同交付：一个工作计划，有自己的预算、里程碑、开票条款和报告义务。

这改变了 ERP 必须做的事情。在常规的生产、采购和库存之上，还有五项要求：

1. **合同成本核算。** 每一笔成本都必须落到正确的合同上，客户可能会审计它是如何落过去的。
2. **项目结构。** 工程、生产、测试和交付作为一个带阶段和里程碑的项目运行，而不是一堆互不相关的订单。
3. **序列号和配置追溯。** 您需要知道哪些组件、哪个版本，装进了哪一台已交付的产品。
4. **出口管制。** 受管制的物项和技术数据在发运之前需要分类、许可证和筛查。
5. **数据安全。** 谁可以看到哪份合同、哪张图纸或哪条客户记录，是一个设计问题，而不是事后才考虑的事。

大多数 ERP 系统都能做到这五项。它们之间的区别在于，有多少是标准功能，有多少需要您自己开发。

## 合同成本核算和项目系统放在首位

在我做过的国防项目中，合同成本核算和项目系统最为关键。设计中的其他一切，都取决于这两项是如何搭建的。

原因很简单。国防合同往往按自己的条款定价、开票和审计，财务要向客户报告合同情况。如果 ERP 无法按合同显示成本、收入和利润，财务控制人员每个月都得在电子表格里重做一遍。

### SAP 如何处理

在 SAP S/4HANA 中，一份合同通常建模为 SAP Project System 中的一个项目。工作分解结构（WBS）承载预算和成本收集对象。合同的销售订单行项目分配到 WBS 元素上，这样收入和成本就汇集在同一个地方。

开票方式取决于合同类型。固定价格合同通常按里程碑开票。

按已发生成本付款的合同可以使用资源相关开票。SAP 的[项目财务控制课程](https://learning.sap.com/courses/project-financials-control-in-sap-s-4hana/performing-resource-related-billing)把它描述为通过动态项目处理器（Dynamic Item Processor）按实际成本开票，并可与里程碑开票计划结合使用。

收入确认、在制品和利润报告随后都基于 WBS 运行。大部分设计工作量都在这里，因为它同时涉及管理会计（CO）、财务会计（FI）、销售与分销（SD）和生产计划（PP）。

设计之前要做一项检查：一些较早的 Project System 功能在 S/4HANA 中属于 SAP 的兼容性范围。在最近几个版本中，SAP 已把其中几项移入永久范围。请对照 SAP Note 2269324，确认您计划使用的每项功能的状态。

### 设计中要回答的问题

这些决策决定了任何 ERP 中的合同成本核算，而不仅仅是 SAP：

1. **系统中的一份合同是什么？** 每份合同一个项目、每个批次一个项目，还是每次交付批次一个项目。
2. **生产成本结算到哪里？** 生产订单结算到 WBS 元素，结算规则决定了合同报告显示什么。
3. **收入如何确认？** 按里程碑、按已发生成本还是按交付数量，以及这如何对应您的会计准则。
4. **间接费用如何分摊？** 客户可能会审计费率，所以这些费率必须能在系统中追溯。
5. **给客户的报告是什么样子？** 先设计报告，再倒推成本对象。

SAP 财务方面的内容，在我的 [SAP FICO 指南](/zh-CN/sap-fico/)中有更深入的介绍。为项目提供数据的生产订单、MRP 和计划周期，见我的 [SAP PP 指南](/zh-CN/sap-pp-production-planning/)。

## 追溯、合规和出口管制

第二组要求是证明您造了什么，以及您可以把它发给谁。这些是横跨多个系统的设计决策，每一项都需要一个唯一的负责人。

### 序列号和配置追溯

国防客户往往希望确切知道每一台已交付产品里装了什么：零件号、序列号、版本以及交付后所做的变更。在 SAP 中，序列号通过物料主数据上的序列号参数文件来控制，正如 SAP 的[序列号课程](https://learning.sap.com/courses/configuring-organizational-and-master-data-in-sap-s-4hana-service/configuring-and-creating-serial-numbers)所示。

仅有序列化并不能实现配置控制。工程结构通常存放在产品生命周期管理（PLM）系统中。

实际构建记录可能在车间采集，而 ERP 持有库存和成本。在开始配置之前，先决定由哪个系统负责设计构型、实际构建构型和维护构型的记录。

车间采集通常是制造执行系统（MES）的工作，例如位于 ERP 之上的 SAP Digital Manufacturing。我关于[制造业中的 ERP 与 MES](/zh-CN/erp-and-mes-manufacturing/) 的文章说明了这条界线在哪里。

### 出口管制和贸易合规

出口管制规则，例如美国的《国际武器贸易条例》（ITAR）和《出口管理条例》（EAR），适用于物项、技术数据和目的地。您的 ERP 需要知道每个物项如何分类，并拦截缺少许可证的发运。

在 SAP 中，这部分由 SAP Global Trade Services（GTS）负责。SAP 的 [GTS 学习内容](https://learning.sap.com/courses/exploring-the-principles-of-sap-governance-risk-and-compliance/describing-international-trade-requirement-processes_c4311e5d-9612-40b2-b990-a14c9e5ce4ff)描述了合规管理，涵盖法律管控、受制裁方名单筛查和禁运检查，并为需要许可证的程序提供许可证监控。

把出口管制当作一个独立的工作流，由独立的人签字确认。分类由您的贸易合规负责人决定，而不是 ERP 团队。

### 关于 SAP 国防行业命名的说明

SAP 在 S/4HANA 中销售一个 Defense & Security 解决方案，很容易让人以为它是给国防制造商用的。其实不是。SAP 的 [Defense & Security 课程](https://learning.sap.com/courses/exploring-organizational-flexibility-in-sap-s-4hana-defense-security)涵盖兵力单元、兵力结构、作战和演习，这是军队的世界。

国防制造商通常运行标准的 SAP S/4HANA 加 Project System，再加上贸易合规，以及按需使用的 PLM 和 MES。在签署许可之前，先确认您实际购买的是哪些行业功能。

## 为什么财务设计决定结果

我看到制造业 ERP 项目失败最常见的原因，是设计没有被整体确认，尤其是在财务方面。在国防制造业中，这个风险更高，因为设计中有很大一部分是合同财务。

它的发生方式是可以预见的。生产、供应链和工程各自确认了自己的设计。

财务签字确认了科目表和成本中心结构。却没有人签字确认从合同到 WBS、到生产订单、到结算、到收入、再到客户报告的完整流程。

缺口会在测试中暴露，更糟的是在第一次月结时暴露。到那时配置已经完成，每一处修复都是一个变更请求。

下面这个顺序能让设计保持完整：

<explainer-flow title="完整确认合同财务设计" caption="只有整个流程都签字确认，设计才算达成一致，而不是每个模块各自确认。" steps="合同类型|成本对象|结算|收入|客户报告|签字确认" notes="固定价格、按成本、混合|每份合同、每个批次或每次交付一个 WBS|生产订单结算到 WBS|按里程碑、已发生成本或数量|基于 WBS 生成，而不是电子表格|财务、项目和运营共同确认" result="开始构建前形成一份一致的设计"></explainer-flow>

计划与设计同样重要。在我领导或挽救过的 21 个 SAP 项目中，我看到的最大错误是一开始没有做好计划。随着报表、接口、转换、增强、表单和工作流（WRICEF）清单不断增长，预算在探索（Explore）阶段就被突破了。

有两个数字需要纳入计划。根据我的经验，数据迁移占工作量的 30% 到 40%，测试约占 35%。为未完结的合同，连同其成本、开票和历史记录，制定一份单独的迁移计划。

## 国防制造业选 SAP、IFS 还是 Infor

通常有三个系统会进入国防制造商的候选名单。哪一个合适，取决于您的规模、工作的项目驱动程度，以及您的客户和合作伙伴已经在用什么。

下表比较了各厂商针对该行业的定位。它基于厂商自己的资料，所以请在脚本化演示中用您的合同检验每一项说法。

| 系统 | 厂商的定位 | 通常适合的企业 | 演示中要测试什么 |
|---|---|---|---|
| SAP S/4HANA 加 Project System | 核心 ERP，并配有项目、合同开票和贸易合规（GTS） | 已经在用 SAP 的大型多工厂制造商、总承包商和供应商 | 从 WBS 到客户报告的合同成本核算；您需要的 PS 功能在兼容性范围中的状态 |
| IFS Cloud | 在 [ifs.com](https://www.ifs.com/en/industries/aerospace-and-defense/manufacturers) 上定位于航空航天和国防制造商，提供项目交付和合规 | 同时运营服务或维护业务的项目型、重资产制造商 | 项目会计的深度，以及制造和服务如何共享同一份记录 |
| Infor CloudSuite Aerospace & Defense | [Infor](https://www.infor.com/resources/cloudsuite-aerospace-defense-introduction) 将其描述为面向该行业的多公司 ERP，涵盖合规、质量和项目交付 | 希望使用行业专用云产品的中型供应商 | 合同成本报告、序列号追溯，以及多少是配置、多少是开发 |

无论您把谁列入候选名单，都请给厂商一份您真实的合同。请他们在自己的系统中先演示合同的建立、一笔成本的过账、一个里程碑的开票和利润的报告，然后再看其他任何东西。

关于 MRP 之上的 SAP 计划，我对 [MRP Live、PP/DS 与 IBP](/zh-CN/mrp-live-vs-pp-ds-vs-ibp/) 的对比说明了每个工具适合什么场景。

## 从哪里开始

国防 ERP 项目的成败在于合同成本核算，所以从这里开始。在任何厂商演示之前，写下您最常见的三种合同类型，以及今天每一种是如何核算成本、开票并向客户报告的。

这一页纸就会成为您的演示脚本，也是对每一个设计的第一次检验。它还会显示出您的财务团队眼下正在手工填补的缺口。

## 常见问题

<details>
<summary>国防制造业最好的 ERP 是什么？</summary>

能按合同核算成本、开票和报告，并把工作作为项目运行的那一套。SAP S/4HANA 加 Project System、IFS Cloud 和 Infor CloudSuite Aerospace & Defense 是常见的候选名单。在比较其他任何方面之前，先用您自己的合同类型测试每一个系统。

</details>

<details>
<summary>国防制造业 ERP 最重要的是什么？</summary>

合同成本核算和项目系统。在我做过的国防制造项目中，这是最关键的领域。如果 ERP 无法按合同显示成本、收入和利润，财务每个月都得在电子表格里重做一遍。

</details>

<details>
<summary>SAP Defense & Security 是给国防制造商用的吗？</summary>

不是。SAP 的 Defense & Security 解决方案涵盖兵力单元、兵力结构、作战和演习，面向的是军队组织。国防制造商通常运行标准的 SAP S/4HANA 加 Project System，再用 SAP Global Trade Services 处理出口管制。

</details>

<details>
<summary>SAP 如何为国防制造商处理出口管制？</summary>

通过 SAP Global Trade Services。它的合规管理涵盖法律管控、受制裁方名单筛查和禁运检查，并为需要许可证的程序提供许可证监控。产品分类应由您的贸易合规负责人负责，而不是 ERP 团队。

</details>

<details>
<summary>国防制造业 ERP 项目为什么会失败？</summary>

最常见的原因是设计没有被整体确认，尤其是在财务方面。每个模块各自确认自己的部分，却没有人确认从合同到项目、到生产订单、到收入、再到客户报告的完整流程。缺口随后会在测试中或第一次月结时暴露出来。

</details>

<details>
<summary>国防制造商除了 ERP 还需要 MES 吗？</summary>

当客户期望从车间获得完整的序列号和实际构建追溯时，通常需要。像 SAP Digital Manufacturing 这样的 MES 会记录每一步发生了什么，并把确认发回 ERP。在配置任何一方之前，先决定由哪个系统负责实际构建记录。

</details>
