SAP Universal ID ist ein kostenloser, persönlicher SAP-Account, der alle Ihre S-User- und P-User-IDs, Zertifikate und Ihre Reputation in der SAP Community bündelt und Sie von Job zu Job begleitet. Seit 2026 ist sie keine Anmeldung mehr: Sie melden sich mit der jeweiligen S-User- oder P-User-ID an, und Benutzer werden automatisch über die E-Mail-Adresse an sie angehängt.

> **Kurze Antwort.** Ein P-User ist Ihr eigener SAP-Benutzer. Ein S-User wird von einem Arbeitgeber oder Kunden unter dessen SAP-Kundennummer vergeben. SAP Universal ID ist die Brieftasche, die alle davon im SAP Account Manager unter account.sap.com auflistet.

Als ich neu bei SAP war, habe ich Wochen gebraucht, um P-User, S-User und deren Zusammenhänge zu verstehen. E-Mails zum Zurücksetzen des Passworts kamen jede Woche.

## S-User vs. P-User vs. Universal ID

Die Tabelle zeigt, wem welche ID gehört, wofür sie dient und was passiert, wenn Sie gehen.

| | P-User | S-User | SAP Universal ID |
|---|---|---|---|
| Wem sie gehört | Ihnen | Ihrem Arbeitgeber oder Kunden, unter dessen SAP-Kundennummer | Ihnen |
| Wer sie anlegt | Sie, durch Registrierung unter account.sap.com | Der Administrator dieses Unternehmens, in SAP for Me | Sie, unter account.sap.com |
| Wofür Sie sie nutzen | SAP Community, Testversionen, Inhalte für Entwickler, SAP Learning | Support-Fälle, Software-Downloads, Lizenzschlüssel, Systemdaten | Alle Ihre Benutzer auflisten, Zertifikate und Community-Reputation behalten |
| Können Sie sich damit anmelden? | Ja | Ja | Nein, seit Januar 2026 nicht mehr |
| Ablauf | Keiner | Standardmäßig 24 Monate, vom Administrator verlängerbar | Keiner |
| Wenn Sie ein Unternehmen verlassen | Nichts ändert sich | Der Administrator löscht ihn, oder er läuft ab | Sie behalten sie. Fügen Sie Ihre neue berufliche E-Mail-Adresse hinzu |

Mein P-User begleitet mich seit etwa 16 Jahren durch verschiedene Stellen. Ich hatte sechs verschiedene S-User, als ich zwischen Unternehmen gewechselt bin. In der Universal ID stehen sie alle in einer Liste.

## Was sich 2026 geändert hat

SAP hat in diesem Jahr zwei Änderungen vorgenommen. Die offiziellen Details stehen auf [SAPs Seite zur Universal ID](https://www.sap.com/account/universal-id.html).

<explainer-timeline title="Wie sich SAP Universal ID 2026 verändert hat" caption="Seit Juli werden Accounts über das Hinzufügen einer E-Mail-Adresse verknüpft. Eine Schaltfläche für manuelles Verknüpfen gibt es nicht mehr." items="Aug. 2025 => Für jeden Benutzer ein Passwort festlegen|20. Jan. 2026 => Universal ID ist keine Anmeldung mehr|13. Juli 2026 => Accounts werden über die E-Mail-Adresse verknüpft" notes="Gefordert von Benutzern mit mehreren verknüpften Identitäten, bis Januar 2026|Anmeldung mit der S-User- oder P-User-ID oder deren E-Mail-Adresse|Manuelles Verknüpfen entfernt. Verknüpfungen von vor Juli bleiben bestehen" highlight="3" source="SAP-Seite zur Universal ID, sap.com"></explainer-timeline>

1. **Januar 2026: Universal ID ist keine Anmeldung mehr.** Sie ist kein Identity-Provider mehr. Sie melden sich mit der S-User- oder P-User-ID oder der E-Mail-Adresse dieses Benutzers und dem Passwort dieses Benutzers an, über SAP Cloud Identity Services (SAP IAS).
2. **13. Juli 2026: Verknüpfung über die E-Mail-Adresse.** Die Optionen zum manuellen Verknüpfen und Trennen sowie die Spalte „Linked“ (Verknüpft) wurden entfernt. Jeder S-User oder P-User, dessen E-Mail-Adresse in Ihrer Universal ID registriert ist, wird automatisch angehängt, und alles, was Sie vor Juli von Hand verknüpft haben, bleibt verknüpft.

Bei keiner der beiden Änderungen wurden Accounts gelöscht. Wenn Sie die Aufforderung von 2025 übersprungen haben, für jeden Benutzer ein Passwort festzulegen, nutzen Sie bei diesem Benutzer „Forgot password“ (Passwort vergessen).

## So verwalten Sie Ihre SAP Universal ID Schritt für Schritt

Zwei Adressen sind hier wichtig, und sie werden leicht verwechselt. **account.sap.com** ist der SAP Account Manager, in dem Ihre Universal ID liegt. accounts.sap.com, mit einem s, ist die Profilseite jedes einzelnen Benutzers, auf der Passwörter und Einstellungen zur Zwei-Faktor-Authentifizierung liegen.

### So erstellen Sie eine SAP Universal ID

1. Gehen Sie zu [account.sap.com](https://account.sap.com/) und starten Sie eine neue Registrierung. Das Formular heißt „Register your SAP ID“.
2. Geben Sie Ihren Namen und eine private E-Mail-Adresse ein, keine berufliche.
3. Lassen Sie den Benutzernamen leer oder wählen Sie einen: bis zu 30 Zeichen, lateinische Buchstaben, Ziffern, Bindestriche und Unterstriche. Bleibt das Feld leer, bildet SAP einen Namen aus Ihrem Namen plus Ziffern.
4. Akzeptieren Sie die Terms of Use, lösen Sie das Captcha und klicken Sie auf **Register**.
5. Geben Sie den Bestätigungscode ein, den SAP Ihnen per E-Mail schickt. Er ist 15 Minuten gültig.

Die Registrierung legt Ihre Universal ID und eine damit verknüpfte Benutzeridentität an. Wenn Sie bereits eine Universal ID haben, registrieren Sie keine zweite. Fügen Sie die neue E-Mail-Adresse der bestehenden hinzu.

### So verknüpfen Sie einen S-User mit der SAP Universal ID

Seit Juli 2026 verknüpfen Sie einen S-User, indem Sie seine E-Mail-Adresse hinzufügen, nicht den Benutzer selbst.

1. Melden Sie sich im SAP Account Manager unter [account.sap.com](https://account.sap.com/) an.
2. Öffnen Sie die Registerkarte **Accounts** und klicken Sie auf **Add accounts** (Accounts hinzufügen).
3. Geben Sie die E-Mail-Adresse des S-Users ein.
4. Geben Sie den Passcode ein, den SAP an diese Adresse sendet.
5. Prüfen Sie die Liste. Jeder S-User und P-User mit dieser E-Mail-Adresse erscheint jetzt unter Ihrer Universal ID.

Wenn der S-User nicht erscheint, weicht seine E-Mail-Adresse von der ab, die Sie hinzugefügt haben. Fragen Sie den Administrator, der ihn angelegt hat, welche Adresse beim Benutzer hinterlegt ist.

### So fügen Sie einen P-User hinzu

Ein alter P-User wird genauso angehängt. Fügen Sie die E-Mail-Adresse hinzu, mit der er registriert wurde, mit den fünf Schritten oben. Wenn Sie gar keinen P-User haben, erhalten Sie mit der Registrierung einer Universal ID im selben Schritt eine Benutzeridentität.

### So setzen Sie Ihr SAP-Passwort zurück

Ein eigenes Universal-ID-Passwort für die Anmeldung auf SAP-Websites gibt es nicht mehr. Sie setzen das Passwort des jeweiligen S-Users oder P-Users zurück.

1. Gehen Sie zu [accounts.sap.com](https://accounts.sap.com/) und klicken Sie auf **Forgot password?** (Passwort vergessen?)
2. Geben Sie die Benutzer-ID (von SAP empfohlen) oder die E-Mail-Adresse ein. Wenn sich mehrere Benutzer diese E-Mail-Adresse teilen, müssen Sie die Benutzer-ID eingeben.
3. Klicken Sie auf **Send**.
4. Öffnen Sie die E-Mail und klicken Sie auf **Click here to reset your password**. Der Link läuft innerhalb von 2 Stunden ab.
5. Geben Sie ein neues Passwort mit mindestens 8 Zeichen ein, mit drei der folgenden Arten: Kleinbuchstaben, Großbuchstaben, Ziffern, Sonderzeichen.
6. Geben Sie es erneut ein und klicken Sie auf **Save**.

Sie können ein Passwort nur einmal alle 24 Stunden ändern oder zurücksetzen. Wenn die E-Mail nie ankommt, sollen Sie laut SAPs Anleitung an sso@sap.com schreiben.

### So entfernen Sie einen Benutzer aus Ihrer Universal ID

Seit dem 13. Juli 2026 gibt es keine Schaltfläche zum Trennen, und einen S-User können Sie nicht selbst löschen. SAPs Antwort lautet, den Administrator des Unternehmens zu fragen, dem er gehört.

1. Bitten Sie den Administrator dieses Unternehmens, den S-User zu löschen.
2. Der Administrator öffnet die App User Management in SAP for Me und klickt in der Spalte Actions auf Delete.
3. Wenn der S-User eine besondere Funktion hat, etwa Softwareempfänger oder technischer Ansprechpartner, muss SAP diese Funktion zuerst auf jemand anderen übertragen.
4. Nach dem Löschen liegt der S-User 12 Monate unter Deleted Users (gelöschte Benutzer) und kann nicht reaktiviert werden.

Um die Universal ID selbst zu löschen, wenden Sie sich an das Customer Interaction Center (CIC) von SAP.

### So ändern Sie die E-Mail-Adresse Ihrer Universal ID

1. Melden Sie sich im SAP Account Manager unter [account.sap.com](https://account.sap.com/) an.
2. Klicken Sie auf der Registerkarte **Accounts** auf **Add accounts** und geben Sie die neue Adresse ein.
3. Geben Sie den Passcode ein, der an die neue Adresse gesendet wird.
4. Öffnen Sie die Registerkarte **Personal Info** (persönliche Daten) und legen Sie die neue Adresse als primär fest.

Behalten Sie Ihre private Adresse als Reserve registriert. Die E-Mail-Adresse eines S-Users ist etwas anderes: Nur der Administrator des Unternehmens kann sie ändern. Wenn sie sich ändert, wandert der S-User zu der Universal ID, die die neue Adresse enthält.

### So aktivieren Sie die Zwei-Faktor-Authentifizierung

SAP bietet im Profil jedes Benutzers eine Zwei-Faktor-Authentifizierung mit zeitbasiertem Einmalpasswort (TOTP).

1. Melden Sie sich unter [accounts.sap.com](https://accounts.sap.com/) an.
2. Scrollen Sie zu **TOTP Two-Factor Authentication** und klicken Sie auf **Activate**.
3. Installieren Sie eine Authenticator-App. SAP schlägt Microsoft Authenticator oder Google Authenticator vor.
4. Scannen Sie den QR-Code mit der App.
5. Geben Sie den Passcode ein, den die App anzeigt, und klicken Sie auf **Activate**.

Die Seite bestätigt dann „You have a device configured for TOTP two-factor authentication“, und SAP sendet eine E-Mail. Wenn Sie das Telefon wechseln, klicken Sie zuerst auf **Deactivate**, bestätigen mit einem Code und aktivieren dann auf dem neuen Gerät erneut. Ihr Super-Administrator kann MFA erzwingen, was Ihre eigene Wahl überschreibt.

## Häufige Fehler bei SAP Universal ID und ihre Lösung

Die meisten Probleme nach den Änderungen von 2026 laufen auf E-Mail-Adressen, Passwörter pro Benutzer und Ablaufdaten hinaus.

| Problem | Wahrscheinlichste Ursache | Lösung |
|---|---|---|
| Ein Benutzer fehlt auf Ihrer Registerkarte Accounts | Seine E-Mail-Adresse weicht von den Adressen in Ihrer Universal ID ab | Fügen Sie diese E-Mail-Adresse unter Accounts hinzu oder bitten Sie den Administrator, die E-Mail-Adresse beim S-User zu korrigieren |
| Benutzer oder E-Mail-Adresse bereits mit einer anderen Universal ID verknüpft | Er liegt unter einer älteren Universal ID, die Sie angelegt haben | Eröffnen Sie ein SAP-Support-Ticket oder wenden Sie sich an das CIC. SAPs KBAs nutzen die Komponente `XX-SER-UID` |
| Anmeldung per E-Mail-Adresse schlägt fehl | Mehrere Benutzer teilen sich diese E-Mail-Adresse | Melden Sie sich stattdessen mit der S-User- oder P-User-ID an |
| Altes Passwort nach Januar 2026 abgelehnt | Jeder Benutzer hat jetzt sein eigenes Passwort | Nutzen Sie „Forgot password“ bei genau diesem Benutzer |
| Passwort gesperrt | Zu viele Fehlversuche | Setzen Sie das Passwort zurück. Passiert mir mindestens einmal im Jahr |
| Passwort lässt sich nicht erneut ändern | Eine Änderung oder Rücksetzung pro 24 Stunden | Warten Sie 24 Stunden |
| E-Mail zum Zurücksetzen kommt nie an | Spamfilter oder falscher Benutzer | Prüfen Sie den Spam-Ordner, versuchen Sie es mit der Benutzer-ID erneut und schreiben Sie dann an sso@sap.com |
| Anmeldung scheitert in einem Browser | Drittanbieter-Cookies blockiert oder Internet Explorer | Erlauben Sie Drittanbieter-Cookies und nutzen Sie einen aktuellen Chrome, Edge, Firefox oder Safari |
| S-User abgelaufen | Sein Ablaufdatum ist überschritten | Der Administrator kann ihn innerhalb von 90 Tagen reaktivieren. Danach wird er gelöscht, und ein neuer S-User ist nötig |
| Angemeldet, aber keine Fälle oder Downloads möglich | Dem S-User fehlt diese Berechtigung | Beantragen Sie sie in SAP for Me. Ihr Administrator genehmigt sie |

Die Universal ID ändert nie Berechtigungen. Jeder S-User behält seine eigenen Berechtigungen, die der Administrator des jeweiligen Unternehmens vergibt.

## Wenn Sie mehrere S-User haben

Berater spüren die Änderung vom Januar am stärksten. Früher deckte eine Anmeldung jeden Kunden ab. Jetzt hat jeder S-User sein eigenes Passwort, und ein Benutzerwechsel bedeutet Abmelden und erneutes Anmelden.

Behandeln Sie jeden S-User als Eigentum des Kunden, nicht als Ihres. Legen Sie im Passwortmanager pro S-User einen Eintrag an, der Kunde und Kundennummer nennt. SAPs Grenzen sind großzügig: Eine Universal ID fasst bis zu 10 E-Mail-Adressen und bis zu 100 S-User oder P-User, die alle Ihnen gehören.

Behalten Sie die Ablaufdaten im Blick. Neue S-User erhalten standardmäßig eine Gültigkeit von 24 Monaten, danach eine Ablaufphase von 90 Tagen mit E-Mails 30, 14 und 2 Tage vor dem Ablauf. Sie können in SAP for Me selbst eine Verlängerung beantragen, und der Antrag landet beim Administrator.

### So finden Sie Ihre S-User-ID

1. Melden Sie sich im SAP Account Manager unter account.sap.com an und öffnen Sie die Registerkarte **Accounts**. Sie listet jeden Benutzer auf, der an Ihre Universal ID angehängt ist.
2. In SAP for Me zeigt **My authorizations & functions** (meine Berechtigungen und Funktionen), was der Benutzer, mit dem Sie angemeldet sind, darf.
3. Wenn Ihnen nie eine ID geschickt wurde, haben Sie möglicherweise keinen S-User. Der Administrator Ihres Unternehmens sieht jeden S-User in der App User Management.

### So finden Sie den Super-Administrator Ihres Unternehmens

SAP legt für einen neuen Kunden den ersten S-User an und macht ihn zum Super-Administrator. Danach legen Administratoren in Ihrem Unternehmen jeden weiteren S-User an. SAP empfiehlt mindestens zwei weitere Super-Administratoren als Vertretung.

1. Melden Sie sich in SAP for Me mit einem beliebigen S-User dieses Unternehmens an.
2. Öffnen Sie **Users & Contacts** und dann **Important contacts** (wichtige Kontakte). Dort stehen Super-Administrator, Cloud-Administrator und Sicherheitsansprechpartner.
3. Wenn der Super-Administrator das Unternehmen verlassen hat und niemand sonst handeln kann, eröffnen Sie einen Fall auf der Komponente `XX-SER-FORME` und nennen die Person, die übernehmen soll.

Wenn Sie noch keinen S-User haben, beginnen Sie bei der Person in der IT, die SAP-Support-Fälle eröffnet. Beachten Sie, dass Administratoren nicht sehen, ob ein S-User an eine Universal ID angehängt ist, und diese Seite deshalb nicht für Sie korrigieren können.

## Checkliste für Start und Ende bei einem Kunden

Berater stoßen zu Beginn und am Ende von Projekten auf diese Probleme. In dieser Reihenfolge würde ich vorgehen.

1. **Vor dem ersten Tag:** Prüfen Sie, ob Ihre Universal ID eine private primäre E-Mail-Adresse hat.
2. **Erster Tag:** Bitten Sie den Administrator des Kunden um einen S-User unter dessen Kundennummer, angelegt mit der E-Mail-Adresse, die Sie dort nutzen werden.
3. **Am selben Tag:** Fügen Sie diese E-Mail-Adresse im SAP Account Manager hinzu und prüfen Sie, ob der neue S-User erscheint.
4. **Erste Woche:** Beantragen Sie nur die Berechtigungen, die Ihre Rolle braucht, und aktivieren Sie die Zwei-Faktor-Authentifizierung, wenn der Kunde sie nicht erzwungen hat.
5. **Während des Projekts:** Melden Sie sich mit der S-User-ID statt mit der E-Mail-Adresse an, wenn sich mehrere Ihrer Benutzer eine Adresse teilen.
6. **Bevor Sie gehen:** Prüfen Sie, ob Ihre private E-Mail-Adresse in Ihrer Universal ID steht. Zertifikate auf einen neuen S-User zu übertragen, erfordert ein Support-Ticket.
7. **Nachdem Sie gegangen sind:** Rechnen Sie damit, dass der S-User gelöscht wird. Ihr P-User und Ihre Universal ID bleiben.

Ein S-User ist an eine Kundennummer gebunden und kann nicht zu einer anderen wechseln, ein neuer Kunde bedeutet also immer einen neuen S-User. Wenn Ihnen der Kunde auch BTP-Zugang gibt, beginnen Sie mit meinem [Leitfaden zum SAP BTP Cockpit](/de/master-the-sap-btp-cockpit-simple-steps/). Anmeldefehler dort sind ein anderes Problem, das mein [Leitfaden zur Fehlerbehebung im BTP Cockpit](/de/sap-btp-cockpit-issues/) behandelt.
