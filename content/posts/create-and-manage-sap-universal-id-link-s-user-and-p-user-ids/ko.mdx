SAP 계정이 여러 개라면(개인 P-User 하나와 고용주나 고객사에서 받은 S-User들), 이 계정들을 하나로 묶어 주는 개인 계정이 SAP Universal ID입니다. 2026년에 두 번 바뀌었습니다. 1월 20일부터 Universal ID는 로그인 수단이 아닙니다. 이제 S-User 또는 P-User ID(또는 그 사용자에 등록된 이메일)와 그 사용자 고유의 비밀번호로 로그인합니다. 7월 13일에는 수동 연결이 사라졌습니다. SAP Account Manager에 이메일 주소를 추가하면, 이메일이 일치하는 모든 사용자가 자동으로 연결됩니다. 아직 만들지 않으셨다면 account.sap.com에서 개인 이메일로 등록한 다음 업무용 주소를 추가하십시오.

SAP를 처음 접했을 때 저는 Universal ID, S-User, P-User가 어떻게 맞물리는지 파악하느라 몇 주를 보냈습니다. Universal ID가 나오기 전에는 이 계정들을 챙기는 일이 악몽이었습니다. 비밀번호를 적어 둔 스프레드시트가 있었고, 어떤 자격 증명이 어디에 쓰이는지 잊을 때마다 재설정 이메일이 쏟아졌습니다.

## S-User, P-User, Universal ID 비교

표에 각 ID의 소유자와 용도를 정리했습니다.

| ID 유형 | 소유자 | 용도 | 회사를 떠날 때 |
|---|---|---|---|
| **P-User** | 본인 | SAP Community, 체험판, 개발자 콘텐츠, SAP Learning | 달라지는 것은 없습니다. 본인 계정입니다 |
| **S-User** | 고용주 또는 고객사(해당 회사의 SAP 고객 번호 기준) | 지원 케이스, 소프트웨어 다운로드, 라이선스 키, SAP for Me의 시스템 데이터 | 관리자가 삭제하거나 만료일이 지나면 사라집니다 |
| **Universal ID** | 본인 | S-User와 P-User를 하나의 목록에 묶고, 학습 인증서와 SAP Community 평판도 담습니다 | 계속 보유합니다. 새 고용주의 이메일을 추가하십시오 |

제 P-User는 약 16년 동안 직장을 옮겨 다니는 내내 저를 따라왔습니다. 회사를 옮기면서 S-User는 여섯 개를 거쳤습니다. Universal ID는 그 계정들이 한 목록에 모이는 곳입니다.

Universal ID에는 업무용 이메일이 아니라 개인 이메일을 쓰십시오. SAP의 공식 FAQ도 같은 권고를 합니다. 회사를 떠나 업무용 메일함을 잃더라도 개인 주소가 있으면 다시 들어갈 수 있습니다.

## 2026년에 바뀐 점

올해 SAP는 두 가지를 바꿨습니다. 둘 다 로그인 방식과 계정 연결 방식에 영향을 줍니다. 공식 상세 내용은 [SAP의 Universal ID 페이지](https://www.sap.com/account/universal-id.html)에 있습니다.

1. **2026년 1월 20일: Universal ID 로그인 중단.** Universal ID는 더 이상 ID 공급자가 아닙니다. S-User 또는 P-User ID(또는 그 사용자에 등록된 이메일)와 그 사용자의 비밀번호로 로그인합니다. 인증은 SAP Cloud Identity Services를 거칩니다. 연결된 ID가 여러 개인 사용자는 2025년 8월부터 2026년 1월 사이에 각 ID의 비밀번호를 설정하라는 안내를 받았습니다. 이 단계를 건너뛰셨다면 각 사용자에서 비밀번호 찾기를 이용하십시오.
2. **2026년 7월 13일: 이메일 주소로 연결.** 수동 연결 및 연결 해제 옵션이 없어졌습니다. 이메일이 Universal ID에 등록된 S-User와 P-User는 모두 자동으로 연결됩니다. 7월 이전에 직접 연결한 계정은 그대로 연결되어 있습니다.

여러 고객사의 S-User를 함께 쓰는 컨설턴트에게 1월 변경은 후퇴입니다. 예전에는 로그인 하나로 모든 계정을 다룰 수 있었습니다. 이제는 S-User마다 다시 비밀번호가 따로 있고, 사용자를 바꾸려면 로그아웃한 뒤 다시 로그인해야 합니다. 어떤 S-User가 어느 고객사와 고객 번호에 속하는지 비밀번호 관리자에 메모해 두십시오.

## Universal ID 설정과 계정 추가

### 1단계: SAP Universal ID 만들기

1. [account.sap.com](https://account.sap.com/)에 접속해 **Register**를 클릭합니다.
2. 이름과 개인 이메일 주소를 입력한 뒤 비밀번호를 설정합니다.
3. 이용 약관에 동의합니다. 마케팅 수신 동의는 선택 사항입니다.
4. 받은 편지함에 도착한 인증 코드를 입력합니다. 코드는 15분 동안 유효합니다.
5. SAP Account Manager에 로그인합니다. 새 P-User가 **Accounts** 탭에 표시됩니다.

전체 과정은 몇 분이면 끝납니다. 다른 SAP 사용자의 이메일 주소를 미리 준비해 두면 바로 이어서 추가할 수 있습니다.

### 2단계: 다른 계정의 이메일 주소 추가하기

1. [account.sap.com](https://account.sap.com/)에서 SAP Account Manager에 로그인합니다.
2. **Accounts** 탭을 열고 **Add accounts**를 클릭합니다.
3. 가져오려는 S-User 또는 P-User가 사용하는 이메일 주소를 입력합니다.
4. 그 주소로 SAP가 보내는 인증 코드를 입력합니다.
5. 목록을 확인합니다. 그 이메일을 쓰는 모든 사용자가 이제 Universal ID 아래에 표시됩니다.
6. 주소마다 같은 과정을 반복한 뒤, **Personal Info** 탭에서 기본 이메일을 지정합니다.

Universal ID 하나에는 이메일 주소를 최대 10개, S-User 또는 P-User를 최대 100개까지 담을 수 있습니다. 사용자 한 명은 하나의 Universal ID 아래에만 둘 수 있고, 모든 사용자는 한 사람의 것이어야 합니다. 이메일이나 사용자를 추가하는 방법은 SAP Knowledge Base Article 2882908에 나와 있습니다.

### 평소 로그인 방법

여러 사용자가 이메일 주소 하나를 공유한다면, SAP는 사용자 ID(S 또는 P 뒤에 숫자가 붙는 형식)로 로그인하라고 권장합니다. 그 사용자들이 비밀번호까지 공유하면 일치하는 사용자가 둘 이상이어서 이메일 로그인이 오류를 냅니다.

사용자를 바꾸려면 로그아웃한 다음 다른 사용자로 로그인합니다. SAP는 세션 안에서 전환하는 기능을 나중에 제공하겠다고 밝혔습니다. 계정 선택 화면에서는 로그인 날짜순으로 정렬하면 가장 최근에 쓴 사용자가 맨 위에 옵니다.

## S-User 또는 P-User 확보하기

### S-User 발급받기

S-User는 SAP가 아니라 회사의 사용자 관리자가 발급합니다. SAP가 만들어 주는 것은 신규 고객의 첫 번째 슈퍼 관리자뿐입니다. 그 뒤로는 관리자가 [SAP for Me의 User Management 앱](https://support.sap.com/content/s4m/help/users/admin.html)에서 S-User를 요청합니다. 새 사용자는 10일간 유효한 활성화 링크를 받습니다. 맡은 역할에 필요한 권한을 관리자에게 요청하십시오.

1. **지원 케이스**: 인시던트를 만들고 추적합니다
2. **소프트웨어 다운로드**: 설치 파일, 패치, 애드온
3. **라이선스 키**: 시스템용 키를 요청합니다
4. **시스템 데이터**: 설치 환경과 시스템을 유지 관리합니다

S-User는 고객 번호 하나에 묶여 있어서 다른 고객 번호로 옮길 수 없습니다. S-User에는 만료일도 있습니다. 만료가 가까워지면 SAP for Me에서 연장을 요청할 수 있고, 그 요청은 관리자의 대기열로 들어갑니다.

SAP 관리자를 찾을 수 없다면 IT 부서에 먼저 문의하십시오. 규모가 작은 회사라면 재무 부서에 물어보십시오. 라이선스 때문에 재무 부서가 S-User 접근 권한을 거의 항상 갖고 있고, 관리자가 누구인지도 압니다.

RISE with SAP와 GROW with SAP 프로그램에서도 모델은 같습니다. 고객사가 자사 고객 번호 아래에서 컨설턴트용 S-User를 발급하고, 계약이 끝나면 삭제합니다. 그것이 당연한 절차입니다. 그 계정은 고객사의 것이지 컨설턴트의 것이 아닙니다.

### P-User 등록하기

본인 이메일로 [account.sap.com](https://account.sap.com/)에 등록하십시오. 그러면 P-User와 Universal ID가 한 번에 생깁니다. P-User로는 SAP Community, 무료 체험판(제 [SAP BTP Cockpit 가이드](/ko/master-the-sap-btp-cockpit-simple-steps/)에 나오는 체험판 같은 것), 개발자 리소스, SAP Learning을 이용할 수 있습니다. 라이선스가 필요한 지원이나 소프트웨어 다운로드는 P-User로 되지 않습니다. 그것이 S-User의 역할입니다.

## 자주 발생하는 접근 오류와 해결 방법

2026년 변경 이후의 문제는 대부분 이메일 주소와 비밀번호에서 비롯됩니다.

| 문제 | 가장 유력한 원인 | 해결 방법 |
|---|---|---|
| Accounts 탭에 사용자가 보이지 않음 | 그 사용자의 이메일이 Universal ID에 등록된 주소와 다름 | Accounts에서 해당 이메일을 추가하거나, 관리자에게 S-User의 이메일을 바로잡아 달라고 요청 |
| 이미 다른 Universal ID에 연결된 사용자라고 표시됨 | 이전에 만든 Universal ID 아래에 남아 있음 | SAP 지원에 케이스를 등록해 해제 요청(SAP KBA에서는 컴포넌트 `XX-SER-UID` 사용) |
| 이메일 로그인 실패 | 여러 사용자가 같은 이메일과 비밀번호를 공유 | S-User 또는 P-User ID로 로그인 |
| 2026년 1월 이후 기존 비밀번호가 거부됨 | 이제 사용자마다 비밀번호가 따로 있음 | 해당 사용자에서 비밀번호 찾기 이용 |
| 비밀번호 잠김 | 틀린 시도 횟수 초과 | 기다리거나 비밀번호 재설정. 저는 1년에 한 번 이상은 겪습니다 |
| S-User가 비활성 또는 만료됨 | 관리자가 삭제했거나 만료일이 지남 | 해당 회사 관리자에게 연장이나 교체 요청. 이전 직장의 계정이라면 놓아 주십시오 |
| 로그인은 되지만 케이스 생성이나 다운로드가 안 됨 | S-User에 해당 권한이 없음 | SAP for Me에서 권한 요청. 관리자가 승인 |

아예 로그인할 수 없다면, SAP는 Universal ID 관련 문의 창구로 Customer Interaction Center(CIC)를 안내합니다. 복구에는 신원 확인이 필요하므로, 마감 때문에 접근 권한이 필요하다면 일찍 시작하십시오.

## 고객사 합류와 철수 체크리스트

컨설턴트는 프로젝트를 시작하고 끝낼 때 이런 문제를 겪습니다. 제가 밟는 순서는 이렇습니다.

1. **첫날 이전:** Universal ID의 기본 이메일이 개인 이메일인지 확인합니다.
2. **첫날:** 고객사 관리자에게 그 회사의 고객 번호 아래 S-User를 요청합니다. 현장에서 쓸 이메일로 만들어 달라고 하십시오.
3. **같은 날:** SAP Account Manager에 그 이메일을 추가하고 새 S-User가 표시되는지 확인합니다.
4. **첫 주:** 맡은 역할에 필요한 권한만 요청합니다. 관리자가 SAP for Me에서 승인합니다.
5. **프로젝트 기간 중:** 여러 사용자가 한 주소를 공유한다면 이메일 대신 S-User ID로 로그인합니다.
6. **떠나기 전:** 그 S-User로 인증서를 취득했다면 개인 이메일이 Universal ID에 들어 있는지 확인합니다. 인증서를 새 S-User로 옮기려면 지원 케이스가 필요합니다.
7. **떠난 뒤:** S-User는 삭제될 것으로 예상하십시오. P-User와 Universal ID는 그대로 남습니다.

고객사가 BTP 접근 권한도 준다면, 그쪽의 로그인 실패는 다른 문제입니다. 401 오류는 제 [BTP Cockpit 문제 해결 가이드](/ko/sap-btp-cockpit-issues/)에서 다룹니다.

## 자주 묻는 질문

<details>
<summary>SAP에서 P-User와 S-User는 어떻게 다릅니까?</summary>

P-User는 개인 계정입니다. 본인이 직접 등록하고, 본인에게 속하며, 이직해도 따라옵니다. SAP Community, 무료 체험판, 개발자 콘텐츠, SAP Learning에 접근할 수 있습니다.

S-User는 고용주 또는 고객사에 속합니다. 그 회사의 사용자 관리자가 고객 번호 아래 SAP for Me에서 만듭니다. 지원 케이스, 소프트웨어 다운로드, 라이선스 키 같은 라이선스 서비스에 접근할 수 있습니다. 회사를 떠나면 회사가 삭제합니다.

SAP Universal ID는 두 유형을 인증서, 커뮤니티 평판과 함께 하나의 목록에 보관합니다.

</details>

<details>
<summary>아직도 SAP Universal ID로 로그인할 수 있습니까?</summary>

아니요. 2026년 1월 20일부터 Universal ID는 더 이상 ID 공급자가 아닙니다. S-User 또는 P-User ID(또는 그 사용자에 등록된 이메일 주소)와 그 사용자의 비밀번호로 로그인합니다. Universal ID는 이제 사용자, 인증서, SAP Community 평판을 담는 지갑 역할을 합니다. 관리하려면 여전히 account.sap.com에서 SAP Account Manager에 로그인합니다.

</details>

<details>
<summary>2026년 7월 이후 S-User를 SAP Universal ID에 연결하려면 어떻게 합니까?</summary>

사용자를 연결하는 대신 S-User의 이메일 주소를 추가합니다. SAP Account Manager에서 Accounts 탭을 열고 Add accounts를 클릭한 뒤, 이메일을 입력하고 SAP가 보내는 인증 코드를 확인합니다. 그러면 그 이메일을 쓰는 모든 S-User와 P-User가 자동으로 Universal ID 아래에 표시됩니다. 2026년 7월 13일 이전에 직접 연결한 사용자는 그대로 연결되어 있습니다.

</details>

<details>
<summary>SAP Universal ID에는 어떤 이메일 주소를 써야 합니까?</summary>

개인 이메일을 기본 주소로 쓰고, 업무용 주소는 그 옆에 추가하십시오. 회사를 떠나 업무용 메일함을 잃더라도 개인 주소가 있으면 Universal ID에 계속 접근할 수 있습니다. SAP도 Universal ID FAQ에서 같은 권고를 합니다.

</details>

<details>
<summary>이직하면 SAP Universal ID는 어떻게 됩니까?</summary>

Universal ID는 본인에게 남습니다. 이전 고용주의 관리자가 S-User를 회수하거나 삭제합니다. 새 고용주가 Universal ID에 이미 등록된 이메일로 S-User를 만들면 자동으로 연결됩니다. 새 이메일을 쓰면 SAP Account Manager에서 그 주소를 추가하십시오.

P-User와 Universal ID는 처음부터 끝까지 그대로입니다.

</details>

<details>
<summary>SAP Universal ID에 연결할 수 있는 계정은 몇 개입니까?</summary>

Universal ID 하나당 이메일 주소는 최대 10개, S-User 또는 P-User는 최대 100개입니다. 모두 본인의 것이어야 합니다. 이를 넘어서면 SAP는 다른 사람을 대신해 사용자를 관리하는 것으로 보며, 공유 계정은 정지로 이어집니다.

</details>

<details>
<summary>SAP Universal ID가 SAP 시스템에서 접근할 수 있는 범위를 바꿉니까?</summary>

아니요. S-User마다 자체 권한을 유지합니다. S-User에 다운로드 권한이 없다면 Universal ID에 추가해도 권한이 생기지 않습니다. 권한은 회사의 사용자 관리자가 SAP for Me에서 부여합니다.

</details>

<details>
<summary>SAP에 로그인할 수 없으면 어떻게 해야 합니까?</summary>

먼저 어떤 사용자로 로그인하는지 확인하십시오. 2026년 1월부터 S-User와 P-User마다 비밀번호가 따로 있으므로 해당 사용자에서 비밀번호 찾기를 이용하십시오. 여러 사용자가 이메일을 공유한다면 사용자 ID로 로그인하십시오.

계정에 등록된 이메일에 접근할 수 없게 되었다면 SAP의 Customer Interaction Center에 문의하거나 지원 케이스를 등록하십시오. SAP가 신원을 확인한 뒤 접근 권한을 복구해 줍니다.

</details>
