SAP Universal ID는 모든 S-User와 P-User ID, 인증서, SAP Community 평판을 담는 무료 개인 SAP 계정이며, 직장을 옮겨도 귀하와 함께 남습니다. 2026년부터 이것은 더 이상 로그인 수단이 아닙니다. 각 S-User 또는 P-User ID로 로그인하고, 사용자는 이메일 주소를 통해 자동으로 Universal ID에 연결됩니다.

> **짧은 답.** P-User는 귀하 자신의 SAP 사용자입니다. S-User는 고용주나 고객사가 자사의 SAP 고객 번호로 발급합니다. SAP Universal ID는 account.sap.com의 SAP Account Manager에 이 모두를 나열하는 지갑입니다.

SAP를 처음 시작했을 때 저는 P-User, S-User, 그리고 무엇이 무엇과 연결되는지를 파악하느라 몇 주를 보냈습니다. 비밀번호 재설정 이메일은 매주 오는 일이었습니다.

## S-User, P-User, Universal ID 비교

아래 표는 각 ID의 소유자, 용도, 그리고 회사를 떠날 때 어떻게 되는지를 정리한 것입니다.

| | P-User | S-User | SAP Universal ID |
|---|---|---|---|
| 소유자 | 귀하 | 고용주 또는 고객사(그들의 SAP 고객 번호 아래) | 귀하 |
| 생성자 | 귀하(account.sap.com에서 등록) | 해당 회사의 관리자(SAP for Me에서 생성) | 귀하(account.sap.com에서 생성) |
| 용도 | SAP Community, 트라이얼, 개발자 콘텐츠, SAP Learning | 지원 케이스, 소프트웨어 다운로드, 라이선스 키, 시스템 데이터 | 모든 사용자 목록 관리, 인증서와 커뮤니티 평판 보관 |
| 로그인에 쓸 수 있는가? | 예 | 예 | 아니요, 2026년 1월부터 불가 |
| 만료 | 없음 | 기본 24개월, 관리자가 연장 가능 | 없음 |
| 회사를 떠날 때 | 변화 없음 | 관리자가 삭제하거나 만료됨 | 그대로 유지. 새 회사 이메일을 추가 |

제 P-User는 약 16년 동안 여러 직장을 거치는 내내 저와 함께했습니다. 회사를 옮기면서 S-User는 여섯 개가 바뀌었습니다. Universal ID는 그 모두가 하나의 목록에 모이는 곳입니다.

## 2026년에 바뀐 것

SAP는 올해 두 가지를 바꿨습니다. 공식 세부 내용은 [SAP의 Universal ID 페이지](https://www.sap.com/account/universal-id.html)에 있습니다.

1. **2026년 1월: Universal ID가 로그인 수단에서 빠졌습니다.** 더 이상 ID 공급자가 아닙니다. S-User 또는 P-User ID나 그 사용자의 이메일 주소, 그리고 그 사용자의 비밀번호로 SAP Cloud Identity Services(SAP IAS)를 통해 로그인합니다.
2. **2026년 7월 13일: 이메일 주소로 연결.** 수동 link/unlink 옵션과 Linked 상태 열이 제거되었습니다. Universal ID에 등록된 이메일을 가진 모든 S-User와 P-User가 자동으로 연결되며, 7월 이전에 수동으로 연결한 것은 그대로 연결된 상태로 남습니다.

두 변경 모두에서 삭제된 계정은 없습니다. 2025년에 사용자별 비밀번호 설정 요청을 건너뛰었다면, 해당 사용자에서 Forgot password(비밀번호 찾기)를 사용하십시오.

## SAP Universal ID 관리 방법: 단계별 안내

여기서는 두 주소가 중요하며, 혼동하기 쉽습니다. **account.sap.com**은 SAP Account Manager로, Universal ID가 있는 곳입니다. s가 붙은 accounts.sap.com은 개별 사용자의 프로필 페이지로, 비밀번호와 2단계 인증 설정이 있는 곳입니다.

### SAP Universal ID 만드는 방법

1. [account.sap.com](https://account.sap.com/)으로 가서 새 등록을 시작합니다. 양식 제목은 "Register your SAP ID"입니다.
2. 이름과 회사 이메일이 아닌 개인 이메일 주소를 입력합니다.
3. 사용자 이름은 비워 두거나 직접 정합니다. 최대 30자이며 라틴 문자, 숫자, 하이픈, 밑줄을 쓸 수 있습니다. 비워 두면 SAP가 이름과 숫자로 만들어 줍니다.
4. Terms of Use(이용 약관)에 동의하고 captcha를 완료한 뒤 **Register**를 클릭합니다.
5. SAP가 이메일로 보낸 인증 코드를 입력합니다. 15분 동안 유효합니다.

이 등록으로 Universal ID와 그에 연결된 사용자 ID가 만들어집니다. 이미 Universal ID가 있다면 두 번째 것을 등록하지 마십시오. 새 이메일을 기존 Universal ID에 추가하십시오.

### S-User를 SAP Universal ID에 연결하는 방법

2026년 7월부터는 사용자 자체가 아니라 그 이메일 주소를 추가해서 S-User를 연결합니다.

1. [account.sap.com](https://account.sap.com/)에서 SAP Account Manager에 로그인합니다.
2. **Accounts** 탭을 열고 **Add accounts**를 클릭합니다.
3. S-User에 등록된 이메일 주소를 입력합니다.
4. SAP가 그 주소로 보낸 패스코드를 입력합니다.
5. 목록을 확인합니다. 그 이메일을 가진 모든 S-User와 P-User가 이제 Universal ID 아래에 나타납니다.

S-User가 나타나지 않으면 그 이메일이 추가한 이메일과 다른 것입니다. 해당 S-User를 만든 관리자에게 어떤 주소가 등록되어 있는지 물어보십시오.

### P-User를 추가하는 방법

예전 P-User도 같은 방식으로 연결됩니다. 위의 다섯 단계를 따라 그 P-User를 등록할 때 쓴 이메일 주소를 추가하십시오. P-User가 전혀 없다면, Universal ID를 등록하는 같은 단계에서 사용자 ID도 생깁니다.

### SAP 비밀번호를 재설정하는 방법

SAP 사이트에 로그인하기 위해 재설정할 별도의 Universal ID 비밀번호는 이제 없습니다. 재설정하는 것은 특정 S-User 또는 P-User의 비밀번호입니다.

1. [accounts.sap.com](https://accounts.sap.com/)으로 가서 **Forgot password?**를 클릭합니다.
2. 사용자 ID(SAP 권장) 또는 이메일을 입력합니다. 여러 사용자가 그 이메일을 공유한다면 사용자 ID를 입력해야 합니다.
3. **Send**를 클릭합니다.
4. 이메일을 열고 **Click here to reset your password**를 클릭합니다. 링크는 2시간 안에 만료됩니다.
5. 소문자, 대문자, 숫자, 기호 중 세 가지를 사용한 8자 이상의 새 비밀번호를 입력합니다.
6. 한 번 더 입력하고 **Save**를 클릭합니다.

비밀번호 변경이나 재설정은 24시간에 한 번만 할 수 있습니다. 이메일이 오지 않으면 sso@sap.com으로 연락하라고 SAP 가이드에 나와 있습니다.

### Universal ID에서 사용자를 제거하는 방법

2026년 7월 13일부터 연결 해제 버튼이 없고, S-User를 직접 삭제할 수도 없습니다. SAP의 답은 그 S-User를 소유한 회사의 관리자에게 요청하라는 것입니다.

1. 해당 회사의 관리자에게 S-User 삭제를 요청합니다.
2. 관리자는 SAP for Me에서 User Management 앱을 열고 Actions 열의 Delete를 클릭합니다.
3. S-User가 소프트웨어 수령인이나 기술 담당자 같은 특수 기능을 맡고 있다면, SAP가 먼저 그 기능을 다른 사람에게 옮겨야 합니다.
4. 삭제된 S-User는 Deleted Users에 12개월 동안 남으며, 다시 활성화할 수 없습니다.

Universal ID 자체를 삭제하려면 SAP의 Customer Interaction Center(CIC)에 연락하십시오.

### Universal ID의 이메일을 변경하는 방법

1. [account.sap.com](https://account.sap.com/)에서 SAP Account Manager에 로그인합니다.
2. **Accounts** 탭에서 **Add accounts**를 클릭하고 새 주소를 입력합니다.
3. 새 주소로 온 패스코드를 입력합니다.
4. **Personal Info** 탭을 열고 새 주소를 기본(primary)으로 설정합니다.

개인 주소는 백업으로 등록해 두십시오. S-User의 이메일은 이와 별개이며, 해당 회사의 관리자만 바꿀 수 있습니다. 그 이메일이 바뀌면 S-User는 새 주소를 가진 Universal ID로 옮겨 갑니다.

### 2단계 인증을 켜는 방법

SAP는 각 사용자 프로필에서 시간 기반 일회용 비밀번호(TOTP) 2단계 인증을 제공합니다.

1. [accounts.sap.com](https://accounts.sap.com/)에서 로그인합니다.
2. **TOTP Two-Factor Authentication**까지 스크롤하고 **Activate**를 클릭합니다.
3. 인증 앱을 설치합니다. SAP는 Microsoft Authenticator나 Google Authenticator를 권장합니다.
4. 앱으로 QR 코드를 스캔합니다.
5. 앱에 표시된 패스코드를 입력하고 **Activate**를 클릭합니다.

그러면 페이지에 "You have a device configured for TOTP two-factor authentication"이라는 확인 문구가 나타나고 SAP가 이메일을 보냅니다. 휴대폰을 바꿀 때는 먼저 **Deactivate**를 클릭하고 코드로 확인한 뒤, 새 기기에서 다시 활성화해야 합니다. 슈퍼 관리자는 MFA를 강제할 수 있으며, 그 경우 귀하의 선택보다 우선합니다.

## SAP Universal ID의 흔한 오류와 해결 방법

2026년 변경 이후의 문제는 대부분 이메일 주소, 사용자별 비밀번호, 만료일로 귀결됩니다.

| 문제 | 가장 가능성 높은 원인 | 해결 방법 |
|---|---|---|
| Accounts 탭에 사용자가 없음 | 그 이메일이 Universal ID에 등록된 주소와 다름 | Accounts에서 그 이메일을 추가하거나, 관리자에게 S-User의 이메일 수정을 요청 |
| 사용자 또는 이메일이 다른 Universal ID에 이미 연결됨 | 예전에 만든 다른 Universal ID 아래에 있음 | SAP 지원 티켓을 제기하거나 CIC에 연락. SAP의 KBA는 컴포넌트 `XX-SER-UID`를 사용 |
| 이메일 로그인 실패 | 여러 사용자가 그 이메일을 공유 | 대신 S-User 또는 P-User ID로 로그인 |
| 2026년 1월 이후 예전 비밀번호가 거부됨 | 이제 각 사용자에게 고유한 비밀번호가 있음 | 해당 사용자에서 Forgot password 사용 |
| 비밀번호 잠김 | 잘못된 시도가 너무 많음 | 비밀번호를 재설정. 저도 적어도 1년에 한 번은 겪습니다 |
| 비밀번호를 다시 바꿀 수 없음 | 변경 또는 재설정은 24시간에 한 번 | 24시간 기다리기 |
| 재설정 이메일이 오지 않음 | 스팸 필터, 또는 다른 사용자 | 스팸함을 확인하고, 사용자 ID로 다시 시도한 뒤, sso@sap.com으로 연락 |
| 특정 브라우저에서만 로그인 실패 | 서드파티 쿠키 차단, 또는 Internet Explorer | 서드파티 쿠키를 허용하고 최신 Chrome, Edge, Firefox 또는 Safari 사용 |
| S-User 만료 | 만료일이 지남 | 관리자가 90일 이내라면 재활성화 가능. 그 후에는 삭제되어 새 S-User가 필요 |
| 로그인은 되지만 케이스 생성이나 다운로드가 안 됨 | S-User에 해당 권한이 없음 | SAP for Me에서 요청. 관리자가 승인 |

Universal ID는 권한을 절대 바꾸지 않습니다. 각 S-User는 해당 회사의 관리자가 부여한 자체 권한을 유지합니다.

## S-User를 여러 개 갖고 있다면

1월 변경을 가장 크게 체감하는 것은 컨설턴트입니다. 예전에는 하나의 로그인으로 모든 고객사를 처리했습니다. 이제는 S-User마다 비밀번호가 따로 있고, 사용자를 바꾸려면 로그아웃했다가 다시 로그인해야 합니다.

각 S-User는 귀하의 것이 아니라 고객사의 자산으로 다루십시오. 비밀번호 관리자에 S-User별 항목을 만들고 고객사 이름과 고객 번호를 적어 두십시오. SAP의 한도는 넉넉합니다. 하나의 Universal ID에 이메일 주소는 최대 10개, S-User 또는 P-User는 최대 100개까지 담을 수 있으며, 모두 귀하 본인의 것이어야 합니다.

만료일을 주의하십시오. 새 S-User는 기본 24개월 유효하며, 그 후 90일의 만료 단계를 거치고, 만료 30일, 14일, 2일 전에 이메일이 옵니다. 연장은 SAP for Me에서 직접 요청할 수 있고, 요청은 관리자에게 전달됩니다.

### 내 S-User ID를 찾는 방법

1. account.sap.com에서 SAP Account Manager에 로그인하고 **Accounts** 탭을 엽니다. Universal ID에 연결된 모든 사용자가 나열됩니다.
2. SAP for Me의 **My authorizations & functions**(내 권한 및 기능)에서 현재 로그인한 사용자가 무엇을 할 수 있는지 보여 줍니다.
3. 한 번도 받은 적이 없다면 S-User가 없는 것일 수 있습니다. 회사 관리자는 User Management 앱에서 모든 S-User를 볼 수 있습니다.

### 회사의 슈퍼 관리자를 찾는 방법

SAP는 신규 고객의 첫 S-User를 만들고 그것을 슈퍼 관리자로 지정합니다. 그 이후에는 회사의 관리자들이 다른 모든 S-User를 만듭니다. SAP는 대비책으로 슈퍼 관리자를 최소 두 명 더 두라고 권장합니다.

1. 해당 회사의 아무 S-User로 SAP for Me에 로그인합니다.
2. **Users & Contacts**를 연 다음 **Important contacts**(주요 연락처)를 엽니다. 슈퍼 관리자, 클라우드 관리자, 보안 담당자가 나열됩니다.
3. 슈퍼 관리자가 퇴사했고 다른 누구도 처리할 수 없다면, 컴포넌트 `XX-SER-FORME`로 케이스를 제기하면서 업무를 넘겨받을 사람을 지정하십시오.

아직 S-User가 없다면, IT 부서에서 SAP 지원 케이스를 제기하는 사람에게서 시작하십시오. 관리자는 S-User가 Universal ID에 연결되어 있는지 볼 수 없으므로, 그 부분은 관리자가 대신 고쳐 줄 수 없다는 점에 유의하십시오.

## 고객사 합류와 이탈 시 체크리스트

컨설턴트는 프로젝트의 시작과 끝에서 이런 문제에 부딪힙니다. 저라면 이 순서로 처리하겠습니다.

1. **첫날 전:** Universal ID의 기본 이메일이 개인 이메일인지 확인합니다.
2. **첫날:** 고객사 관리자에게 그들의 고객 번호로, 그곳에서 쓸 이메일로 만든 S-User를 요청합니다.
3. **같은 날:** 그 이메일을 SAP Account Manager에 추가하고 새 S-User가 나타나는지 확인합니다.
4. **첫 주:** 역할에 필요한 권한만 요청하고, 고객사가 강제하지 않았다면 2단계 인증을 켭니다.
5. **프로젝트 기간 중:** 여러 사용자가 같은 주소를 공유한다면 이메일 대신 S-User ID로 로그인합니다.
6. **떠나기 전:** 개인 이메일이 Universal ID에 있는지 확인합니다. 인증서를 새 S-User로 옮기려면 지원 티켓이 필요합니다.
7. **떠난 후:** S-User는 삭제될 것으로 예상하십시오. P-User와 Universal ID는 남습니다.

S-User는 하나의 고객 번호에 묶여 있어 다른 번호로 옮길 수 없으므로, 새 고객사에서는 항상 새 S-User가 필요합니다. 고객사가 BTP 접근 권한도 준다면 제 [SAP BTP Cockpit 가이드](/ko/master-the-sap-btp-cockpit-simple-steps/)부터 시작하십시오. 그곳의 로그인 실패는 다른 문제이며, 제 [BTP Cockpit 문제 해결 가이드](/ko/sap-btp-cockpit-issues/)에서 다룹니다.

## 자주 묻는 질문

<details>
<summary>SAP Universal ID란 무엇입니까?</summary>

SAP Universal ID는 모든 S-User와 P-User ID, 학습 인증서, SAP Community 평판을 담는 무료 개인 SAP 계정입니다. 고용주가 아닌 귀하의 것이므로 직장을 옮겨도 함께 남습니다. 2026년 1월부터는 로그인에 사용되지 않습니다.

</details>

<details>
<summary>S-User를 SAP Universal ID에 어떻게 연결합니까?</summary>

S-User의 이메일 주소를 추가합니다. account.sap.com의 SAP Account Manager에서 Accounts 탭을 열고 Add accounts를 클릭한 뒤, 이메일을 입력하고 패스코드를 확인합니다. 그 이메일을 가진 모든 S-User와 P-User가 자동으로 연결되며, 2026년 7월 13일 이전에 수동으로 연결한 것은 그대로 연결된 상태로 남습니다.

</details>

<details>
<summary>S-User와 P-User의 차이는 무엇입니까?</summary>

P-User는 개인용입니다. 직접 등록하며 직장을 옮겨도 따라옵니다. S-User는 고용주나 고객사의 관리자가 자사의 SAP 고객 번호로 만들며, 지원 케이스, 다운로드, 라이선스 키에 씁니다. 회사를 떠나면 관리자가 삭제합니다.

</details>

<details>
<summary>지금 SAP Universal ID 로그인은 어떻게 작동합니까?</summary>

2026년 1월부터는 Universal ID로 로그인하지 않습니다. S-User 또는 P-User ID나 그 사용자의 이메일, 그리고 해당 사용자 자신의 비밀번호로 로그인합니다. 여러 사용자가 하나의 이메일을 공유한다면 사용자 ID를 사용하십시오.

</details>

<details>
<summary>내 S-User ID는 어떻게 찾습니까?</summary>

account.sap.com에서 SAP Account Manager에 로그인하고 Accounts 탭을 엽니다. Universal ID에 연결된 모든 사용자가 나열됩니다. 거기에 없다면 회사의 SAP 관리자에게 문의하십시오. 관리자는 SAP for Me의 User Management 앱에서 회사의 모든 S-User를 볼 수 있습니다.

</details>

<details>
<summary>S-User를 여러 개 가질 수 있습니까?</summary>

예. S-User는 고객 번호 사이를 옮길 수 없으므로, 회사나 고객 번호마다 하나씩 갖게 됩니다. 하나의 Universal ID에 이메일 주소는 최대 10개, S-User 또는 P-User는 최대 100개까지 담을 수 있으며, 모두 귀하 본인의 것이어야 합니다.

</details>

<details>
<summary>SAP Universal ID 비밀번호는 어떻게 재설정합니까?</summary>

특정 S-User 또는 P-User의 비밀번호를 재설정합니다. accounts.sap.com으로 가서 Forgot password?를 클릭하고, 사용자 ID를 입력한 뒤 Send를 클릭한 다음, 2시간 안에 이메일의 링크를 사용하십시오. 재설정은 24시간에 한 번 할 수 있습니다.

</details>
