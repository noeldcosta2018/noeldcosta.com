SAP Universal ID 是一个免费的个人 SAP 账户，存放您所有的 S-User 和 P-User ID、证书以及 SAP Community 声誉，换工作时它也跟着您。自 2026 年起，它不再用于登录：您用各个 S-User 或 P-User ID 登录，而用户会通过邮箱地址自动关联到它。

> **简短回答。** P-User 是您自己的 SAP 用户。S-User 由雇主或客户在其 SAP 客户编号下发放。SAP Universal ID 就像一个钱包，在 account.sap.com 的 SAP Account Manager 中列出所有这些用户。

我刚接触 SAP 时，花了好几周才弄明白 P-User、S-User，以及它们之间是怎么关联的。重置密码的邮件几乎每周都有。

## S-User、P-User 与 Universal ID 的区别

下表列出每种 ID 归谁所有、用来做什么，以及您离开公司时会发生什么。

| | P-User | S-User | SAP Universal ID |
|---|---|---|---|
| 归谁所有 | 您 | 您的雇主或客户，在其 SAP 客户编号下 | 您 |
| 由谁创建 | 您，在 account.sap.com 注册 | 该公司的管理员，在 SAP for Me 中创建 | 您，在 account.sap.com 创建 |
| 用途 | SAP Community、试用、开发者内容、SAP Learning | 支持工单、软件下载、许可证密钥、系统数据 | 列出您的所有用户，保留证书和社区声誉 |
| 能否用来登录？ | 能 | 能 | 不能，自 2026 年 1 月起 |
| 有效期 | 无 | 默认 24 个月，管理员可延长 | 无 |
| 离开公司时 | 没有变化 | 管理员删除它，或它到期失效 | 仍归您所有。添加新的工作邮箱 |

我的 P-User 跟了我大约 16 年，陪我换了好几份工作。随着我在不同公司之间流动，我先后有过六个 S-User。Universal ID 就是把它们全部列在一张清单上的地方。

## 2026 年有哪些变化

SAP 今年做了两项变更。官方详情见 [SAP 的 Universal ID 页面](https://www.sap.com/account/universal-id.html)。

<explainer-timeline title="SAP Universal ID 在 2026 年的变化" caption="自 7 月起，添加邮箱地址就是关联账户的方式。手动关联按钮已经没有了。" items="2025 年 8 月 => 为每个用户设置密码|2026 年 1 月 20 日 => Universal ID 不再用于登录|2026 年 7 月 13 日 => 通过邮箱地址关联账户" notes="面向关联了多个身份的用户，持续到 2026 年 1 月|用 S-User 或 P-User ID 或其邮箱登录|手动关联取消。7 月之前建立的关联保持不变" highlight="3" source="SAP Universal ID 页面，sap.com"></explainer-timeline>

1. **2026 年 1 月：Universal ID 不再用于登录。** 它已不再是身份提供方。您用 S-User 或 P-User ID（或该用户的邮箱地址）以及该用户的密码，通过 SAP Cloud Identity Services（SAP IAS）登录。
2. **2026 年 7 月 13 日：通过邮箱地址关联。** 手动关联和取消关联的选项以及 Linked 状态列都已移除。凡是邮箱已登记在您 Universal ID 中的 S-User 或 P-User，都会自动关联；7 月之前手动关联的，保持关联不变。

两次变更都没有删除任何账户。如果您跳过了 2025 年为每个用户设置密码的提示，请在该用户上使用 Forgot password（忘记密码）。

## 如何管理您的 SAP Universal ID：分步说明

这里有两个地址很重要，而且容易混淆。**account.sap.com** 是 SAP Account Manager，您的 Universal ID 就在这里。带 s 的 accounts.sap.com 是每个单独用户的个人资料页面，密码和双因素认证设置都在那里。

### 如何创建 SAP Universal ID

1. 前往 [account.sap.com](https://account.sap.com/)，开始新的注册。表单标题是“Register your SAP ID”。
2. 输入您的姓名和个人邮箱地址，不要用工作邮箱。
3. 用户名可以留空，也可以自己选：最多 30 个字符，可用拉丁字母、数字、连字符和下划线。如果留空，SAP 会用您的姓名加数字生成一个。
4. 接受 Terms of Use（使用条款），完成验证码，然后点击 **Register**。
5. 输入 SAP 发到您邮箱的验证码。验证码 15 分钟内有效。

注册会创建您的 Universal ID，以及一个与之关联的用户身份。如果您已经有 Universal ID，就不要再注册第二个，而是把新邮箱添加到现有的那个。

### 如何把 S-User 关联到 SAP Universal ID

自 2026 年 7 月起，关联 S-User 的方式是添加它的邮箱地址，而不是添加用户本身。

1. 在 [account.sap.com](https://account.sap.com/) 登录 SAP Account Manager。
2. 打开 **Accounts** 选项卡，点击 **Add accounts**。
3. 输入该 S-User 上登记的邮箱地址。
4. 输入 SAP 发到该地址的验证码。
5. 检查列表。使用该邮箱的所有 S-User 和 P-User 现在都会显示在您的 Universal ID 下。

如果 S-User 没有出现，说明它的邮箱与您添加的不一致。请询问创建该用户的管理员，用户上登记的是哪个地址。

### 如何添加 P-User

旧的 P-User 也用同样的方式关联。按上面的五个步骤，添加注册该 P-User 时使用的邮箱地址。如果您根本没有 P-User，注册 Universal ID 的同时就会获得一个用户身份。

### 如何重置 SAP 密码

现在已经没有单独的、用于登录 SAP 网站的 Universal ID 密码需要重置了。您要重置的是具体某个 S-User 或 P-User 的密码。

1. 前往 [accounts.sap.com](https://accounts.sap.com/)，点击 **Forgot password?**
2. 输入用户 ID（SAP 推荐）或邮箱。如果多个用户共用该邮箱，就必须输入用户 ID。
3. 点击 **Send**。
4. 打开邮件，点击 **Click here to reset your password**。链接在 2 小时内失效。
5. 输入至少 8 个字符的新密码，需包含小写字母、大写字母、数字、符号中的三类。
6. 再输入一遍，然后点击 **Save**。

每 24 小时只能修改或重置一次密码。如果一直收不到邮件，SAP 的指南建议写信给 sso@sap.com。

### 如何从 Universal ID 中移除用户

自 2026 年 7 月 13 日起没有取消关联的按钮，而且您不能自己删除 S-User。SAP 给出的办法是请拥有该用户的公司的管理员处理。

1. 请该公司的管理员删除这个 S-User。
2. 管理员在 SAP for Me 中打开 User Management 应用，在 Actions 列中点击 Delete。
3. 如果该 S-User 担任某个特殊职能，例如软件接收人或技术联系人，SAP 需要先把这个职能转给其他人。
4. 删除后，S-User 会在 Deleted Users 中保留 12 个月，且无法重新激活。

如要删除 Universal ID 本身，请联系 SAP 的 Customer Interaction Center（CIC）。

### 如何更改 Universal ID 的邮箱

1. 在 [account.sap.com](https://account.sap.com/) 登录 SAP Account Manager。
2. 在 **Accounts** 选项卡中点击 **Add accounts**，输入新地址。
3. 输入发到新地址的验证码。
4. 打开 **Personal Info** 选项卡，把新地址设为主邮箱。

请保留您的个人邮箱作为备用。S-User 上的邮箱是另一回事：只有该公司的管理员才能修改。它一旦改变，这个 S-User 就会转到持有新地址的那个 Universal ID 下。

### 如何开启双因素认证

SAP 在每个用户的个人资料中提供基于时间的一次性密码（TOTP）双因素认证。

1. 在 [accounts.sap.com](https://accounts.sap.com/) 登录。
2. 滚动到 **TOTP Two-Factor Authentication**，点击 **Activate**。
3. 安装一个身份验证器应用。SAP 建议使用 Microsoft Authenticator 或 Google Authenticator。
4. 用应用扫描二维码。
5. 输入应用显示的验证码，点击 **Activate**。

随后页面会显示“You have a device configured for TOTP two-factor authentication”，SAP 也会发送一封邮件。换手机时，要先点击 **Deactivate** 并用验证码确认，再在新设备上重新激活。您的超级管理员可以强制启用 MFA，这会覆盖您自己的选择。

## SAP Universal ID 常见错误及解决方法

2026 年变更之后，大多数问题都归结为邮箱地址、按用户设置的密码和有效期。

| 问题 | 最可能的原因 | 解决方法 |
|---|---|---|
| 某个用户没有出现在 Accounts 选项卡中 | 它的邮箱与您 Universal ID 中的地址不同 | 在 Accounts 中添加该邮箱，或请管理员更正 S-User 上的邮箱 |
| 用户或邮箱已关联到另一个 Universal ID | 它在您以前创建的旧 Universal ID 下 | 提交 SAP 支持工单或联系 CIC。SAP 的 KBA 使用组件 `XX-SER-UID` |
| 用邮箱登录失败 | 多个用户共用该邮箱 | 改用 S-User 或 P-User ID 登录 |
| 2026 年 1 月后旧密码被拒绝 | 现在每个用户都有自己的密码 | 在该用户上使用 Forgot password |
| 密码被锁定 | 错误尝试次数过多 | 重置密码。我自己每年至少会遇到一次 |
| 无法再次修改密码 | 每 24 小时只能修改或重置一次 | 等待 24 小时 |
| 收不到重置邮件 | 垃圾邮件过滤，或用错了用户 | 检查垃圾邮件，用用户 ID 重试，然后写信给 sso@sap.com |
| 在某个浏览器中登录失败 | 第三方 Cookie 被阻止，或使用了 Internet Explorer | 允许第三方 Cookie，并使用最新版的 Chrome、Edge、Firefox 或 Safari |
| S-User 已过期 | 超过了到期日 | 管理员可在 90 天内重新激活。超过后会被删除，需要新的 S-User |
| 已登录但无法创建工单或下载 | 该 S-User 缺少相应权限 | 在 SAP for Me 中申请，由您的管理员批准 |

Universal ID 从不改变权限。每个 S-User 保留由该公司管理员授予的自身权限。

## 如果您持有多个 S-User

1 月的变更对顾问的影响最大。过去一个登录就能覆盖所有客户。现在每个 S-User 都有自己的密码，切换用户就得退出后重新登录。

把每个 S-User 当作客户的资产，而不是您自己的。在密码管理器中为每个 S-User 建一个条目，注明客户名称和客户编号。SAP 的上限很宽松：一个 Universal ID 最多可容纳 10 个邮箱地址和 100 个 S-User 或 P-User，但它们都必须属于您本人。

留意有效期。新 S-User 默认有效期为 24 个月，之后进入 90 天的即将过期阶段，在到期前 30 天、14 天和 2 天会收到邮件。您可以自己在 SAP for Me 中申请延期，申请会转到管理员那里。

### 如何查找您的 S-User ID

1. 在 account.sap.com 登录 SAP Account Manager，打开 **Accounts** 选项卡。它列出了关联到您 Universal ID 的所有用户。
2. 在 SAP for Me 中，**My authorizations & functions**（我的权限和职能）显示您当前登录的用户能做什么。
3. 如果从没收到过 S-User，您可能根本没有。贵公司的管理员可以在 User Management 应用中看到所有 S-User。

### 如何找到贵公司的超级管理员

SAP 会为新客户创建第一个 S-User，并把它设为超级管理员。此后，贵公司的管理员负责创建其他所有 S-User。SAP 建议至少再设两位超级管理员作为备份。

1. 用该公司的任意一个 S-User 登录 SAP for Me。
2. 打开 **Users & Contacts**，再打开 **Important contacts**（重要联系人）。这里列出超级管理员、云管理员和安全联系人。
3. 如果超级管理员已经离职，且没有其他人能处理，请在组件 `XX-SER-FORME` 上提交工单，写明应由谁接任。

如果您还没有 S-User，先去找 IT 部门里负责提交 SAP 支持工单的人。请注意，管理员看不到某个 S-User 是否已关联到 Universal ID，所以这一侧的问题他们没法替您解决。

## 进入和离开客户项目时的检查清单

顾问会在项目开始和结束时碰到这些问题。我会按以下顺序处理。

1. **第一天之前：** 确认您的 Universal ID 有一个个人主邮箱。
2. **第一天：** 请客户的管理员在其客户编号下为您创建一个 S-User，使用您在那里会用的邮箱。
3. **同一天：** 把该邮箱添加到 SAP Account Manager，并确认新的 S-User 已经出现。
4. **第一周：** 只申请您的角色所需的权限；如果客户没有强制要求，就自己开启双因素认证。
5. **项目期间：** 如果您的多个用户共用同一个地址，请用 S-User ID 而不是邮箱登录。
6. **离开之前：** 确认您的个人邮箱在 Universal ID 中。把证书转到新的 S-User 需要提交支持工单。
7. **离开之后：** 预计该 S-User 会被删除。您的 P-User 和 Universal ID 仍然保留。

S-User 绑定一个客户编号，不能转到另一个编号，所以换一个新客户就意味着要一个新的 S-User。如果客户还给了您 BTP 访问权限，请从我的 [SAP BTP Cockpit 指南](/zh-CN/master-the-sap-btp-cockpit-simple-steps/)开始。那里的登录失败是另一类问题，在我的 [BTP Cockpit 故障排除指南](/zh-CN/sap-btp-cockpit-issues/)中有介绍。

</details>
