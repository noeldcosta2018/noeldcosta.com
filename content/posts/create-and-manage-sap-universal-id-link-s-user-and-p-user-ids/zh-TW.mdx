如果您有不只一個 SAP 帳號（個人的 P-User，加上雇主或客戶給的 S-User），SAP Universal ID 就是把它們串在一起的個人帳號。它在 2026 年變動了兩次。從 1 月 20 日起，它不再是登入方式：現在您要用 S-User 或 P-User 的 ID，或該使用者名下的電子郵件，搭配該使用者自己的密碼登入。從 7 月 13 日起，手動連結功能取消。您在 SAP Account Manager 加入電子郵件地址，所有電子郵件相符的使用者就會自動連結。如果您還沒建立，請用個人電子郵件到 account.sap.com 註冊，再加入您的工作電子郵件地址。

剛接觸 SAP 的時候，我花了好幾個星期才搞懂 Universal ID、S-User 與 P-User 是怎麼搭配運作的。在有 Universal ID 之前，要管理這麼多帳號簡直是惡夢：密碼要靠試算表記，忘了哪組憑證用在哪裡，就得不斷收重設密碼的郵件。

## S-User、P-User 與 Universal ID 比較

下表列出每種 ID 由誰擁有，以及用途。

| ID 類型 | 擁有者 | 用途 | 離職時 |
|---|---|---|---|
| **P-User** | 您 | SAP Community、試用、開發人員內容、SAP Learning | 沒有任何改變，它是您的 |
| **S-User** | 您的雇主或客戶，掛在其 SAP 客戶編號之下 | 支援案件、軟體下載、授權金鑰、SAP for Me 中的系統資料 | 管理員將它刪除，或到期失效 |
| **Universal ID** | 您 | 把您的 S-User 與 P-User 放在同一份清單，另含學習證書與 SAP Community 聲望 | 它仍歸您所有。加入新雇主的電子郵件即可 |

我的 P-User 已經陪著我換過不同工作，大約 16 年了。我在不同公司之間流動，先後用過六個不同的 S-User。Universal ID 就是把它們全部放在同一份清單裡的地方。

Universal ID 請用個人電子郵件，不要用公司電子郵件。SAP 自己的常見問題也這樣建議。如果您離開公司、失去公司信箱，個人信箱就是您回得來的路。

## 2026 年有什麼改變

SAP 今年做了兩項改變，都會影響您如何登入，以及帳號如何連結。官方的詳細說明在 [SAP 的 Universal ID 頁面](https://www.sap.com/account/universal-id.html)。

<explainer-timeline title="SAP Universal ID 在 2026 年的變化" caption="自 7 月起，加入電子郵件地址就是帳號連結的方式，不再有手動連結按鈕。" items="2025 年 8 月 => 為每位使用者設定密碼|2026 年 1 月 20 日 => Universal ID 不再作為登入方式|2026 年 7 月 13 日 => 帳號改以電子郵件地址連結" notes="要求有多個已連結身分的使用者辦理，至 2026 年 1 月止|以 S-User 或 P-User ID，或其電子郵件登入|移除手動連結，7 月前建立的連結仍然保留" highlight="3" source="SAP Universal ID 頁面，sap.com"></explainer-timeline>

1. **2026 年 1 月 20 日：Universal ID 登入關閉。** Universal ID 不再是身分提供者 (identity provider)。您以 S-User 或 P-User 的 ID，或該使用者名下的電子郵件，加上該使用者的密碼登入。驗證透過 SAP Cloud Identity Services 進行。擁有多個已連結身分的使用者，在 2025 年 8 月至 2026 年 1 月之間被要求為每個身分各設一組密碼。如果您略過了這一步，請對每個使用者使用「忘記密碼」功能。
2. **2026 年 7 月 13 日：以電子郵件地址連結。** 手動連結與解除連結的選項已經移除。凡是電子郵件登記在您 Universal ID 下的 S-User 或 P-User，都會自動連結到它。7 月之前您手動連結的帳號仍維持連結。

對於手上有多個客戶 S-User 的顧問來說，1 月的這項改變是倒退。以前一次登入就涵蓋所有帳號。現在每個 S-User 又各有自己的密碼，要切換使用者就得登出再重新登入。請在密碼管理工具裡記下哪個 S-User 屬於哪位客戶、哪個客戶編號。

## 設定 Universal ID 並加入帳號

### 步驟 1：建立您的 SAP Universal ID

1. 前往 [account.sap.com](https://account.sap.com/)，點選 **Register**。
2. 輸入您的姓名與個人電子郵件地址，然後設定密碼。
3. 接受使用條款。行銷訊息的訂閱選項可自行決定是否勾選。
4. 輸入收件匣中的驗證碼，有效時間為 15 分鐘。
5. 登入 SAP Account Manager。您新的 P-User 會列在 **Accounts** 頁籤上。

整個過程只要幾分鐘。請先備好其他 SAP 使用者的電子郵件地址，才能緊接著加入。

### 步驟 2：加入其他帳號的電子郵件地址

1. 登入 [account.sap.com](https://account.sap.com/) 的 SAP Account Manager。
2. 開啟 **Accounts** 頁籤，點選 **Add accounts**。
3. 輸入您想帶進來的 S-User 或 P-User 所使用的電子郵件地址。
4. 輸入 SAP 寄到該地址的通行碼。
5. 檢查清單。每個使用該電子郵件的使用者，現在都會出現在您的 Universal ID 底下。
6. 對每個地址重複上述步驟，然後在 **Personal Info** 頁籤設定您的主要電子郵件。

一個 Universal ID 最多可容納 10 個電子郵件地址，以及最多 100 個 S-User 或 P-User。每個使用者只能歸屬於一個 Universal ID，而且這些使用者必須全都屬於同一個人。SAP Knowledge Base Article 2882908 說明了如何加入額外的電子郵件或使用者。

### 日常登入

當您的多個使用者共用同一個電子郵件地址時，SAP 建議用使用者 ID（S 或 P 後面接數字）登入。如果這些使用者還共用同一組密碼，以電子郵件登入會回傳錯誤，因為符合的使用者不只一個。

要切換使用者，請先登出，再用另一個登入。SAP 表示，之後會支援在工作階段中直接切換。在帳號選擇器裡，可以依登入日期排序，讓您最近使用的使用者排在最上面。

## 取得 S-User 或 P-User

### 配發 S-User

S-User 由貴公司的使用者管理員提供，不是由 SAP 提供。SAP 只會為新客戶建立第一位超級管理員 (super administrator)。之後，管理員在 [SAP for Me 的 User Management 應用程式](https://support.sap.com/content/s4m/help/users/admin.html)中申請 S-User。新使用者會收到有效期 10 天的啟用連結。請向管理員要求您的角色所需的權限：

1. **支援案件**：建立並追蹤事件單
2. **軟體下載**：安裝檔、修補程式與附加元件
3. **授權金鑰**：為系統申請金鑰
4. **系統資料**：維護安裝與系統

S-User 綁定一個客戶編號，無法轉到另一個客戶編號。S-User 也有到期日。接近到期時，您可以在 SAP for Me 申請延長，這項申請會送到管理員的待辦佇列。

如果找不到您的 SAP 管理員，先問 IT 部門。在規模較小的公司，則去問財務部門。基於授權的理由，他們幾乎都有 S-User 存取權，也會知道管理員是誰。

在 RISE with SAP 與 GROW with SAP 專案中，做法相同。客戶在自己的客戶編號下為顧問配發 S-User，合約結束時再刪除。這是預期中的事。那是他們的帳號，不是您的。

### 註冊 P-User

用您自己的電子郵件到 [account.sap.com](https://account.sap.com/) 註冊，一個步驟就同時取得 P-User 與 Universal ID。P-User 涵蓋 SAP Community、免費試用（例如我的 [SAP BTP Cockpit 指南](/zh-TW/master-the-sap-btp-cockpit-simple-steps/)裡用到的那一種）、開發人員資源與 SAP Learning。它不提供授權支援或軟體下載的存取，那是 S-User 的用途。

## 常見存取錯誤與解法

2026 年改變之後，大多數問題都出在電子郵件地址與密碼。

| 問題 | 最可能的原因 | 解法 |
|---|---|---|
| 您的 Accounts 頁籤中缺少某個使用者 | 它的電子郵件與您 Universal ID 中的地址不同 | 在 Accounts 下加入該電子郵件，或請管理員更正 S-User 上的電子郵件 |
| 使用者已與另一個 Universal ID 關聯 | 它掛在您先前建立的舊 Universal ID 底下 | 向 SAP 支援單位提出案件（SAP 的 KBA 使用元件 `XX-SER-UID`），請其解除綁定 |
| 以電子郵件登入失敗 | 多個使用者共用該電子郵件與密碼 | 改用 S-User 或 P-User ID 登入 |
| 2026 年 1 月之後舊密碼被拒絕 | 現在每個使用者都有自己的密碼 | 對該特定使用者使用「忘記密碼」 |
| 密碼被鎖定 | 輸入錯誤次數過多 | 等待，或重設密碼。我自己一年至少遇到一次 |
| S-User 停用或已到期 | 管理員已將它刪除，或已過到期日 | 請該公司的管理員延長或替換。如果是前一份工作的帳號，就放手吧 |
| 已登入但無法建立案件或下載 | 該 S-User 沒有該項權限 | 在 SAP for Me 申請。由管理員核准 |

如果完全無法登入，SAP 列出 Customer Interaction Center (CIC) 作為 Universal ID 協助的聯絡窗口。復原帳號需要驗證身分，所以如果您為了趕期限需要存取權，請盡早處理。

## 加入與離開客戶時的檢查清單

顧問總是在合約開始與結束時碰上這些問題。我會依照下面的順序處理。

1. **第一天之前：** 確認您的 Universal ID 主要電子郵件是個人信箱。
2. **第一天：** 請客戶的管理員在其客戶編號下為您建立 S-User，並使用您在該客戶那裡會用的電子郵件。
3. **同一天：** 在 SAP Account Manager 加入該電子郵件，並確認新的 S-User 出現。
4. **第一週：** 只申請您的角色所需的權限。管理員會在 SAP for Me 中核准。
5. **合約期間：** 如果您的多個使用者共用同一個電子郵件地址，請用 S-User ID 而不是電子郵件登入。
6. **離開之前：** 如果您在該 S-User 底下取得了證書，請確認您的個人電子郵件已在 Universal ID 中。要把證書移到新的 S-User，需要提出支援案件。
7. **離開之後：** 預期該 S-User 會被刪除。您的 P-User 與 Universal ID 則會保留。

如果客戶同時給了您 BTP 的存取權，那邊的登入失敗是另一個問題。我的 [BTP Cockpit 疑難排解指南](/zh-TW/sap-btp-cockpit-issues/)說明了 401 錯誤。

## 常見問題

<details>
<summary>SAP 中的 P-User 與 S-User 有什麼不同？</summary>

P-User 屬於個人。由您自己註冊，歸您所有，換工作時也跟著您。它讓您存取 SAP Community、免費試用、開發人員內容與 SAP Learning。

S-User 屬於您的雇主或客戶。由對方的使用者管理員在 SAP for Me 中、於其客戶編號之下建立。它可存取有授權的服務，例如支援案件、軟體下載與授權金鑰。您離開時，他們會把它刪除。

SAP Universal ID 把這兩種使用者放在同一份清單裡，另外還有您的證書與社群聲望。

</details>

<details>
<summary>我還能用 SAP Universal ID 登入嗎？</summary>

不行。自 2026 年 1 月 20 日起，Universal ID 不再是身分提供者。您以 S-User 或 P-User 的 ID，或該使用者名下的電子郵件地址，搭配該使用者的密碼登入。Universal ID 現在的作用像一個錢包，收納您的使用者、證書與 SAP Community 聲望。您仍然要登入 account.sap.com 的 SAP Account Manager 來管理它。

</details>

<details>
<summary>2026 年 7 月之後，如何把 S-User 連結到我的 SAP Universal ID？</summary>

您要加入的是 S-User 的電子郵件地址，而不是連結使用者。在 SAP Account Manager 中開啟 Accounts 頁籤，點選 Add accounts，輸入電子郵件，並確認 SAP 寄給您的通行碼。使用該電子郵件的所有 S-User 與 P-User，就會自動出現在您的 Universal ID 底下。2026 年 7 月 13 日之前您手動連結的使用者，仍維持連結。

</details>

<details>
<summary>我的 SAP Universal ID 該用哪個電子郵件地址？</summary>

主要地址請用個人電子郵件，並把工作電子郵件地址一併加進去。離開公司、失去公司信箱之後，個人地址能讓您仍然登入得了 Universal ID。SAP 在其 Universal ID 常見問題中也有同樣的建議。

</details>

<details>
<summary>換工作時，我的 SAP Universal ID 會怎麼樣？</summary>

您的 Universal ID 會跟著您。舊雇主的管理員會撤回或刪除該 S-User。如果新雇主以您 Universal ID 中已有的電子郵件建立 S-User，它會自動連結。如果用的是新的電子郵件，請在 SAP Account Manager 加入該地址。

整個過程中，您的 P-User 與 Universal ID 都不受影響。

</details>

<details>
<summary>一個 SAP Universal ID 最多能連結多少個帳號？</summary>

每個 Universal ID 最多 10 個電子郵件地址，以及最多 100 個 S-User 或 P-User。這些全都必須屬於您本人。超出這個範圍，SAP 會視為代他人管理使用者，共用帳號會導致停權。

</details>

<details>
<summary>SAP Universal ID 會改變我在 SAP 系統中可存取的內容嗎？</summary>

不會。每個 S-User 保有自己的權限。如果您的 S-User 沒有下載權限，把它加入 Universal ID 並不會多出這項權限。權限由貴公司的使用者管理員在 SAP for Me 中授予。

</details>

<details>
<summary>如果無法登入 SAP，該怎麼辦？</summary>

先確認您是用哪個使用者在登入。自 2026 年 1 月起，每個 S-User 與 P-User 都有自己的密碼，所以請對那個特定的使用者使用「忘記密碼」。如果有多個使用者共用您的電子郵件，請改用使用者 ID 登入。

如果您已無法存取該帳號上的電子郵件，請聯絡 SAP 的 Customer Interaction Center，或提出支援案件。SAP 會先驗證您的身分，才會恢復存取。

</details>
