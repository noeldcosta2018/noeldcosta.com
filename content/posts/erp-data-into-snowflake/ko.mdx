2026년에 SAP 데이터를 Snowflake로 가져오는 현실적인 방법은 세 가지입니다. 제로 카피 공유를 제공하는 SAP Business Data Cloud, Snowflake가 적재할 클라우드 스토리지로의 SAP Datasphere 복제, 또는 SAP가 허용하는 인터페이스를 쓰는 서드파티 도구입니다. Oracle과 Microsoft Dynamics 365는 더 단순해 보이지만, 각각 함정이 있습니다.

Oracle Fusion Cloud ERP에는 복제할 데이터베이스가 없습니다. Dynamics 365 finance and operations는 몇 주 뒤면 Export to Azure Data Lake를 잃습니다.

추출 도구는 작은 결정입니다. 제가 참여한 제조와 방위 산업 프로그램에서 시간이 들어간 곳은 데이터가 도착한 뒤의 일이었습니다. ERP 테이블 해독, 삭제 처리, 통화와 단위 맞추기, ERP가 적용하던 접근 규칙 재구축입니다.

SAP, Oracle, Dynamics 365 데이터에 대해 제가 실제로 쓴 경로는 미들웨어였습니다. 제 조언은 단일 목적 커넥터가 아니라 더 큰 스택, 즉 눈앞의 시스템 하나보다 더 많은 소스 시스템을 감당할 수 있는 미들웨어를 고르라는 것입니다. 어떤 제품을 고르든, SAP에 대해 사용하는 인터페이스를 아래 노트와 대조해 확인하십시오.

## SAP 데이터를 Snowflake로 가져오기

### SAP Business Data Cloud와 제로 카피 공유

SAP와 Snowflake는 2026년 5월 SAP Sapphire에서 두 가지 공동 제품의 정식 출시를 발표했습니다. 커넥터에 대한 Snowflake의 릴리스 노트 날짜는 2026년 5월 4일입니다.

1. **SAP Snowflake.** SAP Business Data Cloud(BDC) 안에서 인증된 SAP Solution Extension으로 제공되는 Snowflake이며, SAP가 판매와 지원을 맡고 SAP for Me에서 프로비저닝됩니다. Snowflake 계정이 없는 SAP 고객을 대상으로 합니다.
2. **SAP BDC Connect for Snowflake.** 이미 Snowflake를 운영하는 기업을 위한 것입니다. SAP for Me의 초대 링크로 기존 계정을 연결합니다.

두 경우 모두 SAP 데이터 제품은 데이터를 복사하지 않고 카탈로그 연결 데이터베이스로 Snowflake에 마운트됩니다. 이를 쿼리하고 조인할 수 있으며, SAP의 메타데이터로 Cortex Analyst용 시맨틱 뷰를 생성하고, Snowflake 데이터를 BDC로 다시 게시할 수 있습니다.

Snowflake의 [SAP 제로 카피 통합 문서](https://docs.snowflake.com/en/user-guide/data-integration/zero-copy/about-sap-snowflake)에는 AWS, Azure, GCP 상용 리전이 나열되어 있고 정부 리전은 제외되어 있습니다. 방위 산업 업무라면 이 제외 하나만으로도 선택지에서 빠질 수 있습니다.

함정은 범위입니다. 제로 카피는 BDC 데이터 제품을 공유하므로, BDC 구독이 필요하고 SAP가 패키징한 것만 받게 됩니다. 이를 전제로 계획하기 전에, 귀사 릴리스에서 제공되는 데이터 제품과 리포팅 요구를 대조해 보십시오.

특히 사용자 정의 필드와 Z 테이블을 확인하십시오. 이것들이 포함되지 않는다면 사용자 정의 데이터 제품이나 두 번째 경로가 필요합니다.

### SAP Datasphere 복제 플로우

SAP Datasphere 복제 플로우는 SAP가 프리미엄 아웃바운드 통합이라고 부르는 방식을 통해 S/4HANA, ECC, BW의 데이터를 SAP 외 대상으로 옮깁니다. 테넌트에서 이를 활성화하고 규모를 정해야 합니다. SAP의 연결 매트릭스에서 Snowflake는 복제 플로우 대상이 아닙니다.

일반적인 패턴은 클라우드 오브젝트 스토리지(Amazon S3, Azure Data Lake Storage Gen2, Google Cloud Storage)로 복제한 뒤 거기서 Snowflake로 적재하는 것입니다. Datasphere 용량 비용을 내고, 두 단계를 거칩니다.

### ODP 노트: 커넥터를 사기 전에 읽으십시오

SAP Note 3255746 "Unpermitted usage of ODP Data Replication APIs"는 2022년 10월에 처음 게시되었습니다. 2024년 2월 개정판은 ODP(Operational Data Provisioning) Data Replication API의 RFC 모듈을 다룹니다. 고객 또는 서드파티 애플리케이션에서 이 모듈을 사용해 온프레미스나 Cloud Private Edition의 SAP ABAP 소스에 접근하는 것은 SAP가 허용하지 않는다고 명시합니다.

2024년 7월 업데이트는 SAP 데이터를 서드파티 도구로 복제하려면 SAP Datasphere를 쓰라고 안내합니다. 이 노트는 2026년 4월에 다시 개정되었습니다.

2026년 6월에 SAP는 바로 이 API들의 호출자 식별 누락에 대한 취약점 기록 CVE-2026-44754도 게시했습니다. 제가 보기에 이 제한은 문서상의 규정에서 기술적 강제로 옮겨 가고 있습니다. 이 노트는 SAP 로그인이 필요하므로, 벤더의 요약에 기대지 말고 최신 버전을 직접 읽으십시오.

많은 서드파티 SAP 커넥터가 RFC 기반 ODP 위에 만들어졌습니다. 모든 벤더에게 커넥터가 어떤 SAP 인터페이스를 쓰는지 묻고, RFC 기반 ODP라면 그 노트에 대한 입장을 서면으로 받으십시오.

Snowflake의 관리형 수집 서비스인 Snowflake Openflow의 [현재 커넥터 목록](https://docs.snowflake.com/en/user-guide/data-integration/openflow/connectors/about-openflow-connectors)에는 SAP 커넥터가 없습니다(2026년 10월 확인). SAP는 제로 카피 커넥터 항목에만 나옵니다.

## Oracle: E-Business Suite와 Fusion은 서로 다른 문제입니다

**Oracle E-Business Suite**는 귀사가 통제하는 Oracle 데이터베이스에서 실행되므로 로그 기반 변경 데이터 캡처(CDC)를 쓸 수 있습니다. [Openflow Connector for Oracle](https://docs.snowflake.com/en/user-guide/data-integration/openflow/connectors/oracle/about)은 2026년 2월에 정식 제공되었습니다. Oracle XStream을 사용하며, 온프레미스, Exadata, OCI 가상 머신이나 베어메탈의 Oracle Database 11g 이상을 지원합니다.

라이선스는 주의가 필요합니다. 36개월 약정으로 Snowflake를 통해 청구되는 내장 XStream 라이선스를 쓰거나, GoldenGate처럼 XStream 권한이 포함된 자체 Oracle 라이선스를 가져와야 합니다. Snowflake 문서는 Oracle이 XStream에 Enterprise Edition을 요구한다고 명시합니다.

복제되는 테이블마다 기본 키, 고유 제약 조건이나 인덱스, 또는 선언된 논리 키가 필요하며, TRUNCATE는 복제되지 않습니다. 약정하기 전에 필요한 EBS 테이블의 키 보유 여부를 확인하십시오.

Oracle GoldenGate는 또 하나의 검증된 경로입니다. Snowflake는 문서화된 GoldenGate 대상이며, 스테이지 후 병합 방식의 마이크로 배치나 Snowpipe Streaming을 사용합니다.

**Oracle Fusion Cloud ERP**는 SaaS입니다. Openflow Oracle 커넥터는 Fusion Cloud Applications를 명시적으로 지원하지 않습니다. 표준 추출 경로는 Business Intelligence Cloud Connector(BICC)입니다.

BICC는 예약된 전체 또는 증분 추출로, 매니페스트와 함께 압축 CSV 파일을 OCI Object Storage나 Oracle 콘텐츠 서버에 씁니다. 그다음 그 파일을 Snowflake로 옮깁니다. BICC는 기본 키만 따로 추출할 수도 있으며, 삭제는 이렇게 감지합니다.

Oracle의 GoldenGate FAQ에는 GoldenGate가 OCI에서 실행되는 Fusion SaaS 애플리케이션에서 캡처할 수 있다고 되어 있습니다. 이것이 중요하다면 귀사 테넌시와 라이선스에 무엇을 의미하는지 Oracle에 물으십시오.

## Microsoft Dynamics 365: 마감 기한은 실제입니다

Dynamics 365 Finance and Operations에 대해 Microsoft는 2024년 11월 1일에 Export to Azure Data Lake를 지원 중단했습니다. 이 기능은 연장 없이 [2026년 11월 30일에 완전히 중단](https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/fin-ops/get-started/removed-deprecated-features-platform-updates)됩니다. 아직 이것에 의존하는 Snowflake 파이프라인이 있다면, 이번 분기에 가장 먼저 할 일입니다.

대체 수단은 Azure Synapse Link for Dataverse와 Fabric link입니다. Microsoft는 대부분의 고객에게 Fabric link를 권장하지만, 이는 데이터를 Microsoft Fabric에 둡니다. Snowflake가 대상이라면 Synapse Link가 현실적인 선택입니다.

Synapse Link는 finance and operations 테이블을 귀사 스토리지 계정에 Delta Parquet 포맷으로 쓰며, 삭제된 행은 `isDelete` 필드에 표시된 채 유지됩니다. Snowflake는 오브젝트 스토리지의 Delta 파일을 읽기 전용 Iceberg 테이블로 읽을 수 있으며(2025년 4월부터 정식 제공), 적재할 수도 있습니다.

Dynamics 365 Sales와 Customer Service 같은 Dataverse 기반 앱에는 Openflow Connector for Microsoft Dataverse가 정식 제공되고 있습니다. 이 커넥터는 플래그 열로 행을 논리 삭제합니다.

변경 토큰은 7일 동안 활동이 없으면 만료되어 전체 재동기화가 강제되므로, 일정이 끊기지 않게 하십시오. 문서에는 Finance and Operations가 언급되지 않으므로, 직접 테스트하지 않았다면 고객 참여(CE) 앱용 경로로 취급하십시오.

## 선택지 한눈에 보기

2026년 10월 기준으로 제가 ERP별로 후보에 올릴 경로입니다.

| ERP | 현실적인 선택지 | 비고 |
|---|---|---|
| SAP S/4HANA, ECC | SAP Snowflake 또는 BDC Connect for Snowflake를 사용하는 SAP BDC, 오브젝트 스토리지를 거치는 Datasphere 복제 플로우, 서드파티 도구 | 제로 카피는 BDC 데이터 제품만 대상. SAP Note 3255746이 RFC 기반 ODP를 제한. Openflow SAP 커넥터 없음 |
| Oracle E-Business Suite | Openflow Connector for Oracle, Oracle GoldenGate, 서드파티 CDC | XStream 라이선스와 Enterprise Edition 필요. 테이블마다 키 필요. TRUNCATE는 복제되지 않음 |
| Oracle Fusion Cloud ERP | 오브젝트 스토리지로 BICC 추출 후 적재, GoldenGate(Oracle에 확인) | 데이터베이스 직접 접근 불가. Openflow Oracle 커넥터는 Fusion 미지원 |
| Dynamics 365 Finance and Operations | 귀사 스토리지로의 Azure Synapse Link for Dataverse 후 Iceberg 테이블 또는 적재, Fabric link | Export to Azure Data Lake는 2026년 11월 30일 중단. 삭제는 플래그된 행으로 전달 |
| Dynamics 365 Sales, Customer Service | Openflow Connector for Microsoft Dataverse | 논리 삭제. 7일 토큰 만료 시 재동기화 강제 |

## 아무도 비용에 반영하지 않는 데이터 모델 문제

제가 본 모든 ERP 파이프라인은 추출 경로와 상관없이 같은 문제에 부딪혔습니다. 예산은 여기로 들어갑니다.

1. **테이블 복잡성.** ERP 테이블은 분석이 아니라 트랜잭션을 위해 설계되었습니다. SAP S/4HANA에서는 유니버설 저널(`ACDOCA`)과 자재 문서(`MATDOC`)가 많은 ECC 테이블을 대체했으므로, ECC 로직은 그대로 옮겨지지 않습니다. EBS에는 멀티 오그 구조가 있고, Dynamics에는 테이블과 일대일로 대응하지 않는 엔터티가 있습니다. 소스 시스템을 아는 사람에 대한 예산을 잡으십시오.
2. **변경 캡처와 삭제.** 경로마다 삭제를 알리는 방식이 다릅니다. 플래그 열, 키만 담은 추출, 또는 아무 신호도 없는 경우입니다. TRUNCATE와 아카이빙 실행은 소리 없이 Snowflake를 ERP와 어긋나게 만들 수 있습니다. 레코드 수와 잔액은 한 번이 아니라 정기적으로 대사하십시오.
3. **통화와 단위.** ERP 금액은 전표 통화, 현지 통화, 그룹 통화로 존재하며, 환율 유형과 전기일이 따라붙습니다. 수량에는 자재별 환산이 적용되는 단위가 붙습니다. 이것을 SQL로 재구축하는 지점에서 재무가 숫자를 믿지 않게 됩니다.
4. **마스터 데이터.** 자재, 고객, 공급업체, 공장은 ERP와 법인마다 다릅니다. ERP를 두 개 운영한다면 마스터 데이터 매핑은 그 자체로 하나의 프로젝트입니다. [SAP 데이터 마이그레이션이 실패하는 이유](/ko/why-sap-data-migration-fails-and-how-to-fix-it/)에 관한 제 글이 같은 근본 원인을 다룹니다.
5. **권한은 데이터와 함께 오지 않습니다.** ERP는 회사 코드, 플랜트, 손익 센터 제한을 적용했습니다. Snowflake는 그중 아무것도 모릅니다. 핵심 팀 밖의 누군가에게 접근을 열기 전에 행 수준 및 열 수준 보안을, 방위 산업이라면 통제 대상 데이터의 분리까지 다시 구축해야 합니다.

## 효과가 있는 순서

1. **목표 질문부터 정합니다.** 비즈니스 질문 5~10개와 그에 답하는 리포트를 고르십시오. 그것이 필요한 테이블을 결정합니다.
2. **소스를 목록화합니다.** ERP 버전, 배포 방식, 데이터베이스 에디션, 사용자 정의 필드, 그리고 다운스트림 시스템이 의존하는 기존 추출 전부입니다.
3. **도구보다 라이선스를 먼저 정리합니다.** BDC 구독, Datasphere 용량, XStream 권한, 각 벤더의 ODP 노트에 대한 입장입니다. 답은 서면으로 받으십시오.
4. **위의 표를 사용해 ERP별 경로를 고릅니다.** 경로가 섞이는 것은 정상입니다.
5. **소스를 그대로 반영하는 원시 계층을 구축합니다.** 적재 타임스탬프와 삭제 플래그를 유지하십시오.
6. **그 위에 표준화된 모델을 구축합니다.** 통화 및 단위 환산, 마스터 데이터 매핑, 회계 달력입니다.
7. **접근을 열기 전에 행 접근 정책과 마스킹 정책으로 보안을 재구축합니다.**
8. **ERP와 대사하고 그 점검을 자동화합니다.** 재무가 모델을 신뢰하기 전에 반드시 통과해야 하는 것은 ERP와 일치하는 시산표입니다. 재고 금액도 같은 방식으로 점검할 가치가 있습니다.
9. **운영을 이관합니다.** 모니터링, 스키마 변경 처리, 파이프라인별 지정 책임자입니다.

비용 계획에 대해서는 이 시리즈의 [Snowflake 가격과 크레딧 가이드](/ko/snowflake-pricing-credits-explained/)가 지속적인 복제가 청구서에 미치는 영향을 설명합니다.

## 제조 팀이 보통 가장 먼저 원하는 것

제조업의 첫 요청은 예측 가능하며, 데이터 모델을 시험합니다.

1. **재고.** 공장별 재고, 연령 분석, 저회전 품목입니다. 단위와 평가 문제를 일찍 드러냅니다.
2. **OTIF(On-Time In-Full).** 판매 오더, 납품, 확정일이 맞춰져 있어야 하므로 변경 캡처를 시험합니다.
3. **제품 원가.** 표준원가 대 실제원가와 차이입니다. 재무 데이터와 생산 데이터가 대사되어 있어야 합니다.
4. **품질.** 검사 결과, 결함, 부적합이며, ERP 밖의 설비 데이터나 히스토리안 데이터와 결합되는 경우가 많습니다.

저라면 재고로 시작하겠습니다. 마스터 데이터, 단위, 평가를 한 번에 건드리고, 공장 관리자가 실제로 선반에 있는 것과 대조해 확인할 수 있습니다. 아직 ERP 자체를 고르고 있다면 제 [제조업을 위한 최고의 ERP](/ko/best-erp-for-manufacturing/) 가이드가 선정 측면을 다룹니다.

플랫폼부터 비교하고 계십니까? [Snowflake vs Databricks](/ko/snowflake-vs-databricks/)를 보십시오.

## 자주 묻는 질문

<details>
<summary>SAP 데이터를 Snowflake로 어떻게 가져옵니까?</summary>

SAP가 지원하는 선택지는 데이터를 복사하지 않고 SAP 데이터 제품을 공유하는, SAP Snowflake 또는 BDC Connect for Snowflake를 사용하는 SAP Business Data Cloud입니다. 다른 하나는 클라우드 오브젝트 스토리지로의 SAP Datasphere 복제 플로우이며, 그 뒤 Snowflake가 적재합니다. 서드파티 도구도 있지만, 어떤 SAP 인터페이스를 쓰는지 SAP Note 3255746과 대조해 확인하십시오.

</details>

<details>
<summary>SAP Snowflake는 정식 제공되고 있습니까?</summary>

네. SAP Snowflake와 SAP BDC Connect for Snowflake는 2026년 5월 SAP Sapphire에서 정식 출시가 발표되었습니다. Snowflake 문서는 정부 리전을 제외하고 있으며, 이는 방위 산업과 공공 부문에 중요합니다.

</details>

<details>
<summary>서드파티 도구가 아직 ODP로 SAP 데이터를 추출할 수 있습니까?</summary>

SAP Note 3255746은 ODP Data Replication API의 RFC 모듈을 고객이나 서드파티가 사용하는 것은 허용되지 않는다고 명시합니다. SAP는 대신 Datasphere를 쓰라고 안내합니다. 각 벤더에게 어떤 인터페이스를 쓰는지, 그 노트에 어떻게 대응하는지 물으십시오. 최신 노트는 SAP 지원 포털에서 직접 읽으십시오.

</details>

<details>
<summary>Oracle Fusion Cloud ERP 데이터를 Snowflake로 어떻게 옮깁니까?</summary>

Fusion은 SaaS이므로 데이터베이스 CDC 도구는 적용되지 않으며, Snowflake의 Openflow Oracle 커넥터도 이를 지원하지 않습니다. 표준 경로는 오브젝트 스토리지로의 BICC 추출 후 Snowflake로 적재하는 것입니다. 삭제를 감지할 수 있도록 기본 키를 별도로 추출하십시오.

</details>

<details>
<summary>Dynamics 365 Finance and Operations에서 Export to Data Lake를 무엇이 대체합니까?</summary>

Azure Synapse Link for Dataverse 또는 Fabric link입니다. Export to Azure Data Lake는 2026년 11월 30일에 완전히 중단됩니다. Snowflake가 대상이라면 Synapse Link가 귀사 스토리지에 Delta Parquet를 쓰고, Snowflake는 이를 Iceberg 테이블로 읽거나 적재할 수 있습니다.

</details>
