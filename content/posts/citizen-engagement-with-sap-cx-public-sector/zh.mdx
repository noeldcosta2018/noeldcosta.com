一家中型欧洲政府机构负责许可证、地方税和日常市民服务，它在 SAP Customer Experience（CX）上重建了与市民的互动方式。机构用 SAP Service Cloud 管理案件，用 SAP Customer Data Cloud 实现一次登录和授权同意，用 SAP Emarsys 发送提醒，用 SAP Commerce Cloud 处理付款，再通过 SAP Business Technology Platform（BTP）把它们与后台系统连接起来。处理时间缩短了近 50%。最关键的改变比任何一个模块都简单：市民和工作人员看到的是同一个请求的同一个状态。

市民已经开始期待公共服务像网上银行一样清晰。这是我们从受访者那里听到的。他们希望登录一次，在一个地方看到所有事项，并相信自己的请求得到了公平处理。旧系统做不到这一点。各部门各自保存记录，每个窗口都问同样的问题，工作人员还要重新录入已经在别处收到的数据。

我们学到的第一件事很简单：设计之前先倾听。早期的大部分优先事项来自窗口前的投诉、调查记录和简短的交谈，这些比任何规划文档都有用。

## 四个模块，四类问题

我们选用了 SAP CX 产品组合中的几个部分，每个都有明确的任务。

| 模块 | 解决的问题 | 带来的变化 |
|---|---|---|
| SAP Service Cloud | 案件分散在各部门，没有共享视图 | 工作人员有统一的案件视图，市民可以跟踪状态 |
| SAP Customer Data Cloud | 每项服务各有一套登录，授权同意不透明 | 一次安全登录；市民可以查看并管理自己的授权 |
| SAP Emarsys（现为 SAP Engagement Cloud） | 市民主动追问机构，机构从不主动联系市民 | 续期、费用和截止日期提醒 |
| SAP Commerce Cloud | 现场付款，人工对账 | 在线付款，即时收据，财务数据直接更新 |

**Service Cloud** 成了主力。无论请求来自线上、电话还是窗口，都走同一套流程。承办人员终于能看到，刚刚申请停车许可的市民，上周还打电话咨询过一个税务问题。我们在系统内设定了服务水平，这迫使各方承担责任。当办理时限清晰而现实时，市民是看得出来的。

我们只让聊天机器人处理简单的事。一位市民告诉我们，不用在电话里排队等候，就能快速查到办公时间，这让她松了一口气，但她也说：“如果有争议，我要找真人。”我们同意她的看法。

**Customer Data Cloud** 终结了许可证、税务和营业许可各用一套登录的局面，也让授权同意变得可见。在一次反馈会上，一位本地企业主说：“至少现在我知道数据去了哪里。以前感觉像是盲签。”这种透明度比我们预想的更重要。

**Emarsys** 把模式从等电话改成了主动发送提醒、截止日期通知和进展更新。它教会了我们克制。提醒太多就会被忽略。续期或税务截止日期的通知之所以受到关注，是因为它与市民切身相关。

**Commerce Cloud** 把申请、费用和确认放进同一次在线操作。收据即时生成，队伍变短，财务人员也不必再整晚核对电子表格。

## 改变设计的那次测试运行

我记得有一次测试运行，市民门户显示“处理中”，而工作人员的屏幕显示“等待审批”。同一个请求，两个状态。这种不一致带来的是更多来电，而不是更少。

我们的解决办法，是让两边读取同一条 Service Cloud 记录里完全相同的数据。来电量开始下降，靠的就是这个修复，而不是任何功能。我们由此明白，市民最看重的是清晰，甚至胜过速度。

## 通过 SAP BTP 连接后台

一开始，我们低估了系统之间的缝隙里藏着多少手工工作。市民可以在线申请许可证，但工作人员仍要手工把请求推送到 ERP。付款以电子方式到账，却要到周末才与财务核对。社会服务部门运行着自己的案件管理系统，其他人都看不到。

BTP 成了连接的纽带。Service Cloud 与 S/4HANA 及旧平台连通之后：

1. 许可证申请直接在 ERP 中启动工作流。
2. 通过 Commerce Cloud 的付款实时更新财务记录。
3. 在隐私规则允许的范围内，社会服务案件的状态对其他部门可见。

社会福利项目是最难的部分。隐私规则划定了界限，所以我们只在摘要层面开放案件状态，绝不开放详细记录。即便如此，也起到了作用。住房部门可以看到某位市民是否已在接受援助项目，从而避免重复援助。一位承办人员对我说：“我第一次不用翻四个系统，就能看到一位市民案件的全貌。”

## 360 度市民视图

“360 度市民视图”起初听起来像行话。对工作人员和市民来说，它的意思很简单：别再让人把自己的情况讲五遍。我们把身份信息、交易、服务请求和沟通历史整合进一个档案。当有人申请住房补助时，承办人员还能看到他正在办理的一项医疗理赔，以及他最近与税务部门的一次沟通。机构开始像一个整体那样行事。

数据清理进展缓慢，有时还很枯燥。但错误减少之后，信任随之上升。建立在重复记录之上的 360 度视图，会把重复记录展示给每一个人。

## 成果

| 领域 | 之前 | 之后 |
|---|---|---|
| 处理时间 | 基准水平 | 缩短近 50% |
| 跟踪请求 | 打电话和到窗口询问 | 市民在线跟踪申请 |
| 登录 | 每个部门一个账户 | 一次安全登录，授权同意清晰可见 |
| 员工数据录入 | 在系统之间重复录入 | 统一案件视图，员工只处理例外情况 |
| 付款 | 现场支付，每周人工对账 | 在线支付，即时收据 |

许可证、税费和执照终于遵循同样的步骤，市民也注意到了这种一致性。市民不再问“我的申请到哪一步了？”，因为他们自己就能看到。

## 对其他公共部门项目的经验

1. **先倾听。** 用窗口投诉、调查和满意度评分来确定优先级，而不是照着厂商的演示脚本走。
2. **只显示一个状态。** 市民和员工必须看到同一条记录。没有什么比这更能迅速减少来电。
3. **全渠道不等于只做移动端。** 所有人都说“移动优先”，但年长居民更喜欢网页或电话。我们让市民从线上开始，再切换到电话，由员工从同一个节点接着办理。
4. **先自动化简单的情形。** 我们从续期入手，因为那里规则清晰。员工担心复杂案件会失去控制，所以我们循序渐进，这份耐心赢得了信任。
5. **发送提醒，而不是营销。** 消息只限于截止日期和案件进展。
6. **集成之前先清理数据。** 否则 360 度视图会把所有错误一次性暴露出来。

最大的经验也是最简单的一条：尊重人们的时间。我们这样做之后，信任随之而来。关于公共部门 SAP 项目的合规方面，请参阅我的[SAP 公共部门合规](/zh-CN/sap-implementation-public-sector-compliance/)指南。关于同一行业的采购案例，请看我的 [SAP Ariba 阿联酋公共部门案例研究](/zh-CN/sap-ariba-implementation-uae-public-sector/)。

### 此后 SAP 产品组合发生了哪些变化

有一个名称变了。2026 年 2 月，SAP 把 SAP Emarsys 更名为 [SAP Engagement Cloud](https://news.sap.com/2026/02/sap-engagement-cloud-advances-enterprise-engagement-strategy/)。SAP Marketing Cloud 已经到达生命周期终点，因此新项目会用 Engagement Cloud 来做主动沟通。上述设计经验并不依赖产品名称。

## 常见问题

<details>
<summary>哪些 SAP CX 模块最适合公共部门的市民互动？</summary>

在这个项目中：用 SAP Service Cloud 做案件管理，用 SAP Customer Data Cloud 实现一次登录和授权同意，用 SAP Emarsys（现为 SAP Engagement Cloud）发送提醒，用 SAP Commerce Cloud 处理付款。先从案件层入手，再加身份，然后是主动触达和付款。

</details>

<details>
<summary>SAP CX 给这家机构带来了哪些成果？</summary>

处理时间缩短了近 50%。市民可以在线跟踪申请，不必再打电话；一次登录取代了多次登录；员工不再在系统之间重复录入数据；付款转到线上，并即时出具收据。

</details>

<details>
<summary>SAP Service Cloud 与政府使用的普通 CRM 有什么不同？</summary>

销售型 CRM 围绕线索和销售漏斗构建。Service Cloud 围绕案件、服务水平和问题解决构建，并在网页、电话和窗口之间提供统一视图。与 SAP BTP 和 S/4HANA 连接之后，市民的请求可以直接启动后台工作流，无需任何人重新录入。

</details>

<details>
<summary>在公共部门的 SAP CX 推广中，应如何处理隐私和授权同意？</summary>

让市民拥有一个身份，并能看到和修改自己的授权设置，SAP Customer Data Cloud 支持这一点。部门之间只在必要的层级共享敏感信息：在这个案例中，社会服务案件只显示摘要状态，不显示详细记录。透明的授权同意也有助于满足欧盟的 GDPR 合规要求。

</details>

<details>
<summary>如何衡量市民互动项目是否成功？</summary>

按案件类型统计的解决时长、首次联系解决率、在线完成的交易占比、市民满意度评分、服务成本，以及查询状态的来电是否真的减少。仅看门户注册数意义不大；如果人们注册之后仍然打电话查状态，说明透明度问题并没有解决。

</details>

<details>
<summary>SAP BTP 在面向市民的服务中起什么作用？</summary>

它把面向市民的前端与后台连接起来。没有它，数字化的请求仍然要被重新录入财务或案件系统。有了它，许可证申请会启动 ERP 工作流，付款会实时更新财务记录，案件状态也会在隐私规则允许的范围内在部门之间流转。

</details>
