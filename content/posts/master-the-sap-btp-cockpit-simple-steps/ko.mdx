SAP BTP Cockpit은 SAP Business Technology Platform을 관리하는 웹 콘솔입니다. 글로벌 계정, 하위 계정, 엔타이틀먼트, 서비스, 사용자, 런타임, 비용을 여기서 관리합니다. SAP 사용자로 `https://cockpit.btp.cloud.sap`에 로그인하면 가장 가까운 지역 Cockpit으로 리디렉션됩니다.

짧은 답: `cockpit.btp.cloud.sap`을 열고 글로벌 계정을 고른 다음, 이 순서로 작업하십시오. 디렉토리와 하위 계정을 계획하고, 엔타이틀먼트를 할당하고, 런타임을 활성화하고, 서비스 인스턴스를 만들고, ID 공급자를 연결해 역할 컬렉션을 할당한 뒤, 알림과 비용 추적을 켭니다. 트라이얼 계정은 `https://cockpit.hanatrial.ondemand.com/trial/`을 사용하며 최대 90일간 운영됩니다.

저는 처음에 이것을 파악하는 데 며칠이 걸렸습니다. 고생의 대부분은 뒤의 단계를 앞의 단계보다 먼저 한 데서 왔습니다. 아래 순서는 제가 지금 새 글로벌 계정마다 쓰는 순서입니다.

이름에 관해 한 가지. 2026년 5월 Sapphire에서 SAP는 BTP, SAP Business Data Cloud, AI Foundation을 하나로 묶는 SAP Business AI Platform을 발표했습니다([SAP News](https://news.sap.com/2026/05/sap-sapphire-keynote-business-ai-platform-power-autonomous-enterprise/)). 2026년 10월 현재 관리 콘솔은 여전히 SAP BTP Cockpit으로 문서화되어 있으므로, 이 글에서도 그 이름을 씁니다.

## SAP BTP Cockpit에 로그인하는 방법

SAP 문서가 제시하는 진입점은 하나, `https://cockpit.btp.cloud.sap`입니다. 여기서 가장 가까운 지역 Cockpit으로 리디렉션됩니다([SAP Help, Access the Cockpit](https://help.sap.com/docs/btp/sap-business-technology-platform/4e750660b72e4fd6b2485ffb0b3cbdca)). 지역 게이트웨이를 직접 열 수도 있습니다.

1. 유럽, 중동, 아프리카는 `https://emea.cockpit.btp.cloud.sap`.
2. 아메리카는 `https://amer.cockpit.btp.cloud.sap`.
3. 아시아태평양은 `https://apac.cockpit.btp.cloud.sap`.
4. EU Access 계정은 `https://eu-access.cockpit.btp.cloud.sap`.

게이트웨이는 Cockpit에 도달하는 경로만 결정합니다. 해당 지역의 하위 계정으로 제한하지는 않습니다. 중국 사용자에게는 전용 진입점 `https://cockpit.cn40.platform.sapcloud.cn`이 있습니다.

회사가 자체 ID 공급자로 플랫폼 사용자를 로그인시킨다면 `idp` 매개변수를 추가하십시오. 예를 들면 `https://cockpit.btp.cloud.sap?idp=mytenant.accounts.ondemand.com`입니다. 이것이 없으면 기본 SAP ID service로 들어가게 되어 계정이 하나도 보이지 않을 수 있습니다. 이전 기능 세트 A나 Neo 환경의 계정은 다른 URL을 사용하며, SAP 문서에 나와 있습니다.

## 글로벌 계정과 하위 계정: Cockpit의 구성

모든 것은 계층 구조 안에 있습니다. **글로벌 계정**은 SAP와의 계약을 구현한 것입니다. 구매한 엔타이틀먼트와 할당량을 보유하며, 지역과 환경에 독립적입니다.

**하위 계정**은 실제 작업이 이루어지는 곳입니다. 각각 하나의 지역에 속하며, 그 안에서 애플리케이션을 배포하고, 서비스를 사용하고, 구성원과 권한을 관리합니다. 하위 계정은 서로 독립적이며, 이는 보안과 데이터 분리에 중요합니다.

**디렉토리**는 그 둘 사이에 두는 선택적 폴더입니다. 예를 들어 사업부별로 하위 계정을 묶고, 자체 엔타이틀먼트와 권한을 가질 수 있습니다. SAP는 글로벌 계정과 가장 아래 하위 계정 사이에 최대 5단계의 디렉토리를 허용합니다([SAP Help, Account Model](https://help.sap.com/docs/btp/sap-business-technology-platform/8ed4a705efa0431b910056c0acdbf377)).

<explainer-org title="BTP 글로벌 계정의 구성" caption="모든 하위 계정은 한정된 하나의 풀에서 할당을 받습니다. 첫 하위 계정을 만들기 전에 이름과 배분을 합의하십시오." chain="글로벌 계정 => SAP와의 계약과 구매한 서비스|디렉토리 => 예를 들어 사업부별로 하위 계정을 묶음" side="엔타이틀먼트 => 각 하위 계정이 할당을 받는 한정된 풀" roles="Finance-Dev => 개발용, 무료 또는 소규모 플랜|Finance-Test => 테스트용, 자체 사용자와 역할 컬렉션|Finance-Prod => 운영용, Go-Live 전에 알림 설정" highlight="side"></explainer-org>

하위 계정 아래에는 런타임별 계층이 있습니다. Cloud Foundry를 활성화하면 하위 계정마다 org가 하나 생성되고, 그 안에 space를 만듭니다. Kyma를 활성화하면 하나 이상의 Kubernetes 클러스터가 프로비저닝되며, 이를 namespace로 나눕니다.

## SAP BTP Cockpit 설정 방법: 단계별 안내

### 1단계. 로그인하고 올바른 글로벌 계정 열기

위와 같이 로그인한 뒤 글로벌 계정을 선택합니다. Cockpit은 한 번에 하나의 글로벌 계정만 보여 줍니다. 어느 계정의 구성원도 아니라면 Cockpit이 그렇게 알려 줍니다. 아래 오류 섹션을 참조하십시오.

Joule은 Cockpit 툴바의 다이아몬드 아이콘에서 사용할 수 있습니다. BTP 관련 질문에 답하고 관리 작업을 수행할 수 있지만, 귀하의 권한이 허용하는 작업만 가능합니다.

### 2단계. 디렉토리와 하위 계정 이름을 먼저 종이 위에서 계획하기

대부분의 팀이 몇 년 동안 따라다닐 혼란을 만드는 곳이 바로 여기입니다. 예전에 함께 일한 한 고객사는 이름이 제각각인 하위 계정이 50개 이상이었고, 아무도 아무것도 찾지 못했습니다. 프로젝트 도중에 그것을 풀어내는 일은 고통스럽습니다.

영역별로 개발, 테스트, 운영을 분리하십시오. 예를 들면 `Finance-Dev`, `Finance-Test`, `Finance-Prod`입니다. 규모가 큰 조직은 사업부별로 디렉토리를 추가합니다. `Landscape: Dev`나 코스트 센터 같은 레이블을 사용하십시오. Account Explorer에서 이것으로 필터링할 수 있습니다.

### 3단계. 하위 계정 만들기

글로벌 계정 관리자이거나, 자체 엔타이틀먼트를 관리하는 디렉토리의 디렉토리 관리자여야 합니다. 그런 다음 [SAP Help, Create a Subaccount](https://help.sap.com/docs/btp/sap-business-technology-platform/05280a123d3044ae97457a25b3013918)에 따라 진행합니다.

1. 글로벌 계정에서 **Account Explorer**를 엽니다.
2. **Create > Subaccount**를 선택합니다.
3. 표시 이름과, 필요하면 설명을 입력합니다.
4. **Subdomain**을 입력합니다. 구독한 애플리케이션 URL의 일부가 되며, 해당 지역 안에서 고유해야 합니다.
5. 지역과 상위 항목(글로벌 계정 또는 디렉토리)을 선택합니다.
6. 운영용이면 **Used for production**을 체크하고, **Advanced**에서 레이블을 추가합니다.
7. 운영에 쓰이는 것이라면 **Enable beta features**는 끈 상태로 두십시오. 한 번 켜면 끌 수 없습니다.
8. 저장한 다음 환경을 활성화하고 사용자를 추가합니다.

### 4단계. 엔타이틀먼트 할당하기

**엔타이틀먼트**는 하위 계정이 사용할 수 있는 서비스와 플랜, 그리고 받을 할당량을 결정합니다. 글로벌 계정에는 한정된 풀이 있고, 이를 디렉토리와 하위 계정에 배분합니다.

하위 계정에서 **Entitlements**를 열고 **Configure Entitlements > Add Service Plans**를 선택한 뒤, 서비스, 플랜, 할당량을 고르고 **Save**합니다. 저는 최소한으로 시작해 필요에 따라 늘리며, 이 방식으로 고객사들은 쓰지 않는 서비스에 들어갈 비용을 수천 단위로 절약했습니다.

### 5단계. 런타임 활성화하기: Cloud Foundry, Kyma 또는 ABAP 환경

환경은 하위 계정 개요의 **Enable**, Service Marketplace, 또는 btp CLI에서 활성화합니다. 하나의 하위 계정에서 여러 환경을 실행할 수 있습니다. 아래 표는 SAP의 환경 문서를 바탕으로 세 가지를 비교한 것입니다.

| 환경 | 무엇인가 | 잘 맞는 경우 | 주의할 점 |
|---|---|---|---|
| Cloud Foundry | 오픈 소스 Cloud Foundry 기반의 SAP BTP, Cloud Foundry runtime. buildpack이 앱을 빌드하고 실행합니다 | SAP Cloud Application Programming Model(CAP)을 포함한 Java, Node.js, Python 앱 | 대부분의 SAP 팀에게 성숙한 기본 선택지 |
| Kyma | SAP BTP, Kyma runtime: 오픈 소스 Kyma 프로젝트 기반의 완전 관리형 Kubernetes 런타임 | 컨테이너화된 마이크로서비스, 서버리스 함수, 이벤트 기반 확장 | Kubernetes 역량이 필요. Kyma 무료 플랜은 글로벌 계정당 한 번, 최대 30일 |
| ABAP 환경 | 현재 이름은 SAP Business AI Platform, ABAP environment. 릴리스된 객체 위의 ABAP Cloud | S/4HANA 옆에서 확장을 만드는 ABAP 개발자 | 전용 SAP HANA Cloud 데이터베이스를 갖춘 별도 시스템으로, 사이징과 과금이 따로 이루어짐 |

개발자들이 아키텍처 계획에는 맞지만 자신들의 경험에는 맞지 않는 새 환경을 배워야 해서 프로젝트가 몇 달씩 지연되는 것을 보았습니다. 기술적으로 더 낫더라도 팀이 개발할 수 없는 런타임은 더 나쁜 선택입니다.

### 6단계. 서비스 인스턴스, 바인딩, 키 만들기

하위 계정에서 **Services > Service Marketplace**를 열고 서비스 타일을 고른 뒤 **Create**를 선택합니다. 플랜은 신중히 고르십시오. 잘못된 플랜은 추가 비용을 만든다고 SAP 자체 튜토리얼이 경고합니다([SAP Developers](https://developers.sap.com/tutorials/btp-cockpit-instances.html)). 만든 모든 것은 **Services > Instances and Subscriptions**에 나타납니다.

인스턴스를 애플리케이션에 바인딩하면 BTP가 자격 증명을 주입합니다. BTP 애플리케이션이 아닌 도구에는 **service key**를 만드십시오. 키 이름은 `key1`이 아니라 `jenkins-deployment`처럼 누가 쓰는지 알 수 있게 지으십시오.

### 7단계. ID 공급자를 연결하고 역할 컬렉션 할당하기

회사에 이미 Microsoft Entra ID나 Okta 같은 ID 공급자가 있다면 BTP 사용자를 수작업으로 관리하지 마십시오. SAP Cloud Identity Services 테넌트를 그 공급자에 대한 프록시로 사용하십시오. 하위 계정에서 **Security > Trust Configuration**으로 가서 **Establish Trust**를 선택하면 OpenID Connect 신뢰 관계가 자동으로 만들어집니다.

그런 다음 사용자에게는 **Security > Users > Assign Role Collection**에서, 또는 그룹을 통해 역할 컬렉션을 할당합니다. 역할 컬렉션에 대한 제 접근 방식은 다음과 같습니다.

1. 개인이 아니라 직무를 중심으로 만듭니다.
2. 의미가 있을 만큼 구체적으로, 하지만 수백 개를 관리해야 할 만큼 세분화하지는 않습니다.
3. 비상시를 위한 관리자 컬렉션을 하나 둡니다.
4. 분기마다 할당을 검토합니다. 사람들은 직무를 바꾸고도 예전 접근 권한을 그대로 갖고 있습니다.

### 8단계. BTP를 S/4HANA 및 다른 시스템에 연결하기

BTP 작업의 대부분은 통합입니다. 제가 가장 자주 설정하는 패턴은 다음과 같습니다.

| 시나리오 | 설정 방법 |
|---|---|
| 온프레미스 또는 Private Edition의 S/4HANA | 사내 네트워크에 Cloud Connector, 하위 계정에 destination을 두고 OData 또는 SOAP API 사용 |
| SuccessFactors 같은 SAP 클라우드 앱 | destination과 Integration Suite 또는 Event Mesh, 확장은 CAP로 개발 |
| Salesforce나 Workday 같은 비SAP 시스템 | Integration Suite 어댑터 또는 사용자 정의 통합 흐름 |
| 자체 API 공개 | Integration Suite의 API Management: 설계, 게시, 모니터링 |

Cloud Connector는 BTP로 나가는 아웃바운드 터널을 열기 때문에 인바운드 방화벽 규칙이 필요 없습니다. BTP가 실제로 필요로 하는 시스템과 URL 경로만 노출하십시오. 통합 설계는 제 [SAP CPI 글](/ko/sap-cpi/)에서 더 깊이 다룹니다.

### 9단계. 모니터링과 알림 설정하기

모니터링은 필요해지기 전에 설정하십시오. 저는 매일 아침 커피를 마시며 대시보드를 확인합니다. 이제는 일과가 되었고, "시스템이 왜 멈췄지?" 하는 순간을 여러 번 막아 주었습니다.

SAP Alert Notification service는 플랫폼과 애플리케이션 이벤트를 이메일, Slack 및 기타 채널로 보냅니다. 제 일반적인 설정은 중요한 앱에는 이메일, 절대 멈추면 안 되는 것에는 Slack webhook입니다. 애플리케이션별 응답 시간과 오류율은 Cloud Foundry 또는 Kyma 화면에서 확인하십시오.

### 10단계. 사용량과 비용 추적하기

중요한 페이지는 두 가지입니다. 각 하위 계정의 **Usage Analytics**는 청구 기준이 아닌 실제 사용량을 보여 주며, 24시간마다 갱신됩니다. 글로벌 계정의 **Costs and Usage**는 서비스, 디렉토리, 하위 계정별 월 비용을 청구 명세서와 같은 용어로 보여 줍니다.

소비 기반 계약에서는 임계값에 이메일 알림을 보내는 **budgets**도 설정할 수 있습니다. 예산을 초과해도 사용이 멈추지는 않습니다. 멈추는 것은 여전히 귀하의 몫입니다. 사용하지 않는 인스턴스는 매달 삭제하고, 갱신할 때마다 엔타이틀먼트 소비 현황을 확인하십시오.

## 자동화와 사용자 지정 도메인

Cockpit에서 클릭하는 방식은 규모가 커지면 감당이 안 됩니다. BTP 명령줄 인터페이스(btp CLI)와 SAP Cloud Management service API로 하위 계정 생성, 엔타이틀먼트 할당, 환경 활성화 같은 계정 작업을 스크립트로 처리할 수 있습니다.

한 프로젝트에서 신규 개발자 12명의 환경이 필요했습니다. 하루 종일 Cockpit을 클릭하는 대신 스크립트를 실행하고 커피를 마시러 갔습니다. 돌아왔을 때는 모든 것이 준비되어 있었습니다.

한 프로젝트에서는 배포 자동화로 설정 시간이 80% 줄었습니다. service key와 CF CLI를 파이프라인에 연결하자 배포가 몇 시간에서 몇 분으로 줄었습니다. 사용자 지정 도메인은 SAP Custom Domain service로 설정하며, 한 고객 프로젝트에서는 경영진이 더 전문적인 느낌을 바로 알아챘습니다.

## SAP BTP Cockpit 트라이얼과 무료 티어

SAP에는 무료로 시작하는 방법이 두 가지 있으며, 혼동하기 쉽습니다. 트라이얼은 학습용이고, 무료 티어 플랜은 실제 엔터프라이즈 계정 안에 있습니다. 아래 표는 [SAP Help, Trial Accounts and Free Tier](https://help.sap.com/docs/btp/sap-business-technology-platform/046f127f2a614438b616ccfc575fdb16)를 요약한 것입니다.

| | 트라이얼 계정 | 무료 티어 서비스 플랜 |
|---|---|---|
| Cockpit URL | `cockpit.hanatrial.ondemand.com/trial/` | `cockpit.btp.cloud.sap` |
| 계정 유형 | 별도의 트라이얼 글로벌 계정 | Pay-As-You-Go 또는 CPEA 엔터프라이즈 계정 |
| 기간 | 최대 90일, 이후 삭제 | 무료 플랜에는 기간 제한 없음. Kyma 무료 플랜은 최대 30일 |
| 운영 사용 | 불가, 팀 개발도 불가 | 가능. 대부분의 서비스는 유료 플랜으로 업그레이드 가능 |
| 제공 내용 | `dev` space가 있는 Cloud Foundry 하위 계정. Kyma와 ABAP도 사용 가능 | SAP Discovery Center에서 Free Tier 태그가 붙은 서비스 |

트라이얼은 최대 30일 단위로 운영되며, 계속 로그인하는 동안 자동으로 연장됩니다. 30일 동안 로그인하지 않으면 계정이 정지되고 이후 삭제됩니다. 트라이얼 애플리케이션은 매일 밤 중지되므로 수동으로 다시 시작해야 합니다.

## BTP Cockpit의 흔한 오류와 해결 방법

모두 원인이 문서화되어 있고 해결 방법은 간단합니다.

1. **"Your user does not belong to any global account."** 글로벌 계정 관리자가 Global Account Viewer 같은 역할 컬렉션과 함께 귀하를 구성원으로 추가해야 합니다. 관리자가 없다면 SAP Note 2669325에 SAP for Me를 통한 우회 방법이 설명되어 있습니다.
2. **회사 계정으로 로그인한 뒤 글로벌 계정이 보이지 않음.** BTP는 두 ID 공급자에 있는 같은 이메일을 서로 다른 두 사용자로 취급합니다. 관리자가 사용한 공급자를 `?idp=` 매개변수로 지정해 로그인하십시오.
3. **Service Marketplace에 서비스가 없음.** 하위 계정에 해당 엔타이틀먼트가 없습니다. 먼저 Entitlements에서 플랜을 추가하십시오.
4. **"Subdomain already exists."** 하위 도메인은 지역마다 고유합니다. 이름에 사업부나 단계를 추가하십시오.
5. **예상치 못한 요금.** 유료 플랜으로 인스턴스가 만들어졌습니다. Instances and Subscriptions와 Costs and Usage에서 플랜을 확인하십시오.
6. **트라이얼 앱이 밤사이 중지됨.** 정상입니다. 다시 시작하고, 트라이얼이 정지되지 않도록 계속 로그인하십시오.

런타임과 배포 오류는 제 [BTP Cockpit 문제 해결 가이드](/ko/sap-btp-cockpit-issues/)에서 더 깊이 다룹니다.

## S/4HANA 프로그램에서 Cockpit의 위치

저는 21개의 SAP 프로그램을 이끌거나 구해 냈습니다. 클린 코어 프로그램에서 BTP는 사이드 바이 사이드 확장이 실행되는 곳이며, 그 덕분에 S/4HANA는 SAP 표준에 가깝게 유지됩니다. 그런 확장이 어디에 놓이는지는 제 [클린 코어 가이드](/ko/sap-clean-core-strategy-what-it-means-for-your-business/)에서 설명합니다.

Cockpit은 '무엇'을 저장할 뿐, '왜'는 절대 저장하지 않습니다. 계정 구조, 명명 규칙, 엔타이틀먼트 배분과 각각의 이유를 기록해 두십시오. 이를 변경할 때는 현업과 IT로 구성된 설계 위원회(design authority)의 승인을 받으십시오.

BTP 계정이 계획 없이 불어났다면, 더 추가하기 전에 [저와 이야기하십시오](/ko/contact-noel-erp-support/).

## 자주 묻는 질문

<details>
<summary>SAP BTP Cockpit 로그인 URL은 무엇입니까?</summary>

`https://cockpit.btp.cloud.sap`을 사용하십시오. 가장 가까운 지역 Cockpit으로 리디렉션됩니다. `https://emea.cockpit.btp.cloud.sap`, `https://amer.cockpit.btp.cloud.sap`, `https://apac.cockpit.btp.cloud.sap` 같은 지역 게이트웨이도 사용할 수 있습니다. 트라이얼 계정은 `https://cockpit.hanatrial.ondemand.com/trial/`을 사용합니다.

</details>

<details>
<summary>SAP BTP에서 글로벌 계정과 하위 계정의 차이는 무엇입니까?</summary>

글로벌 계정은 SAP와의 계약입니다. 구매한 엔타이틀먼트를 보유하며 특정 지역에 묶여 있지 않습니다. 하위 계정은 그 안에 있고, 각각 하나의 지역에 속하며, 앱을 배포하고 서비스를 사용하고 사용자를 관리하는 곳입니다.

</details>

<details>
<summary>SAP BTP에서 하위 계정은 어떻게 만듭니까?</summary>

글로벌 계정 관리자로서 Account Explorer를 열고 Create > Subaccount를 선택합니다. 표시 이름, 지역 안에서 고유한 하위 도메인, 지역, 상위 항목을 입력합니다. 저장한 뒤 엔타이틀먼트를 할당하고 Cloud Foundry 같은 환경을 활성화합니다.

</details>

<details>
<summary>SAP BTP의 엔타이틀먼트란 무엇입니까?</summary>

엔타이틀먼트는 서비스 플랜을 사용할 권리이고, 할당량은 그것을 얼마나 사용할 수 있는지를 뜻합니다. 글로벌 계정이 계약에 따라 이를 받고, 귀하가 디렉토리와 하위 계정에 배분합니다. 하위 계정에서는 Entitlements > Configure Entitlements > Add Service Plans를 선택합니다.

</details>

<details>
<summary>SAP BTP 트라이얼은 무료이며 기간은 얼마나 됩니까?</summary>

네, 최대 90일까지 무료입니다. 계속 로그인하는 동안 기간이 자동으로 연장되며, 30일 동안 로그인하지 않으면 계정이 정지됩니다. 개인 학습용이며 운영이나 팀 개발용이 아닙니다. 더 오래 쓰려면 무료 티어 서비스 플랜이 있는 엔터프라이즈 계정을 만드십시오.

</details>

<details>
<summary>Cloud Foundry와 Kyma 중 어떤 BTP 런타임을 선택해야 합니까?</summary>

CAP를 포함한 Java, Node.js, Python 앱이라면 Cloud Foundry를 선택하십시오. 컨테이너는 buildpack이 처리해 줍니다. 컨테이너화된 마이크로서비스와 이벤트 기반 확장에는 관리형 Kubernetes 런타임인 Kyma를 선택하되, 팀에 Kubernetes 역량이 있을 때만 그렇게 하십시오. S/4HANA 확장을 만드는 ABAP 개발자는 대개 ABAP 환경이 맞습니다.

</details>

<details>
<summary>SAP BTP는 이제 SAP Business AI Platform이라고 부릅니까?</summary>

2026년 5월 SAP는 BTP, SAP Business Data Cloud, AI Foundation을 하나로 묶는 SAP Business AI Platform을 발표했습니다. SAP 문서는 ABAP 환경 등 일부에서 이미 새 이름을 쓰고 있습니다. 2026년 10월 현재 관리 콘솔은 여전히 같은 URL의 SAP BTP Cockpit으로 문서화되어 있습니다.

</details>

<details>
<summary>ID 공급자를 SAP BTP Cockpit에 어떻게 연결합니까?</summary>

SAP Cloud Identity Services 테넌트를 설정하고, Microsoft Entra ID나 Okta 같은 회사 ID 공급자를 여기에 연결합니다. 하위 계정에서 Security > Trust Configuration으로 가서 Establish Trust를 선택해 OpenID Connect 신뢰 관계를 만듭니다. 그런 다음 사용자나 그룹에 역할 컬렉션을 할당합니다.

</details>
