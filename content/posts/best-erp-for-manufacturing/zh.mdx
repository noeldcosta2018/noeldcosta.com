制造业没有唯一最好的 ERP。对全球化、多工厂或受到严格监管的制造商，SAP S/4HANA 依然是标杆。对中端市场的离散制造企业，Epicor Kinetic 或 Infor CloudSuite Industrial 通常更合适。中端市场的流程制造商应当看看 Sage X3 或 Infor M3，重资产行业看 IFS Cloud，小型制造商看 Acumatica 或 Cetec。本指南写给在 2026 年为制造业 ERP 做入围名单的企业主、COO 和 CIO。先看接近文末的推荐表，再去读它指向的那两三个系统的详细介绍。

制造业 ERP 和零售或专业服务业的 ERP 完全是两种东西。您要同时应付物料清单、工艺路线、倒班排班、设备校准、废品率和批次追溯。一套“也能做制造”的通用 ERP，通常只跟踪库存，到此为止。让它把一个有缺陷的零件追溯到生产批次，它就露馅了。

我参与过足够多的 ERP 推广，知道什么能撑过上线、什么撑不过。下面这些系统我都合作过，见过它们经受住考验，也知道每一个适合用在哪里。多数制造商是照着功能清单买的。真正要紧的功能，是您的团队在倒班压力下会用到的那些。

## 制造业 ERP 必须做什么

六项能力，把制造业 ERP 和通用 ERP 区分开：

1. **库存管理**：在一个地方管理原材料、在制品和成品
2. **生产计划与排产**：让人力、设备和物料与需求对齐
3. **物料需求计划（MRP）**：让您既不会多订，也不会断料
4. **车间执行**：实时记录产量、停机和偏差
5. **质量管理**：用于检验、审核和不合格品处理
6. **批次和序列号追溯**：食品、制药和国防行业必须具备，汽车行业也越来越需要

## 各系统详解

### SAP S/4HANA（通过 RISE 或 GROW）

在企业级规模上，SAP 依然领先。当您需要 MES 集成、跨多个工厂的批次追溯，以及一套面对复杂性眼都不眨的系统时，S/4HANA 就是标杆。生产逻辑位于它的核心，财务和运营共用一个数据模型。

它昂贵，也复杂。实施团队的费用不低，变革管理的工作量也很大。

较新的选项是 GROW with SAP，它建立在 S/4HANA Cloud Public Edition 之上。它只适用于新实施，运行 SAP 的标准流程，不允许修改核心。作为回报，它让中端市场的制造商也够得着 SAP，这是 RISE 从未做到的。

**适合谁用**：具备多工厂复杂性或监管压力的全球制造商（制药、国防、航空航天），以及已经在用 SAP ECC、计划在主流维护于 2027 年结束之前迁移的企业。愿意采用标准流程的中端市场制造商，应当看看 GROW。

**短板**：成本和周期总是被低估。合作伙伴会报 12 个月。要加上缓冲。Clean Core 的纪律，如今限制了许多 ECC 制造商过去依赖的大量 ABAP 定制开发。这对控制成本是好事，但如果您的流程依赖这些定制，就很痛苦。我写的[制造业中的 SAP](/zh-CN/sap-manufacturing-industry-secrets/)指南，讲了怎样让它在车间里真正跑起来。

### Oracle NetSuite

仅限云端的 ERP，把财务、供应链、库存和生产放进一套系统，在多地点的中端市场制造业中有长期的实践记录。

制造方面的深度够用，但谈不上深。工单、物料清单、需求计划和基础的车间控制，它处理得不错。基于约束的排产或紧密的 MES 集成，就会让它吃力。

**适合谁用**：增长很快、已经超出入门级会计软件的能力、又还没准备好上 SAP 的制造商。适合带有电商或直销业务的多主体架构。

**短板**：常常需要附加模块，价格也随之攀升。签约前，要拿到书面的三年报价，而不只是第一年的。定制开发需要 SuiteScript 技能。

### Microsoft Dynamics 365

在以微软产品为主的环境中表现很好。财务能力强，与 Power BI 的集成好，Power Automate 又能减少集成工作量。同时做离散和流程生产的混合模式制造商，常常发现它很合适。

AI 功能需要干净的数据才有用。主数据一团糟时，AI 层只会添噪声。先把数据质量搞好。

**适合谁用**：以 Azure 和 Microsoft 365 为标准技术栈的公司。

**短板**：对于纯车间作业，制造功能的成熟度不如 Epicor 或 Infor。

### Infor CloudSuite Industrial

为单件小批生产车间（job shop）和离散制造商打造（很多人仍把这个产品叫作 SyteLine）。它的高级计划与排程和 PLM 功能，能处理按订单设计和混合模式的工作，又不会变得笨重。

它适合在生产排程上需要深度的制造商，尤其是共享设备上同时有大量订单的情形，在这类场景里，NetSuite 或 Dynamics 会露出短板。对食品和化工这类流程行业，Infor 的 M3 产品是更对口的选择。

**适合谁用**：排程复杂的中端市场离散和混合模式制造商。

**短板**：界面能用，但与较新的云产品相比显得过时。

### Epicor Kinetic

在车间里靠得住。MES、排产和车间执行说到做到，多数团队很快就能上手。就它要做的事而言，它并没有被过度设计。

不是最炫的系统。但是一套您在车间里可以信任的系统。

**适合谁用**：想要经过验证的车间能力、又不想要 SAP 的复杂度和价格的离散制造商。

**短板**：财务落后于运营这一侧。有些公司会在它旁边另外运行一套财务系统。

### IFS Cloud

当资产和库存同样重要时（航空航天、国防、能源、公用事业），IFS 就说得通了。它把 ERP、企业资产管理（EAM）和现场服务管理（FSM）合在一个产品里。很少有竞争对手做到这一点。

深度带来了实施上的工作量。没有认真的资源承诺，就别规划六个月的推广。

**适合谁用**：处于受监管行业的重资产制造商，设备生命周期、维护和合规是驱动运营的因素。

### Acumatica

对想要成长而又不想重新实施的小型制造商，性价比不错。基于浏览器，模块化。它的授权按您使用的应用和消耗的资源收费，用户数不限，这在您想让整个工厂都用上系统时很有帮助。

在复杂的车间场景上，它的深度不及 Epicor 或 Infor。对于没有重度 MES 需求的简单生产，它能胜任。

**适合谁用**：想要现代云 ERP、又不想承担企业级成本和复杂度的中小型制造商。

### Sage X3

面向中端市场的流程制造：制药、食品饮料、化工。批次管理、批次追溯和监管合规都是内置的。更适合流程制造，而不是离散制造。对一家中等规模、受监管的流程制造商，它可以提供 GxP 批次追溯，又没有 SAP 项目群那样的沉重负担。

**适合谁用**：需要追溯和合规、又不想要 SAP 那种负担的中端市场流程制造商。

### DELMIAWorks 和 Cetec ERP

DELMIAWorks（前身是 IQMS，现属 Dassault Systèmes）为小型离散制造商打造，车间控制能力很强。Cetec 是低成本选项：云端部署，上线快，对不想过度投入的小型工厂来说容易扩展。

如果预算是主要的约束，而且业务比较简单，Cetec 值得认真看一看。

## 常见的实施挑战

无论您选哪套系统，决定它能不能成功的，都是这些问题。其中大多数在项目启动之前就已经定了。

| 挑战 | 会出什么问题 | 如何避免 |
|---|---|---|
| **目标不清** | 一开始没有 KPI 或成功标准 | 在选择供应商之前，先把成功衡量标准写下来 |
| **过度定制** | 把每一个旧习惯都硬塞进新系统 | 先梳理工作流程；先改流程，再改软件 |
| **低估变革管理** | 用户抵触；培训仓促 | 在每个团队指定一位变革推动者；尽早沟通 |
| **脏数据** | 糟糕的主数据导致上线错误 | 在项目启动之前指定数据负责人 |
| **范围蔓延** | 项目进行中不断增加功能 | 为上线定义一个最小范围；其余分阶段推进 |
| **测试不充分** | 没做完整的流程测试就上线 | 用真实数据做端到端测试，尤其是财务流程 |
| **没有上线后计划** | 支持逐渐减弱；用户回到电子表格 | 在上线前规划好稳定期和 Hypercare |

培训总是被低估。没受过培训的用户不会用系统，他们会绕开它，这就违背了初衷。数据清理也总是超时。两样都要预留额外的时间。

## 制造业选云端还是本地部署

对多数新的制造业 ERP 项目，云端是默认选项。更新自动到达，您不用运营基础设施，扩展也更容易。代价是失去对更新时机的控制：不管新版本是否适合您的生产日历，您都会收到它。

对 SAP 而言，多数新的制造业项目群会选 RISE（私有云）或 GROW（公有云）。本地部署的 S/4HANA 仍在销售，通常是出于数据驻留、主权或工厂联网方面的原因而选用。如果您今天在运行 SAP Solution Manager，请注意它的主流维护将于 2027 年底结束，有限的延长维护可到 2030 年。SAP 引导客户转向 [SAP Cloud ALM](https://support.sap.com/en/alm/faq.html)，把它作为后继产品。

对高安全环境、网络连接不稳定的工厂，以及云模式不支持的集成架构，本地部署仍然说得通。这份清单里的多数供应商两种都提供，所以决定通常取决于 IT 政策，而不是 ERP 的能力。

## 按制造商类型给出的推荐

从这里开始，再去读您所在那一行指向的两三个系统的详细介绍。

| 制造商类型 | 入围的 ERP 选项 | 原因 |
|---|---|---|
| **小型（100 人以下）** | Acumatica、Cetec ERP | 价格实惠、云端、无需重新实施即可扩展 |
| **中端市场，标准流程** | GROW with SAP、Epicor Kinetic、Acumatica | 着眼于 SAP 的未来选 GROW；重视车间选 Epicor |
| **离散制造** | Epicor Kinetic、Infor CloudSuite Industrial、DELMIAWorks | MES、排产和车间控制能力强 |
| **流程制造** | Sage X3、Infor M3 | 批次追溯、合规、针对流程制造的专用流程 |
| **混合模式** | Infor CloudSuite Industrial、Dynamics 365 | 无需大量定制即可兼顾离散和流程 |
| **全球化企业** | RISE with SAP S/4HANA、IFS Cloud | 多工厂、多币种、深度的合规与集成 |
| **重资产** | IFS Cloud；超大型体量则选 RISE with SAP | ERP、EAM 和现场服务合在一个系统里 |

一家 50 人的工厂，流程可能比一家 500 人的工厂更复杂。不要按人数来选。看看您的生产类型、工作流程的复杂度，以及您手里能支撑这套系统的团队。如果 SAP 和 Oracle 都在您的清单上，我写的 [SAP 与 Oracle 对比](/zh-CN/sap-vs-oracle-which-erp-is-better-for-your-business/)会更深入地讲这个选择。

## 常见问题

<details>
<summary>如何选择最适合制造业的 ERP？</summary>

从您的生产类型（离散的按订单生产或按库存生产，带批次和配方的流程生产，或混合模式）和您最大的运营缺口入手。用这些缺口去筛选系统，而不是用供应商的功能清单。

尽早让车间主管参加演示。销售演示里看起来很流畅的东西，在一位于班次开始时登记工单的主管眼里，可能完全是另一回事。他们的反应，比分析师评分更重要。

</details>

<details>
<summary>制造业中使用最广泛的 ERP 是什么？</summary>

在大型制造商中，SAP 部署得最广泛。在中端市场，Epicor、Infor、NetSuite、Dynamics 365，以及现在的 GROW with SAP 都很常见。

使用最广泛，不等于最合适。SAP 在企业级的地位，反映的是它的深度，而不是它适合每一种业务。

</details>

<details>
<summary>MES 和 MRP 有什么区别？</summary>

制造执行系统（MES）管理实时的车间活动：设备数据、人工、质量事件和在制品。它回答的是“车间里现在正在发生什么？”

物料需求计划（MRP）根据需求和提前期，算出该买什么、什么时候买。它回答的是“为了满足排产，我需要订什么？”

多数制造业 ERP 都包含 MRP。MES 要么是与 ERP 集成的独立系统，要么是 ERP 车间模块的一部分。生产越复杂，越有可能需要一套专用的 MES。

</details>

<details>
<summary>有免费的制造业 ERP 吗？</summary>

ERPNext 是开源的，自行托管免费。它涵盖制造业的基础功能：物料清单、生产订单和库存。

问题在于，自行托管需要内部的技术能力来完成搭建、维护和升级。它适合有技术人员、流程又简单的小型制造商。

</details>

<details>
<summary>SAP 在制造业中用来做什么？</summary>

SAP S/4HANA 在一套系统里涵盖生产计划（PP）、工厂维护（PM）、质量管理（QM）、物料管理（MM），以及所有这些与财务的集成。在大规模场景下，它能处理多工厂排产、批次追溯、与 MES 和 SCADA 系统的集成，以及全球合规。

它复杂，也昂贵。对大型制造商而言，它的深度值得这个代价。我写的 [SAP PP 指南](/zh-CN/sap-pp-production-planning/)详细讲了生产计划模块。

<summary>制造业 ERP 选型中最大的错误有哪些？</summary>

有三个错误反复出现：买下永远用不上的功能，低估实施工作量（尤其是数据迁移和培训），以及在没有每天要用系统的那些人参与的情况下，仅凭供应商演示做选择。

第三个代价最大。一套技术上正确、却让车间员工无法接受的系统，会被人绕开。被人绕开的系统，比没有系统还糟。

</details>
