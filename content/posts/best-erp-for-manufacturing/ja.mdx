製造業にとって唯一最良のERPというものはありません。グローバルで複数工場を持つ製造業や、規制の厳しい製造業では、SAP S/4HANAがいまも基準です。中堅のディスクリート製造なら、Epicor KineticかInfor CloudSuite Industrialのほうが合うことが多いでしょう。中堅のプロセス製造業はSage X3かInfor M3を、資産集約型の業種はIFS Cloudを、小規模な製造業はAcumaticaかCetecを検討してください。このガイドは、2026年に製造業向けERPの候補を絞り込むオーナー、COO、CIOに向けたものです。まず終盤の推奨表から読み、そこで示された2、3のシステムについて詳細を読んでください。

製造業向けのERPは、小売やプロフェッショナルサービス向けのERPとは別の生き物です。部品表、作業手順、シフトのスケジュール、機械の校正、スクラップ率、ロットのトレーサビリティを、同時に扱うことになります。「製造にも対応する」という汎用ERPは、たいてい在庫を追えるだけで終わります。不良部品を生産バッチまでさかのぼって追跡させると、破綻します。

私は、十分な数のERPのロールアウトに関わってきたので、本稼働後も生き残るものと、そうでないものが分かります。以下のシステムは、いずれも実際に扱い、持ちこたえるところを見てきましたし、それぞれがどこに合うかも分かっています。多くの製造業は、機能一覧で選びます。重要なのは、シフト勤務のプレッシャーの下でチームが実際に使う機能です。

## 製造業向けERPに求められること

製造業向けERPと汎用ERPを分ける機能は、6つあります。

1. **在庫管理**：原材料、仕掛品、完成品を1か所で管理する
2. **生産計画とスケジューリング**：人員、機械、資材を需要に合わせる
3. **資材所要量計画（MRP）**：過剰発注も欠品も避ける
4. **製造現場の実行管理**：生産量、停止時間、逸脱を、発生した時点で記録する
5. **品質管理**：検査、監査、不適合の管理
6. **ロットとシリアルのトレーサビリティ**：食品、医薬品、防衛では必須で、自動車でも求められるケースが増えている

## 各システムの詳細

### SAP S/4HANA（RISE経由またはGROW経由）

SAPは、エンタープライズ規模では依然としてトップです。MESとの連携、複数工場にまたがるバッチのトレーサビリティ、そして複雑さを難なくこなすシステムが必要なら、S/4HANAが基準になります。生産のロジックが中核にあり、財務と業務が1つのデータモデルを共有しています。

高価で、複雑です。導入チームは安くなく、チェンジマネジメントの負担も大きくなります。

より新しい選択肢が、S/4HANA Cloud Public Editionを基盤とするGROW with SAPです。新規導入のみが対象で、SAPの標準プロセスで動き、コアの修正は認められません。その代わり、RISEにはできなかった形で、SAPを中堅の製造業の手が届く範囲に引き寄せました。

**向いている企業**：複数工場の複雑さや規制の重みを抱えるグローバル製造業（医薬品、防衛、航空宇宙）と、すでにSAP ECCを使っていて、メインストリームメンテナンスが2027年に終わる前に移行を計画している企業です。標準プロセスを採用する意思のある中堅製造業は、GROWを検討してください。

**弱み**：コストとスケジュールは、いつも過小に見積もられます。パートナーは12か月と見積もるでしょう。余裕を持たせてください。クリーンコアの規律により、多くのECC利用の製造業が頼ってきた大規模なABAPのカスタマイズは、いまでは制限されます。コスト管理には良いことですが、プロセスがそれに依存していると痛みを伴います。私の[製造業におけるSAP](/ja/sap-manufacturing-industry-secrets/)のガイドで、現場で機能させるための要点を扱っています。

### Oracle NetSuite

財務、サプライチェーン、在庫、生産を1つのシステムにまとめる、クラウド専用のERPです。複数拠点を持つ中堅製造業で、長い実績があります。

製造の機能は、深いというより、十分というレベルです。作業指示、部品表、需要計画、基本的な製造現場の管理は、うまくこなします。制約ベースのスケジューリングや、MESとの密な連携は、荷が重くなります。

**向いている企業**：入門レベルの会計ソフトでは手狭になり、まだSAPには踏み出せない、急成長中の製造業です。ECや直販を伴う複数法人の構成にも向いています。

**弱み**：アドオンのモジュールが必要になることが多く、それに伴って価格も上がります。契約前に、初年度だけでなく3年分の価格を書面で取っておいてください。カスタマイズにはSuiteScriptのスキルが必要です。

### Microsoft Dynamics 365

Microsoft中心の環境で、うまく機能します。財務に強く、Power BIとの連携も良好で、Power Automateによって連携の手間が減ります。ディスクリートとプロセスの両方の生産を行うミックスモードの製造業にとっては、相性のよいことが多くあります。

AI機能は、役に立たせるためにクリーンなデータが必要です。散らかったマスタデータの上では、AIの層はノイズを増やすだけです。まずデータ品質を直してください。

**向いている企業**：AzureとMicrosoft 365で標準化している企業です。

**弱み**：純粋な製造現場の業務については、製造機能がEpicorやInforほど成熟していません。

### Infor CloudSuite Industrial

ジョブショップとディスクリート製造向けに作られています（多くの人がいまもSyteLineと呼ぶ製品です）。高度な計画・スケジューリングとPLMの機能により、重くなることなく、受注設計生産やミックスモードの業務をこなします。

生産スケジューリングに深みを求める製造業、特に共有設備で多数の注文が同時に動く現場に向いています。そうした現場では、NetSuiteやDynamicsだと不足が出ます。食品や化学といったプロセス産業には、InforのM3のほうが適した選択肢です。

**向いている企業**：スケジューリングが複雑な、中堅のディスクリート製造およびミックスモード製造の企業です。

**弱み**：画面は使えますが、新しいクラウド製品と並べると古さが目立ちます。

### Epicor Kinetic

製造現場で信頼できます。MES、スケジューリング、製造現場の実行管理は、うたっているとおりに動き、ほとんどのチームがすぐに慣れます。担う仕事に対して、作り込みすぎてもいません。

派手なシステムではありません。現場で信頼できるシステムです。

**向いている企業**：SAPの複雑さや価格を避けつつ、実績のある製造現場の機能を求めるディスクリート製造の企業です。

**弱み**：財務が業務面に後れを取っています。別の財務システムを併用している企業もあります。

### IFS Cloud

在庫と同じくらい資産が重要な場合（航空宇宙、防衛、エネルギー、公益事業）は、IFSが理にかないます。ERP、エンタープライズ資産管理（EAM）、フィールドサービス管理（FSM）を1つの製品にまとめています。そうした競合は、ほとんどありません。

機能の深さは、導入の手間を伴います。本格的なリソースの投入なしに、6か月のロールアウトを計画してはいけません。

**向いている企業**：設備のライフサイクル、保守、コンプライアンスが事業運営を左右する、規制業種の資産集約型の製造企業です。

### Acumatica

再導入なしで成長したい小規模な製造業にとって、コストパフォーマンスが高い製品です。ブラウザベースで、モジュール式です。ライセンスは、使うアプリケーションと消費するリソースに対して課金され、ユーザー数は無制限です。工場全体をシステムに載せたいときに助かります。

複雑な製造現場のシナリオでは、EpicorやInforのような深みはありません。MESへの要求が重くない、単純な生産なら、期待に応えます。

**向いている企業**：エンタープライズ並みのコストや複雑さなしに、モダンなクラウドERPを求める、小規模から中堅の製造企業です。

### Sage X3

中堅のプロセス製造向けです。医薬品、飲食料品、化学が対象です。バッチ管理、ロットのトレーサビリティ、規制対応が組み込まれています。ディスクリートよりも、プロセス向きです。規制のかかる中規模のプロセス製造業なら、SAPプログラムの重さなしに、GxPのバッチトレーサビリティを実現できます。

**向いている企業**：SAPの負担なしに、トレーサビリティとコンプライアンスを必要とする、中堅のプロセス製造企業です。

### DELMIAWorksとCetec ERP

DELMIAWorks（旧IQMS、現在はDassault Systèmesの一部）は、小規模なディスクリート製造向けで、製造現場の管理に強みがあります。Cetecは低コストの選択肢です。クラウドで、すばやく導入でき、過剰に投資したくない小さな工場でも拡張しやすい製品です。

予算が最大の制約で、運営がシンプルなら、Cetecは真剣に検討する価値があります。

## よくある導入の課題

どのシステムを選んでも、うまくいくかどうかを左右するのは、こうした問題です。その大半は、プロジェクトが始まる前に決まります。

| 課題 | 何がうまくいかないか | 避け方 |
|---|---|---|
| **目標が不明確** | 開始時にKPIも成功基準もない | ベンダーを選ぶ前に、成功の尺度を書き出す |
| **過剰なカスタマイズ** | 昔からの習慣をすべて新システムに押し込む | まずワークフローをマッピングする。ソフトウェアを変える前に、プロセスを変える |
| **チェンジマネジメントの過小評価** | ユーザーが抵抗する。トレーニングが急ぎになる | 各チームにチェンジチャンピオンを置く。早い段階から周知する |
| **汚れたデータ** | 不正確なマスタデータが、本稼働時のエラーを招く | プロジェクトの開始前に、データの責任者を決める |
| **スコープクリープ** | プロジェクトの途中で機能が追加される | 本稼働に必要な最小限のスコープを定義する。残りは段階的に進める |
| **不十分なテスト** | プロセス全体のテストなしで本稼働する | 実データでエンドツーエンドにテストする。特に財務のフロー |
| **本稼働後の計画がない** | サポートが薄れ、ユーザーがスプレッドシートに戻る | 本稼働の前に、安定化とハイパーケアを計画する |

トレーニングは、いつも過小評価されます。トレーニングを受けていないユーザーは、システムを使いません。回避して作業します。それでは本末転倒です。データのクレンジングも、いつも長引きます。どちらにも、余分な時間を組み込んでください。

## 製造業ではクラウドかオンプレミスか

新しい製造業向けERPプロジェクトの大半では、クラウドが標準です。アップデートは自動で届き、インフラを自分で運用する必要はなく、拡張も容易です。引き換えに失うのは、アップデートのタイミングを自分で決める自由です。生産カレンダーに合うかどうかにかかわらず、新しいリリースが適用されます。

SAPでは、新しい製造業向けプログラムの大半が、RISE（プライベートクラウド）かGROW（パブリッククラウド）を選びます。オンプレミスのS/4HANAもいまも販売されており、選ばれるのは、たいていデータレジデンシー、主権、工場の接続性が理由です。現在SAP Solution Managerを使っているなら、そのメインストリームメンテナンスが2027年末に終わり、2030年まで限定的な延長保守があることに注意してください。SAPは、後継として[SAP Cloud ALM](https://support.sap.com/en/alm/faq.html)を案内しています。

オンプレミスが理にかなうのは、高いセキュリティが求められる環境、接続が不安定な工場、クラウドモデルが対応できない連携アーキテクチャの場合です。この一覧のベンダーの大半は両方を提供しているため、決め手は、ERPの機能ではなく、ITポリシーになるのがふつうです。

## 製造業のタイプ別の推奨

まずここから始め、自社の行が指す2、3のシステムについて、詳細を読んでください。

| 製造業のタイプ | 候補に挙げるERP | 理由 |
|---|---|---|
| **小規模（100人未満）** | Acumatica、Cetec ERP | 手頃で、クラウドで、再導入なしで拡張できる |
| **中堅、標準プロセス** | GROW with SAP、Epicor Kinetic、Acumatica | SAPを軸にした将来に向けてはGROW。製造現場重視ならEpicor |
| **ディスクリート製造** | Epicor Kinetic、Infor CloudSuite Industrial、DELMIAWorks | 強力なMES、スケジューリング、製造現場の管理 |
| **プロセス製造** | Sage X3、Infor M3 | バッチのトレーサビリティ、コンプライアンス、プロセス固有のフロー |
| **ミックスモード** | Infor CloudSuite Industrial、Dynamics 365 | 大がかりなカスタマイズなしで、ディスクリートとプロセスの両方に対応 |
| **グローバル企業** | RISE with SAP S/4HANA、IFS Cloud | 複数工場、多通貨、深いコンプライアンスと連携 |
| **資産集約型** | IFS Cloud。非常に大規模な環境にはRISE with SAP | ERP、EAM、フィールドサービスを1つのシステムで |

50人の工場が、500人の施設よりも複雑なプロセスを動かしていることもあります。従業員数で選ばないでください。見るべきは、生産のタイプ、ワークフローの複雑さ、そしてシステムを支えるチームです。候補にSAPとOracleの両方が入っているなら、私の[SAPとOracleの比較](/ja/sap-vs-oracle-which-erp-is-better-for-your-business/)で、その選択をさらに掘り下げています。

## よくある質問

<summary>製造業に最適なERPは、どう選べばよいですか？</summary>

まず、生産のタイプ（ディスクリートの受注生産か見込み生産、バッチと配合を伴うプロセス、あるいはミックスモード）と、運用上の最大のギャップから始めます。ベンダーの機能一覧ではなく、そのギャップに照らして、システムを絞り込んでください。

製造現場の監督者を、早い段階でデモに参加させてください。営業のプレゼンテーションでは滑らかに見えるものも、シフトの開始時に作業指示を入力する監督者の目には、まったく違って見えることがあります。その反応は、アナリストのスコアよりも重要です。

</details>

<details>
<summary>製造業で最も広く使われているERPは何ですか？</summary>

大手製造業で最も広く導入されているのは、SAPです。中堅の領域では、Epicor、Infor、NetSuite、Dynamics 365、そしていまではGROW with SAPが、いずれも一般的です。

最も広く使われていることと、最も適していることは同じではありません。エンタープライズ層でのSAPの地位は、その機能の深さを反映したもので、すべての運営に合うという意味ではありません。

</details>

<details>
<summary>MESとMRPの違いは何ですか？</summary>

製造実行システム（MES）は、リアルタイムの製造現場の動きを管理します。機械のデータ、人員、品質イベント、仕掛品です。「いま、現場で何が起きているか」に答えます。

資材所要量計画（MRP）は、需要とリードタイムに基づいて、何をいつ買うかを割り出します。「スケジュールを満たすために、何を発注する必要があるか」に答えます。

ほとんどの製造業向けERPにMRPは含まれています。MESは、ERPと連携する別のシステムか、ERPの製造現場モジュールの一部です。生産が複雑になるほど、専用のMESが必要になる可能性が高まります。

</details>

<details>
<summary>製造業向けの無料のERPはありますか？</summary>

ERPNextはオープンソースで、セルフホスティングなら無料です。部品表、製造指図、在庫といった製造の基本をカバーしています。

ただし、セルフホスティングには、セットアップ、保守、アップグレードのための社内の技術スキルが必要です。技術者がいて、プロセスがシンプルな小規模製造業には向いています。

</details>

<details>
<summary>製造業でSAPは何に使われますか？</summary>

SAP S/4HANAは、生産計画（PP）、プラントメンテナンス（PM）、品質管理（QM）、資材管理（MM）、そしてそれらすべてを1つのシステムで結ぶ財務連携をカバーします。大規模な環境では、複数工場のスケジューリング、ロットのトレーサビリティ、MESやSCADAシステムとの連携、グローバルなコンプライアンスに対応します。

複雑で、高価です。大手製造業にとっては、その深さが投資を正当化します。私の[SAP PPガイド](/ja/sap-pp-production-planning/)で、生産計画モジュールを詳しく説明しています。

</details>

<details>
<summary>製造業向けERPの選定で、最も大きな失敗は何ですか？</summary>

繰り返し出てくるのは3つです。使わない機能を買うこと。実装の労力（特にデータ移行とトレーニング）を過小評価すること。そして、そのシステムを毎日使う人たちを抜きにして、ベンダーのデモで選ぶことです。

3つ目が、最も高くつきます。技術的には正しくても、製造現場のスタッフが受け入れられないシステムは、回避されます。回避されているシステムは、システムがないよりも悪い状態です。

</details>
