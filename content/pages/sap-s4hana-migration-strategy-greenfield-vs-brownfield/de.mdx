## Wie verwenden Sie das S/4HANA Migration Strategy Tool?

Die Nutzung des S/4HANA Migration Assessment Tool ist einfach, aber was es aufdeckt, kann Sie später vor teuren Fehltritten bewahren. Die Idee ist, Ihnen zu helfen, eine Entscheidung zu treffen, Greenfield, Brownfield oder etwas dazwischen, basierend darauf, wo Ihr System heute steht und wohin Sie wollen. So gehen Sie dabei vor:

#### 1\. **Systemalter (Jahre seit Go-Live)**

Beginnen Sie damit auszuwählen, wie lange Ihr aktuelles [SAP-System](https://noeldcosta.com/sap-implementation/) bereits läuft. Ein neueres System (1–4 Jahre) tendiert eher zu Brownfield, besonders wenn noch alles reibungslos funktioniert. Ein System mittleren Alters (5–9 Jahre), wie in diesem Beispiel, hat möglicherweise Ineffizienzen angesammelt, enthält aber noch Wertvolles, das es zu bewahren lohnt. Ältere Systeme (10+ Jahre) bringen Unternehmen oft dazu, einen saubereren Schnitt in Betracht zu ziehen.

#### _**2\. Anzahl kundeneigener Objekte (Z-Objekte)\***_

Custom Code ist in der Migrationsplanung ein großes Thema. Wenn Sie bei 151–400 kundeneigenen Objekten liegen, ist das ein mittleres Maß an Komplexität. Genug, um relevant zu sein. Je mehr Z-Code Sie haben, desto schwieriger wird eine saubere Konvertierung, vor allem wenn Sie nicht wissen, was aktiv genutzt wird. Brownfield kann diese Dinge intakt lassen, aber Greenfield gibt Ihnen die Chance, gründlich aufzuräumen.

#### 3\. **Datenqualität**

Als Nächstes bewerten Sie Ihre Daten. Seien Sie ehrlich. Sind sie sauber? Konsistent? Wenn Ihre Antwort „etwas Validierung, einige Inkonsistenzen“ lautet, landen Sie im Mittelfeld. Sie haben wahrscheinlich Daten, die nutzbar sind, aber vor dem Umzug vorbereitet werden müssen. Greenfield zwingt Sie möglicherweise ohnehin zur Bereinigung. Brownfield könnte sie unverändert mitnehmen, und das kann riskant sein. Das Tool berücksichtigt das.

#### 4\. **Bedarf an Neugestaltung von Geschäftsprozessen**

Wenn Sie nur „einige Schlüsselbereiche“ neu gestalten, deutet das darauf hin, dass Sie nicht alles komplett umbauen. In diesem Fall wird Selective Transition zu einer echten Option. Damit können Sie reparieren, was kaputt ist, ohne das gesamte System wegzuwerfen. Vollständige Neugestaltung? Dann tendieren Sie zu Greenfield. Minimale Änderungen? Dann reicht Brownfield möglicherweise aus.

#### 5\. **Aufbewahrung historischer Daten**

Brauchen Sie wirklich jede Transaktion aus dem letzten Jahrzehnt? Oder nur die wichtigen Geschäftsbelege? „Selektive“ Aufbewahrung bedeutet, dass Sie einen Teil der Vergangenheit zurücklassen können. Das passt gut zu Greenfield oder Selective Transition, wo Sie nicht alle historischen Daten ins neue System übernehmen. Brownfield bringt alles mit, sofern Sie es nicht filtern.

#### 6\. **Projektbudget (USD)**

Zuletzt, aber keineswegs unwichtig, ist Ihr Budget. Ein mittleres Budget ($1M–$5M) schließt eine vollständig kundenspezifische Selective Transition oft aus, es sei denn, der Scope ist sehr eng gefasst. Greenfield und Brownfield können beide in diesen Rahmen passen, aber Scope-Kontrolle ist entscheidend. Brownfield ist anfangs oft günstiger; Greenfield kostet heute vielleicht mehr, spart Ihnen aber langfristig Wartungsaufwand. Das Tool gewichtet genau diesen Trade-off.

Sobald Sie jeden dieser Parameter ausgefüllt haben, klicken Sie einfach auf **"Calculate Recommendation"**. Sie erhalten einen Strategievorschlag plus eine Erklärung, die direkt auf Ihre Eingaben abgestimmt ist. Es ist keine magische Formel, aber es gibt Ihnen einen belastbaren Ausgangspunkt, dem man leichter vertraut als einem Bauchgefühl oder einem Vendor-Pitch.

## Wie das Tool entscheidet

Das Tool bewertet nicht einfach Antworten. Es verbindet die Punkte: was Sie haben, was Sie wollen und was schiefgehen könnte, wenn Sie den falschen Weg wählen.

-   **Systemalter**  
    Ältere Systeme (10+ Jahre) deuten oft auf Greenfield hin. Aber wenn die Dinge stabil und sauber sind, kann Brownfield trotzdem funktionieren.
    
-   _Custom Code (Z-Objekte)_\*  
    Eine hohe Zahl an Anpassungen erhöht das Risiko. Brownfield behält sie bei; Greenfield gibt Ihnen die Chance auf einen Neustart.
    
-   **Datenqualität**  
    Schlechte oder inkonsistente Daten verschieben die Empfehlung in der Regel weg von Brownfield. Migration bereinigt sie nicht, sie verschiebt sie nur.
    
-   **Prozessneugestaltung**  
    Wenn Sie nur einige wenige Bereiche anpassen, passt Brownfield. Größere Änderungen? Dann tendiert das Tool zu Greenfield oder Selective.
    
-   **Datenaufbewahrung**  
    Sie brauchen die vollständige Historie? Dann ist Brownfield einfacher. Selective oder Greenfield erfordern mehr Filterung und Vorbereitung.
    
-   **Budget**  
    Ein begrenztes Budget schränkt die Optionen ein. Das Tool wird nichts empfehlen, was Sie wahrscheinlich nicht sauber umsetzen können.
    

Es zielt nicht auf Perfektion, sondern auf eine Richtung, die auf Basis Ihrer aktuellen Situation Sinn ergibt.

## Was können Sie Ihrer SAP Implementation Roadmap sonst noch hinzufügen?

Nachdem Sie Ihre Basismodule ausgewählt haben, gibt es hier einige weitere Dinge, die Sie Ihrem Plan hinzufügen sollten:

**1)  Zeitschätzungen** - Tragen Sie realistische Termine für jeden Teil ein. Das Tool gibt Ihnen einige Startwerte basierend auf Ihrer Unternehmensgröße, aber Sie kennen Ihr Team am besten - wenn Sie für bestimmte Module mehr Zeit brauchen, passen Sie es an.

**2) Teambedarf -** Klären Sie, wen Sie in jeder Phase brauchen. Einige Module benötigen spezialisierte Berater, und Ihr internes Team wird im Verlauf des Projekts unterschiedliche Rollen haben.

**3) Kostenaufschlüsselung -** Geld ist wichtig - schlüsseln Sie auf, was Sie wann ausgeben werden. Das hilft besonders, wenn Sie Budgetfreigaben von Führungskräften brauchen, die die Zahlen sehen wollen.

**4) Systemanbindungen -** Haben Sie andere [Systeme, die mit SAP sprechen müssen](https://noeldcosta.com/sap-license-negotiation-10-key-points-to-consider-in-2024/)? Dann stellen Sie sicher, dass diese Anbindungen in Ihrem Plan enthalten sind. Ich habe einmal erlebt, dass sich ein Projekt um drei Monate verzögert hat, weil eine [wichtige Lagerverwaltungssystem](https://noeldcosta.com/why-2025-trump-tariffs-mean-higher-prices-for-everyone/)-Anbindung vergessen wurde.

**5) Schulungspläne -** Behandeln Sie Schulungen nicht als Nachgedanken. Planen Sie konkrete Zeiten für die Schulung verschiedener Gruppen ein. Das Accounting-Team braucht andere Schulungen als das Lagerpersonal.

**6) [Testphasen](https://noeldcosta.com/sap-quality-gates-implementation/) -** Planen Sie immer reichlich Zeit für Tests ein. Ich habe noch nie ein Projekt mit zu viel Testzeit gesehen, aber viele, bei denen nicht genug eingeplant war.

**7) Go-Live-Ansatz -** Entscheiden Sie, ob Sie alles auf einmal einschalten oder Module nacheinander ausrollen. Es gibt keine richtige Antwort - es hängt von Ihren Geschäftsanforderungen ab.
