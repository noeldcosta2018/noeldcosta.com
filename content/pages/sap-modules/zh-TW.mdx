主要的 SAP 模組包括財務會計（FI）、管理會計（CO）、物料管理（MM）、銷售與配銷（SD）、生產規劃（PP）、品質管理（QM）、工廠維護（PM）、人力資本管理（HCM）、延伸倉庫管理（EWM）和專案系統（PS）。在它們背後是技術模組：Basis、ABAP、SAP Business Technology Platform（BTP）和 SAP Integration Suite。

在 SAP S/4HANA 中，SAP 現在把這些模組歸入不同的業務線，例如財務、尋源與採購、製造、供應鏈和銷售。舊的模組代碼並沒有消失。顧問、徵才廣告和設定選單每天都還在使用它們。

## 功能性與技術性 SAP 模組的差別

SAP 模組分為兩類。

1. **功能模組**對應一個業務流程。財務負責結帳，採購負責購買，銷售負責銷售，生產負責製造。業務使用者每天都登入這些模組。
2. **技術模組**負責底層系統的運作。它們涵蓋系統管理、自訂開發、整合和擴充。使用者很少看到它們，但每個功能模組都依賴它們。

大家也會談到產業模組，例如 SAP S/4HANA Utilities 或 Retail。它們建立在核心模組之上，而不是取代核心模組。下文會進一步說明。

我看過一些團隊陷入困境，不是因為系統不能用，而是因為他們並不真正了解每個模組負責什麼，或一個模組的變更會如何波及其他模組。您不需要學會每一項功能。您需要知道的，是足以做出好選擇的程度。

## SAP 功能模組清單

下表列出核心功能模組、各自的功能，以及它們目前在 SAP S/4HANA 中的位置。業務線名稱取自 SAP 自己的 S/4HANA Cloud Public Edition 2608 Feature Scope Description。

| 模組 | 完整名稱 | 功能 | S/4HANA 業務線 |
|---|---|---|---|
| FI | 財務會計（Financial Accounting） | 總帳、應付與應收帳款、資產會計、財務結帳和法定報表 | 財務 |
| CO | 管理會計（Controlling） | 成本中心、內部訂單、產品成本計算和利潤分析，用於內部報告 | 財務 |
| MM | 物料管理（Materials Management） | 請購單、採購單、收貨、庫存和發票驗證 | 尋源與採購、供應鏈 |
| SD | 銷售與配銷（Sales and Distribution） | 報價、銷售訂單、定價、交貨和開立發票（訂單到收款） | 銷售 |
| PP | 生產規劃（Production Planning） | 物料需求規劃（MRP）、物料清單、途程和生產訂單 | 製造 |
| QM | 品質管理（Quality Management） | 檢驗規劃、檢驗批、結果記錄和品質通知 | 製造 |
| PM | 工廠維護（Plant Maintenance） | 設備的維護通知、工單和預防性維護計畫 | 資產管理 |
| HR / HCM | 人力資本管理（Human Capital Management） | 員工資料、組織管理、時間管理和薪資 | 人力資源 |
| SuccessFactors | SAP SuccessFactors | SAP 的雲端人資套件：核心人資（Employee Central）、招募、學習、績效 | 人力資源（獨立的雲端產品） |
| EWM | 延伸倉庫管理（Extended Warehouse Management） | 儲位層級的存放、進貨與出貨處理、揀貨和倉庫作業 | 供應鏈（倉儲） |
| PS | 專案系統（Project System） | 工作分解結構、網路、專案預算和成本 | 研發／工程 |
| TRM | 資金與風險管理（Treasury and Risk Management） | 現金管理、流動性預測、金融工具和避險 | 財務 |

有幾個模組不在這份核心清單中，但經常被提到。客戶服務（CS）處理服務訂單和合約，現在歸在服務業務線下。

環境、健康與安全（EHS）處理事故與合規，列在製造之下。運輸與交貨處理則歸在供應鏈之下。

### 核心模組如何相互連結

沒有任何功能模組是單獨運作的。SD 中的一張銷售訂單會檢查 MM 中的庫存，在庫存不足時觸發 PP 的生產，並在開立發票時把營收過帳到 FI。接著由 CO 接手成本和利潤。

正是這條鏈，讓一個模組中的設計決策波及其他模組。在 SD 中改一個定價條件，就會改變進入 FI 的內容。在 QM 中漏掉一個檢驗類型，貨品就可能在 MM 中被凍結。

### 人資：SAP HCM 或 SuccessFactors

人資是包裝方式變化最大的模組。地端客戶可以使用 SAP HCM for SAP S/4HANA，SAP 仍透過自己的學習課程教授人事管理、時間管理和薪資。

SAP 在人資上的雲端方向是 SuccessFactors。在 S/4HANA Cloud Public Edition 中，人力資源範圍涵蓋核心人資和工時記錄，以及與外部人資系統的整合。SuccessFactors 就是 SAP 自己為這個外部系統提供的選項。

## SAP 技術模組

技術模組不會出現在流程圖上，但它們決定系統能否保持穩定、快速和連通。常見的有：

| 模組 | 功能 |
|---|---|
| Basis | 系統管理：安裝、使用者與角色管理、系統間的傳輸、修補程式和效能監控 |
| ABAP | SAP 的程式語言，用於 ERP 內的自訂報表、表單、介面和增強 |
| SAP BTP | SAP Business Technology Platform：在 ERP 核心之外建置擴充功能和應用程式，並提供資料、AI 和整合服務 |
| SAP Integration Suite | 透過 API、事件和整合流程連接 SAP 與非 SAP 系統。SAP PI/PO 的後繼產品 |
| SAP BW/4HANA | 資料倉儲，用於跨 SAP 與非 SAP 來源的報表 |
| SAP Analytics Cloud | 雲端的儀表板、規劃和分析 |

這裡有兩個日期很重要。SAP Learning 指出，作為 SAP Process Orchestration 底層平台的 SAP NetWeaver 7.5，主流維護至 2027 年底，並可選擇延長維護至 2030 年底。

SAP 把 SAP Integration Suite 定位為目標平台。我的 [SAP CPI 與 Integration Suite](/zh-TW/sap-cpi/) 指南說明了這項移轉。

關於建立在這些模組之上的報表與規劃，請參考我的 [SAP Analytics Cloud 指南](/zh-TW/sap-analytics-cloud/)。

我看過專案停滯，不是因為財務沒設定好，而是因為有人低估了管理傳輸所需的工作量，或沒有規劃介面測試。這種事在出錯之前不會被注意到。一旦出錯，大家就只看得到它。

## SAP S/4HANA 如何組織模組

在 SAP ECC 中，模組是每個人做規劃時的基本單位。在 SAP S/4HANA 中，SAP 依業務線組織其範圍，舊的模組則位於這些業務線之內。

SAP 的 S/4HANA Cloud Public Edition 2608 Feature Scope Description（文件版本日期為 2026 年 10 月 8 日）列出以下業務線：

1. 資產管理
2. 財務
3. 人力資源
4. 製造
5. 專業服務
6. 研發／工程
7. 銷售
8. 服務
9. 尋源與採購
10. 供應鏈

同一份文件另外列出了產業範圍，包括公部門、銀行、保險、石油與天然氣，以及零售。

這種組織方式帶來三項實務上的變化：

1. **財務會計與管理會計共用一本日記帳。**在 S/4HANA 中，FI 和 CO 的過帳都進入通用日記帳（universal journal），兩者之間的調節工作因此減少。這也是為什麼現在很多人把「FICO」當成同一個領域。
2. **倉庫管理換了位置。**傳統的倉庫管理（WM）由 EWM 取代，EWM 可以內嵌在 S/4HANA 中執行，也可以作為獨立系統。
3. **代碼保留了下來。**業務線名稱是 SAP 銷售和撰寫產品文件的方式。FI、MM 和 SD 仍是專案團隊溝通時使用的語言。

### 為什麼 ECC 的日期對模組規劃很重要

SAP 在 2020 年 2 月宣布，包含 SAP ECC 在內的 SAP Business Suite 7 核心應用程式，主流維護至 2027 年底，並可選擇延長維護至 2030 年底。SAP 也承諾維護 S/4HANA 至 2040 年底。

如果您目前使用 ECC，您的模組選擇就與這次移轉綁在一起。我的 [ECC 移轉至 S/4HANA 指南](/zh-TW/ecc-to-s4hana-migration/)說明了各種路徑、步驟和期限。

## 產業模組

核心模組出現在每一次導入中。產業模組則處理核心模組涵蓋不到的流程：公用事業計費、石油與天然氣的合資會計、零售門市營運、公部門預算與補助款。

我記得一個公用事業專案，客戶以為 SD 可以處理他們的計費。結果不行。差得遠了。

我們必須迅速轉向 IS-U，老實說，這從第一天起就應該納入討論。

產業模組仍然運行在 FI、MM 和其他模組之上。它們改變的是這些模組在您的產業中如何運作。如果您的產業有對應的產業模組，請及早納入範圍，即使您還不確定會深入到什麼程度。

## 該從哪些 SAP 模組開始

多數企業不會一次啟用整套系統。依我的經驗，大多數公司從財務、人資和採購開始。

這很合理。每家公司都需要結帳、發薪水，以及購買所需的東西。等這個基礎穩定之後，再依企業實際的業務內容，加入銷售、生產、品質和維護。

選擇時，請看四件事：

1. **先看您的流程。**在挑選模組之前，先釐清企業在做什麼。製造商需要 PP 和 QM。服務業公司可能更需要 PS。
2. **整合點。**每多加一個模組，就會與其他模組和外部系統產生介面。請為測試編列預算。
3. **產業需求。**受法規管制的計費、補助款或合資事業，可能需要產業解決方案，而不是核心模組。
4. **團隊的負荷能力。**每個模組在業務端都需要一位流程負責人。如果沒有人負責，它就會偏離方向。

不是每個模組都需要在第一天上線。想要一次做完所有事情，結果很少會好。

## 常見問題

<details><summary>主要的 SAP 模組有哪些？</summary>主要的 SAP 功能模組是財務會計（FI）、管理會計（CO）、物料管理（MM）、銷售與配銷（SD）、生產規劃（PP）、品質管理（QM）、工廠維護（PM）、人力資本管理（HCM）、延伸倉庫管理（EWM）和專案系統（PS）。主要的技術模組是 Basis、ABAP、SAP BTP 和 SAP Integration Suite。</details>

<details><summary>SAP 核心模組有哪些？</summary>核心模組是幾乎每家公司都會使用的模組：財務用 FI 和 CO，採購與庫存用 MM，銷售用 SD。製造商會再加上 PP 和 QM。依我的經驗，大多數公司從財務、人資和採購開始，再加入其他模組。</details>

<details><summary>SAP 技術模組是什麼？</summary>技術模組負責系統的運作，而不是業務流程。Basis 負責系統管理，ABAP 是自訂程式碼的程式語言，SAP BTP 承載核心之外的擴充功能和應用程式，SAP Integration Suite 則把 SAP 與其他系統連接起來。SAP BW/4HANA 和 SAP Analytics Cloud 負責報表與規劃。</details>

<details><summary>SAP S/4HANA 中還有 SAP 模組嗎？</summary>有的。SAP 現在依業務線撰寫 S/4HANA 的文件，例如財務、尋源與採購、製造、供應鏈和銷售。FI、CO、MM、SD 和 PP 等模組代碼，仍在專案團隊、職稱和設定中使用。</details>

<details><summary>SAP SuccessFactors 是 S/4HANA 的模組嗎？</summary>不是。SuccessFactors 是 SAP 獨立的雲端人資套件。它與 S/4HANA 整合。S/4HANA Cloud Public Edition 的人資範圍涵蓋核心人資和工時記錄，並與外部人資系統（例如 SuccessFactors）整合。地端客戶仍可使用 SAP HCM for SAP S/4HANA。</details>

<details><summary>可以只導入一個 SAP 模組嗎？</summary>技術上可以。很多公司先從財務開始，之後再擴充。您仍然需要 Basis、使用者管理，通常還需要一些整合，所以實務上很少真的只有一個模組。</details>
