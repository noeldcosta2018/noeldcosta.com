主なSAPモジュールは、財務会計（FI）、管理会計（CO）、在庫/購買管理（MM）、販売管理（SD）、生産計画（PP）、品質管理（QM）、設備保全（PM）、人事管理（HCM）、拡張倉庫管理（EWM）、プロジェクト管理（PS）です。その背後には技術モジュールがあります。Basis、ABAP、SAP Business Technology Platform（BTP）、SAP Integration Suiteです。

SAP S/4HANAでは、SAPはこれらのモジュールを、財務、調達、製造、サプライチェーン、販売といった業務領域（Line of Business）にまとめています。従来のモジュールコードがなくなったわけではありません。コンサルタント、求人広告、設定メニューでは、今も毎日使われています。

## SAPの機能モジュールと技術モジュールの違い

SAPのモジュールは2つのグループに分かれます。

1. **機能モジュール**は業務プロセスに対応します。財務は帳簿を締め、購買は買い、販売は売り、生産は作ります。業務ユーザーが毎日ログインするのはこちらです。
2. **技術モジュール**は、その下でシステムを動かします。管理、独自開発、連携、拡張をカバーします。ユーザーが目にすることはまれですが、すべての機能モジュールがこれに依存しています。

SAP S/4HANA UtilitiesやRetailのような業種別モジュールが話題になることもあります。これらはコアモジュールを置き換えるのではなく、その上に乗るものです。詳しくは後で説明します。

システムが動かなかったからではなく、各モジュールが何を担っているのか、あるモジュールの変更がほかのモジュールにどう波及するのかを本当には理解していなかったために苦労したチームを見てきました。すべての機能を覚える必要はありません。うまく選べるだけの知識があれば十分です。

## SAPの機能モジュール一覧

下の表は、中核となる機能モジュールと、それぞれの役割、そして現在のSAP S/4HANAでの位置づけをまとめたものです。業務領域の名称は、SAP自身のS/4HANA Cloud Public Edition 2608のFeature Scope Descriptionに基づいています。

| モジュール | 正式名称 | 何をするか | S/4HANAの業務領域 |
|---|---|---|---|
| FI | Financial Accounting（財務会計） | 総勘定元帳、買掛金・売掛金、固定資産会計、決算、法定報告 | 財務 |
| CO | Controlling（管理会計） | 内部報告のための原価センタ、内部指図、製品原価計算、収益性分析 | 財務 |
| MM | Materials Management（在庫/購買管理） | 購買依頼、購買発注、入庫、在庫、請求書照合 | 調達、サプライチェーン |
| SD | Sales and Distribution（販売管理） | 見積、受注、価格設定、出荷、請求（受注から入金まで） | 販売 |
| PP | Production Planning（生産計画） | 資材所要量計画（MRP）、部品表、作業手順、製造指図 | 製造 |
| QM | Quality Management（品質管理） | 検査計画、検査ロット、結果記録、品質通知 | 製造 |
| PM | Plant Maintenance（設備保全） | 設備の保全通知、作業指図、予防保全計画 | 資産管理 |
| HR / HCM | Human Capital Management（人事管理） | 従業員記録、組織管理、就業管理、給与計算 | 人事 |
| SuccessFactors | SAP SuccessFactors | SAPのクラウド型人事スイート：コア人事（Employee Central）、採用、学習、パフォーマンス | 人事（別のクラウド製品） |
| EWM | Extended Warehouse Management（拡張倉庫管理） | 棚番レベルの保管、入庫・出庫処理、ピッキング、倉庫タスク | サプライチェーン（倉庫管理） |
| PS | Project System（プロジェクト管理） | WBS、ネットワーク、プロジェクト予算と原価 | R&D／エンジニアリング |
| TRM | Treasury and Risk Management（財務・リスク管理） | 資金管理、流動性予測、金融商品、ヘッジ | 財務 |

この中核リストの外にあっても、よく話題に上るモジュールがいくつかあります。カスタマーサービス（CS）はサービス指図と契約を扱い、現在はサービスの業務領域に属しています。

環境・安全衛生（EHS）はインシデントとコンプライアンスを扱い、製造の下に記載されています。輸送と出荷処理はサプライチェーンの下にあります。

### コアモジュールのつながり

単独で動く機能モジュールはありません。SDの受注はMMで在庫を確認し、在庫が不足していればPPで生産を起動し、請求されるとFIに収益を転記します。その後、COが原価と利益を取り込みます。

この連鎖があるため、あるモジュールでの設計判断がほかのモジュールに波及します。SDの価格条件を変えれば、FIに計上される内容が変わります。QMで品質検査タイプを省けば、MMで品目がブロックされたままになることがあります。

### 人事：SAP HCMかSuccessFactorsか

人事は、提供形態が最も大きく変わったモジュールです。オンプレミスのお客様はSAP HCM for SAP S/4HANAを使うことができ、SAPは今も人事管理、就業管理、給与計算に関する自社の学習コースでこれを教えています。

人事に関するSAPのクラウドの方向性はSuccessFactorsです。S/4HANA Cloud Public Editionでは、人事の範囲はコア人事と勤怠記録に加え、外部の人事システムとの連携をカバーしています。その外部システムとしてSAP自身が用意している選択肢がSuccessFactorsです。

## SAPの技術モジュール

技術モジュールはプロセスマップには現れませんが、システムが安定し、高速で、つながった状態を保てるかどうかを決めます。代表的なものは次のとおりです。

| モジュール | 何をするか |
|---|---|
| Basis | システム管理：インストール、ユーザーとロールの管理、システム間の移送、パッチ適用、パフォーマンス監視 |
| ABAP | ERP内の独自レポート、帳票、インタフェース、拡張のためのSAPのプログラミング言語 |
| SAP BTP | SAP Business Technology Platform：ERPのコアの外で拡張機能やアプリを構築し、データ、AI、連携のサービスも提供する |
| SAP Integration Suite | API、イベント、インテグレーションフローを通じて、SAPとSAP以外のシステムを接続する。SAP PI/POの後継 |
| SAP BW/4HANA | SAPとSAP以外のソースをまたぐレポーティングのためのデータウェアハウス |
| SAP Analytics Cloud | クラウド上のダッシュボード、計画、分析 |

ここでは2つの日付が重要です。SAP Learningによると、SAP Process Orchestrationの基盤であるSAP NetWeaver 7.5のメインストリームメンテナンスは2027年末までで、オプションの延長メンテナンスは2030年末までです。

SAPは、移行先としてSAP Integration Suiteを位置づけています。その移行については、私の「[SAP CPIとIntegration Suiteのガイド](/ja/sap-cpi/)」で取り上げています。

モジュールの上でのレポーティングと計画については、私の「[SAP Analytics Cloudガイド](/ja/sap-analytics-cloud/)」をご覧ください。

財務の設定が不十分だったからではなく、移送の管理に必要な工数を誰かが過小評価したり、インタフェーステストを計画していなかったりしたために、プロジェクトが止まるのを見てきました。うまくいかなくなるまで気づかない類いのことです。そして、そうなると、それしか目に入らなくなります。

## SAP S/4HANAでのモジュールのまとめ方

SAP ECCでは、誰もが計画の単位にしていたのはモジュールでした。SAP S/4HANAでは、SAPは業務領域ごとに範囲を整理し、従来のモジュールはその中に収まっています。

SAPのS/4HANA Cloud Public Edition 2608のFeature Scope Description（ドキュメントバージョン2026年10月8日付）には、次の業務領域が記載されています。

1. 資産管理
2. 財務
3. 人事
4. 製造
5. プロフェッショナルサービス
6. R&D／エンジニアリング
7. 販売
8. サービス
9. 調達
10. サプライチェーン

同じドキュメントには、公共部門、銀行、保険、石油・ガス、小売などの業種別の範囲が別に記載されています。

このまとめ方に伴って、実務上の変更が3つあります。

1. **財務会計と管理会計が1つの仕訳を共有します。** S/4HANAでは、FIとCOの転記はユニバーサルジャーナルに入るため、両者の間の照合作業が減ります。多くの人が今「FICO」を1つの領域として話すのはそのためです。
2. **倉庫管理が移りました。** 従来の倉庫管理（WM）はEWMに道を譲りました。EWMはS/4HANAに組み込んで、または別システムとして動きます。
3. **コードは残りました。** 業務領域の名称は、SAPが製品を販売し、文書化するときの呼び方です。プロジェクトチームは今もFI、MM、SDで話します。

### ECCの日付がモジュール計画にとって重要な理由

SAPは2020年2月、SAP ECCを含むSAP Business Suite 7のコアアプリケーションのメインストリームメンテナンスを2027年末まで、オプションの延長メンテナンスを2030年末までとすることを発表しました。また、S/4HANAを2040年末まで保守することも約束しました。

現在ECCを使っているなら、モジュールの選択はその移行と結び付いています。移行パス、手順、期限については、私の「[ECCからS/4HANAへの移行ガイド](/ja/ecc-to-s4hana-migration/)」で取り上げています。

## 業種別モジュール

コアモジュールはどの導入にも登場します。業種別モジュールは、コアモジュールではカバーできないプロセスを扱います。公益事業の料金請求、石油・ガスの共同事業会計、小売の店舗運営、公共部門の予算と補助金などです。

ある公益事業のプロジェクトを覚えています。クライアントは、SDで料金請求を処理できると思い込んでいました。できませんでした。まったく足りませんでした。

私たちは急いでIS-Uに方向転換する必要がありました。正直に言えば、IS-Uは初日から議論に含めておくべきでした。

業種別モジュールも、FI、MMなどの上で動きます。それらの要素が自社の業界でどう振る舞うかを変えるものです。自社の業界向けのモジュールがあるなら、どこまで深く使うかがはっきりしなくても、早い段階でスコープに入れてください。

## どのSAPモジュールから始めるか

ほとんどの企業は、スイート全体を一度に稼働させるわけではありません。私の経験では、ほとんどの企業は財務、人事、購買から始めます。

それは理にかなっています。どの企業も、帳簿を締め、従業員に給与を支払い、使うものを購入する必要があります。販売、生産、品質、保全は、その基盤が安定してから、事業の実際の内容に応じて続きます。

選ぶときは、4つのことを確認してください。

1. **まずプロセス。** モジュールを選ぶ前に、事業が何をしているかを整理してください。製造業にはPPとQMが必要です。サービス企業にはPSのほうがはるかに必要かもしれません。
2. **連携ポイント。** モジュールを追加するたびに、ほかのモジュールや外部システムとのインタフェースが生まれます。テストの予算を確保してください。
3. **業界の要件。** 規制のある料金請求、補助金、共同事業には、コアモジュールではなく業種別ソリューションが必要になることがあります。
4. **チームの能力。** 各モジュールには、業務側にプロセスオーナーが必要です。オーナーがいなければ、モジュールは迷走します。

すべてのモジュールを初日に本稼働させる必要はありません。すべてを一度にやろうとして、うまくいくことはめったにありません。

## よくある質問

<details><summary>主なSAPモジュールは何ですか？</summary>主なSAPの機能モジュールは、財務会計（FI）、管理会計（CO）、在庫/購買管理（MM）、販売管理（SD）、生産計画（PP）、品質管理（QM）、設備保全（PM）、人事管理（HCM）、拡張倉庫管理（EWM）、プロジェクト管理（PS）です。主な技術モジュールは、Basis、ABAP、SAP BTP、SAP Integration Suiteです。</details>

<details><summary>SAPのコアモジュールとは何ですか？</summary>コアモジュールは、ほぼすべての企業が使うモジュールです。財務のためのFIとCO、購買と在庫のためのMM、販売のためのSDです。製造業はPPとQMを加えます。私の経験では、ほとんどの企業は財務、人事、購買から始め、その後に残りを加えます。</details>

<details><summary>SAPの技術モジュールとは何ですか？</summary>技術モジュールは、業務プロセスではなくシステムを動かすものです。Basisはシステムを管理し、ABAPは独自コードのためのプログラミング言語、SAP BTPはコアの外で拡張機能やアプリをホストし、SAP Integration SuiteはSAPをほかのシステムに接続します。SAP BW/4HANAとSAP Analytics Cloudは、レポーティングと計画を担います。</details>

<details><summary>SAP S/4HANAにもSAPモジュールはありますか？</summary>はい。SAPは現在、S/4HANAを財務、調達、製造、サプライチェーン、販売などの業務領域ごとに文書化しています。FI、CO、MM、SD、PPといったモジュールコードは、今もプロジェクトチーム、職種名、設定で使われています。</details>

<details><summary>SAP SuccessFactorsはS/4HANAのモジュールですか？</summary>いいえ。SuccessFactorsは、SAPの別のクラウド型人事スイートです。S/4HANAと連携します。S/4HANA Cloud Public Editionの人事の範囲は、コア人事と勤怠記録をカバーし、SuccessFactorsなどの外部の人事システムと連携します。オンプレミスのお客様は、引き続きSAP HCM for SAP S/4HANAを使うことができます。</details>

<details><summary>SAPモジュールを1つだけ導入することはできますか？</summary>技術的には可能です。多くの企業は財務から始めて、後で拡張します。それでもBasis、ユーザー管理、そして通常はある程度の連携が必要なため、実際には1つのモジュールだけの構成になることはまれです。</details>
