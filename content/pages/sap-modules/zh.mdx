主要的SAP模块包括财务会计（FI）、管理会计（CO）、物料管理（MM）、销售与分销（SD）、生产计划（PP）、质量管理（QM）、工厂维护（PM）、人力资本管理（HCM）、扩展仓库管理（EWM）和项目系统（PS）。在它们背后是技术模块：Basis、ABAP、SAP业务技术平台（BTP）和SAP Integration Suite。

在SAP S/4HANA中，SAP现在把这些模块归入财务、寻源与采购、制造、供应链和销售等业务线。旧的模块代码并没有消失。顾问、招聘广告和配置菜单每天都还在使用它们。

## SAP职能模块与技术模块：区别在哪里

SAP模块分为两类。

1. **职能模块**对应一个业务流程。财务负责关账，采购负责买，销售负责卖，生产负责制造。业务用户每天都要登录这些模块。
2. **技术模块**在底层运行系统。它们涵盖系统管理、定制开发、集成和扩展。用户很少看到它们，但每个职能模块都依赖它们。

人们也会谈到行业模块，比如SAP S/4HANA Utilities或Retail。它们叠加在核心模块之上，而不是取代核心模块。下文会详细介绍。

我见过有团队陷入困境，不是因为系统不能用，而是因为他们并不真正清楚每个模块负责什么，或者一个模块的变更会怎样波及其他模块。您不需要学会每一项功能。您需要知道的，是足以做出正确选择的那部分。

## SAP职能模块清单

下表列出了核心职能模块、每个模块做什么，以及它如今在SAP S/4HANA中的位置。业务线名称来自SAP自己为S/4HANA Cloud Public Edition 2608发布的功能范围说明（Feature Scope Description）。

| 模块 | 全称 | 做什么 | S/4HANA业务线 |
|---|---|---|---|
| FI | 财务会计（Financial Accounting） | 总账、应付账款和应收账款、资产会计、财务结账和法定报告 | 财务 |
| CO | 管理会计（Controlling） | 用于内部报告的成本中心、内部订单、产品成本核算和利润分析 | 财务 |
| MM | 物料管理（Materials Management） | 采购申请、采购订单、收货、库存和发票校验 | 寻源与采购、供应链 |
| SD | 销售与分销（Sales and Distribution） | 报价、销售订单、定价、交货和开票（从订单到收款） | 销售 |
| PP | 生产计划（Production Planning） | 物料需求计划（MRP）、物料清单、工艺路线和生产订单 | 制造 |
| QM | 质量管理（Quality Management） | 检验计划、检验批、结果记录和质量通知 | 制造 |
| PM | 工厂维护（Plant Maintenance） | 设备的维护通知、工单和预防性维护计划 | 资产管理 |
| HR / HCM | 人力资本管理（Human Capital Management） | 员工档案、组织管理、时间管理和薪资核算 | 人力资源 |
| SuccessFactors | SAP SuccessFactors | SAP的云端人力资源套件：核心人力资源（Employee Central）、招聘、学习、绩效 | 人力资源（独立的云产品） |
| EWM | 扩展仓库管理（Extended Warehouse Management） | 仓位级存储、入库和出库处理、拣配和仓库任务 | 供应链（仓储） |
| PS | 项目系统（Project System） | 工作分解结构、网络、项目预算和成本 | 研发/工程 |
| TRM | 资金与风险管理（Treasury and Risk Management） | 现金管理、流动性预测、金融工具和套期保值 | 财务 |

有几个模块不在这份核心清单中，但经常被提到。客户服务（CS）处理服务订单和合同，现在归入服务业务线。

环境、健康与安全（EHS）处理事故和合规，列在制造之下。运输和交货处理归入供应链。

### 核心模块如何相互连接

没有哪个职能模块是单独工作的。SD中的一张销售订单会在MM中检查库存，库存不足时在PP中触发生产，开票时把收入过账到FI。然后CO接手成本和利润。

正是这条链条，让一个模块中的设计决策会波及其他模块。在SD中改一个定价条件，就改变了进入FI的内容。在QM中漏掉一种检验类型，货物就可能在MM中被冻结。

### 人力资源：SAP HCM还是SuccessFactors

人力资源是组织方式变化最大的模块。本地部署的客户可以运行SAP HCM for SAP S/4HANA，SAP仍在通过自己关于人事管理、时间管理和薪资核算的学习课程讲授它。

SAP在人力资源方面的云端方向是SuccessFactors。在S/4HANA Cloud Public Edition中，人力资源范围涵盖核心人力资源和时间记录，以及与外部人力资源系统的集成。SuccessFactors就是SAP为这个外部系统提供的自家选项。

## SAP技术模块

技术模块不会出现在流程图里，但它们决定了系统能否保持稳定、快速和互联。常见的有：

| 模块 | 做什么 |
|---|---|
| Basis | 系统管理：安装、用户和角色管理、系统间传输、打补丁和性能监控 |
| ABAP | SAP的编程语言，用于在ERP内部开发自定义报表、表单、接口和增强 |
| SAP BTP | SAP业务技术平台：在ERP核心之外构建扩展和应用，并提供数据、AI和集成服务 |
| SAP Integration Suite | 通过API、事件和集成流连接SAP和非SAP系统。SAP PI/PO的后继产品 |
| SAP BW/4HANA | 用于跨SAP和非SAP数据源报告的数据仓库 |
| SAP Analytics Cloud | 云端的仪表板、计划和分析 |

这里有两个日期很重要。SAP Learning指出，SAP Process Orchestration底层平台SAP NetWeaver 7.5的主流维护到2027年底，可选的延长维护到2030年底。

SAP把SAP Integration Suite定位为目标平台。我的[SAP CPI与Integration Suite](/zh-CN/sap-cpi/)指南讲解了这次迁移。

关于在这些模块之上的报告和计划，请参阅我的[SAP Analytics Cloud指南](/zh-CN/sap-analytics-cloud/)。

我见过项目停滞，不是因为财务没有配置好，而是因为有人低估了管理传输所需的工作量，或者没有为接口测试做计划。这种事在出问题之前您不会注意到。而一旦出了问题，您眼里就只剩下它了。

## SAP S/4HANA如何组织这些模块

在SAP ECC中，模块是大家做计划时围绕的单位。在SAP S/4HANA中，SAP按业务线来组织范围，旧的模块位于各条业务线之内。

SAP为S/4HANA Cloud Public Edition 2608发布的功能范围说明（文档版本日期为2026年10月8日）列出了以下业务线：

1. 资产管理
2. 财务
3. 人力资源
4. 制造
5. 专业服务
6. 研发/工程
7. 销售
8. 服务
9. 寻源与采购
10. 供应链

同一份文档单独列出了行业范围，包括公共部门、银行、保险、石油和天然气以及零售。

这种组织方式带来了三个实际变化：

1. **财务会计和管理会计共用一个日记账。**在S/4HANA中，FI和CO的过账都进入通用日记账，所以两者之间的对账工作大大减少。这就是为什么现在很多人把“FICO”当作一个领域来说。
2. **仓库管理换了位置。**经典的仓库管理（WM）让位于EWM，EWM可以嵌入在S/4HANA中运行，也可以作为独立系统运行。
3. **代码保留了下来。**业务线名称是SAP销售和记录产品时使用的方式。FI、MM和SD仍然是项目团队之间的交流方式。

### 为什么ECC的日期对模块规划很重要

SAP在2020年2月宣布，包含SAP ECC在内的SAP Business Suite 7核心应用的主流维护到2027年底，可选的延长维护到2030年底。SAP还承诺对S/4HANA的维护持续到2040年底。

如果您今天在运行ECC，您的模块选择就与这次迁移绑定在一起。我的[ECC到S/4HANA迁移指南](/zh-CN/ecc-to-s4hana-migration/)讲解了各条路径、步骤和截止日期。

## 行业模块

核心模块出现在每一次实施中。行业模块处理核心模块无法覆盖的流程：公用事业计费、石油和天然气的合资会计、零售门店运营、公共部门的预算和拨款。

我记得一个公用事业项目，客户以为SD能处理他们的计费。它不能。差得远。

我们不得不迅速转向IS-U，说实话，这本该从第一天起就纳入讨论。

行业模块仍然运行在FI、MM和其他模块之上。它们改变的是这些部分在您所在行业中的行为方式。如果您的行业有对应的行业模块，请尽早把它纳入范围，即使您还不确定会做到多深。

## 应该从哪些SAP模块开始

大多数企业不会一次性启用整个套件。根据我的经验，大多数公司从财务、人力资源和采购开始。

这是合理的。每家公司都需要关账、给员工发工资、采购所需的东西。等这个基础稳定之后，再根据企业实际的业务，跟进销售、生产、质量和维护。

做选择时，请看四件事：

1. **先看您的流程。**在挑选模块之前，先梳理企业实际在做什么。制造商需要PP和QM。服务型企业可能更需要PS。
2. **集成点。**您每增加一个模块，都会与其他模块和外部系统产生接口。请为测试留出预算。
3. **行业要求。**受监管的计费、拨款或合资业务，可能需要的是行业解决方案，而不是核心模块。
4. **您团队的能力。**每个模块都需要业务一方有一位流程负责人。如果没人负责，它就会偏离方向。

不是每个模块都需要在第一天上线。试图一次做完所有事情，结果很少会好。

## 常见问题

<details><summary>主要的SAP模块有哪些？</summary>主要的SAP职能模块有财务会计（FI）、管理会计（CO）、物料管理（MM）、销售与分销（SD）、生产计划（PP）、质量管理（QM）、工厂维护（PM）、人力资本管理（HCM）、扩展仓库管理（EWM）和项目系统（PS）。主要的技术模块有Basis、ABAP、SAP BTP和SAP Integration Suite。</details>

<details><summary>SAP核心模块是哪些？</summary>核心模块是几乎每家公司都会运行的模块：财务方面的FI和CO，采购和库存方面的MM，以及销售方面的SD。制造商还会加上PP和QM。根据我的经验，大多数公司从财务、人力资源和采购开始，然后再加上其他模块。</details>

<details><summary>SAP技术模块是什么？</summary>技术模块运行的是系统，而不是业务流程。Basis负责系统管理，ABAP是用于自定义代码的编程语言，SAP BTP承载核心之外的扩展和应用，SAP Integration Suite把SAP与其他系统连接起来。SAP BW/4HANA和SAP Analytics Cloud负责报告和计划。</details>

<details><summary>SAP S/4HANA中还有SAP模块吗？</summary>有。SAP现在按业务线来记录S/4HANA，例如财务、寻源与采购、制造、供应链和销售。项目团队、职位名称和配置中仍在使用FI、CO、MM、SD和PP这些模块代码。</details>

<details><summary>SAP SuccessFactors是S/4HANA的一个模块吗？</summary>不是。SuccessFactors是SAP独立的云端人力资源套件。它与S/4HANA集成。S/4HANA Cloud Public Edition的人力资源范围涵盖核心人力资源和时间记录，并与SuccessFactors等外部人力资源系统集成。本地部署的客户仍然可以运行SAP HCM for SAP S/4HANA。</details>

<details><summary>可以只实施一个SAP模块吗？</summary>从技术上讲，可以。很多公司从财务开始，之后再扩展。您仍然需要Basis、用户管理，通常还需要一些集成，所以在实践中很少真的只有一个模块。</details>
