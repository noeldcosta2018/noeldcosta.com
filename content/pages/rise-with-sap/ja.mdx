RISE with SAPは、既存のSAPのお客様がオンプレミスのERPを1つのサブスクリプションでクラウドへ移行するための、SAPの提供形態です。クラウドERP（通常はSAP Cloud ERP Private、旧称SAP S/4HANA Cloud Private Edition）、SAPが管理する技術運用、変革のためのツール、そしてRISE with SAP Methodologyをまとめたものです。

私は、その中の3つの部分で企業を支援しています。契約前のRISE契約のレビュー、移行に関するアドバイス、そしてシステムとチームの準備ができているかどうかの確認です。このページでは、2026年10月時点でRISEとは何か、SAPが運用するものとお客様の側に残るもの、そして私の詳しいガイドでどこを深掘りしているかを説明します。

## 2026年のRISE with SAPとは

SAPはRISE with SAPを、「実績ある方法論、専門家のガイダンス、エージェント主導のツールチェーン」を使ってオンプレミスのERPを刷新する道筋と説明しています（[RISE with SAPの製品ページ](https://www.sap.com/products/erp/rise.html)より）。これは契約とデリバリーのパッケージです。独立したERP製品ではありません。

2025年に名称が変わりましたが、検索では今も古い名称が使われています。現在の位置づけは次のとおりです。

1. **SAP Cloud ERP Private**は、ほとんどのRISE契約の中核となるプライベートクラウドERPです。多くの人は今も、SAP S/4HANA Cloud Private Editionや「rise with sap s/4hana cloud」という名前で検索しています。
2. **SAP Cloud ERP**はSAPのクラウドERPの名称で、そのパブリックエディションが「rise with sap public cloud」と言うときに指しているものです。RISEはどちらのエディションでも構築できます。
3. **SAP GROW**（今も広くGROW with SAPと呼ばれています）は、SAPを初めて導入する企業向けの提供形態で、パブリックエディション上に構築されます。
4. **SAP RISE**と**RISE with SAP**は同じものです。「SAP RISE」は短い検索語にすぎません。

エディションの選択は、ほとんどの企業が誤る判断です。RISEはプライベートクラウドのことだと思い込んでいるからです。私のガイド「[RISE with SAPのパブリッククラウドとプライベートクラウドの比較](/ja/rise-with-sap-public-vs-private-cloud/)」では、設定、アップグレード、業種、移行パスについて、各エディションで何ができるかを取り上げています。そこでの私のルールは、非常に特殊な設定を必要としない標準プロセスならパブリッククラウドに移せる、というものです。

## RISE with SAPのマネージドサービス：SAPが運用するものと、お客様の側に残るもの

「SAPが運用する」という言葉が、予算面の想定外の多くを引き起こします。SAPの[マネージドクラウドサービスのページ](https://www.sap.com/products/erp/cloud-erp-private/features/managed-cloud-services.html)によると、このサービスはインフラにとどまらず、オペレーティングシステム、SAP HANAデータベース、SAP Cloud ERP Privateアプリケーションの管理を含みます。それが技術運用です。

業務プロセス、マスタデータ、月次決算は、引き続きお客様のものです。導入そのものもそうです。役割分担の要点は次のとおりです。

| 領域 | RISEのもとでSAPが運用するもの | お客様またはパートナーの側に残るもの |
|---|---|---|
| ホスティング | ハイパースケーラー上またはSAPのデータセンター内のインフラ | データ所在地のルールに合うプロバイダーとリージョンの選択 |
| 技術運用 | オペレーティングシステム、SAP HANAデータベース、アプリケーション運用、監視、セキュリティ | プライベートエディションでアップグレードをいつ適用するかの判断とそのテスト |
| 業務プロセス | SAPの標準コンテンツとベストプラクティス | プロセス設計、設定上の判断、機能面のサポート |
| データ | データが置かれるデータベース | マスタデータのクレンジング、マッピング、移行、所有 |
| 独自コード | 拡張のためのプラットフォーム | 独自オブジェクトの修正、廃止、作り直し |
| プログラム | オンボーディング、方法論、品質ゲート | パートナーの選定、ガバナンス、テスト、トレーニング、切替 |

詳細な項目が必要なら、SAP Help Portalが[パブリック、プライベート、オンプレミスの各エディションの提供内容の比較](https://help.sap.com/docs/SAP_S4HANA_CLOUD_PE/b89b8b9026e1456bb2a1df7c0d59c937/1485d139460246d2a4b936c0bb0ca272.html)を公開しています。より高い可用性のSLAや災害復旧などのオプションは、別の項目になります。これらは私の「[RISE with SAPの契約と価格のガイド](/ja/rise-with-sap-contract-pricing/)」で取り上げています。

## RISE with SAP Methodology（「adoption framework」として検索されているもの）

「RISE with SAP adoption framework」と検索する人がよくいます。SAP自身の名称は**RISE with SAP Methodology**です。初期のRISEのお客様が受け取っていた、まとまりのないオンボーディング資料に代わるものです。

SAPの[RISE with SAP Methodologyのページ](https://www.sap.com/products/erp/rise/methodology.html)によると、この方法論は3つの実務的な要素で構成されています。

1. **SAP Cloud ALMでのSAP Activateロードマップ。** プロジェクトは、おなじみのフェーズで進みます。Discover、Prepare、Explore、Realize、Deploy、Runです。
2. **品質ゲート。** 各フェーズの終わりにアンケートに回答するチェックポイントで、SAPとパートナーが同じ状況を把握できるようにします。
3. **オンボーディングと準備。** オンボーディングセッション、Discoverフェーズでのデジタルディスカバリーアセスメントのツールキット、そしてSAPがSAP Cloud ERP Privateパッケージの利用権に含まれるとしている変革準備サービスです。

SAPによる2026年のRISEの説明では、ツールチェーンに含まれる変革ツールとして[SAP Signavio、SAP LeanIX、WalkMe](https://learning.sap.com/courses/discovering-the-autonomous-enterprise/exploring-the-strategy-updates-for-rise-with-sap-and-sap-grow_ddbdcd8d-bf12-4298-a71e-a2c895a3673c)の名前も挙げています。SAPは現在、移行と刷新のためのAIアシスタントもそのツールチェーンの一部として説明しています。実際にどの利用権があるかは発注書によって決まるため、各ツールを名前で確認してください。

この方法論は、役に立つ枠組みです。難しい判断を代わりにしてくれるわけではありません。品質ゲートはフェーズが完了したことを確認するもので、スコープ、エディション、データ計画がそもそも正しかったかどうかは教えてくれません。

## RISE with SAPでの私の支援内容

最初から私が主導することもあります。物事がうまくいかなくなったときに、立て直しのために呼ばれることもあります。私が主導または立て直しを担った21のSAPプログラム全体で、私が行うRISEの仕事は3つのサービスに分かれます。

それぞれに明確な成果物があるため、何に対して費用を払っているのかがわかります。

| サービス | 最も役立つタイミング | 得られるもの |
|---|---|---|
| 契約レビュー | 最初のRISEの発注書に署名する前、または更新の前 | 設計に照らした発注書の一行ずつの読み込みと、交渉すべき条件の一覧 |
| 移行アドバイス | 移行パス、エディション、パートナーを選んでいるとき | 理由を文書にした、エディションと移行パスについての推奨 |
| 準備状況の確認 | スケジュールやパートナーの見積もりを確定する前 | SAP Readiness Checkと自社システムの読み解き、そしてスコープを決める未解決の論点 |

### 1. RISE契約のレビュー

RISEの過剰支出の大半は、更新時ではなく、最初の発注書で決まります。私が最もよく目にする3つの落とし穴は、更新条件、FUEのサイジング、AIクレジットです。Full Use Equivalent（FUE）は、SAPがERPのサブスクリプション価格の基準にしている利用量の指標です。

私はRISEの契約に、必ず2つのことを交渉で盛り込みます。含まれるモジュールを名前で明記すること、そしてフェーズ別の価格設定です。これにより、初日から全スコープの費用を払うのではなく、フェーズの本稼働に合わせて支払うことになります。最初の本稼働まで9か月から18か月かかるプログラムでは、まだシステムに触れないユーザーの分まで払うのは、無視できない金額です。

レビューで得られるもの：

1. **スコープの確認。** 発注書にあるすべてのモジュール、アドオン、クラウドサービスを、設計が必要とするものと比較します。
2. **サイジングの確認。** FUEの数を、職種名ではなく、人々が実際にシステムをどう使うかに照らして検証します。
3. **交渉項目の一覧。** 更新条件、AIクレジットの条件、含まれるモジュール、フェーズ別の価格設定を、購買部門がSAPに持ち込める論点として書き出します。

FUEの数え方、サブスクリプションに含まれるものと含まれないもの、SAPに投げかけるべき質問は、すべて私の「[RISE with SAPの価格ガイド](/ja/rise-with-sap-contract-pricing/)」にまとめています。これはプログラムの実務に基づく実践的なガイダンスであり、法的助言ではありません。発注書は、契約担当の弁護士にも必ず読んでもらってください。

### 2. RISEの移行アドバイス

RISEは外側の包みです。その中身は今もERPの移行であり、パスは3つあります。グリーンフィールド（新規導入）、ブラウンフィールド（システムコンバージョン）、またはセレクティブデータトランジションです。パブリックエディションは新規導入のみなので、エディションの選択とパスの選択は一緒に決める必要があります。

私のパスのルールはこうです。ほかのシステムから移行する場合や、新しいプロセスを定義する必要がある場合はグリーンフィールド。プロセスが定義されていて機能している場合はブラウンフィールド。一部の領域のプロセスを定義し直す必要がある場合はセレクティブです。

移行アドバイスで得られるもの：

1. **エディションの推奨。** プロセスがどれだけ標準的か、どの業種で事業をしているかに基づいて、パブリックかプライベートかを推奨します。
2. **パスの推奨。** プロセスとデータの調査結果に基づいて、グリーンフィールド、ブラウンフィールド、セレクティブのいずれかを推奨します。
3. **現実的なスケジュール。** RISEのプログラムでは9か月から18か月で計画します。パブリックエディションでのGROWのプログラムは、通常6か月から9か月です。
4. **パートナー向けのブリーフ。** お客様自身の言葉で書いたスコープです。パートナーが自分たちの設計ではなく、お客様の設計に基づいて見積もれるようにします。

詳しい手順、ツール、SAP ECCの保守期限は、私の「[ECCからS/4HANAへの移行ガイド](/ja/ecc-to-s4hana-migration/)」にあります。パスごとに何が予算を左右するかについては、私のガイド「[S/4HANA移行のコスト](/ja/s4hana-migration-cost/)」をお読みください。

### 3. RISEの準備状況の確認

SAP Readiness Checkは、ECCシステムの中で何がS/4HANAと衝突するかを教えてくれます。それにどう対処すべきかは教えてくれません。準備状況の確認は、その結果を、予算を付けられる判断に変えます。

準備状況の確認で得られるもの：

1. **SAP Readiness Checkの読み解き。** 簡素化項目、アドオン、独自コードへの影響、インタフェース、財務データの品質を、判断を下す立場の人に向けて説明します。
2. **独自コードの見通し。** どのオブジェクトが壊れるか、そして修正するよりも廃止すべきものはどれかです。
3. **インタフェースとデータの見通し。** 各インタフェースの両端と、移行前にデータのクレンジングが必要な箇所です。
4. **未解決の論点。** チェックでは答えが出ない判断の一覧で、これが移行アセスメントのスコープになります。

Readiness Checkがカバーする範囲、実行方法、足りない部分については、私のガイド「[SAP Readiness CheckとS/4HANA移行アセスメント](/ja/sap-readiness-check-migration-assessment/)」で取り上げています。ECCからの移行ではなく、SAPを初めて導入する場合は、私の「[GROW with SAPのページ](/ja/sap-implementation/grow-with-sap/)」から始めるのがよいでしょう。

## RISE with SAPは適しているか

RISEが最も合うのは、既存のSAPのお客様で、ECCまたはオンプレミスのS/4HANAシステムが事業の中核にあり、技術スタックの運用を自社のチームやホスティングプロバイダーではなくSAPに任せたい場合です。標準プロセスを受け入れる意思がない場合や、スコープ、データ、独自コードについての判断を社内で引き受けられる人がいない場合は、あまり合いません。

契約前に、次の質問をしてください。

1. パブリックエディションとプライベートエディションのどちらにするか決めたか、それともプライベートを前提にしているか。
2. 独自オブジェクトのうち、今も使われているものを把握しているか。
3. FUEの数は、人々がシステムをどう使うかに基づいているか、それとも職種名に基づいているか。
4. 契約価格は、展開のフェーズに沿っているか。
5. SAPが運用するのは技術レイヤーだけである以上、本稼働後の機能面のサポートは誰が担うのか。

このうち2つ以上に明確な答えがないなら、発注書の後ではなく、前に解決してください。
