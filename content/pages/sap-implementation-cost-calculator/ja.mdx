SAPプログラムの多くは、間違った数字を持って取締役会に上がります。ライセンスは適切に見積もられても、それ以外のすべて（パートナーサービス、設定、データ移行、研修、チェンジ、本稼働後のサポート）は1行の予備費にまとめられ、カットオーバーを迎えると持ちこたえません。

私がこの計算ツールを作ったのは、CIOとCFOが大手SIと交渉の席に着く前に、根拠のある範囲を手にできるようにするためです。対象はSAPに特化しています。S/4HANA Cloud、S/4HANAオンプレミス、BTP、RISE with SAPです。汎用のERPではありません。SAPプログラムの費用の形は、NetSuiteやDynamicsの導入とは違います。このツールはそれを反映しています。

大事な意味でのベンダー中立でもあります。私は導入そのものを売っていません。数字は、価格表ではなく、私が追跡してきた50件以上のプログラムから来ています。

## 使い方

下のフォームに入力してください。数字を最も大きく動かすのは、ユーザー数、対象モジュール、導入モデル（RISE、パブリッククラウド、プライベートクラウド、オンプレミス）、国、カスタマイズの度合いです。初期値は中堅企業によくあるパターンに合わせてあります。御社の状況に合わせて調整してください。

計算はすべてお使いのブラウザ内で実行されます。何も送信されず、何も保存されません。ページを再読み込みして、何度でもやり直せます。

## 計算式

見積もりは、SAPの価格体系に固有の固定費と変動費の要素を組み合わせています。

**プログラム費用 = (ライセンスまたはサブスクリプション × ユーザー数 × 導入モデル乗数) + パートナーの導入サービス + データ移行 + カスタマイズとABAP開発 + 研修とチェンジ + BTPとインフラ + 本稼働後のサポート + 予備費**

RISEとS/4HANA Cloudでは、ライセンスの部分はサブスクリプションで、フルユース相当（FUE）のユーザー数とエディションで規模が決まります。S/4HANAオンプレミスでは、永久ライセンスに、ライセンス費用の約22%の年間保守費が加わります。国とカスタマイズの乗数が最終的な範囲を調整します。結果にはカテゴリー別の内訳が表示されるので、費用が実際にどこにかかるのかを確認できます。

## SAP導入の実際のコスト

多くのSAPプログラムは、導入期間全体で**年間売上高の2〜6パーセント**を費やすことになります。着地点は、規模、業種の複雑さ、規制の負荷、標準からどこまで外れる計画かで決まります。

1. **小規模企業（従業員200人未満）**：通常は15万〜50万ドルです。範囲は限定的で、FI、CO、MMなどの標準モジュールが中心です。Business OneやGROW with SAPであることも多いです。
2. **中堅企業（従業員200〜1,000人）**：50万〜200万ドルです。モジュールの幅が広がり、連携の範囲も本格的になります。RISEやS/4HANA Cloud Public Editionがよく選ばれます。
3. **大企業（従業員1,000人以上）**：200万〜1,000万ドル以上です。複数の法人と複数の国、並行元帳を使うFI/CO、規制の複雑さがあり、S/4HANA Cloud Private Editionかオンプレミスであることが多いです。
4. **グローバルコングロマリット（従業員10,000人以上）**：1,000万〜5,000万ドル以上です。複数地域への展開、グループ連結、大規模なチェンジ。

業種によっても差が出ます。ある製造業のお客様では、構成を見直して不要なモジュールを外し、ライセンス費用を32%減らす手助けをしました。別のお客様は、必要のないプレミアムサポートに契約しかけていました。契約内容を1か所調整しただけで、年間22万ドルの節約になりました。節約の余地は、誰かが設定画面に触れる前の、契約書の中にあります。

## カテゴリー別のコスト内訳

私が率いてきたほとんどのSAPプログラムでは、費用の配分はおおよそ次のようになります。

| カテゴリー | 一般的な割合 | 対象 |
|---|---|---|
| パートナーの導入サービス | 30〜45% | 大手SIのコンサルティング、設定、プロジェクト管理、SAP Activateによる導入 |
| ソフトウェアライセンスまたはサブスクリプション | 15〜25% | S/4HANAのエディション、BTPサービス、RISEのバンドル、アドオン（Ariba、SuccessFactors、Concur） |
| 社内チームの工数 | 10〜20% | プロセスオーナー、FI/COリード、Basis管理者、現場の専門家（ベンダーの見積もりにはまず入らない） |
| データ移行 | 5〜15% | 旧システムからの抽出、クレンジング、SAP Migration Cockpit、検証 |
| カスタマイズとABAP開発 | 5〜15% | ABAP、CDSビュー、Fioriアプリ、BTP拡張、CPIによる連携 |
| 研修とチェンジマネジメント | 5〜10% | エンドユーザー研修、スーパーユーザー、社内周知、SAP Enable Nowのコンテンツ |
| BTPとインフラ | 5〜10% | BTPサービス、プライベートクラウド向けのハイパースケーラーホスティング、ネットワーク、ミドルウェア |
| 本稼働後のサポートと予備費 | 10〜15% | ハイパーケア、AMS、範囲の変更、想定外の要件 |

S/4HANAの標準プロセスに近い形で進める企業は、下限付近に収まります。何でもカスタマイズする企業は、上限付近になります。多くのSAPプログラムで、カスタマイズは自分で最も制御しやすい変数です。

## この計算ツールを使うのはどんな人か

1. **CFOと財務チーム**が、契約の署名前に複数年にわたるSAP投資の規模を見積もる。
2. **CIOとプログラムディレクター**が、大手SIの提案をベンダー中立の基準値に照らして検証する。
3. **調達責任者**が、交渉の前にSAPのライセンス見積もりとパートナーの日額単価に根拠を求める。
4. **独立系のSAPコンサルタントやアドバイザー**が、顧客のビジネスケースに透明性のある見積もりを載せる。
5. **中堅企業**が、コンサルティング会社に頼まずに、初めてのS/4HANAのビジネスケースをまとめる。

## 計算ツールを使う利点

1. **根拠のある数字。** プログラム全体の費用をカテゴリー別の内訳で現実的に示し、ステアリングコミッティ向けの資料に使える規模感です。
2. **速い。** スプレッドシートを作る必要はありません。情報を入力すれば、数秒で結果が出ます。
3. **SAPに特化。** 汎用のERP平均ではなく、S/4HANAのエディション、BTP、RISEの価格パターンを軸に作っています。
4. **ベンダー中立。** パートナーの価格表ではなく、私が追跡してきた50件以上のSAPプログラムから作りました。
5. **交渉に使える。** カテゴリー別の内訳で費用の落ち着き先が見えるので、契約の署名前にSIパートナーとの話し合いが鋭くなります。

出力がパートナーの見積もりと大きく違うなら、その差こそ、署名する前に話し合う価値があります。署名したあとではなく。

## よくある質問

<details>
<summary>この計算ツールのSAPコスト見積もりは、どのくらい正確ですか？</summary>

見積もりは、SAP固有の価格パターンと、私が追跡してきた50件以上のプログラムに基づいています。確定価格の見積書ではなく、根拠を持って予算を組むための基準値として設計しています。最終的な数字は、ライセンス交渉、導入モデルの選択、スコープの規律、データ品質、標準のS/4HANAからどこまでカスタマイズするかで決まります。

出力は、ベンダーとの対話の出発点として使ってください。SIパートナーの数字がこれより大幅に低い、または高い場合は、契約書に署名する前にその差を問いただす価値があります。

</details>

<details>
<summary>SAP計算ツールには、どのコスト項目が含まれていますか？</summary>

S/4HANAのライセンスまたはサブスクリプション、BTPサービス、パートナーの導入サービス、社内チームの工数、データ移行、ABAPとFioriのカスタマイズ、研修とチェンジマネジメント、インフラとホスティング、本稼働後のサポート、予備費です。選択した予測期間にわたる継続的なAMSと保守の費用も算出します。

「社内チームの工数」は、ほとんどのSIの見積もりが省く項目です。財務リード、Basis管理者、プロセスオーナーは、数か月にわたってプログラムに5割以上の時間を割くことになります。このコストは現実のものですが、パートナーの価格表には載りません。

</details>

<details>
<summary>RISE with SAPとS/4HANA Cloudの各エディションに対応していますか？</summary>

はい。導入モデルの選択肢には、RISE with SAP、S/4HANA Cloud Public Edition（GROW with SAP）、S/4HANA Cloud Private Edition、S/4HANAオンプレミスがあります。ライセンスの形はそれぞれ異なります。RISEはインフラと基本サービスをサブスクリプションにまとめています。Public Editionはカスタマイズの制限が厳しめです。Private Editionは自由度が高い分、費用も高くなります。オンプレミスは永久ライセンスに加えて、年間約22%の保守費がかかります。

</details>

<details>
<summary>カスタマイズの度合いは、SAPのコストにどう影響しますか？</summary>

大きく影響します。大幅にカスタマイズする企業は、導入費用が通常30〜50%多くなります。しかも、その負担は本稼働で終わりません。カスタムのABAPやZコードは保守が必要で、S/4HANAのリリースごとに再テストが必要で、次の担当チームへの引き継ぎも要ります。計算ツールでは、カスタマイズの度合いが低、中、高のそれぞれに乗数を適用し、このパターンを反映しています。

カスタマイズの判断で最も安上がりなのは、たいていの場合、カスタマイズしないことです。S/4HANAの標準プロセスは、何十年もかけて磨かれてきました。見極めるべきは、その逸脱が競争優位をもたらすのか、規制要件を満たすためなのかです。答えが「昔からそうしているから」なら、考え直してください。

</details>

<details>
<summary>計算ツールは、どのモジュールに対応していますか？</summary>

S/4HANAの標準的なモジュール構成です。財務会計（FI）、管理会計（CO）、購買・在庫管理（MM）、販売管理（SD）、生産計画（PP）、品質管理（QM）、プラント保全（PM）、人事管理（SuccessFactors経由のHCM）、調達（Ariba）、グループレポーティングです。モジュールを追加するごとに、設定と連携の工数は増えます。計算ツールはこれを織り込んでいます。

</details>

<details>
<summary>この見積もりをSAPのビジネスケースに使えますか？</summary>

はい。出力はS/4HANAプログラムの取締役会レベルの投資判断を支えられる規模感で、単一の数字ではなく範囲で示すので、もともとの不確実性が見えます。ステアリングコミッティに持ち込む資料には、カテゴリー別の内訳と予備費の前提を必ず含めてください。

SIパートナーがビジネスケースも書いているなら、それは問題です。インセンティブがずれています。パートナーの商業的な利害の外で計算した独立した数字。それがこの計算ツールの目的です。

</details>

<details>
<summary>SAPの継続的な保守とサポートはどうなりますか？</summary>

継続的な保守、アプリケーション保守運用サービス（AMS）、追加の機能強化として、導入費用総額の年15〜20パーセントを見込んでください。計算ツールは、指定した年数にわたってこれを算出するので、複数年の見通しを最初から取締役会資料に載せられます。

ハイパーケア（本稼働後の最初の30〜90日間）への投資が足りない企業は、本来テストで見つかるはずだった不具合の修正に、契約社員の日額単価で3か月分に相当する費用を払うことがよくあります。適切なハイパーケア投資は通常プロジェクト総費用の3〜5パーセントで、契約書に署名する前に盛り込んでおくべきです。

</details>

<details>
<summary>RISE with SAPは、S/4HANAをオンプレミスで運用するより安いですか？</summary>

必ずしもそうではありません。比較する期間として妥当な、5〜7年で見るならなおさらです。RISEは初期費用が低く、サブスクリプションの金額が読みやすく、ハイパースケーラーの調達を自分で管理する必要もありませんが、サブスクリプションは毎年積み上がります。S/4HANAオンプレミスは、初期のライセンス費用とインフラ支出が大きい一方、サブスクリプションはなく、年間の保守費はライセンス費用の約22%です。

既存のBasisの運用能力があり、7年以上の視点で見る組織では、オンプレミスのほうが総保有コスト（TCO）で低くなることが多いです。SAPにスタックの運用を任せたく、設備投資（Capex）より運用費（Opex）を好む組織では、RISEが勝ちます。計算ツールでは両方をモデル化できます。

</details>
