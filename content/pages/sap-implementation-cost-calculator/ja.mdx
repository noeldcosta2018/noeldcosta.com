ほとんどのSAPプログラムは、誤った数字のまま取締役会に上がります。ライセンスは適切にサイジングされても、それ以外のすべて（パートナーサービス、設定、データ移行、トレーニング、チェンジマネジメント、本番稼働後サポート）は、単一の予備費の行に押し込まれ、カットオーバーに入ると持ちこたえません。

私はこの計算ツールを、CIOやCFOがtier-1 SIとテーブルを挟んで向き合う前に、根拠を持って説明できるレンジを把握できるように作りました。これはSAPに特化しています。S/4HANA Cloud、S/4HANA on-premise、BTP、そしてRISE with SAPです。汎用的なERPではありません。SAPプログラムのコスト構造は、NetSuiteやDynamicsの導入とは異なります。この計算ツールはその違いを反映しています。

また、重要な意味でベンダーニュートラルでもあります。私は導入を売っているわけではありません。数字は価格表からではなく、私が追跡してきた50件超のプログラムから得ています。

## 使い方

以下のフォームに入力してください。数字に最も大きく影響する入力項目は、ユーザー数、対象モジュール、導入モデル（RISE、パブリッククラウド、プライベートクラウド、オンプレミス）、国、そしてカスタマイズレベルです。デフォルト値は、典型的なミッドマーケットのパターンを反映しています。自社の状況に合わせて調整してください。

## 計算式

この見積りは、SAPの価格体系に特有の固定要素と変動要素を組み合わせています。

**プログラムコスト = （ライセンスまたはサブスクリプション × ユーザー数 × 導入モデル係数） + パートナー導入サービス + データ移行 + カスタマイズおよびABAP開発 + トレーニングとチェンジマネジメント + BTPとインフラ + 本番稼働後サポート + 予備費**

RISEおよびS/4HANA Cloudでは、ライセンス要素はサブスクリプションです。これはFull Use Equivalent (FUE)ユーザー数とエディションでサイジングされます。オンプレミスのS/4HANAでは、永続ライセンスに加え、ライセンス費用の約22%の年間保守がかかります。国別係数とカスタマイズ係数が最終レンジを調整します。カテゴリ別の内訳は結果に表示されるため、実際にどこに費用が着地するのか確認できます。

## SAP導入の実際のコスト

ほとんどのSAPプログラムでは、導入期間全体を通じて**年間売上高の2%から6%**を費やすことになります。どこに着地するかは、企業規模、業界の複雑さ、規制負荷、そして標準からどこまで逸脱するつもりかで決まります。

1. **小規模企業（従業員200人未満）:** 通常は$150K〜$500Kです。対象範囲は限定的で、FI、CO、MMのような標準モジュールが中心です。Business OneまたはGROW with SAPであることが多いです。
2. **ミッドマーケット（従業員200人〜1,000人）:** $500K〜$2Mです。モジュール構成はより広く、実際の統合範囲も発生します。RISEまたはS/4HANA Cloud Public Editionが一般的です。
3. **大企業（1,000人超）:** $2M〜$10M+です。複数法人、複数国、並行元帳を伴うFI/CO、規制対応の複雑さがあり、S/4HANA Cloud Private Editionまたはオンプレミスであることが多いです。
4. **グローバル複合企業（10,000人超）:** $10M〜$50M+です。複数地域へのロールアウト、グループ連結、大規模なチェンジマネジメントが伴います。

業界は重要です。私はある製造業のクライアントで、ライセンス構成を見直し、不要なモジュールを削ることで、ライセンス費用を32%削減しました。別のクライアントは、不要なプレミアムサポートにサインする直前でした。契約を1点調整しただけで、年間$220,000を削減できました。こうした節約余地は、誰かが設定画面に触れる前、つまり契約の中にあります。

## カテゴリ別コスト内訳

私が担当してきたほとんどのSAPプログラムでは、支出はおおむね次のように着地します。

| Category | Typical share | What it covers |
|---|---|---|
| パートナー導入サービス | 30–45% | Tier-1 SIのコンサルティング、設定、プロジェクト管理、SAP Activateによるデリバリー |
| ソフトウェアライセンスまたはサブスクリプション | 15–25% | S/4HANAの各エディション、BTPサービス、RISEバンドル、アドオン（Ariba、SuccessFactors、Concur） |
| 社内チーム工数 | 10–20% | プロセスオーナー、FI/COリード、basis管理者、業務SME（ベンダー見積りにはまず含まれません） |
| データ移行 | 5–15% | 旧システムからの抽出、クレンジング、SAP Migration Cockpit、検証 |
| カスタマイズおよびABAP開発 | 5–15% | ABAP、CDSビュー、Fioriアプリ、BTP拡張、CPI経由の統合 |
| トレーニングとチェンジマネジメント | 5–10% | エンドユーザートレーニング、スーパーユーザー、コミュニケーション、SAP Enable Nowコンテンツ |
| BTPとインフラ | 5–10% | BTPサービス、プライベートクラウド向けハイパースケーラーホスティング、ネットワーク、ミドルウェア |
| 本番稼働後サポートと予備費 | 10–15% | ハイパーケア、AMS、スコープ変更、想定外要件 |

標準のS/4HANAプロセスに近い運用を維持する企業は、低い方のレンジに収まります。何でもカスタマイズする企業は、高い方のレンジに行きます。カスタマイズは、ほとんどのSAPプログラムで最もコントロールしやすい変数です。

## この計算ツールを使うメリット

1. **根拠を持って説明できる数字。** ステアリングコミッティ向け資料に使えるよう、カテゴリ別に分解された現実的な総プログラムコストを把握できます。
2. **速い。** スプレッドシートを作る必要はありません。詳細を入力すれば、数秒で結果が出ます。
3. **SAP特化。** 汎用ERPの平均値ではなく、S/4HANAの各エディション、BTP、RISEの価格パターンを前提に作っています。
4. **ベンダーニュートラル。** パートナーの価格表ではなく、私が追跡してきた50件超のSAPプログラムをもとに作っています。
5. **交渉に使える。** カテゴリ別の内訳によって、実際にどこに費用が着地するのか見えるため、契約締結前にSIパートナーとの会話の精度が上がります。

もし計算ツールの出力がパートナー見積りと大きく違うなら、その差こそ契約前に話すべき論点です。契約後ではありません。

<summary>この計算ツールによるSAPコスト見積りの精度はどの程度ですか？</summary>

この見積りは、SAP固有の価格パターンと、私が追跡してきた50件超のプログラムに基づいています。固定価格の見積書ではなく、根拠を持って予算化するためのベースラインを提供することを目的としています。最終的な数字は、ライセンス交渉、導入モデルの選択、スコープ管理、データ品質、そして標準のS/4HANAからどこまでカスタマイズするかによって変わります。

この出力は、ベンダーとの会話の出発点として使ってください。SIパートナーの数字がこれより大幅に低い、または高い場合、その差は契約締結前に精査する価値があります。

<details>
<summary>このSAP計算ツールには、どのコスト要素が含まれていますか？</summary>

S/4HANAのライセンスまたはサブスクリプション、BTPサービス、パートナー導入サービス、社内チーム工数、データ移行、ABAPおよびFioriのカスタマイズ、トレーニングとチェンジマネジメント、インフラとホスティング、本番稼働後サポート、そして予備費バッファです。さらに、選択した年数にわたる継続的なAMSと保守も試算します。

「社内チーム工数」は、ほとんどのSI見積りで抜け落ちる項目です。財務リード、basis管理者、プロセスオーナーは、数か月にわたり50%以上をこのプログラムに割くことになります。そのコストは現実のものであり、パートナーの価格表には出てきません。

</details>

<details>
<summary>RISE with SAPやS/4HANA Cloudの各エディションにも対応していますか？</summary>

はい。導入モデルの選択肢には、RISE with SAP、S/4HANA Cloud Public Edition（GROW with SAP）、S/4HANA Cloud Private Edition、そしてS/4HANA on-premiseが含まれています。それぞれライセンス構造が異なります。RISEはインフラと基本サービスをサブスクリプションに含み、Public Editionはカスタマイズ制約がより厳しく、Private Editionはより高コストで自由度が高く、オンプレミスは永続ライセンスに加えて年間約22%の保守費がかかります。

</details>

<details>
<summary>カスタマイズレベルはSAPコストにどう影響しますか？</summary>

大きく影響します。大幅にカスタマイズする企業は、通常、導入費用が30〜50%高くなります。そしてその上振れは本番稼働で終わりません。カスタムのABAPやZコードは保守が必要で、S/4HANAのリリースごとに再テストが必要になり、次のチームへの引き継ぎも必要です。この計算ツールでは、この傾向を反映して、Low、Medium、Highのカスタマイズ係数を適用しています。

最も安いカスタマイズ判断は、たいてい「やらないこと」です。標準のS/4HANAプロセスは何十年もかけて洗練されてきました。まず問うべきは、その逸脱が競争優位を生むのか、あるいは規制要件を満たすためなのかです。答えが「昔からそうやってきたから」なら、見直した方がいいです。

</details>

<details>
<summary>この計算ツールはどのモジュールに対応していますか？</summary>

標準的なS/4HANAモジュール群に対応しています。財務会計（FI）、管理会計（CO）、在庫購買管理（MM）、販売管理（SD）、生産計画（PP）、品質管理（QM）、設備保全（PM）、人材管理（HCM via SuccessFactors）、調達（Ariba）、そしてGroup Reportingです。モジュールを追加するたびに、設定と統合作業は増えます。この計算ツールはそれを織り込んでいます。

</details>

<details>
<summary>この見積りはSAPのビジネスケースに使えますか？</summary>

はい。出力は、S/4HANAプログラムの取締役会レベルの投資ケースを支えることを想定したサイズになっており、単一値ではなくレンジで示すことで、内在する不確実性が見えるようにしています。ステアリングコミッティに持ち込む資料には、カテゴリ別内訳と予備費の前提を必ず含めてください。

もしSIパートナーがビジネスケースも書いているなら、それは問題です。インセンティブが一致していません。パートナーの商業的利害の外で算出された独立した数字。それがこの計算ツールのポイントです。

</details>

<details>
<summary>継続的なSAP保守とサポートはどう考えるべきですか？</summary>

継続的な保守、アプリケーションマネジメントサービス（AMS）、追加改善には、年間で総導入費用の15〜20%を見込んでください。この計算ツールは、指定した年数にわたってこれを試算するため、複数年の視点を最初から取締役会資料に載せられます。

ハイパーケア（本番稼働後の最初の30〜90日）への予算が不足している企業は、テストで捕捉できたはずの問題の修正に、結果として3か月分の契約要員日額に相当する費用を払うことがよくあります。適切なハイパーケア投資は、通常、総プロジェクト費用の3〜5%です。これは契約締結前に契約へ入れておくべきです。

</details>

<details>
<summary>RISE with SAPは、S/4HANAをオンプレミスで運用するより安いですか？</summary>

必ずしもそうではありません。比較すべき期間は5〜7年であり、そこが意味のある比較ウィンドウです。RISEは初期費用が低く、予測しやすいサブスクリプションで、ハイパースケーラー調達を管理する必要もありません。ただし、サブスクリプションは毎年積み上がります。オンプレミスのS/4HANAは、初期ライセンス費用とインフラ支出が高い一方、サブスクリプションはなく、年間保守はライセンス費用の約22%です。

既存のbasis運用能力があり、7年以上の期間で見る組織では、TCOでオンプレミスの方が低く出ることがよくあります。スタック管理をSAPに任せたい組織や、CapexよりOpexを好む組織では、RISEが勝ちます。この計算ツールなら両方をモデル化できます。

</details>
