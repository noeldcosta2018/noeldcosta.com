我做这个计算器，是想在 CIO 和 CFO 与一线系统集成商面对面谈判之前，先给他们一个站得住脚的区间。它专门针对 SAP：S/4HANA Cloud、本地部署的 S/4HANA、BTP 和 RISE with SAP。不是通用 ERP。SAP 项目的成本结构，与 NetSuite 或 Dynamics 的推广实施不同，计算器反映的正是这一点。

它在真正重要的意义上也不绑定厂商：我不卖实施服务。这些数字来自我跟踪过的 50 多个项目，而不是价格表。

## 计算公式

估算结果由 SAP 定价所特有的固定部分和可变部分组合而成。

**项目成本 = (许可或订阅费 × 用户数 × 部署系数) + 合作伙伴实施服务 + 数据迁移 + 定制与 ABAP 开发 + 培训与变革 + BTP 与基础设施 + 上线后支持 + 应急储备**

对于 RISE 和 S/4HANA Cloud，许可部分是订阅费，按 Full Use Equivalent（FUE）用户数和版本来定价。对于本地部署的 S/4HANA，则是永久许可，外加约为许可费 22% 的年度维护费。国家系数和定制化系数会调整最终区间。结果中会按类别给出明细，让您看清钱到底花在了哪里。

## SAP 实施的真实成本

多数 SAP 项目在整个实施周期内，最终花掉的金额相当于**年收入的 2% 到 6%**。落点取决于企业规模、行业复杂度、监管负担，以及您打算偏离标准多远。

1. **小型企业（200 人以下）**：通常为 15 万至 50 万美元。范围有限，使用 FI、CO、MM 等标准模块，常见的是 Business One 或 GROW with SAP。
2. **中型企业（200 至 1000 人）**：50 万至 200 万美元。模块范围更广，集成范围实实在在，常见的是 RISE 或 S/4HANA Cloud Public Edition。
3. **大型企业（1000 人以上）**：200 万至 1000 万美元以上。多主体、多国家，FI/CO 采用并行分类账，监管复杂，常见的是 S/4HANA Cloud Private Edition 或本地部署。
4. **全球性集团（1 万人以上）**：1000 万至 5000 万美元以上。多区域推广，集团合并，大规模变革。

行业很重要。我帮助一家制造业客户纠正了许可组合，砍掉不需要的模块，把许可成本降低了 32%。另一家客户差一点就要签下他们并不需要的高级支持服务：一次合同调整，每年就为他们省下 22 万美元。在任何人碰配置界面之前，省钱的空间就已经在合同里了。

## 按类别划分的成本构成

在我主持过的大多数 SAP 项目中，支出大致是这样分布的。

| 类别 | 典型占比 | 涵盖内容 |
|---|---|---|
| 合作伙伴实施服务 | 30% 至 45% | 一线系统集成商的咨询、配置、项目管理、SAP Activate 交付 |
| 软件许可或订阅 | 15% 至 25% | S/4HANA 各版本、BTP 服务、RISE 套餐、附加产品（Ariba、SuccessFactors、Concur） |
| 内部团队投入的时间 | 10% 至 20% | 流程负责人、FI/CO 负责人、Basis 管理员、业务专家（很少出现在供应商报价中） |
| 数据迁移 | 5% 至 15% | 遗留系统数据抽取、清洗、SAP Migration Cockpit、验证 |
| 定制与 ABAP 开发 | 5% 至 15% | ABAP、CDS 视图、Fiori 应用、BTP 扩展、通过 CPI 的集成 |
| 培训与变革管理 | 5% 至 10% | 最终用户培训、关键用户、沟通、SAP Enable Now 内容 |
| BTP 与基础设施 | 5% 至 10% | BTP 服务、私有云的超大规模云服务商托管、网络、中间件 |
| 上线后支持与应急储备 | 10% 至 15% | Hypercare、AMS、范围变更、未预见的需求 |

紧贴 S/4HANA 标准流程的企业，落在较低的一端。什么都要定制的企业，落在较高的一端。在大多数 SAP 项目里，定制化是最可控的单一变量。

S/4HANA 许可或订阅、BTP 服务、合作伙伴实施服务、内部团队投入的时间、数据迁移、ABAP 和 Fiori 定制、培训与变革管理、基础设施与托管、上线后支持，以及应急储备。它还会按您选定的年数，测算持续发生的 AMS 和维护费用。

<details>
<summary>它涵盖 RISE with SAP 和 S/4HANA Cloud 各版本吗？</summary>

涵盖。部署模式选择器包括 RISE with SAP、S/4HANA Cloud Public Edition（GROW with SAP）、S/4HANA Cloud Private Edition 和本地部署的 S/4HANA。每一种的许可形态都不同：RISE 把基础设施和基础服务打包进订阅费，Public Edition 对定制的限制更严，Private Edition 自由度更高但成本也更高，本地部署则是永久许可，外加约 22% 的年度维护费。

</details>

<details>
<summary>定制化程度如何影响 SAP 成本？</summary>

影响很大。大量定制的企业，实施阶段通常要多花 30% 到 50%，而且这部分额外开销不会在上线时结束。定制的 ABAP 和 Z 代码需要维护，每个 S/4HANA 版本发布都要重新测试，还要交接给下一个团队。计算器对低、中、高三档定制化分别应用一个系数，反映的就是这种规律。

最便宜的定制决策，通常是不做定制。S/4HANA 的标准流程经过几十年的打磨。关键的门槛问题是：这种偏离能否给您带来竞争优势，或者是否用来满足监管要求。如果答案是“我们一直都是这么做的”，请重新考虑。

</details>

<details>
<summary>SAP 的持续维护和支持怎么算？</summary>

请按每年实施总成本的 15% 到 20%，来规划持续的维护、应用管理服务（AMS）和增量改进。计算器会按您指定的年数做出预测，让多年期的视图从一开始就出现在董事会文件中。

对上线后强化支持期（Hypercare，即上线后的头 30 到 90 天）投入不足的企业，往往要付出相当于三个月外部顾问日费的代价，去修复本该在测试中发现的问题。合适的 Hypercare 投入通常是项目总成本的 3% 到 5%，并且应当在签约前就写进合同。

</details>

<details>
<summary>RISE with SAP 比本地部署 S/4HANA 更便宜吗？</summary>

放在五到七年的周期里看，不一定。五到七年，才是有意义的比较窗口。RISE 的前期成本较低，订阅费可预测，也不用自己去采购超大规模云服务商的资源，但订阅费每年都在累积。本地部署的 S/4HANA 前期许可成本和基础设施支出更高，但没有订阅费，年度维护费约为许可费的 22%。

对于已经具备 Basis 能力、并且时间跨度在七年以上的组织，本地部署的总拥有成本（TCO）往往更低。对于希望由 SAP 来管理整套技术栈、并且更倾向运营支出（Opex）而非资本支出（Capex）的组织，RISE 更有优势。计算器可以让您对两种方案都建模。

</details>
