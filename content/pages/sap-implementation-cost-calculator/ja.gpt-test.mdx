ほとんどのSAPプログラムは、間違った数字のまま取締役会に上がります。ライセンスは適切にサイジングされても、それ以外のすべて（パートナーサービス、設定、データ移行、トレーニング、チェンジ、稼働後サポート）は、1つの予備費の行に押し込まれ、カットオーバーに入ると持ちこたえません。

私はこの計算ツールを、CIOやCFOがtier-1 SIとテーブルを挟んで向き合う前に、根拠のあるレンジを持てるように作りました。これはSAPに特化しています。S/4HANA Cloud、S/4HANA on-premise、BTP、そしてRISE with SAPです。汎用的なERPではありません。SAPプログラムのコスト構造は、NetSuiteやDynamicsの導入とは違います。この計算ツールはその違いを反映しています。

また、重要な意味でベンダーニュートラルでもあります。私は導入を売っているわけではありません。数字は価格表ではなく、私が追跡してきた50件超のプログラムから出しています。

## 使い方

以下のフォームに入力してください。数字に最も大きく影響するのは、ユーザー数、対象モジュール、導入モデル（RISE、パブリッククラウド、プライベートクラウド、オンプレミス）、国、そしてカスタマイズ水準です。初期値は典型的なミッドマーケットのパターンを反映しています。自社の状況に合わせて調整してください。

この計算ツールは完全にブラウザ内で動作します。どこにも送信されず、何も保存されません。必要なだけ何度でもリフレッシュしてやり直せます。

## 計算式

この見積りは、SAPの価格体系に特有の固定要素と変動要素を組み合わせています。

**プログラム費用 = （ライセンスまたはサブスクリプション × ユーザー数 × 導入モデル係数） + パートナー導入サービス + データ移行 + カスタマイズとABAP開発 + トレーニングとチェンジ + BTPとインフラ + 稼働後サポート + 予備費**

RISEとS/4HANA Cloudでは、ライセンス要素はサブスクリプションで、Full Use Equivalent (FUE)ユーザー数とエディションで決まります。オンプレミスのS/4HANAでは、永続ライセンスに加えて、ライセンス費用の約22%の年間保守がかかります。国別係数とカスタマイズ係数で最終レンジを調整します。カテゴリ別の内訳は結果に表示されるので、実際にどこに費用が落ちるのか確認できます。

## SAP導入の実際の費用

ほとんどのSAPプログラムでは、導入ライフサイクル全体で**年間売上高の2〜6%**を使うことになります。どこに着地するかは、企業規模、業界の複雑さ、規制負荷、そして標準からどこまで外れるつもりかで決まります。

1. **小規模企業（従業員200人未満）:** 通常は$150K〜$500K。対象範囲は限定的で、FI、CO、MMのような標準モジュールが中心です。多くはBusiness OneまたはGROW with SAPです。
2. **ミッドマーケット（従業員200〜1,000人）:** $500K〜$2M。モジュール構成は広がり、実際の統合スコープも出てきます。RISEまたはS/4HANA Cloud Public Editionが一般的です。
3. **大企業（1,000人超）:** $2M〜$10M+。複数法人、複数国、並行元帳を伴うFI/CO、規制対応の複雑さがあり、S/4HANA Cloud Private Editionまたはオンプレミスになることが多いです。
4. **グローバル複合企業（10,000人超）:** $10M〜$50M+。複数地域へのロールアウト、グループ連結、大規模なチェンジが伴います。

業界は重要です。私はある製造業のクライアントで、ライセンス構成を見直し、不要なモジュールを削ることで、ライセンス費用を32%削減しました。別のクライアントは、不要なプレミアムサポートに署名する寸前でした。契約を1点調整しただけで、年間$220,000を削減できました。節約余地は、誰かが設定画面に触る前、つまり契約の中にあります。

## カテゴリ別の費用内訳

私が担当してきたほとんどのSAPプログラムでは、費用配分はおおむね次のようになります。

| カテゴリ | 一般的な比率 | 含まれる内容 |
|---|---|---|
| パートナー導入サービス | 30–45% | Tier-1 SIのコンサルティング、設定、プロジェクト管理、SAP Activateによるデリバリー |
| ソフトウェアライセンスまたはサブスクリプション | 15–25% | S/4HANAの各エディション、BTPサービス、RISEバンドル、アドオン（Ariba、SuccessFactors、Concur） |
| 社内チーム工数 | 10–20% | プロセスオーナー、FI/COリード、basis管理者、業務SME（ベンダー見積りにはまず入っていません） |
| データ移行 | 5–15% | レガシーからの抽出、クレンジング、SAP Migration Cockpit、検証 |
| カスタマイズとABAP開発 | 5–15% | ABAP、CDSビュー、Fioriアプリ、BTP拡張、CPI経由の連携 |
| トレーニングとチェンジマネジメント | 5–10% | エンドユーザートレーニング、スーパーユーザー、コミュニケーション、SAP Enable Nowコンテンツ |
| BTPとインフラ | 5–10% | BTPサービス、プライベートクラウド向けハイパースケーラーホスティング、ネットワーク、ミドルウェア |
| 稼働後サポートと予備費 | 10–15% | ハイパーケア、AMS、スコープ変更、想定外の要件 |

標準のS/4HANAプロセスに近い企業は、低い方に着地します。何でもカスタマイズする企業は、高い方に着地します。カスタマイズは、ほとんどのSAPプログラムで最もコントロールしやすい変数です。

<summary>この計算ツールのSAP費用見積りはどの程度正確ですか？</summary>

この見積りは、SAP特有の価格パターンと、私が追跡してきた50件超のプログラムに基づいています。固定価格の見積書ではなく、予算策定のための根拠あるベースラインを提供することを目的にしています。最終的な数字は、ライセンス交渉、導入モデルの選択、スコープ統制、データ品質、そして標準S/4HANAからどこまでカスタマイズするかで変わります。

この出力は、ベンダーとの会話の出発点として使ってください。SIパートナーの数字がこれより大幅に低い、または高いなら、その差は契約締結前に掘り下げる価値があります。

<details>
<summary>このSAP計算ツールには、どの費用要素が含まれていますか？</summary>

S/4HANAのライセンスまたはサブスクリプション、BTPサービス、パートナー導入サービス、社内チーム工数、データ移行、ABAPおよびFioriのカスタマイズ、トレーニングとチェンジマネジメント、インフラとホスティング、稼働後サポート、そして予備費バッファです。さらに、選択した年数にわたる継続的なAMSと保守も見込みます。

「社内チーム工数」は、ほとんどのSI見積りで抜け落ちる項目です。財務リード、basis管理者、プロセスオーナーは、何か月にもわたって50%以上このプログラムに張り付くことになります。このコストは現実のもので、パートナーの価格表には出てきません。

<details>
<summary>RISE with SAPやS/4HANA Cloudの各エディションにも対応していますか？</summary>

はい。導入モデルの選択肢には、RISE with SAP、S/4HANA Cloud Public Edition（GROW with SAP）、S/4HANA Cloud Private Edition、そしてS/4HANA on-premiseが含まれています。それぞれライセンス構造が異なります。RISEはインフラと基本サービスをサブスクリプションに含み、Public Editionはカスタマイズ制約がより厳しく、Private Editionはより自由度が高い一方で費用も上がります。オンプレミスは永続ライセンスに加え、年間約22%の保守がかかります。

</details>

<details>
<summary>カスタマイズ水準はSAP費用にどう影響しますか？</summary>

大きく影響します。大幅にカスタマイズする企業は、通常、導入費用が30〜50%高くなります。そしてその上振れは本稼働で終わりません。カスタムのABAPやZコードは保守が必要で、S/4HANAのリリースごとに再テストし、次のチームへ引き継がなければなりません。この計算ツールでは、Low、Medium、Highのカスタマイズ係数でこの傾向を反映しています。

最も安いカスタマイズ判断は、たいてい「やらないこと」です。標準のS/4HANAプロセスは何十年もかけて磨かれてきました。まず問うべきは、その逸脱が競争優位を生むのか、あるいは規制要件を満たすためなのかです。答えが「昔からそうしてきたから」なら、見直した方がいいです。

</details>

<details>
<summary>この計算ツールはどのモジュールに対応していますか？</summary>

標準的なS/4HANAモジュール群です。Financial Accounting (FI)、Controlling (CO)、Materials Management (MM)、Sales and Distribution (SD)、Production Planning (PP)、Quality Management (QM)、Plant Maintenance (PM)、Human Capital Management (HCM via SuccessFactors)、Procurement (Ariba)、そしてGroup Reportingです。モジュールを追加するたびに、設定と統合作業は増えます。この計算ツールはそれを織り込んでいます。

</details>

<details>
<summary>この見積りはSAPのビジネスケースに使えますか？</summary>

もしSIパートナーがビジネスケースも書いているなら、それは問題です。インセンティブが一致していません。パートナーの商業的利害の外で計算された独立した数字を持つこと。それがこの計算ツールのポイントです。

<details>
<summary>継続的なSAP保守とサポートはどう考えればよいですか？</summary>

継続的な保守、アプリケーションマネジメントサービス（AMS）、追加改善には、年間で総導入費用の15〜20%を見込んでください。この計算ツールでは、指定した年数にわたってこれを投影するので、複数年の視点を最初から取締役会資料に載せられます。

ハイパーケア（本稼働後30〜90日）への予算を削りすぎた企業は、テストで見つけるべきだった問題の修正に、結果として3か月分の契約者日額相当を払うことがよくあります。適切なハイパーケア投資は通常、総プロジェクト費用の3〜5%です。しかも契約締結前に契約へ入れておくべきです。

</details>

<details>
<summary>RISE with SAPは、S/4HANAをオンプレミスで運用するより安いですか？</summary>

必ずしもそうではありません。比較すべき期間は5〜7年であり、そこが意味のある比較窓です。RISEは初期費用が低く、サブスクリプションも予測しやすく、ハイパースケーラー調達を自社で管理する必要もありません。ただし、サブスクリプションは毎年積み上がります。オンプレミスのS/4HANAは、初期ライセンス費用とインフラ費用が高い一方、サブスクリプションはなく、年間保守はライセンス費用の約22%です。

既存のbasis運用能力があり、7年以上の期間で見る組織では、オンプレミスの方がTCOで低く出ることがよくあります。逆に、スタック管理をSAPに任せたい組織や、CapexよりOpexを好む組織では、RISEが勝ちます。この計算ツールなら両方をモデル化できます。

</details>
